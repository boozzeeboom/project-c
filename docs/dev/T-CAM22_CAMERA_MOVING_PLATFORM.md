# T-CAM22 — SpringArm дёргается на движущейся платформе (паром)

> **Файл:** `Assets/_Project/Scripts/Core/SpringArmCamera.cs`
> **Симптом (от пользователя):** стоя на кабинке парома в движении персонаж выглядит
> нормально, а камеру «сильно дёргает туда-сюда»; «микролаги платформы накладываются».

## 1. Что происходит на самом деле

Персонаж на пароме движется не сам: `NetworkPlayer.ApplyPlatformCarry()` каждый кадр
добавляет к его `CharacterController.Move()` дельту трансформа кабинки (только
translation + yaw). Поэтому **позиция цели камеры — это позиция платформы**, и все
особенности её сигнала камера видит как «движение игрока».

Два независимых механизма ломали именно камеру:

### 1.1 Ступеньки сетевых тиков во входе лага

Кабинку двигает `ParomRoute.Update()`:
- хост/оффлайн — `_trolley.position = worldPos` каждый кадр (гладко);
- клиент — из `NetworkVariable<float> _netS`, которая меняется **тиком сети** (30 Гц).

То есть на клиенте позиция цели — ступенчатая функция: 33 мс стоит, потом прыжок
~0.15–0.3 м (9 м/с × тик).

`UpdateLag()` считал «скорость» как `|target.position − _lagTargetPos| / dt`. Это не
скорость, а остаток пружины: на ступеньке он скачет `0 → 18 м/с → 0` **каждый тик**.
Дальше:
- `dynamicLagEnabled` менял `effXZ` (`0.15 → 0.045 c`) с частотой тика;
- гистерезис `vertBoost` (`6.5 / 3.5 м/с`) щёлкал туда-обратно;
- каскад exp-фильтров (`UpdateLag` → `SmoothPosition` → `UpdateLookAt`) превращал
  ступеньку в пилообразный «догон-стоп-догон» — визуально «туда-сюда».

### 1.2 Anti-pop держал точку в МИРОВЫХ координатах

`ResolveCollision()` при кратком промахе `SphereCast` отдаёт замороженную
`_lastCollisionPos` (мировая точка). На пароме (9 м/с) она уезжает вместе с миром,
пока игрок едет: камера приклеена к точке в воздухе, затем срывается.

Плюс stale-guard (`antiPopStaleDistance = 0.35 м`) на 9 м/с истекает за ~40 мс —
то есть на движущейся платформе защита не работала вообще: камера каждый кадр
прыгала между «упёрлась в стену» и «свободно».

## 2. Что изменено (всё — только камера)

1. **`Target Signal` (новые поля):**
   - `targetSignalInterpolation` (вкл) — лаг читает не `target.position`, а сэмпл
     из истории позиции цели;
   - `targetSignalDelay` (0.07 с) — насколько камера отстаёт от цели; должен быть
     ≥ одного сетевого тика (30 Гц ≈ 0.033 с; 0.07 — с запасом на джиттер).
   История: `SampleTargetPosition()` копит `(Time.time, position)` (обрезка до
   `max(delay*2, 0.2) c`), `EvaluateTargetSample()` линейно интерполирует на
   `now − delay`. Ступенька становится равномерным движением, ценой задержки в тик.
   Телепорт (> 10 м за кадр) историю сбрасывает — камера не поедет через мир.
2. **Скорость цели** считается по сглаженному сэмплу (`_sampledTargetVelocity`),
   а не по остатку пружины. `dynamicLag` и `vertBoost` перестали дребезжать и
   больше не зависят от fps (раньше `остаток / dt` зависел).
   Задержка сэмпла при этом **вычитается из времени лага** (пол — 20% от базы),
   чтобы суммарная инерция осталась спроектированной (walk 0.15/0.05 с), а не
   складывалась с задержкой: иначе на 9 м/с персонаж уезжал бы с центра экрана.
3. **Anti-pop относительно цели:** `antiPopFollowTarget` (вкл) — позиция холда
   = `_lagTargetPos + (_lastCollisionPos − _collisionLagPos)`, то есть замороженная
   точка едет вместе с платформой и держит дистанцию до стены. Держится окном по
   времени (`antiPopTime` 0.2 с), мировой stale-guard на этом пути не применяется.
   Выкл = старое поведение (`_lastCollisionPos` в мире + stale-guard).
4. Шип-режим (`_isShip`) намеренно **без** задержки: цель корабля двигает
   `NetworkTransform` с интерполяцией (сигнал уже гладкий), лаг там и так выключен.

FO-контракт сохранён: история сэмплов — мировые точки, едет в
`TryApplyGlobalMotionCameraTranslation()`; на restore (`TryRestoreGlobalMotionCameraHistory`)
история сбрасывается на текущую лаг-цель; `_sampledTargetPos` / `_prevSampledTargetPos`
добавлены в finite-check. Структура `GlobalMotionCameraHistorySnapshot` не менялась.

## 3. Тюнинг без перекомпиляции (инспектор префаба `ThirdPersonCamera`)

| Поле | Дефолт | Что делает |
|---|---|---|
| `targetSignalInterpolation` | on | выкл = камера снова читает сырую позицию цели |
| `targetSignalDelay` | 0.07 | больше = глаже, но камера «позже»; меньше = отзывчивее, риск остаточной ступеньки |
| `antiPopFollowTarget` | on | выкл = старое мировое anti-pop поведение |

## 4. Откат

- Мягкий: `targetSignalInterpolation = false`, `antiPopFollowTarget = false` — код
  идёт по старым веткам один в один.
- Жёсткий: revert коммита (только `SpringArmCamera.cs` + эта нота + чейнджлог).

## 5. Проверка (Play Mode — пользователем, агент не запускает)

1. Клиент на пароме в движении: камера едет ровно, без «догон-стоп»; горизонт не дёргается.
2. Хост на пароме — регрессии нет (движение плавное, лаг тот же на вид).
3. Пешком/бег по земле — инерция как раньше (добавлена только задержка сэмпла 0.07 с).
4. Стоя у стены: подошёл — поджалась и стоит; отошёл — отъехала (~0.3 с), без
   «мячика» и без рывка при отпускании anti-pop.
5. Прыжок/падение — вертикальный boost срабатывает, без брыков.
6. Корабль (ship-режим) и зум колесом — без изменений.
7. F8/F9 (floating origin) — попа камеры нет, 0 ошибок в Console.
