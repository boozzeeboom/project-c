## 2. Измеренная проблема (до изменения)

### 2.1 Плотность источников

| Метрика | Значение |
|---|---|
| Источников под `WorldRoot_0_0/PRIMUM_LIGHTS` | **2 087** (19 чанков) |
| Группы | `PRIMUM_OUTLIGHT` 753, `PRIMUM_INLIGHT` 1 334 (из них ADMIN — 530) |
| Пул (`PrimumLightPool`) | `maxActive` 96, `activeRadius` 140 м, `checkInterval` 0.25 с, `hysteresis` 0.1 |
| Источников в радиусе 140 м от типовой точки | медиана **412**, p90 664, максимум 867 |
| Выборок, где в радиусе ≤ 96 источников | **0 из 418** (100 % переполнено) |
| Расстояние до 96-го ближайшего | медиана **46.7 м**, p10 20.8 м, p90 68.9 м |
| Источников в радиусе 6 м от лампы | медиана **4**, p90 10, максимум 18 |
| `Light.range` | min 3.5 / медиана **6.0** / max 14.0 м |

Вывод: лимит 4 на объект переполняется уже в радиусе 6 м почти на каждой поверхности.

### 2.2 Ограничения рендера (до изменения)

| Параметр | Значение | Файл |
|---|---|---|
| Rendering path | `Forward` (`m_RenderingMode: 0`) | `ProjectC_URP_Renderer.asset` |
| Additional Lights | `PerPixel` (`m_AdditionalLightsRenderingMode: 1`) | `ProjectC_URP.asset` |
| Per-object limit | **4** (`m_AdditionalLightsPerObjectLimit`) | `ProjectC_URP.asset` |
| `maxPerObjectLights` (жёсткий потолок шейдерного цикла) | **8** | URP `UniversalRenderPipeline.maxPerObjectLights` |
| Тени дополнительных источников | **выключены** (`m_AdditionalLightShadowsSupported: 0`) | `ProjectC_URP.asset` |
| HDR / MSAA | HDR off / MSAA 1 | `ProjectC_URP.asset` |
| SRP Batcher / Dynamic Batching | on / off | `ProjectC_URP.asset` |

### 2.3 Почему это давало два симптома

- **«Вспыхивает на определённом угле камеры»** — рендерер получает только 4 ближайших источника из отсечённых по камере; при повороте четвёрка «победителей» пересобирается рывком. Плюс пул щёлкает `Light.enabled` в одном кадре (без плавности), а гистерезис обесценен: `_desired` режется по расстоянию, а не по состоянию «уже горит».
- **«Загорается только в упор»** — бюджет 96 на 412+ источников в радиусе 140 м: всё дальше ~20–47 м пул просто выключает.

### 2.4 Что ещё показала сцена (ограничения для альтернатив)

| Факт | Значение |
|---|---|
| Рендереров в `PRIMUM` | 19 944 |
| `isStatic` / запечённый лайтмап | 0 / 0 |
| `LightProbeGroup` в сцене | 0 групп, 0 проб |
| Мешей с вершинными цветами | 0 |
| Материалов | 444 (443 `URP/Lit`, 1 `Unlit` — эмиссия лампы `PM_LAMP_GLOW_WARM`) |
| Decal Renderer Feature | отсутствует (3 фичи: EdgeDetection, VolumetricClouds, DistantFocus) |

Запекание GI и пробы в текущей архитектуре недоступны: правила проекта запрещают static-флаги (Floating Origin), а система проб не развёрнута.

## 3. Что изменено

| | Было | Стало |
|---|---|---|
| `ProjectC_URP_Renderer.m_RenderingMode` | `0` (Forward) | **`2` (ForwardPlus)** |
| `renderingMode` в рантайме (проверено) | Forward | **ForwardPlus** |
| `UniversalRenderPipeline.maxVisibleAdditionalLights` | — | **256** (D3D12, desktop) |
| `settings.maxAdditionalLightsCount` (per-object limit) | 4 | 4 — **в Forward+ не применяется** |

`Forward+` использует кластерный световой цикл (`UniversalRenderer.usesClusterLightLoop`), индекс источников на объект берётся из кластеров, а не из списка «4 ближайших». Потолок — 256 видимых дополнительных источников на камеру.

Остальные настройки URP **не менялись**: `PerPixel`, тени дополнительных источников выключены, HDR off, MSAA 1, рендер-фичи прежние.

## 4. Пилот: здание ADMIN

### 4.1 Объект пилота

| Параметр | Значение |
|---|---|
| Чанк | `PRIMUM_ADMIN_S0_ADM_P1_01H` |
| Источников | **530** (PENDANT 26 / SCONCE 421 / TABLE 83) |
| Габарит облака источников | 71 × 19 × 124 м |
| Источников в 140 м от центра | **631** |
| `Light.range` ADMIN | 3.5 … 8 м (521 переопределён) |
| Y источников | 2502.40 … 2521.43 |

ADMIN выбран потому, что это единственная зона, где плотность источников на единицу объёма максимальна, есть 4 этажа, крылья, библиотека с двойным просветом и главный зал — то есть все типовые интерьерные условия сразу.

### 4.2 Что должен сделать пользователь (Play Mode, вручную)

1. Ночь (время 21–24), зайти в ADMIN, встать в главном зале.
2. Пройти весь первый этаж: зал → ресепшн → лестница → коридор к крыльям.
3. Подняться на 2-й и 3-й этаж, пройти библиотеку и оба крыла.
4. В каждой точке **повернуть камеру на 360°** и зафиксировать: есть ли «вспышки» и «пропадания» света на поверхностях.
5. Записать строку из консоли: `[PRIMUM/Lights] фокус: … , активных источников: N из 2087`.

### 4.3 Ворота приёмки пилота

| № | Ворота | Как измеряется | Порог |
|---|---|---|---|
| G1 | Все включённые пулом источники реально освещают поверхности | визуально, поворот камеры в 3–4 точках ADMIN | нет «пропадания» света на стене при повороте |
| G2 | Бюджет пула не голодает внутри здания | лог пула | `N` ≥ 90 при нахождении в ADMIN |
| G3 | Нет новых ошибок/предупреждений URP | Console после входа в здание | 0 новых записей |
| G4 | Стоимость кадра приемлема | Profiler / GPU ms, кадр в ADMIN vs кадр на улице вне здания | прирост ≤ **+2.0 мс** GPU на кадр |
| G5 | Нет артефактов Forward+ на существующих фичах | EdgeDetection, VolumetricClouds, DistantFocus визуально | без изменений относительно Forward-базиса |
| G6 | День/ночь и группы не сломаны | переключение времени суток | интенсивности `PRIMUM_OUTLIGHT`/`PRIMUM_INLIGHT` работают как раньше |

**Пилот принят**, если G1–G6 выполнены. **Пилот отклонён**, если провален G1, G2 или G4.

### 4.4 Если G2 провален (бюджет, а не лимит)

`maxActive` пула поднимается 96 → 160…192 (потолок Forward+ — 256), `activeRadius` можно уменьшить 140 → 90–100 м, чтобы бюджет тратился на видимую зону. Это отдельное изменение и отдельный коммит.

## 7. План Б — если пилот отклонён

Направление: интерьерный свет перестаёт быть настоящими `Light`-компонентами. Обоснование из §2: теней у дополнительных источников нет (свет проходит сквозь стены), лимит на объект жёсткий, а `LightProbeGroup`/GI в проекте отсутствуют.

| Шаг | Что делается | Стоимость |
|---|---|---|
| B1 | Интерьерные `PRIMUM_INLIGHT` внутри зданий (1 334, включая ADMIN 530) не создаются; остаются только уличные | −1 334 реальных источника |
| B2 | Интерьерный вариант материала: `SH/ambient × _InteriorAmbient`, глобальное значение ведёт `AdditionalLightIntensityController` (0.2–0.4 днём, 1.0 ночью) | 1 глобальное свойство |
| B3 | Аддитивное «пятно» у светильника: плоский quad с Unlit Additive, глобальный `_InteriorGlow` по кривой `PRIMUM_INLIGHT` | 0 источников, фрустум-каллинг бесплатный |
| B4 | (опционально, если нужен объём) fake point lights: до 4 ламп на объект через `MaterialPropertyBlock` в object space, затухание в шейдере | 0 источников, математика в шейдере |

Пилот Б тоже начинается с ADMIN: B2+B3 на ADMIN, проверка G1/G3/G6, затем весь город.

Что в плане Б **не используется** и почему:

- запечённые лайтмапы — `isStatic = 0`, 19 944 рендерера, запрет static-флагов из-за Floating Origin;
- `LightProbeGroup` — 0 групп, запекание + мировые координаты ломаются при rebase;
- декали — в рендерере нет `DecalRendererFeature`;
- возврат к большему числу реальных ламп — `m_AdditionalLightShadowsSupported: 0`, свет не удерживается стенами.

## 8. Риски Forward+

| Риск | Оценка | Контроль |
|---|---|---|
| Рост GPU-времени на кластерный световой цикл | средний; зависит от числа пикселей и источников в кластере | G4 (≤ +2.0 мс) |
| Память под кластеры/тайлы | низкий для desktop (96 источников < 256) | Profiler Memory |
| Несовместимость на мобильных/GLES | `maxVisibleAdditionalLights` = 32 на мобильном стеке | не целевая платформа сейчас; при сборке под мобильные — отдельная проверка |
| Расхождение с ванильным Forward в рендер-фичах проекта | низкий, фичи не зависят от per-object light loop | G5 |
| Двухкамерность (`MainCamera` в BootstrapScene + `ThirdPersonCamera`) | не влияет на путь рендера, только на выбор фокуса пула | уже решено в `PrimumLightPool.FindFocusCamera` |
