# 20 — Координация вылетов из дока (T-NS-DEPART4)

> **Дата:** 2026-11-25 | **Код:** `NpcShipController.cs`, `NpcShipTrafficManager.cs`, `NpcProximityZone.cs`
> **Связано с:** `11_DOCK_NAV_RESEARCH.md` §5 (п. 5 «departure mutex»), ITERATIONS T-NS-WF06c / T-NS-DEPART3.

## 1. Симптомы (от пользователя)

1. Много кораблей в доке города по окончании dwell взлетают **все сразу** и
   толкаются корпусами.
2. На взлёте большие корабли **поднимают хвост, нос остаётся** — вплоть до
   переворота. После выхода в `Cruising` всё выправляется само.

## 2. Корневые причины (по коду, до правок)

### P0 — мьютекс вылета ждал один тик

`Docked`-ветка `NavTick` (T-NS-WF06c):

```csharp
if (useDepartureSpacing && Time.time >= _departWaitNextAt) {
    _departWaitNextAt = Time.time + 3f;
    if (!tm.IsDepartureClear(...)) return;   // ждём...
}
// ...а на СЛЕДУЮЩЕМ тике условие Time.time >= _departWaitNextAt ложно,
// блок пропущен целиком — корабль взлетает.
ship.ExitDocked(); SetMode(Lifting);
```

Ожидание длилось 1 FixedUpdate (20 мс): `depart-wait` в логе был, координации — нет.

### P1 — мьютекс отпускался слишком рано и не по тому центру

- Занятым считался только чужой `Lifting`/`Yawing`. Как только первый корабль
  набрал 60 м и развернулся (≈10–15 с), следующий взлетал, пока первый ещё
  шёл низко над доком горизонтально.
- Центр — позиция станции `fromLocationId` маршрута. Корабль, поставленный в
  чужой док (не совпадает с маршрутом), проверял чужую окрестность.
- Не было очереди: кто первый опросил после паузы — тот и полетел
  (недетерминированный порядок, «голодание» отдельных кораблей).

### P1 — ориентацию на взлёте никто не держал

`TickLift` писал `linearVelocity = (0, LiftSpeed, 0)` и `angularVelocity = 0`,
но **поворот не корректировал** (уровень ставился один раз в `SetMode(Lifting)`).
Контактный решатель PhysX (соседний кинематический корабль, козырёк/пад,
выталкивание из перекрытия при снятии `isKinematic`) поворачивает тело внутри
шага; обнуление `angularVelocity` гасит скорость, но накопленный угол остаётся
и копится. Длинный корпус цепляется носом → хвост задирается. `ShipController`
для NPC силы не применяет (`_hasNpcPilot && _pilots.Count == 0 → return`), т.е.
выравнивать некому, пока `TickYaw`/`FlyToward` не перепишут поворот чисто по yaw.

### P2 — фиксированный chimney 60 м

Высокие соседи (Гигант/Пещера/Мастодонт) могут быть выше 60 м над падом
соседа: разворот (`Yawing`) и уход в `Cruising` шли сквозь их корпуса.

## 3. Решение

### 3.1 Очередь + слот вылета (TrafficManager)

`TryAcquireDeparture(npc, radius, minGap, out reason)`:

1. Запрос регистрирует/освежает заявку `npcId → (since, refreshedAt)`.
   Заявки, не освежённые 5 с, протухают (корабль ушёл из Docked/игрок взял управление).
2. **Слот занят**: у соседа в радиусе (по позиции его старта) `IsDepartureActive`.
3. **Пауза**: соседний слот освобождён меньше `departureMinGapSec` назад.
4. **Очередь (FIFO)**: у соседа в радиусе есть живая заявка раньше нашей
   (равенство — меньший `NpcInstanceId`). Полный порядок → без дедлоков.
5. Иначе — разрешение, заявка удаляется.

Центр — **собственная позиция корабля** (док, где он реально стоит).

Контроллер опрашивает раз в `departurePollSec` (1 с) и **между опросами ждёт**
(fix P0). `depart-wait` в Nav-логе пишется только при смене причины.

### 3.2 Удержание слота (контроллер)

Слот выдан в момент взлёта (`_departStartPos`, `_departStartAt`) и держится, пока:

- режим `Lifting`/`Yawing` — всегда;
- иначе — пока горизонтальное удаление от точки старта < `departureClearDistance`
  \+ собственный габарит (полудиагональ XZ коллайдера);
- сброс: `Docked`/`Berthing`, либо `departureHoldMaxSec` (страховка от вечного удержания,
  проверяется в самом свойстве — работает и когда NavTick не идёт, напр. рулит игрок).

### 3.3 Адаптивный chimney

В момент выдачи слота: `climb = max(departClimbMeters, top(соседей) + margin + (y − bottom(своего)) − y)`
по соседям, чьи XZ-габариты (+margin) перекрывают наш. Кап `departClimbMaxMeters`.
Хранится **относительно** `LiftStartY` (`_liftClimb`) — Floating Origin-безопасно.

### 3.4 Удержание ориентации на взлёте

Каждый тик `TickLift`: yaw из проекции `forward` на горизонт (не `eulerAngles.y` —
он врёт при большом тангаже), `MoveRotation(RotateTowards(rot, level, liftLevelRateDeg·dt))`.
Плюс мягкий возврат по XZ к точке старта (≤ `liftHoldXZSpeed`) — корабль не
«съезжает» из своего колодца на соседа после толчка.

## 4. Floating Origin / сейвы

- Новый мировой кэш один: `_departStartPos` — сдвигается в `ApplyRebaseTranslation`.
- `_liftClimb` относительный. Очередь в TrafficManager хранит только id и время.
- Схема сейва не менялась. Восстановленный `Lifting` без `_liftClimb` берёт
  `departClimbMeters`, слот не удерживает (старт уже был до рестарта).

## 5. Kill-switch

`useDepartureSpacing = false` → старт без очереди/слота (как до WF06c).
Выравнивание и адаптивный chimney — всегда (поведение «правильного» взлёта).

## 6. Проверка (вручную, Play Mode — пользователь)

1. 4+ корабля в одном доке с одинаковым dwell.
2. Ожидание: взлетают **по одному**, следующий — только когда предыдущий ушёл по
   горизонтали от своего пада (≈120 м + габарит) и прошла пауза 4 с.
3. Большие корабли поднимаются ровно (тангаж/крен ≈ 0), над крышами соседей.
4. NavLog (при включении): `depart-wait` с причинами `slot:/gap:/queue:`,
   `dwell-done` с `climb=`.
5. F8 во время очереди/подъёма → 0 errors, порядок не ломается.

## 7. T-NS-DEPART5 — выходные курс-гейты (2026-11-25, по фидбэку после DEPART4)

**Фидбэк:** очередность появилась, но корабли всё ещё мешают и таранят друг
друга, а не выходят на свободный курс.

### 7.1 Причины (по коду)

1. После chimney курс шёл **прямо на станцию** (`SetCruiseTarget` → `PlanRoute` от пада):
   все корабли к одной цели — один коридор из дока.
2. `TickCruise` сразу тянул высоту к `ProfileY()` цели (±`returnVerticalCap`) —
   снижение над доком, обратно к соседям.
3. Ship-to-ship avoidance в доке: сферы 120–180 м → конфликт при 240–360 м
   центр-центр. Отлетевший и только что поднявшийся корабли уходили в
   `Separate`/`AvoidYield` прямо над падами — это и был «танец с толчками».
4. Заходящие (`Berthing`) не видны никому (`IsAvoidable`), вылет мог стартовать
   под спускающийся на соседний пад корабль.

### 7.2 Решение

- **Курс-гейт**: кольцо `departGateRadius` (500 м, не меньше clear + 2 габарита)
  вокруг точки старта, `departGateCount` (8) гейтов, гейт 0 — по курсу на первую
  точку плана, затем ±1, ±2… Занят — чужой активный гейт ближе
  `departGateSeparation` (150) + габариты. Гейт вставляется **первой точкой
  `_navPlan`** (FO-сдвиг уже есть, лог `depart-gate k=… busy=…`). Цель ближе
  1.2×R — гейт не нужен.
- `TickYaw` разворачивает на `NavGoal()` (гейт), а не на станцию.
- На плече к гейту `TickCruise` держит **высоту гейта** (верх chimney), не профиль цели.
- Гейт снимается: точка взята (`depart-gate-done reached`), replan/divert
  (`PlanRoute`), Docked/Berthing, таймаут `departureHoldMaxSec`.
- **Расхождение**: пара, где оба `IsDepartureCoordinated` (слот или гейт), не
  маневрирует друг от друга — разводят очередь, разные гейты и радиальные курсы.
  Корабль на плече к гейту видит `Berthing` как препятствие.
- **Прибывающие в очереди**: `arrival:` — `Berthing` с назначенным падом в XZ-досягаемости
  (габариты + 30 м) → ждём, но не дольше 45 с с начала заявки (защита от дедлока
  holding ↔ занятый пад).
- Chimney при гейтах: выше **всех стоящих в доке** внутри кольца (плечо идёт над ними),
  пролётных — только с перекрытием габаритов.

Kill-switch: `useDepartGates = false` → курс как в DEPART4.

### 7.3 Проверка

1. 4+ корабля в доке, одна цель. Ожидание: взлёт по очереди, каждый уходит
   **своим лучом** (разные гейты, ≥45° между соседними), без снижения над доком.
2. Нет `avoid-ship`/`yield-ship` между вылетающими в Nav-логе.
3. Заход на соседний пад во время очереди → `depart-wait arrival:`, потом вылет.
