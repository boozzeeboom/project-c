# Паром — постмортем серии T-PAROM-04…12 + Фаза 1 (T-PAROM-13 внедрён)

> Статус: код серии откачен; идёт инструментированная Фаза 1.
> T-PAROM-13 внедрён (sleepThreshold=0 + replay yaw-only, изолированно).
> Этот документ — честный разбор + журнал замеров. Слепых фиксов не делаем.
> v1: `00_PAROM_DESIGN.md`.

## 1. Исходный симптом (некритичный!)

Стоя на движущейся кабинке/палубе, персонаж немного дёргается; зависит от
скорости платформы и изменения высоты. Увеличение Probe-параметров не помогает
(ожидаемо: они влияют только на детект, не на гладкость дельты). Со слов
плейтестера изначально — «не критично». Серия фиксов сделала хуже стартового —
откачено. Цена/польза: не жечь на это недели, симптом мелкий.

## 2. Методологическая ошибка серии

Чинили вслепую, без инструментов: ни одного замера до/после (кадровый лог
дельт, счётчик миганий `isGrounded`, fps-корреляция). Каждая итерация —
гипотеза + код + «проверь на глаз». Так нашли одно реальное (SmoothStep, §4),
остальное — качели.

## 4. Твёрдая находка: движковый SmoothStep (остаётся true после отката)

Исполнение в редакторе 6000.5.2f1: `SmoothStep(0, 0.15, 0.483) = 0.071`
вместо 1.0 — функция считает Эрмита от сырого `t`, нормализации по диапазону
нет (0.15 × Hermite(0.483) = 0.0712, сошлось до 4-го знака). Документация
обещает обратное. Правило: только `SmoothStep(0, 1, x)` или ручной Эрмит.
Попутно: редактор по факту 6000.5.2f1, в AGENTS pinned 6000.4.1f1 — дрейф
зафиксировать отдельно. Откат этот факт не отменяет: чистый синус провиса
(T-PAROM-02) от SmoothStep не зависит и работает.

## 5. Почему T-PAROM-12 сломал (главный урок)

Два связанных контура, а не один:

- **Контур позиции** (carry-дельта): точный, работает. Арифметика попов
  (bias −2 против вертикали палубы) верна количественно.
- **Контур контакта** (`isGrounded` ← движение вниз; аниматор ← `isGrounded`;
  устойчивость стойки ← контакт): bias −2 — это НЕ только «прижим», это
  СИГНАЛ grounded для CharacterController (флаг выставляется по коллизии
  нисходящего Move).

Убрав bias, убрали сигнал: `isGrounded=false` навсегда → аниматор завис в Fall,
контакт нестабилен → скидывает сильнее. Пенетрацию нельзя чинить удалением
сигнала контакта. Правильные направления (на будущее, не сейчас): гистерезис
репорта `isGrounded` наружу при сохранении физического bias; малый bias
вместо −2 (компромисс, мерить); репорт `IsGrounded=true` пока `_onPlatform`.

## 6. План нормального ресерча (Фаза 1 введена)

1. Инструменты СНАЧАЛА: T-DIAG-FERRY (маркер для поиска/удаления).
   `ParomRoute`: постоянный gated-лог пути раз в секунду (`_debugLog`:
   s, позиция, yaw, dir, сон/скорость RB) — дважды пригождался, оставляем.
   `NetworkPlayer` (ВРЕМЕННО, удалить после замеров): пока `_onPlatform` —
   флики `isGrounded`/с, входы в Fall/с, макс. вертикаль carry-дельты за
   секунду (мм), fps, макс. dt кадра (мс) и кадры с dt > 50 мс (ловля фризов).
   Лог `[DIAG-FERRY]` раз в секунду. Поведение не меняют.
2. Замер baseline на откаченном коде (лог `паром_2.txt`, проезд в 1 сторону):
   контакт в установившемся режиме ЗДОРОВ (flips=0, fallEntries=0 все 9 с
   после 7231); ранние флики 1–5/с + falls 1/с — переходный процесс после
   посадки (entered 6971), не патология. Пара left(7106)/entered(7231) с паузой
   DIAG между — стоянка на промежуточной станции (dwell: RB спит → detach;
   отправление → attach), штатно. Аномалия: maxCarryY до 160 мм/кадр при
   потолке гладкого хода ~45 мм (1.4 м/с × 32 мс) — скачок s ~1 м за кадр:
   либо тик-ступенька клиента, либо фриз ~0.1 с. Различаем maxDt/hitchFrames
   + ответом «хост или клиент».
3. Замер `паром_3.txt` (ХОСТ — сеть отпадает): фризов нет (maxDt ≤ 59 мс),
   фризовая теория мертва. Detaches 7176/7651 = стоянки B1/B2 (штатно).
   Флики до 5/с + falls + пики 190 мм кучкуются ПЕРЕД станциями (склоны +
   касп синуса + лаг тела). Пики без фликов на спусках — догоняющие дельты.
   Открыто: источник stale-кэша (пропуски зонда?) и направление сползания.
   Добавлено смещение игрока от центра платформы (Фаза 1c): различает реальный
   сполз (rel растёт) и стояние с краю (rel константа + фликер на границе).
3. Одна гипотеза → один замер → вердикт. Первым кандидатом — T-PAROM-07
   (yaw-only): единственное снятие симптома в серии.
4. Критерий stop: исходное «не критично» — чинить до «незаметно», не до идеала.

## 7. Фаза 1, замер паром_3 (хост, одиночка): сон в движении доказан

Лог `паром_3.txt` (хост — сеть отпадает полностью):

- **RB спит В ДВИЖЕНИИ**: `sleep=True` при растущем s (строки 6861/6881/7011).
  Телепорты будят через раз. IsSleeping-фильтр рубит carry на ходу.
- **Тело отстаёт от трансформа на 0.3–0.8 м** (rbPos vs trolley): зонд
  и коллизии CC видят старый пол, carry ведёт по свежему — постоянный
  конфликт контакта. Большие лаги = эпизоды сна (замороженное тело).
- **Оба detaches (7176, 7651) — стоянки B1/B2** (прибытие + dwell + сон).
  Штатные, не патология. Спам entered/left = станции, не болезнь.
- **Флики (до 5/с) + falls + пики 190 мм кучкуются ПЕРЕД станциями**
  (подход: крутой склон + касп синуса + лаг тела), после re-attach — тишь.
- maxDt 31–59 мс, hitchFrames ≤ 2 — фризов ~0.1 с НЕТ, фризовая теория мертва.
  Пики 190 мм при гладком потолке ~45–80 мм = догоняющие дельты после
  1–2-кадровых промахов зонда (кэш не обновляется на промахах) + эпизоды сна.

Вывод: чинить детект (сон) и качающуюся крышу (тангаж) — оба паромные,
оба доказаны логом. T-PAROM-13: `sleepThreshold=0` + replay yaw-only (07),
изолированно. Прогноз: flips→0, falls→0, left/entered только... вообще
никаких (без сна detach на стоянках тоже уйдёт — платформа валидна всегда),
maxCarryY ≤ ~50 мм. Каспы станций (08) — только если останутся пики
на подходах.
