0. Резюме и ключевые цифры

«Эльо» — прототип правил и движка настольной мини-игры по сцене «Год 2089. «Эльо»» (книга «Интеграл Пьявица», стр. 313–320). Разрабатывался как автономный веб-прототип (чистый JS + HTML, не сцена Unity) в папке docs/dev/elio/. Идея: три фракции сражаются на гексагональной доске; цель — убить вражеского Линейного (короля) или удержать центральный гекс «Ц».

2. Дизайн игры: доска, флоты, правила

2.1 Доска — 64 клетки (схема)

Три гексагональных поля радиуса 2 по 19 клеток каждое, шесть спорных мостов и один центральный гекс «Ц». Поля расположены: Плюсы сверху, Минусы снизу-слева, Нули снизу-справа. Жёлтые ворота — три гекса, смежных с «Ц» (вход на «Ц» только с них).

2.3 Правила в сжатом виде (шпаргалка «1 правило = 1 строка»)

  1. Игроков 3: Плюсы, Минусы, Нули. Никаких очков за фигуры — это шахматы, не блэкджек.
  2. Доска: 64 клетки (3 поля по 19 + 6 мостов + «Ц»). Вход на «Ц» только с жёлтых гексов полей.
  3. Линейный — король: в Основном режиме его гибель = немедленная победа убийцы; в Длинном — фракция выбывает.
  4. Защита = максимум из источников, не сумма; Линейный и Инженер дают соседям щит 1.
  5. Оттеснение — ход-действие только военной фигурой на соседнюю клетку; атакующий остаётся на месте.
  6. Удержание «Ц» тикает в начале собственного хода держателя; вход в «Ц» не засчитывается как тик.
  7. Порядок хода: Цикл (первый ход Плюсы), Стрелка (первый ход случайный, далее по стрелке) или Передача (отдаёшь любому из двух других).
  8. Лимит 90 полуходов: «Ц» занят активной фигурой → победа стоящего; пуст или инертный → ничья.
  9. Книжный режим («обе Линейные» → Нули) в текущем движке не реализован.

3. Система координат доски

Цель: простая запоминаемая адресация каждой клетки без осевых координат у игрока. Рассмотрены три варианта:

ВариантФорматПлюсыМинусыВердикт
AОсевые с префиксом: P-0,-1Однозначно, легко считать соседейОтрицательные числа и запятые плохо читаютсяТолько внутренний формат
BЛокальные поле-буква-цифра: P-C3Коротко, привычно (шахматный стиль), явно зонаНужно один раз объяснить локальность строк/столбцовВыбран (радиальная схема, канон)
CГлобальные осевые с буквами: E7Одна система на всю доскуРазреженная сетка, много пустых адресовОтклонён

Внутри движка — глобальные осевые (q,r); для игроков, UI и логов — радиальные коды P-C3, Z-A3, Ц. Вход на «Ц» только с жёлтых гексов: P-C5, M-E1, Z-A3.

5. LLP-арена: модели против встроенного ИИ

5.1 Архитектура матча

Каждая фракция управляется своей моделью через постоянные субагенты (subagent с параметром model, проверено на opencode/iceman-free). Оркестратор присылает в сессию компактное состояние доски, список легальных действий (move, support, skip) и требует ответа только в формате JSON. Нелегальный ответ или ошибка — ретрай с текстом ошибки (до 2 попыток), затем применяется ход и пишется лог.

{"kind":"move","pieceId":"P-D7","to":{"q":2,"r":-2}} {"kind":"support","zeroId":"Z-F27","targetId":"Z-C25"} {"kind":"skip"}

7. UI/UX прототипа

7.1 Дизайн-система

  • Цвета: фон #1a1a2e, панели #23234a, золото #c9a227, Плюсы #5b9bd5, Минусы #e05a5a, Нули #9aa0a6, текст #e8e8f0.
  • Компоненты: карточка, золотая/серая кнопка, тост (справа внизу, 3 сек, очередь до 3), попап с оверлеем, переключатель 2D↔3D, подсветка ходов (пульсирующие сферы).
  • Типографика: заголовки Georgia/serif золотом, основной текст Segoe UI 13px, лог моноширина 11px.

7.2 Взаимодействие

  • Клик по своей фигуре → пульсирующие маркеры ходов → клик по маркеру или целевому гексу (2D и 3D).
  • Наведение → tooltip: тип, фракция, клетка, статус нуля, описание.
  • Поддержка: клик по нулю → клик по цели щита. Оттеснение — как ход displace.
  • Режимы: селекторы порядка хода, типа игры, удержания 1–5, лимита; кнопки Новая игра / Ход ИИ / Авто-игра / Стоп / Экспорт / Импорт / Replay; лог ходов с автопрокруткой.

7.3 Переключение 2D/3D

Один HTML-файл с двумя режимами: 2D (SVG) и 3D (Three.js). Состояние игры общее, не сбрасывается при переключении; позиции фигур синхронизируются. Переход: fade-out 300 мс → поворот камеры / перестройка → fade-in 300 мс.

Почему 10 фигур остаются каноном: любая добавленная пешка усиливает борьбу за центр «Ц», а это выгоднее всего Нулям — их задача не убивать, а стоять и блокировать. В цикле перекос достигает 66–69 % в пользу Нулей. Варианты с пешками оставлены как тест-серия с кандидатами на фикс: 3 скитальца вместо 5, запрет скитальцам входа в «Ц», отмена обязательного первого хода пешкой.

9. Выводы и дорожная карта

9.1 Что установлено

  • Канон игры отделил от книги: стрелка в сцене — выбор роли, а не порядка хода; нейтралитет нулей книгой не установлен (BOOK_SCENE_NOTES.md).
  • Добавление Линкора и Бомбардира (v1.3) оживило короля: убийств выросло с 0/400 (v1.2) до 21.75 % в эталоне.
  • Фикс инертного «Ц» и случайный первый ход в «Стрелке» дают лучший баланс: 35.9 / 33.4 / 29.3.
  • Встроенный эвристический ИИ v1.3c превосходит тестируемые LLM в дуэли 3–0: LLM не планируют на центр и повторяют фигуры.
  • Исправлены 3 P0-бага и ряд P1 (v1.3d); integrity-guard подтверждает 0 нарушений целостности на выборке.
  • 10 фигур / 30 очков — сбалансированный канон; варианты с пешками (10+1, 15) перекошены в Нули.

9.2 Дорожная карта

  1. Перепрогнать баланс под правила v1.4 (удержание «Ц» по собственным ходам, порог 1–5).
  2. Протестировать правило «шах» — если 10.75 % убийств в Основном режиме покажутся случайностью.
  3. Добить баланс 15-фигурного варианта (кандидаты: −2 скитальца Нулям, запрет входа скитальцев в «Ц»).
  4. Продолжить LLP-арену: v3-промпт, большая выборка, чистый 400-партийный прогон p0.
  5. Вариант «Передача хода» уже в движке и UI (канон random); оставить repeat/back как опции, не канон.
