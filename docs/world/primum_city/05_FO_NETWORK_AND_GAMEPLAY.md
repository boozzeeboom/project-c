# 05. Floating Origin, сеть, NavMesh и геймплей (фаза 5)

Дата: 2026-10-17. Цель фазы: город не ломает FO и сетевой старт, по нему можно ходить (NavMesh),
в него можно зайти (интерьеры), к нему можно пристыковаться (порт/пады).

---

## 1. Floating Origin: две подсистемы (не путать)

| # | Подсистема | Правило для города |
|---|---|---|
| **A** | Сдвиг мира (`GlobalMotionControlledRebaseSlice`, F8 / авто >256 м / F9) | корень `PRIMUM` — ребёнок `WorldRoot_0_0` → едет бесплатно 🟢; коллайдеры хранят только локальные `center/size` → тоже 🟢; **никаких собственных кэшей мировых `Vector3`** в скриптах города (если появятся — `ApplyRebaseTranslation` на обоих путях) |
| **B** | Допуск при старте (`GlobalSceneNativeExecutor.BuildPreparation`) | цензит **только** `NetworkObject` (и маркеры). Пока город — статика (меши + коллайдеры, без `NetworkObject`/`Rigidbody`), он гейту невидим и **каталог трогать не нужно** |

**Статик-флаги:** объекты города **не помечаем static** (запечённый static batching/occlusion ломается при
сдвиге мира; в проекте по этой же причине руины `isStatic=false`).

## 2. Проверка FO (руками, пользователем)

1. Загрузить мир, встать в городе, нажать **F8** → ожидаем `runtimeRebase.Completed`, город на месте,
   консоль без ошибок.
2. **F9** → мир и город вернулись, геометрия не «отстала».
3. Симптом ошибки: город остался на месте, мир уехал → значит контент лежит **не под корнем сцены**
   (классическая ошибка из `09S_NEW_CONTENT_PIPELINE.md` §1–2).

## 3. Сетевой контент города (когда появится)

Как только в городе появляется объект с `NetworkObject` (дверь-лифт, сундук, точка NPC, пад, маркет-зона),
действует пайплайн `floatingorigin/09S_NEW_CONTENT_PIPELINE.md` §3.2 — **иначе Host падает** на
`uncontrolled_network_source_before_native_sweep`:

1. положить объект под корень своей сцены (`WorldScene_0_0`), в пределах одной сцены;
2. проверить физику: для `ownership = ShipOrRigidbodyRoot` в сабтри обязателен `Rigidbody`, для
   `SceneOwnedNetworkGameplay` — наоборот, его быть не должно;
3. запечь `GlobalSceneSourceMarker` (`sourceId` строго через `GlobalObjectId.GetGlobalObjectIdSlow`);
4. добавить observation в блок своей сцены в `GlobalMotionPilotSceneCatalog` (`layoutHash` — алгоритмом
   `AuditGlobalSceneCatalog.LayoutHash`, предок с маркером обязателен);
5. добавить entry (`treatment = Unmanaged`, `ownership` по факту, `spatial = false`, `reviewNote` осмысленный);
6. пересчитать `layoutHash` предков и `dependencyHash` сцены → `TryCompile` → `DigestHex` →
   поле `_sceneLayoutDigest` в `GlobalMotionPilotProfile.asset`;
7. перед Host: консоль 0 errors, `AuditGlobalSceneCatalog.Run()` без новых расхождений.

Инструмент: меню **`ProjectC/World/Floating Origin/Bake Pilot Catalog (Preview + Apply)`** (делает пп. 3–7,
требует вписанный `reviewNote`, есть `DryRun()`).

> ⚠️ **Блокер:** `NetworkPrefabsList` не назначен → **динамический сетевой спавн сломан**
> (`chunk_system/01_CURRENT_STATE.md:83-84`). Значит весь интерактив города должен быть
> **scene-placed** (в сцене/префабе), а не «заспавнен в рантайме».

## 4. NavMesh и проходимость

1. Городские поверхности, по которым ходим (площадь, улицы, ступени, мостки), входят в bake NavMesh сцены.
2. Интерьеры: либо в общем bake (если интерьеры в мешах блоков), либо в bake интерьерных префабов.
3. В проекте уже есть пример запечённого NavMesh (`Scenes/NavMesh-SPAWN_TEST.asset`) — формат и хранение
   берём оттуда.
4. Лестницы/пандусы: проверять угловые лимиты bake (в городе есть крутые сходы террас — при необходимости
   добавить `NavMeshModifier` с меньшим углом на конкретных участках).
5. Проверка — Play Mode (пользователь): пройти от порта через площадь в жилой квартал, зайти в дом,
   подняться на 2 этаж.

## 5. Привязка геймплея (по мере надобности)

| Что | Паттерн в проекте |
|---|---|
| Входы в дома | дверные листья/петли уже есть в модели (`*_DOOR_LEAF`, `*_HNG`) — вешать интерактив на них, не пересобирая проём |
| Интерьеры «по требованию» | вынести в интерьерные префабы и грузить по триггеру/дистанции (паттерн `PLACEMENT_SCRIPTS/…`, как у ферм) |
| Порт/пады/маркет-зоны | прецедент `Scripts/Editor/PortStationCreator.cs` (DockStation + пады + маркет-зона + SO-данные) |
| Квесты/точки | `TriggerZone_*`, `Respawn_*` — ставить после того, как город встал на место |
| Слои | геймплейные слои не смешивать с `PRIMUM`; пары физики «город × игрок/корабли/зоны» проверить в матрице |

## 6. Критерии приёмки фазы 5

- [ ] F8/F9: город едет с миром, 0 errors (проверяет пользователь)
- [ ] `AuditGlobalSceneCatalog.Run()` не показывает новых расхождений по `WorldScene_0_0`
- [ ] каждый новый `NetworkObject` города имеет маркер + запись в каталоге + сходящийся digest
- [ ] NavMesh: маршрут порт → площадь → жилой квартал → интерьер проходим
- [ ] матрица физики: город сталкивается с игроком и кораблями, не мешает зонам/докам
