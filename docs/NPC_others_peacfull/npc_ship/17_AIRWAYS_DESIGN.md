# 17 — Дизайн: глобальные магистрали (воздушные трассы)

> **Project C: The Clouds** | Unity 6000.5.2f1 | NGO 2.13.0
> **Дата:** 2026-09-25 | **Статус:** дизайн принят пользователем, реализация — следующим тикетом
> **Связано с:** `13_` §3C (граф трасс), `14_ROUTE_GRAPH_DESIGN.md`,
> `15_MESH_DISCS_DESIGN.md`, `16_BOUNCE_RESEARCH.md` (C2 — форма детура)
> **Вопрос пользователя:** боксами задаю глобальные трассы; мелкие пути —
> не вручную; корабль сам находит маршрут; короткие перелёты не должны
> пользоваться магистралью; поймут ли корабли где поворачивать.

---

## 1. Ответы на вопросы (коротко)

* **Где поворачивать** — да, поймут: магистраль = цепочка перекрывающихся
  боксов; поворот = следующий бокс (граф Дейкстры по боксам). Корабль летит
  центр→центр существующей механикой цепочки (`NavGoal`, yaw-сглаживание);
  перекрытие гарантирует: поворот происходит внутри чистого объёма.
* **Короткие перелёты** — не пользуются: правило `dist < airwayMinUseDist`
  (дефолт 2000 м) + чистая прямая → прямой полёт, магистраль даже не смотрим.
  Плюс стоимостное сравнение (ниже): магистраль берётся, только если выгодна.
* **Мелкие пути** — не вручную: магистраль отвечает только за дальние плечи;
  первая/последняя миля (порт↔вход, выход↔пад) — существующими слоями
  (навигатор/граф/лидар/Berthing) без изменений.

## 2. Данные (что рисует дизайнер)

* `AirwaySegment` (MonoBehaviour) на боксе-объёме в сцене:
  `lineId` (строка, напр. `"NORTH_TRUNK"`), размер = размер бокса.
  Отдельный коллайдер не нужен — читаем `transform` + габариты компонента.
* Связи — АВТОМАТИЧЕСКИ по перекрытию/касанию объёмов (дизайнер просто
  рисует цепочку перекрывающихся боксов). Явные `links` — для развязок:
  соединения линий через разрыв + пересадки Б→А (см. §3.1).
* Подсказки: `stations` — перетащить объекты с `DockStationController`
  (только крайние боксы; LocationId читается вживую). Середина — пусто.
* Коллайдер бокса — обязательно **триггер** (иначе стена для лидара/физики).
* Направления — двусторонние (v1). Эшелоны уже разводят встречных по высоте.
* Сертификация чистоты — ручная: бокс = «здесь свободно, я проверил».
  Лучами НЕ верифицируем (в этом смысл ручного слоя). Editor-валидатор
  (gaps + зарытые центры) — отдельным тулом, после v1.

## 3. Рантайм (server-only)

* `AirwayDirectory` (static): строится лениво из сцены (сегменты всех линий);
  хранит ТРАНСФОРМЫ (центры — резолвом вживую) + индексную смежность
  (инвариантна к сдвигу — перестроение при F8 НЕ нужно, только при
  загрузке/выгрузке сцен; плюс сброс по `sceneLoaded` против залипания).
* `TryBuildRoute(a, b, goalLocationId, ...)` в `PlanRoute` ПЕРЕД графом:
  1. Короткое плечо (`dist < airwayMinUseDist`) — пас, прямой полёт.
  2. Входы: до 3 ближайших боксов (по объёму); выходы: до 3, сначала
     обслуживающие цель (`stationIds` крайних боксов), потом ближайшие.
     Нет пары — `no-entry` (молча).
  3. Перебор пар вход×выход (макс 3×3): свой/соседний — пас (`near-box`,
     молча); Дейкстра по каждой паре; лучший ride побеждает.
     Не та линия у старта — пробуется следующая (перебор, не первый попавшийся).
  4. Детур > `airwayMaxDetour` — пас; точек > `airwayMaxWp` — пас.
* Точки: вливание (ближайшая точка входного бокса — влёт с любой стороны),
  середина — центры, съезд (ближайшая точка выходного к цели — вылет
  напротив фермы). Y всех точек — профиль вызывателя (вертикаль — эшелонам).
* `how=airN` в лог; несходства цены/длины/пути — `air-fail`.

## 3.1. Пересадки между линиями (модель пользователя)

* Линии НЕ обязаны перекрываться. Пересадка Б→А — это `links` между боксом
  линии Б и боксом линии А в точке пересадки (развязка): Дейкстра идёт
  сквозь links как по обычным рёбрам. Рисуешь развязку = ставишь links.
* Корабль Б2→А3: candidates входа на линии Б, выходы на линии А (по hints
  цели), путь через links-развязку — автоматически, вести не надо.
* A1→Б2 при магистрали только-А: hints не совпадут, детур не окупится —
  legacy (как требует модель: «магистраль А никуда не приведёт»).
* Корабль НЕ выбирает «линию»: он перебирает пары вход×выход по всем линиям
  и берёт дешёвый ride. Принадлежность линии — следствие, не решение.

## 4. Почему это бьёт в C2 (форма детура)

Сегодня обход строится от скалы (касательные с двух сторон → возврат).
Магистраль строится от МАРШРУТА (дизайнер провёл чистую линию заранее):
корабль не открывает географию, а едет по ней. Тактика остаётся для
первой/последней мили и непредвиденного (меши вне боксов, стая).

## 5. Что НЕ делаем (v1)

* Рулевые объёмы («стены коридора ведут») — только топология (центры);
  ведение объёмом = новые режимы = новые баги. v2 при необходимости.
* Односторонние полосы/развязки/светофоры — встречные разведены эшелонами.
* Ручные трассы последней мили — их ведёт существующая система.
* Мутация SO/сцены из кода; мировые кэши (всё живьём или индексное).

## 7. Проверка (пользователь, Play Mode, NOT RUN агентом)

1. Дальний leg вдоль магистрали: `how=airN`, полёт бокс→бокс без входов
   в WallFollow; `SUMMARY`: прерывания шип-эвойдом не выросли.
2. Короткий перелёт соседей: магистраль не используется (`direct/bypass`,
   `airN` нет) — милли не трогаем.
3. Регресс: `useAirways=false` = бит-в-бит; боксов нет = no-op.
4. F8 на магистрали: точки не протухли, 0 errors.
5. Console → 0 errors.
