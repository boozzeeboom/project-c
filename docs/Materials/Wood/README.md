# Wood — процедурное дерево (кольцевые срезы + фактура волокна)

> Статус: **PROTOTYPE v2.2** (граф собран с нуля под дерево; v1 — копия бронзы — отклонён).
> Проверено агентом: импорт OK, `ShaderHasError = false`, `isSupported = true`,
> `GetShaderMessages = 0`, структурный аудит графа чистый.
> **v2.1: сила рельефа разделена по видам** — общий `_Bump_Strength` удалён из графа,
> у волокна / пор / царапин свои коэффициенты (см. «Рельеф: почему нет общего множителя»).
> **v2.2: добавлен рельеф колец** — `_Rings_Bump` (годичные кольца × свой коэффициент),
> вход высоты стал четырёхчленным.
> **Визуал и Play Mode — `NOT RUN`** (тесты и скриншоты делает только пользователь).

## Зачем v2 (что было не так в v1)

v1 был текстовой копией `BronzeEdgeNoise_forTEST.shadergraph`: сохранялись топология,
все 38 свойств блэкборда и вся металлическая обвязка (патина с вертикальным bias,
`Metallic = Lerp(...)`, ослабление потёртостей через гладкость/металличность). Даже
после замены ядра тона материал **читался как металл**: вид определяла не логика
дерева, а чужой каркас.

v2 — **собственный граф**, где доминируют деревянные слои (кольца → волокно → поры),
а от бронзы заимствованы **только две детали**: маска кромок по `|x|,|y|,|z|` и
набор царапин с маской. Металличности в материале нет вообще.

## Что построено

```
Position (object-space, m_Space = 0)
 ├─ СУЧКИ/СВИЛЬ  ProceduralWoodKnots  → близость к центру сучка (Worley F1), 0..1
 ├─ КОЛЬЦА        ProceduralWoodRings  ← сучки уходят во вход Knots
 │                 late = smoothstep(1 − sharp, 1, frac(r + свиль + сучки))      = Ring_Amount × late
 ├─ ВОЛОКНО       ProceduralWoodGrain  → ridged fbm, растянутый вдоль локальной Y  = Grain_Amount × grain
 ├─ ПОРЫ          ProceduralWoodPores  → точки в центрах ячеек Worley             = Pores_Amount × pores
 ├─ КРОМКИ (из бронзы): |x|,|y|,|z| → Smoothstep(_Edge_Position − _Edge_Width, _Edge_Position)
 │                 → попарные × → Add → Add → Saturate → × _Edge_Wear
 ├─ ЦАРАПИНЫ (из бронзы): ScratchA/B/C → Smoothstep(_Scratch_Threshold, +_Scratch_Band)
 │                 → Add → × Smoothstep(mask) → × _Scratch_Amount
 └─ wear = Saturate(кромки + царапины)

BaseColor  = Lerp(Lerp(Lerp(Lerp(_Wood_Color, _LateWood_Color, кольца),
                                              _Grain_Color, волокно),
                                              _Pore_Color,  поры),
                                              _Wear_Color,  wear)
Smoothness = Lerp(Lerp(_Smoothness, _LateWood_Smoothness, кольца), _Wear_Smoothness, wear)
NormalTS   = Normal From Height(волокно×_Grain_Bump + поры×_Pore_Bump + царапины×_Scratch_Bump
                                + кольца×_Rings_Bump,
                                Strength = 1.0 — константа; общего множителя в графе нет)
Metallic / Emission / Occlusion — не подключены (диэлектрик; блок Metallic = дефолт 0)
```

Итог графа: 101 нод (92 обычных + 9 блоков мастер-стека), **132 ребра**,
41 свойство блэкборда (36 float + 5 color), 379 JSON-документов.
`doubleDriven = 0`, висячих ссылок на слоты/ноды/свойства — 0.

## Требования к геометрии

1. **Локальная ось Y = вдоль волокна** (ствол, брус, доска, ножка мебели).
   Волокно — это `ridged fbm` с `p.y * 0.12`, то есть штрихи тянутся по Y.
2. **Origin (пивот) — внутри массы, на оси «ствола».** Кольца считаются как
   `r = length(p.xz)`, то есть это изолинии расстояния от локальной оси Y.
   Пивот, вынесенный за габарит, даст однобокие дуги вместо кольцевых срезов.
3. **Годичные кольца видны на срезе** — на торце (плоскость XZ) и по всей длине
   как прямые полосы. Для доски это означает: срез смотрится на торце
   (торец ⊥ Y), пласть — полосы волокна.
4. **Единичный локальный масштаб** для кромочной маски: `|x|,|y|,|z|` растут до 1.0
   на габарите 2×2×2. На меше другого размера подбирается `_Edge_Position`
   (у куба 1×1×1 — порядка 0.5) либо нормализуется геометрия.
5. **Локальный масштаб влияет на частоту.** Всё процедурное — в object-space,
   поэтому масштабирование объекта в сцене масштабирует и кольца с волокном
   (это осознанный компромисс FO-safe шума, а не баг).

## Ядро шума — `Assets/_Project/Shaders/ProceduralWoodNoise.hlsl`

Правило проекта **T-BRONZE01** соблюдено: все функции **одно-выходные** (File-режим),
сигнатуры = порядок слотов CF-нод. Мульти-выходные функции ломаются при перезаписи
графа, поэтому новых параметров — только новыми функциями, сигнатуры не менять.

| Функция (имя CF-ноды) | Входы | Выход | Что считает |
|---|---|---|---|
| `ProceduralWoodKnots` | `ObjectPos, KnotsScale, KnotsWarp, KnotsSeed` | `Knots` | Worley F1, `saturate(1 − d×1.35)² × Warp` — величина сдвига колец у сучка |
| `ProceduralWoodRings` | `ObjectPos, RingScale, RingSharpness, WarpAmount, Knots, RingSeed` | `Rings` | `r = length(p.xz)`, свиль крупным fbm (`−0.5`), `+ Knots`, `frac(r)` → узкая полоса поздней древесины |
| `ProceduralWoodGrain` | `ObjectPos, GrainScale, GrainStretch, GrainDetail, GrainSeed` | `Grain` | `1 − \|fbm·2 − 1\|` от координат, растянутых по XZ (`GrainStretch`) и сжатых по Y (`0.12`) |
| `ProceduralWoodPores` | `ObjectPos, PoresScale, PoresSeed` | `Pores` | Worley F1 → точки в центрах ячеек (`1 − smoothstep(0.18, 0.42, d)`) |
| `ProceduralWoodScratchA/B/C` | `ObjectPos, ScratchScale, ScratchStretch, ScratchDetail, ScratchSeed` (+ `ScratchAngle` у C) | `Scratch` | **заимствовано у бронзы**, механизм 1:1 (три направления, сдвиги `+17.3`, `+41.1`) |
| `ProceduralWoodScratchMask` | `ObjectPos, ScratchMaskScale, ScratchMaskSeed` | `ScratchMask` | **заимствовано у бронзы** (fbm-пятно, гасящее царапины на участках) |

Хеш без `sin`, value-noise + 3-октавный fbm, Worley 3×3×3 — весь шум в object-space,
`AbsoluteWorld` не используется.

## Рельеф: почему нет общего множителя (v2.1)

Нода `Normal From Height` считает `Out = SafeNormalize(T − Strength · surfGrad)`, где
`surfGrad` **линеен** по входу `In`. Вход собран как
`In = волокно×_Grain_Bump + поры×_Pore_Bump + царапины×_Scratch_Bump + кольца×_Rings_Bump`, поэтому слагаемое
каждого вида входит в градиент ровно со своим коэффициентом:

```
∇In = _Rings_Bump·∇(кольца) + _Grain_Bump·∇(волокно) + _Pore_Bump·∇(поры) + _Scratch_Bump·∇(царапины)
Out = SafeNormalize(T − Strength · ∇In)
```

То есть `_Grain_Bump` / `_Pore_Bump` / `_Scratch_Bump` **и есть** сила рельефа своего вида,
отдельная от остальных. Общий `_Bump_Strength` был пятым множителем поверх всей суммы: он
тянул сразу все виды пропорционально их градиентам, а самый высокочастотный вид (поры,
`_Pores_Scale ≈ 117`) даёт наибольшие `ddx/ddy` — поэтому сильнее всех откликался на общий
множитель, и усилить им волокно, не раздув поры, было нельзя.

Сделано: удалено ребро `PropertyNode 'Bump Strength' → NormalFromHeight.Strength` (слот
`Strength` теперь не подключён, значение `1.0`), удалены PropertyNode, свойство
`_Bump_Strength` и его слот-документ — на тот момент 368 документов, 128 рёбер,
40 свойств блэкборда (в v2.2 — 379 / 132 / 41, см. ветку колец ниже).
Значения пресета домножены на бывший множитель `0.6` (1.23→0.738, 0.35→0.21, 0.23→0.138),
поэтому внешний вид не изменился.

Проверено (2026-10-06):

## FO-safe (Floating Origin)

- Весь шум — от `Position (Object)`, `m_Space = 0`; вход `ObjectPos` у всех CF-нод.
  `AbsoluteWorld` в графе — 0 вхождений.
- Вариативность между объектами — сид-свойствами (`_Rings_Seed`, `_Knots_Seed`,
  `_Grain_Seed`, `_Pores_Seed`, `_Scratch_Seed`), а не мировой позицией.
- Ребейз (F8 / авто / F9) не может «сдвинуть» рисунок: он привязан к локальным
  координатам меша.
- **Проверка F8/F9 — `NOT RUN`** (за пользователем).

## Как собран граф (и грабли формата `.shadergraph`)

Граф собран не копированием бронзы, а генерацией потока документов: шаблоны
документов узлов/слотов берутся из бронзового файла (формат), состав узлов, слоты,
свойства и рёбра — свои. Полезные факты формата:

1. `.shadergraph` — поток JSON-документов, разделитель строго `}\n\n{`.
   **Пустая строка внутри документа обрывает документ**: `MultiJsonInternal.Parse`
   берёт подстроку от `{` до первого `\n\n`. Пункт критичен при любой скриптовой правке.
2. **Последний документ в потоке сохраняет свою закрывающую `}`** (её не съедает
   разделитель). При сборке файла из списка документов финальную `}` нужно дописать —
   иначе импорт падает с `JSON parse error: Missing a comma or '}' after an object member`.
3. Свойства блэкборда адресуются по `m_ObjectId` (32 hex); `PropertyNode`
   ссылается на свойство через `"m_Property": {"m_Id": "<m_ObjectId свойства>"}`,
   корень графа — через список `m_Properties`.
4. Блоки мастер-стека **входят** в `m_Nodes` корня и дополнительно перечислены в
   `m_VertexContext.m_Blocks` / `m_FragmentContext.m_Blocks`.
5. Целевой рендер — URP Lit (`UniversalTarget` + `UniversalLitSubTarget`), Forward.

## Возможные шаги на подстройку (после визуального теста)

- Крупные кольца на мебели: `_Rings_Scale` 3–4; срез бревна: 8–12.
- Мелкая деталь (ящик, дощечка): `_Grain_Scale` 25–35, `_Pores_Scale` 80–120.
- Сухие доски без сучков: `_Knots_Warp` 0.15–0.25.
- Мокрое/лакированное дерево: `_Smoothness` 0.5–0.65, `_LateWood_Smoothness` 0.35.
- Выгоревшее дерево: тянуть `_Wood_Color` к серому (0.55/0.5/0.45), `_Wear_Color` светлее.
