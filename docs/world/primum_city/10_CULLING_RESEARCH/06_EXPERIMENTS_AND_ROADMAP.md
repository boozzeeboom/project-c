## 1. Методика замеров (обязательна для всех A/B)

Из `06_REFERENCE/04_OCCLUSION_CULLING_RESEARCH.md` §2 + уточнения отчётов A/C/F:

| Требование | Значение |
|---|---|
| Метрики | `UnityStats.drawCalls`, `setPassCalls`, `triangles`; разложение по `srpBatcherDrawCalls` / `hybridBatcherDrawCalls` / `shadowCasters`; Profiler → Rendering (CPU culling), Frame Debugger (по проходам) |
| Равный кадр | сравнивать только на одинаковом `frameCount`; **FPS первых ~1 500 кадров врёт** (23.5→34.1 без изменений) |
| Прогрев | ≥1 500 кадров; 3 прогона, медиана |
| Камера | фиксированная точка, fov 60, far **реальный** (30/60/120 км по пресету) и отдельно far 1000 для сверки со старым замером |
| Точки | центр `(39593.1, 2509.6, 39833.8)` yaw 337.5°; улица (узкая); крыша; 1 км от города |
| Изоляция | Scene View в небо; `AtmosphereCamera` выключена; статичная `BootstrapScene/MainCamera` не должна влиять на `Camera.main` |
| Визуал | скриншоты до/после на 3 точках; отдельно ночь (эмиссия/тени) |
| FO-регресс | F8 → объект на месте, 0 errors; F9 → возврат; 2–3 минуты полёта на корабле (2–3 ребейза) — видимость не мигает |
| Ограничения | не менять `NetworkManager`, `ClientSceneLoader`, `ScenePlacedObjectSpawner`; не трогать коллайдеры/слой физики дверей без проверки масок |

**Что нужно до экспериментов (2–3 часа работы):**
1. Editor-скрипт «CullingBench»: перелёт камеры по 4 точкам, запись `UnityStats`/`ProfilerRecorder` в CSV
   на равном кадре (запускает пользователь в Play Mode).
2. Метка в Frame Debugger: `Camera` / `Directional Shadow Map` — для разложения по проходам.
3. Счётчик «видимых/включённых рендереров» — без него нельзя сравнивать эксперименты.

## 2. Эксперименты

### E0. Разложение дверного счёта по проходам (0.5 дня, без правок)

**Цель:** подтвердить, что 17 766/22 027 DC — это `material slots × проходы`, а не артефакт.
**Как:** Frame Debugger из центра: `Camera` (opaque + depth prepass) vs `Directional Shadow Map` (каскад 0/1);
Parallel: `UnityStats.shadowCasters`, `triangles`.
**Ожидание:** двери ~5.2 слота/инстанс; ×4.45 draw/renderer в A; тени 8–46 %.
**Kill:** тени <30 % счёта → приоритеты в плане меняются (но low-code всё равно полезен).

### E1. Low-code двери (2–4 дня) — **первый настоящий шаг**

**Изменения:** слой `PRIMUM_DOORS` (11 префабов), `layerCullDistances` 120–150 м,
`shadowCastingMode=Off` дальним (или всем — визуальное решение), гистерезис 2–4 Гц.
**Мерить:** DC/FPS на 4 точках, визуал теней дверей, raycast-маски после смены слоя.
**Ожидание:** 26 981 → **5 000–9 000** (−67…−81 %); двери в кадре — сотни.
**Kill:** экономия <30 % / заметная потеря теней / поломка raycast → откатить слой, оставить только GRD-путь.
**FO:** после F8/F9 нет «залипшей» видимости.

### E2. Аудит шейдеров/DOTS (1–3 дня)

**Цель:** понять, включается ли GRD без переписывания города.
**Как:** включить `BrgStripping=Keep All` + GRD на тестовой сцене/копии; проверить шейдерные ошибки;
инвентаризация 49 городских Shader Graph + 6 дверных + 8 кастомных шейдеров; проверить, что материалы
`ProceduralSteel` не используются в `WorldScene_0_0` (F: 0 ссылок; C: 40 шейдеров без DOTS).
**Ожидание:** 0 ошибок после ≤2 дней правок; иначе — оценка объёма.
**Kill:** >5 дней правок или Shader Graph не даёт инстанс-варианты → откат к E3/E5.

### E3. GRD + GPU occlusion: пилот (2–3 недели)

**Как:** `m_GPUResidentDrawerMode=1`, `GPUResidentDrawerEnableOcclusionCullingInCameras=1`,
`smallMeshScreenPercentage=1–2 %`; сначала 1 чанк, затем вся сцена; Frame Debugger ищет `Hybrid Batch Group`,
GPU debug views (Visible/Culled Instances).
**Мерить:** DC, SetPass, треугольники, CPU/GPU-время, тени, створки дверей, F8/F9.
**Ожидание:** 26 981 → **1 500–2 500**; двери — десятки (≤~72) пар mesh×material.
**Kill:** нет `Hybrid Batch Group` / створки/тени ломаются / шейдерные ошибки → откат, вариант E5.

### E4. «Немёрженный город» — контрольный тест (1 день)

**Как:** копия сцены; revert PRIMUM-инстанса к prefab asset (16 468 MR) — без отката коммита.
**Ожидание:** 25–40 тыс. DC (верхняя оценка C; verifier: диапазон), редактор/загрузка хуже.
**Kill:** <25 тыс. DC → модель слотов неверна, пересчитать.
**Зачем:** проверить гипотезу заказчика «не склеивать» на реальном кадре, а не по модели.

### E5. CPU VisibilityDirector — MVP (5–8 дней)

**Как:** lite-версия без Burst на 200 строк: группы `doors/interior/lamps/ruins/ships`, frustum+distance,
гистерезис, мультикамерный union, `Renderer.enabled`/`forceRenderingOff`, обновление 2–4 Гц.
**Мерить:** DC/FPS, CPU culling (Profiler), артефакты/поппинг.
**Ожидание:** 26 981 → **5 500–8 000**; ≤0.3 мс на 7–9 тыс. рендереров (группами).
**Kill:** >0.7 мс / артефакты → урезать гранулярность (только двери/руины).

### E6. Пере-грануляция города B2: пилот на `S9_TRD-S2` (1–2 недели)

**Как:** пере-склейка одного чанка по **B2** (дом × материал, только геометрия ≥1 м; мелочь/интерьеры
остаются чанк-батчами), prefab-ассет, не scene-overrides; сравнить слоты/AABB/DC/окклюзию/визуал.
**Ожидание (J):** 104 живых рендерера → ~330 B2; слоты ×1.9, **+40 % DC без окклюзии** — поэтому
делать только после зелёного GRD и при окклюзии ≥35 % видимых слотов; отдельно решить бюджет теней.
**Kill:** цвет +>15 % / тени +>25 % без бюджета / DC растут → откат, остаётся A.

### E7. Portal/PVS: пилот одного чанка (2–3 дня оценка + 2–3 недели)

**Как:** raycast-бейк по 10 817 боксам для `S9_TRD-S2`; доля видимых ячеек с уличных точек.
**Ожидание:** видимых ячеек <35 %; иначе 6–10 недель не оправданы.
**Kill:** >35 % / бейк >2 ч/чанк / город меняется чаще раза в 2 недели.

### E8. Базовый замер на реальном far (0.5 дня)

Повторить baseline на far 30/60/120 км (не 1000) и на 4 точках — иначе все «до/после» несравнимы
с игровым кадром. Ожидание: DC растёт с far (больше батчей/дверей), но порядок сохраняется.

### E9. Тени дверей: визуальный допуск (0.5 дня, решение заказчика)

A/B с включёнными/выключенными тенями дверей на 3 точках + ночь. Нужно решение: тени дверей — часть
картинки или можно отключать дальше 40–80 м? От этого зависит Ф0.

### E11. Корабли: P0/P1/P2 (3–5 дней) — обязательный параллельный трек

**Как:** вынести 250 BoxCollider и 9 `DoorController` из FBX-инстанса; затем greeble-мерж (359 объектов
→ 10 сабмешей) и `LODGroup` (300/900/2500 м). Мерить Frame Debugger на одном тяжёлом инстансе
(40064, 2512, 39449) до/после.
**Ожидание:** тяжёлый **973 slot / ~2 919 DC → ~92 slot / ~276 DC** (после P3); все корабли
**~4 917 → ~480 DC**. P1 уже даёт 973→~620.
**Kill:** двери/слоты перестали работать; реимпорт FBX ломает prefab; scene-diff >1 000 строк.

### E12. Фермы: двери + тени (1 день)

**Как:** `Primum_farms_DOORS` (270 MR) на слой `PRIMUM_DOORS` с дистанцией 120–150 м;
`shadowCastingMode=Off` геометрии ферм; замер из города (1 км) и на ферме.
**Ожидание:** −270 рендереров/≈−640 слотов из города, −1.27 млн тр в shadow pass.
**Kill:** визуальные дефекты ворот/тени на ферме.

### E13. Воспроизводимость мержа (1–2 дня) — до любой переклейки

**Как:** манифест + Unity-тул `PrimumCityRebatch` в git; dry-run на одном чанке, `Σtris ±0.1 %`,
сборка prefab-ассета (не scene-overrides); `PRIMUM_CITY.prefab` — в VCS/Lore.
**Kill:** расхождение >0.1 % / тул не воспроизводит чанк.

## 5. Откат (rollback)

| Что | Как |
|---|---|
| Слой дверей / `layerCullDistances` | вернуть слой префабам, обнулить массив камер |
| `shadowCastingMode` | вернуть `On` (одна правка на префабы) |
| GRD/BRG-настройки | вернуть `m_GPUResidentDrawerMode: 0`, `BrgStripping: 0`, occlusion off (как 18.10) |
| Пере-грануляция города | scene-копия + revert PRIMUM-инстанса; prefab-ассет не трогать |
| Шейдеры | отдельная ветка/копия; не мержить до зелёного пилота |
| Сцена | коммит-бэкап `WorldScene_0_0` перед каждым экспериментом; 63 МБ — аккуратно |
