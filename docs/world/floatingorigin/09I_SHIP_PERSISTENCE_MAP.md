## 3. Риски персистенции кораблей (найдены статикой + сейвом)

- Имя-корабль — Yandex-conflict-копия префаба
  (`Ship_Light_root (копия с компьютера...).prefab`). ID стабилен, пока
  объект не пересоздан; любое переименование/переинстанс = mismatch =
  «корабль пропал». Рекомендация (контент, редактор): переименовать
  префаб и объект в чистое имя без суффикса.
- Restore двигает ТОЛЬКО существующие scene-корабли (match по
  `ShipPersistentId`); спавна кораблей из сейва нет. Рантайм-заспавненные
  (не scene-placed) корабли после рестарта вернуться не могут по построению.
- `ShutdownForMainMenu`: `SaveNow` пропускается при `wasGlobal`
  (global-сессии) — выход через меню полагается на 5с-тик (устаревание
  до 5с) + global checkpoint path. Резких потерь не даёт, но свежайшие
  секунды движения могут не записаться.
- Подозрительно (не доказано): флот в сейве ~160000, игрок+корабль ~63 —
  разные порядки в одном файле. Возможна рассинхронизация фреймов записей
  или флот реально улетел. Ждать лога следующего перезахода.

## 4. Что план говорит про корабли (ответ на вопрос)

- T-FO08 (стадия «NavMesh, AI, корабли»): выполнено частично —
  08A/08B (NPC), 08D (broadcast отката), 08C-verdict (ship-adapter
  ОТЛОЖЕН: требует v2-миграции репликации NT→Replicator + топологию).
- 06CM–06CW: dormant protocol-owned ShipDeck lifecycle coordinator —
  IMPLEMENTATION-BLOCKED (06CR: нет legitimate single producer),
  никогда не bound. Это и есть «запланированная работа по кораблям»,
  она не закрыта и не поможет здесь напрямую (про пассажиры/поколения,
  не про restore позиций).
- §4 приёмки: docking/recall/autopilot/торговля — OPEN (только тесты).
- Для «корабли пропадают»: план не содержит spawn-from-save; если
  подтвердится потеря scene-кораблей при стабильных ID — это новый
  тикет (сверить `Restored X/22` + `No save for` в логе).
