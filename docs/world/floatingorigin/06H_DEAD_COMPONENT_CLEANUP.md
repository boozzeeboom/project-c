# T-FO06H — удаление мёртвых компонентов BootstrapScene

Дата: 2026-09-09. Предыдущий этап: T-FO06G, `3518391d`.

## 1. Что сделано

Из `BootstrapScene` удалены три компонента, ссылавшихся на намеренно удалённые классы, и сцена сохранена.

Удаление выполнено через штатный `GameObjectUtility.RemoveMonoBehavioursWithMissingScript` ровно на трёх опознанных объектах, а не сплошной чисткой сцены.

## 2. Несохранённые изменения оказались безобидными

Сохранение пользователем добавило в файл ровно три строки:

```yaml
_globalMotionProfile: {fileID: 0}
_globalSpawnBootstrap: {fileID: 0}
_globalSessionCoordinator: {fileID: 0}
```

Это сериализация полей, добавленных кодом на этапе T-FO05E, со значением «не назначено». Никакой посторонней работы в несохранённом состоянии не было, поэтому прежнее опасение снято фактами.

## 3. Подтверждение опознания

Diff показал `m_EditorClassIdentifier` удаляемых компонентов — полные имена классов:

| Объект | Класс из файла сцены | GUID |
|---|---|---|
| `[ShipKeyToast]` | `ProjectC.Ship.Key.ShipKeyToast` | `7e4592bf…` |
| `[ShipKeyServer]` | `ProjectC.Ship.Key.ShipKeyServer` | `d915eb76…` |
| `[ShipOwnershipRegistry]` | `ProjectC.Ship.Network.ShipOwnershipRegistry` | `75a1a615…` |

Это независимо подтверждает опознание из T-FO06G, сделанное по GUID и комментариям в коде.

**Замечание по методу:** `m_EditorClassIdentifier` содержал имя класса напрямую, и диагностику стоило читать сразу вместе с ним — это дало бы имена без обхода через комментарии. Инструмент этап назад этого поля не читал.

## 4. Проверки

Скрипт отказывался работать при несохранённой сцене, при количестве отсутствующих компонентов, отличном от трёх, при неоднозначном имени объекта и при любом отклонении в счётчиках.

Зафиксировано после операции:

- отсутствующих компонентов: `3 → 0`;
- количество GameObject — без изменений; количество корней — без изменений;
- количество компонентов — ровно `−3`;
- сцена не помечена как изменённая, файл на диске изменился;
- ни один из трёх GUID в сохранённом файле не найден.

Diff по файлу сцены: `3` добавленные строки (поля пользователя) и `39` удалённых — три блока `MonoBehaviour` и три ссылки в `m_Component`. Других изменений нет.

## 5. Состояние редактора

После сохранения Unity перестала отвечать на запросы инструментов, при этом процессы живы, а лог показывает успешный импорт сцены без ошибок и затем тишину.

Работа этапа завершена и проверена на файловой системе, поэтому данные не под угрозой. Проверка компиляции и дальнейшие шаги требуют восстановления связи с редактором.

## 6. Остаток

1. Восстановить связь с редактором и перепроверить компиляцию.
2. Определить минимальный набор сцен пилота и составить каталог только для него; теперь у `BootstrapScene` есть основание для `saved = true` и отсутствуют missing-скрипты.
3. Профиль: каталог, `SceneLayoutDigest`, ссылка на пилотный список, одна Spatial-запись.
4. Markers, prepared frames, native scene executor.
5. Выбрать пилотный префаб как `PlayerPrefab`, вывести legacy position services и `ClientSceneLoader`.
6. Trusted account issuer, explicit store ownership.
7. Пользовательский Host + client gate.

Global mode/world shift выключены, `jitter fixed` не заявляется.
