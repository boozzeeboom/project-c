# T-CHAR-UVRB — алгоритм и повторный ресерч

> v2, 2026-10-26. Проверенная локальная версия: Blender 5.2.3 LTS.
> Unity import, визуальная приёмка и Play Mode: **NOT RUN**.

## 1. Что действительно обобщается

UV charting, параметризация и перенос данных между UV-картами не зависят от того,
изображает меш человека, нож или прибор. Но выбор швов, бюджет изображения и сохранение структуры ассета
зависят от самой сетки/материала. Универсальный вход не равен гарантированно лучшему выходу.

v1 был настроен на один плотный меш Tripo: `PC_Char_City_LowerCraftsman_APOSE_v02`.
Наивный Smart UV дал 5966 островов (5572 <50 faces), сглаженный прокси 200 итераций — 1562 (1409 мелких).
В v1 итог после специальных merge/PCA/SLIM: 88 островов против исходных 211,
CV 0.102 против 0.233, сумма UV-площадей 0.430 против 0.642, 11 flipped faces против 0.
Эти числа — **исторический результат v1**, а не доказательство для других объектов или v2.

## 2. Первичные источники, перечитанные для v2

Получены прямыми HTTP-запросами к первичным источникам; API дополнительно проверен
через RNA локального Blender (`probe_api_v2.py`). Поисковый интерфейс не вернул пригодный текст;
это ограничение исследования отмечено явно, а не заменено выдуманными ссылками.

1. **Blender Manual — UV Operators**:
   https://docs.blender.org/manual/en/latest/modeling/meshes/editing/uv.html
   `Minimum Stretch` использует **Scalable Locally Injective Mapping (SLIM)**; `no_flip` доступен в локальном RNA.
   Smart UV проецирует группы по нормалям и подходит также для механических объектов/архитектуры.
2. **Blender Manual — Editing UVs / Pack Islands**:
   https://docs.blender.org/manual/en/latest/modeling/meshes/uv/editing.html
   Fraction задаёт расстояние относительно UV-квадрата. Concave packing и точная Fraction-упаковка
   дороже простых методов; число островов влияет на стоимость и полезную площадь.
3. **Blender Manual — Render Baking**:
   https://docs.blender.org/manual/en/latest/render/cycles/baking.html
   Emit переносит цвет/данные; Normal имеет отдельный tangent-space режим. Margin нужен для фильтрации и mipmaps.
   Эти режимы не следует смешивать: RGB normal map нельзя просто перепроецировать без смены tangent basis.
4. **ETH Zürich, Rabinovich et al., Scalable Locally Injective Mappings (2017)**:
   https://igl.ethz.ch/projects/slim/
   Локально-инъективная инициализация и flip-preventing энергия — существенные предпосылки гарантии метода.
   Нельзя переносить математическую гарантию на произвольный повреждённый вход без проверки результата.
5. **CGAL Surface Mesh Parameterization**:
   https://doc.cgal.org/latest/Surface_mesh_parameterization/index.html
   Требования manifold/orientability, cut graphs и различия между fixed/free-boundary методами.
   Диск — выбранный надёжный контракт нашего charting, **не** утверждение, что все методы работают только на дисках.

Страница Blender glTF exporter дважды не загрузилась по сети. Полная семантика обменного экспорта
по ней не подтверждена. Локальный RNA подтвердил наличие flags export_skins/export_morph/export_animations;
это не доказательство безошибочного переноса любого ассета.

## 3. Исправления прежних выводов

- `χ=V−E+F=1` — полезный необходимый фильтр для нашего контракта, но не универсальный сертификат диска
  на non-manifold комплексе. v2 проверяет граничную петлю и UV; повреждённые случаи могут отклоняться.
- Smooth меняет только аналитический прокси. Он может испортить **выбор швов**, но не уменьшает толщину оригинального клинка.
- Числа 20–60 итераций и 30–45° не обоснованы как общие предметные пресеты. Настройки v2 — явно обозначенные
  эвристики, проверяемые по результату, а не правила, выведенные из названия класса ассета.
- Join в v1 мог уничтожить разделение объектов и при этом успешно пройти проверку `meshes == 1`.
- Material roughness=0.9 и единственный BaseColor не являются сохранением PBR даже для персонажа.
- Source UV с overlap может быть намеренным. Не надо автоматически считать его повреждённым или удалять.
- Сумма UV-площадей при overlap не равна занятой площади атласа.
- Сохранение числа арматур/габаритов не проверяет веса, костную иерархию, анимационные кривые и shape keys.

## 4. Геометрический pipeline v2

### 4.1 Подготовка

Импортировать поддерживаемый файл в отдельный headless Blender. Не объединять mesh objects.
Preflight проверяет полигоны, координаты, материалы, UV-зависимости и поддерживаемые modifiers.
Для каждого mesh создаётся копия для baking с исходными вершинами/нормалями, отдельно — аналитическая копия.

В аналитической копии допустимо соединение только **точно совпадающих однозначных встречных boundary edges**:
два ребра, противоположный обход, совместимый материал, не authored seam/sharp, угол меньше защитного порога.
Не выполняется поиск близких вершин по глобальному радиусу. `--connect-splits off` оставляет исходную связность.
Каждый loop получает исходный corner ID; число faces/loops и перестановка IDs проверяются после операции.
Обратно передаются только UV. Вершины, custom shading, веса и shape keys исходного объекта не свариваются.

### 4.2 Защищённые границы и сегментация

Защищены существующие seams, sharp edges, material boundaries, сильный диэдральный угол,
а также геометрические перегибы flat-shaded faces. Merge и сглаживание границ не переходят эти границы.

Кандидат без сглаживания вычисляется всегда. При преимущественно плавной геометрии добавляется сглаженный:
число итераций оценивается через отношение площади оболочки к медиане квадрата длины ребра и ограничено 1..600.
Однородная смена единиц измерения не должна менять это отношение; отдельный численный тест это проверяет.
Эвристика не распознаёт части тела и не гарантирует удачные художественные швы.

Smart UV на копии → метки чартов → merge мелких островов. Порог площади вычисляется **по связной оболочке**,
не по всему мешу. Merge оставлен с χ-гейтом; границы сглаживаются по всем edge-neighbours, не только трём.

### 4.3 Топология и параметризация

Проверяются χ, число использований chart edges, степени граничных вершин и единственная связная граничная петля.
Неподходящие чарты режутся PCA-плоскостью до 8 раундов; остатки изолируются по faces или операция отклоняется.
Полная математическая сертификация произвольного non-manifold комплекса не заявляется.

Развёртка `MINIMUM_STRETCH`, `no_flip=True`, затем Average Islands Scale и Pack Islands.
После неё отдельно измеряются UV flips, вырожденные треугольники и overlap через Blender UV Select Overlap.

При нарушении метрик локальный fallback изолирует затронутые faces, повторно проверяет дисковость
(PCA без обратного merge) и разворачивает/упаковывает снова, максимум два раза.
Порог overlap/flips при этом **не ослабляется**. Непринятый кандидат не публикуется.

### 4.4 Разрешение и выбор кандидата

Начальное auto-разрешение — степень двойки не ниже размеров исходных изображений, при их отсутствии 512.
Для корректного неперекрывающегося source atlas падение площади компенсируется увеличением разрешения в пределах бюджета.
Большие исходные изображения не уменьшаются молча. Конечный размер ограничен `--max-res`.

Проверка тонких островов оценивает **долю площади поверхности** на островах с bbox шириной <2 px.
Default допускает 0.1% (`--subpixel-area .001`), строгий режим `0` требует каждый остров.
Это измеримый бюджет потери микродеталей, не гарантия читаемости каждой заклёпки/надписи.
Один микроскопический треугольник больше не требует текстуру 524288×524288 для всей модели.

Для валидного source UV применяется score из числа островов, CV и площади; нужен измеримый выигрыш.
В любом режиме кандидат обязан пройти жёсткие UV checks и бюджет. Если подходящего кандидата нет,
исходные UV и материалы сохраняются (`unchanged`); если UV не было — операция завершается ошибкой.
Семантическое качество швов на лице/логотипе этим score не оценивается.

## 5. Материалы

Поддерживаемый контракт: один Surface Principled на слот, static shading dependencies.
Входы RGB/scalar запекаются через временный Emit. Константы каждого слота сохраняются, не заменяются картой соседнего слота.
Отдельные карты Roughness/Metallic/Alpha/Emission сохраняют свои цветовые пространства; HDR/scalar пишутся float EXR.
Base Color сохраняется как sRGB PNG. Нет автоматического преобразования всех inputs в BaseColor.

Нормали: source UV фиксируется в Normal Map, затем Cycles NORMAL выводит результат в basis target UV.
Для normal-pass используется временный opaque Diffuse с той же normal-веткой: тест выявил,
что Alpha<1 у Principled способен давать нулевую нормаль в normal-pass.
После supersampling/downscale нормали нормализуются. Итоговая Normal Map привязана к target UV.

Отдельный тест с наклонённой нормалью и повёрнутыми source UV сравнивает восстановленный вектор в пространстве объекта,
а не равенство RGB. Отдельный gradient-тест измеряет перенос цвета между разными UV.

## 6. Сохранение и проверки

- Геометрия/polygons/vertex weights/material indices/original UV/colors/shape keys сравниваются по хешам.
- Имена объектов, родители, matrix_basis/matrix_parent_inverse, кости и pose matrices проверяются отдельно.
- Сравниваются action keyframes и часть данных modifiers/constraints; это не полный animation-equivalence test.
- После сохранения packed `.blend` выполняется повторное открытие и сравнение native data/material graph.
- FBX/GLB export — opt-in и `NOT_VERIFIED`; native QA не подменяет interchange QA или Unity import.
- Только после успешного native QA результат копируется в новую выходную папку.
- Отчёты/логи/fixtures живут вне Assets; исходные файлы не перезаписываются.

## 7. Граница достоверности

Алгоритм не чинит произвольную геометрию и не является ретопологией/децимацией. Вновь запечённая карта — ресэмплинг,
а не восстановление потерянных деталей. Поддержка неизвестного shader graph не заявляется.
Ни число островов, ни нулевые flips не доказывают визуальное улучшение. Приёмка в игре остаётся за пользователем.
Фактические результаты, включая отказанные кандидаты, записываются в [ITERATIONS.md](ITERATIONS.md).
