# T-ENG02: EngineThrusterVisual — по одному pivot на каждый визуал (multi-unit)

## Симптом (репорт)

Корабль с 2 двигателями (`Ship_medium_base`, 2× `Slot_Engine`): при yaw оба
мотора «вращаются вместе вокруг общего центра», а не каждый вокруг своей точки.
Ощущение, что «точки складываются».

## Корневые причины (проверено в живой сцене через MCP)

1. **Компонент держит только ОДНУ пару `_pivotPoint` + `_visuals`.**
   Схему «2 визуала — 2 точки» в пределах одного слота выразить нечем.
   Раздельные компоненты на разных слотах работают независимо (статики нет),
   но это не покрывает кейс «несколько моторов в одном компоненте/слоте».

2. **Якоря на корабле-примере стоят в ~24 м от моторов** (замер в рантайме):
   - `Engine_PDTT_Unit` (40131.87, 2504.23, 40021.80) vs
     `Slot_Engine/RotationAnchor` (40138.13, 2502.40, 39998.85) → плечо ~23.9 м;
   - `Engine_PDTT_Unit (1)` (40128.54, 2504.13, 40021.75) vs
     `Slot_Engine 2/RotationAnchor` (40122.83, 2502.70, 39999.35) → плечо ~23.2 м.
   - Оба плеча почти параллельны (−Z, за корму) и угол отклонения общий
     (один `yawNorm` + одинаковые `SmoothDamp`) → оба мотора синхронно
     описывают дуги на 24-метровом радиусе. Визуально это и есть «вращение
     вокруг общего центра». Математика поворота при этом корректна:
     `pivot + R·(base − pivot)` в пространстве слота; неверна расстановка.

## Решение

1. **`EngineThrusterVisual`: список `List<ThrusterUnit> _thrusters`**,
   где `ThrusterUnit = { Pivot, Visuals, Propeller? }`.
   - Общий вход (thrust/yaw → `_currentAngle`, `_currentRpm`) считается один раз;
   - поза считается **поканально**: `target_i = pivot_i + R·(base_i − pivot_i)`,
     базовые позы кешируются на юнит в пространстве слота (как сейчас);
   - легаси-поля `_pivotPoint/_visuals/_propeller` остаются как fallback:
     если список пуст — работает одиночный юнит из них (все существующие
     префабы и `ShipPresetCreator`-корабли продолжают работать без ресейва);
   - `ShipPresetCreator` переведён на заполнение списка для новых кораблей.
2. **Диагностика misplacement**: `OnDrawGizmosSelected` рисует якорь + плечо
   до визуала (красным, если плечо > `_leverWarnDistance`, по умолчанию 5 м);
   в `Start` — `Debug.LogWarning` с дистанцией на юнит.
3. **Контент-фикс `Ship_medium_base.prefab`**: оба `RotationAnchor` перенесены
   в центры своих моторов (Slot-local: `(13.04, 0.63, -5.55)` и `(9.71, 0.53, -5.6)`,
   = `EngineVisuals.local + Motor.local`). При плече ~0 отклонение = чистый
   yaw-поворот на месте, без орбитального увода.

## Что НЕ делаем

- Не меняем физику/ввод/шейк; `ShipPartShake` не трогаем.
- Не мигрируем легаси-поля в префабах массово (нет churn'а 20 префабов);
  fallback покрывает их в рантайме.
- Не запускаем Play Mode / скриншоты — runtime-проверка за пользователем.

## Проверка (пользователь, manual)

1. Console → 0 errors после компиляции.
2. Открыть `Ship_medium_base`: у каждого `Slot_Engine` гизмо — жёлтая сфера
   якоря внутри мотора, короткое плечо (не красное).
3. Play: A/D (yaw) — каждый мотор поворачивается на месте вокруг себя;
   моторы не «улетают» вбок. W/S — обороты/тряска как раньше.
4. Новый корабль через `Tools/Project C/Create Ship Preset` — список `_thrusters`
   заполнен одной записью, легаси-поля пустые, поведение то же.
