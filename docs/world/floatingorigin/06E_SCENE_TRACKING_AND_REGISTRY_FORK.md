## 2. Поправка к отчётам 06C и 06D

В 06C и 06D утверждалось, что остальные префабы и сцены остаются за Lore VCS. **Это было неточно.** Фактическая проверка `git ls-files`:

- `Assets/_Project/Scenes/World/WorldScene_0_0.unity` — **уже отслеживается** в Git;
- отслеживается **43** префаба, включая 20 капитанских префабов кораблей.

Причина: правила игнорирования добавлялись позже, а на уже отслеживаемые файлы `.gitignore` не действует. Таким образом правила блокируют добавление **нового** контента, но часть существующего контента ведётся в Git. Проверенные ранее утверждения об изоляции пилотных ассетов остаются верны — неверной была характеристика остального проекта.

## 3. Важно: несохранённое состояние сцены

`BootstrapScene` в редакторе имеет несохранённые изменения (`isDirty=true`), зафиксированные ещё при первом осмотре на этапе 06A — они предшествуют этой работе.

В коммит попадает **версия файла с диска**. Несохранённые изменения редактора в него не входят. Сцена мной не сохранялась: авторство этих изменений не подтверждено, а сохранение сцены — решение пользователя.

Байты файла на диске не менялись с момента снимка 06A: контрольная сумма совпадает во всех последующих проверках.

## 4. Развилка: как применить пилотный реестр

Установленный факт из кода запуска: эффективный реестр перед стартом собирается из **всех** списков в `NetworkConfig.Prefabs.NetworkPrefabsLists` плюс встроенных записей `Prefabs.Prefabs`. Проверка каталога вызывается с перечислением списков до старта и с признаком live-реестра после старта.

Отсюда следует: пилотный список обязан **заменять** default-список, а не добавляться к нему. Способ замены — открытый вопрос с разными последствиями.

### Вариант A — заменить список в сцене

Убрать `DefaultNetworkPrefabs.asset` из `NetworkManager` в `BootstrapScene` и подставить пилотный список.

Последствие: **текущая игра перестаёт работать.** Спавн всех 58 зарегистрированных префабов — корабли, NPC, предметы, сундуки, ресурсы, зоны — начнёт отклоняться, потому что реестр станет пилотным для всех режимов, включая legacy. Обратимо только откатом сцены.

### Вариант B — условная подмена только в global-пути

Оставить сцену с default-списком. В той ветке, которая уже включается лишь при назначенном и включённом `_globalMotionProfile`, подставлять пилотный список до подготовки запуска.

Последствие: legacy-режим сохраняет текущее поведение полностью; пилотный реестр действует только когда пилот явно активирован. Требует небольшой правки кода и аккуратности с существующей защитой «ownership конфигурации при старте», которая сравнивает хеш конфигурации до и после подготовки — подмену нужно выполнять до снятия этого хеша.

### Вариант C — отдельная пилотная сцена bootstrap

Полная изоляция, но появляется вторая тяжёлая сцена, требующая синхронного сопровождения с основной.

### Рекомендация

**Вариант B.** Он соответствует уже принятому в этой архитектуре принципу: всё global-поведение включается только при явно назначенном профиле, а legacy-путь остаётся неизменным. Вариант A ломает работающую игру без необходимости, вариант C создаёт дублирование сцены.

Ни один из вариантов в этом этапе не реализован: выбор влияет на работоспособность текущей игры и требует подтверждения.
