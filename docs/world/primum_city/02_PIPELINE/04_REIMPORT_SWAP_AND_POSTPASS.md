# 04. Подмена FBX 1:1 и пост-проход (проверено на 23 чанках)

**Когда применять:** после любого прогона Blender-конвейера — замена FBX-моделей в проекте
без пересборки префаба и сцены.

---

## 1. Почему 1:1 и как это делается

Модели лежат в `Assets/_Project/Art/Models/Primum/Chunks/<чанк>.fbx`. Unity связывает их с префабом
по **GUID из `.meta`**. Если положить новый FBX **по тому же пути с тем же именем**, GUID сохраняется,
Unity переимпортирует модель на месте, а `PRIMUM_CITY.prefab` и сцена обновятся **сами** — пересборка
префаба/сцены не нужна.

```powershell
$staged = 'Q:\…\New Folder\_deliver_doors\<чанк>.fbx'
$asset  = 'C:\Projects\ProjectC_client\Assets\_Project\Art\Models\Primum\Chunks\<чанк>.fbx'
Copy-Item $asset  'Q:\…\New Folder\_versions\<чанк>_before_swap_<дата>.fbx' -Force   # бэкап
Copy-Item $staged $asset -Force
```

Затем в Unity: `refresh_unity` (force, assets, wait_for_ready).

## 2. Что ломается при подмене (замерено)

| Что | Факт | Что делать |
|---|---|---|
| **Слои** | новые объекты модели приходят на `Default`; у префаба слой был «запечён» | скриптовый пост-проход: рекурсивно `PRIMUM` |
| **Оверрайды старых объектов теряются** | `SetActive(false)` на дверях, добавленные компоненты, коллайдеры — привязаны к старым объектам | пост-проход заново: выключить двери, обновить реестры |
| **Счётчики мешей меняются** | двери/свет стали отдельными объектами | пересчитать числа приёмки |
| **Сцена становится dirty** | изменение модели меняет инстанс | `MarkSceneDirty` + `SaveScene` |
| Материалы | переиспользуются по имени/пути | проверено: churn нет |
| **Геометрия, скрытая ручными правками** | если что-то было выключено вручную на объектах модели — оно вернётся включённым | только скриптовый пост-проход |

> **Главный урок:** любые ручные правки внутри объектов модели теряются при подмене.
> Всё, что должно сохраняться, — отдельные объекты вне модели или скриптовый пост-проход.

## 3. Пост-проход (обязателен после каждой подмены)

Скрипт Unity (`execute_code` MCP):

1. `PrefabUtility.LoadPrefabContents("Assets/_Project/Prefabs/City/PRIMUM_CITY.prefab")`.
2. Для каждого чанка `PRIMUM_*`:
   * рекурсивно назначить слой `PRIMUM` (8);
   * выключить всех детей узла `DOORS` (проёмы пустые до расстановки префабов);
   * выключить детей `OUTLIERS` (улетевшие объекты);
   * **включить** детей `DOOR_PARTS_UNASSIGNED` — это видимая геометрия, скрывать нельзя.
3. `SaveAsPrefabAsset`.
4. Сцена: пересчитать реестры (`03_DOORS/registries/`), `MarkSceneDirty`, `SaveScene`.

## 4. Проверка после подмены (обязательно)

| Проверка | Ожидание |
|---|---|
| Ассет == стейдж | MD5 файла в проекте совпадает с `_deliver_doors` |
| Модель в Unity | `DOORS` в модели = число из лога прогона |
| Сцена == модель | то же число, все двери неактивны |
| Высоты дверей | медиана ≈ 2.2 м; выше 2.9 м — единицы (широкие проёмы) |
| Утечки `_DOOR` | 0 объектов вне узлов |
| Слои | 0 объектов вне `PRIMUM` |
| Консоль | без ошибок импорта |

## 5. Текущие узлы модели (после v13)

```
<чанк>.fbx
├── <чанк>_M_<материал>            ← батчи оболочки
├── <чанк>_INT_<материал>          ← батчи интерьера
├── DOORS/<имя>_<W>x<H>_X          ← двери (выключены; пивот низ по центру)
├── DOORS_BIG/<...>                ← крупные дверные сборки (если есть)
├── LAMPS/<...>                    ← светильники (включены)
├── DOOR_PARTS_UNASSIGNED/<...>    ← детали без двери (включены)
└── OUTLIERS/<...>                 ← улетевшие объекты (выключены)
```
