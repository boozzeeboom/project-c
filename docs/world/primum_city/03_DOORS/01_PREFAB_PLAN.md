# ПЛАН: префабы дверей и расстановка в проёмы (следующая фаза)

**Вход:** 3 038 выключенных дверей + реестры (`03_DOORS/registries/`).
**Выход:** в каждом проёме — префаб двери нужного типа; старые дверные группы остаются выключенными
как «заглушки» до приёмки, затем удаляются.

---

## 1. Типы префабов (по требованию заказчика)

| # | Тип | Когда применяется | Примечания |
|---|---|---|---|
| 1–3 | **Одиночные** (3 варианта) | ширина по реестру **0.75–1.25 м**, H 1.95–2.45 | основная масса дверей (≈85–90 %) |
| 4 | **Двустворчатая** | ширина **1.3–2.4 м** (два полотна) | подъезды, торговые лавки |
| 5 | **Ангарная / ворота** | ширина **≥ 2.4 м** или H > 2.6 | мастерские (`S8_GW`), широкие проёмы |
| 6 | **Администрация** (набор) | чанк `ADMIN_S0_ADM_P1_01H` | своя стилистика; 135 дверей, включая парадный 12.63×4.17 |
| 7 | **Дворцы** (набор) | дома-дворцы (уточнить список домов) | своя стилистика, крупные полотна |

**Свет** (отдельная фаза, после дверей): 2 уличных (фонарь на столбе, настенный), 2–3 фасадных,
2–3 интерьерных. **Администрацию и дворцы не трогать** — у них свои светильники.

## 2. Контракт пивота (критично)

* Пивот префаба = **низ по центру** проёма (совпадает с пивотом дверной группы в реестре).
* Ось **+Y вверх**; «лицо» двери — по локальной оси **+Z** (или −Z — зафиксировать один вариант
  и при расстановке добавлять поворот, если нужно).
* Масштаб префаба — **1**; размер подгоняется не масштабом, а выбором типа/варианта.
* Префаб содержит: раму/наличники (по желанию), полотно, фурнитуру; **проём должен оставаться
  проходимым** (коллайдер — отдельно, не в префабе, если не решено иначе).

## 3. Алгоритм расстановки (Editor-скрипт)

1. Прочитать все `doors_registry_*.csv`.
2. Для каждой строки:
   * определить тип по `w`/`h` + чанк + имя (`ADMIN_*` → набор администрации; «дворец» → набор дворцов;
     `GATE`/широкое → ворота; `w ≥ 1.3` → двустворчатая; иначе одиночная);
   * вычислить **локальную** позицию/поворот: `local = parent.InverseTransformPoint(world_pos)`,
     `localRot = Quaternion.Inverse(parent.rotation) * Quaternion.Euler(0, rot_y, 0)`;
   * `PrefabUtility.InstantiatePrefab(typePrefab)` под узел `<чанк>/DOORS_PREFAB`;
   * выставить позицию/поворот, слой `PRIMUM`;
   * оригинальную группу (`DOORS/<имя>`) оставить **выключенной** как заглушку (реестр уже хранит её).
3. Ведение карты: обновить реестр (колонка `prefab` = имя префаба, `status` = placed) —
   чтобы повторный запуск не дублировал.
4. После приёмки — удалить выключенные заглушки пачкой (или оставить, они невидимы).

## 4. Подбор типа: статистика для порогов

Из реестров (3 038 дверей):

| Показатель | Значение |
|---|---|
| Ширина p10 / медиана / p90 | 0.86 / 1.02 / ~1.35 |
| Высота медиана | 2.24 м (типовой ряд 2.05–2.45) |
| Двери ≥ 1.3 м шириной | ~10 % (двустворчатые) |
| Двери ≥ 2.4 м | ~2 % (ворота/парадные) |
| Выше 2.9 м | 5 (ADMIN 1, S8_GW 4) |

## 5. Приёмка

| Критерий | Норма |
|---|---|
| Расставлено | 3 038 / 3 038 (или явный список исключений) |
| Пивот на полу | низ префаба == pos_y реестра (±0.02 м) |
| Ориентация | полотно в плоскости проёма (проверить 10 случайных) |
| Пересечения | префаб не выходит за стену > 0.05 м |
| Старые заглушки | выключены, реестр помечен |
| Проёмы | проходимы (коллайдеры не мешают) |
| Видео/скрин | визуальная проверка заказчиком 5–10 дверей разных типов |

## 6. Риски и как снимаем

| Риск | Снятие |
|---|---|
| Пивот префаба не «низ по центру» | тест на 3 дверях перед массовой расстановкой |
| Ширина в реестре включает наличники/фурнитуру | допуск ±0.05 м; при несовпадении — ближайший вариант + запись в отчёт |
| Дворцы не идентифицированы | до расстановки составить список домов-дворцов (по именам/чанкам) |
| Сетевой спавн дверей | `NetworkPrefabsList` не назначен (известный долг) — если двери будут динамическими |
| Повторный прогон расстановки | карта в реестрах (`prefab`, `status`) защищает от дублей |

## 7. Порядок работ

1. **Пилот:** 5–10 дверей разных типов в одном чанке (например `S9_TRD-N`) → визуальная проверка.
2. Создать 3 одиночных + двустворчатую + ворота; отдельно наборы ADMIN и дворцов.
3. Массовая расстановка по реестрам, отчёт по исключениям.
4. Приёмка заказчиком, удаление заглушек.
5. Свет: пилот → массово (кроме ADMIN/дворцов).
