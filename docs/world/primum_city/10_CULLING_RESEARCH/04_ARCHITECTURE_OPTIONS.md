## 3. Разбор ключевых путей

### 3.1 Low-code (Ф0) — обязательный первый шаг

Почему первым:
- даёт **−67…−78 %** за 2–4 дня, без переделки города/шейдеров;
- бьёт по главному источнику — дверям (84 % кадра);
- FO-safe по конструкции: дистанции/слой — скаляры, `shadowCastingMode` — per-renderer, данные
  читаются из живых трансформов;
- снимает риск «вложили 3 недели в GRD и не завелось», оставляя измеримый выигрыш.

Что входит:
1. Новый слой `PRIMUM_DOORS` (11 префабов → все инстансы наследуют); двери сейчас на `PRIMUM` (8).
2. `Camera.layerCullDistances[layer] = 120–150 м` для геймплейной камеры; `layerCullSpherical=false`.
3. `Renderer.shadowCastingMode = Off` дверям дальше ~40–80 м — либо сразу всем (решение заказчика
   по визуалу), либо дешёвым distance-менеджером с гистерезисом (2–4 Гц, группами).
4. Фиксы: `QualitySettings.shadowDistance` no-op (URP читает ассет); `Camera.main`-мина
   (`DetailDistanceCuller`); устаревшие числа far.
5. A/B на реальном far 30 км и 3 точках (центр/улица/крыша).

Ограничения: `layerCullDistances` **не влияет на тени** (нужен отдельный рычаг); резкая граница
(нет гистерезиса); перенос слоя затрагивает raycast/физику — проверить маски.

### 3.2 GPU Resident Drawer + GPU occlusion (Ф1) — главный путь к «сотням»

Факты:
- URP 17.5 уже содержит `GPUResidentDrawer`, `GPUResidentDrawerMode.InstancedDrawing`, GPU-окклюзию
  (Hi-Z: пирамида глубин → compute → indirect), `smallMeshScreenPercentage`, debug views.
- Требования: `BrgStripping = KeepAll` (сейчас `0 = KeepIfEntitiesGraphics`; enum KeepIfEntitiesGraphics=0,
  StripAll=1, KeepAll=2 — **блокер**), DOTS-инстансинг в шейдерах, Forward+ (уже включён), RawBuffer/D3D12 (есть).
- FO-safe: ничего не запекается, Hi-Z строится каждый кадр, инстансы из живых трансформов;
  после ребейза — разовое обновление матриц (замерить спайк).
- Двери: 2 598 инстансов из 11 префабов → десятки (≤~72) пар mesh×material → **десятки–сотни** команд вместо 17.7k
  draw calls. Город (761 уникальных батч-мешей) останется ~761 draw/проход, но GPU-окклюзия сможет
  отсекать батчи по Hi-Z.

Риски/что проверить пилотом: тени под GRD (URP shadow pass идёт через `CreateShadowRendererList`),
анимация створок дверей (изменение инстанс-матриц), **Shader Graph + DOTS-инстансинг**: город — 49
материалов на 15 графах, двери — 6 на 5 графах; Shader Graph 17.5 умеет DOTS, но требует настройки
графов, а в текущих `.shadergraph` ключей instancing/DOTS нет → **объём работы [UNVERIFIED]**, не
«0.5–1 день на ProceduralSteel» (его материалы в сцене не используются — 0 ссылок).

### 3.3 Гранулярность города (Ф2) — не «обязательно», а «когда нужен <2k»

Сейчас: A (чанк×материал), 1 656–1 806 слотов, AABB 129 м, DC_A 2 292 / DC_B 1 647 (модель J).
J посчитал альтернативы: **B2 (дом × материал, только геометрия ≥1 м)** — 3 182 слота, AABB 6.3 м,
DC_A 3 904 / DC_B 2 302 (**+40 %**); полный «дом» — 6 214 слотов, +146 %; ячейки 20/30 м — +76/+50 %.
Поэтому B2 — **не бесплатное улучшение**, а обмен +40 % DC на гранулярность; он оправдан только если
GRD/Hi-Z снимает ≥35 % видимых слотов B2 и решён отдельный бюджет теней (+56 % кастеров). Ячейки
10–30 м и «блоки» (чанк уже 26–228 м) — не делать. Требуется пересборка 23 чанков (2–4 недели) и
воспроизводимый тул/манифест (сейчас мерж невоспроизводим).

### 3.4 CPU VisibilityDirector (Ф3) — не замена GRD, а слой управления

Что реально даёт:
- иерархию «мир → чанк → улица → дом → группа дверей» с фрустум/дистанция/тени-бюджетами;
- мультикамерный union (важно: `Renderer.enabled` глобален для всех камер);
- группы для кораблей/интерьеров/крупных объектов вне GRD;
- гистерезис и обновление на 2–4 Гц (каденция), чтобы уложиться в 2 мс;
- FO-safe: живые трансформы, без мировых кэшей.

Что **не** даёт: окклюзию «за стеной» без отдельного occlusion-механизма. Поэтому он не заменяет
GRD/PVS, а дополняет: бюджет теней, distance-группы, мультикамера, корабли, а также fallback, если
GRD не взлетит.

### 3.5 Portal/PVS (Ф4) — максимальный эффект, высокая цена

Прокси-оценка по коллайдерам: в фрустуме ~2 881 **рендерер** дверей, «видимо» ~10 (99 % скрыто) — потенциал
огромный. Но:
- offline-бейк по 10 817 боксам/ячейкам: 6–10 недель (авто-порталы + бейкер + рантайм + тулинг);
- rebake при каждой правке города (город ещё меняется);
- FO-safe только если данные в **локальных координатах ячейки/корня**;
- ошибки видимости (луч в центр двери упирается в стену) требуют аккуратной геометрии порталов.
Брать только если после Ф1/Ф2 не хватает и бюджет L0 <1k.

### 3.6 Umbra — закрытая ветка

- 6 бейков упали (`Failure in split phase`), данных нет;
- baked-PVS в мировых координатах → после FO-ребейза (первый T ≈ **56 км!**) карта описывает прошлое;
- static-флаги запрещены правилом FO;
- публичного runtime-типа `OcclusionCullingData`/API подмены данных нет → «Umbra-on-proxies»
  технически невозможно;
- террейн не Renderer → в окклюзию не попадает; карта города в котловине неполна.
**Решение: не инвестировать.** Оставшиеся гипотезы (H1–H4 из A §2.3) — только как дешёвый эксперимент
для понимания, не как путь к продакшену.

## 4. Готовые ассеты: почему не они

Подробно — `07_ASSETS_AND_PRIOR_ART.md` и `B_ASSET_LANDSCAPE.md`. Кратко:
- ни один платный ассет не декларирует Unity 6.x/URP 17.5 (только 2019.4/2022.3), все — per-seat;
- они куллят **готовые рендереры**, а 4 949 дверей и так фрустум-куллятся; выигрыш только у скрытых;
- **порядок величины** даёт не culling, а дедуп/инстансинг дверей — это встроенный GRD, не покупка;
- SECTR/порталы требуют авторинга на 2 161–2 363 проёма и дублируют наш стриминг; Mesh Baker/Poly Few
  усугубляют склейку/режут треугольники, а не DC; Perfect Culling может быть **измерителем потолка**
  окклюзии, не продакшн-решением; GPU Instancer Pro — только после дедупа и с риском FO-матриц.
- **Вывод:** покупать не нужно; деньги/время — в GRD-пилот и low-code.

## 6. Рекомендуемая последовательность

```
Ф0 (2–4 дня)   low-code двери + фиксы + A/B на реальном far 30 км + E0 (Frame Debugger)
      │  gate: подтверждён счёт дверей; экономия ≥30 %; нет визуальных дефектов
      ▼
Ф1 (2–3 нед)   GRD-пилот: BrgStripping=2, DOTS-инстансинг, GPU RD + occlusion,
      │        двери как инстансы, тени/створки/FO; 1 чанк → вся сцена
      │  gate: Hybrid Batch Group; DC ≤2 500; F8/F9 без артефактов; тени ок
      ▼
Ф2 (2–4 нед)   пере-грануляция города по блокам/домам (если нужен <2k) + HLOD L1
      │        параллельно: CPU VisibilityDirector для мультикамеры/кораблей/бюджетов
      ▼
Ф3 (опция)     Portal/PVS или HLOD-импостор L2 — только если бюджет L0 <1k обязателен
```

Ключевая развилка: **если GRD-пилот зелёный — свой GPU-culling не пишем** (это 6–10 недель дубля
engine). Если красный — откат к Ф0+Ф3 (CPU-директор + low-code), ожидание 5.5–8k DC без окклюзии.
Полный план — `05_RECOMMENDED_ARCHITECTURE.md`, эксперименты — `06_EXPERIMENTS_AND_ROADMAP.md`.
