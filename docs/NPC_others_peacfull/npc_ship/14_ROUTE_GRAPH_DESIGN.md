# 14 — Дизайн: граф трасс вокруг пиков (структурное курсирование)

> **Project C: The Clouds** | Unity 6000.5.2f1 | NGO 2.13.0
> **Дата:** 2026-09-24 | **Статус:** дизайн принят, реализация T-NS-GRAPH01

> `13_NAV_COORDINATOR_RESEARCH.md` §3C, `ITERATIONS.md` (WF04..WF18, NAV11..NAV16)
> **Лор-ограничение:** корабли ОБЛЕТАЮТ пики вокруг (не перелетают сверху).
> Высота — core gameplay, вертикаль в обходе заморожена.

---

## 1. Проблема

`PlanRoute` (T-NS-NAV11/NAV16) — это «прямая + до 2 дисков + до 2 bypass»:

* хребет из 3+ пиков подряд планом не разрешается — третий пик встречает
  уже реактивный `WallFollow`, а не план;
* воронка (все маршруты через один проход) планом не видна вообще;
* встречные leg'и планируют вслепую друг от друга (только чёт/нечет разводка);
* каждая нога заново «открывает географию» — памяти трасс нет.

Лестница `recovery → scatter → divert → hotspot → replan → retreat`
работает как эвакуация, но не как курсирование: каждый клин стоит
10–60 с ползания + смену маршрута. Локальным steering это не лечится
(вывод `13_` §1: стая/клин/вогнутость — структурные слои).

## 2. Решение: кольцо-гейты + Дейкстра (паттерн GATE04)

Вокруг каждого диска `PeakRegistry` строим кольцо из 8 гейтов
(радиус `r + navBypassDist`, на `ProfileY`). Маршрут = кратчайший путь
по графу «старт → гейты → цель», рёбра — только по чистым прямым
(`LegClear` тем же фильтром стен). Локальный steering остаётся тактикой
последней мили (меши-скалы, которых в дисках нет) и непредвиденным.

```
A ──► gate(диск1) ──► gate(диск2) ──► B
│         ↕ (кольцо)      ↕              │
└────── direct (если LegClear) ──────────┘
```

* Узлы — мировые точки, считаются вживую каждый `PlanRoute`
  (паттерн `ResolveTargetStation`/`GateApproach`): F8-безопасно
  по построению, кэша мировых координат нет.
* Диски ниже профиля игнорируются (как раньше: пролёт выше пика —
  не препятствие, `PeakRegistry.FindBlockingDisc` §81).
* Цель внутри диска (`mountain-home`, T-NS-DOCK01) — граф не строим,
  ведёт `Berthing` напрямую (щель 100–500 м закрыта зондом Overhead).
* Лимит: не более 8 блокирующих дисков, гейтов 8/диск, точек маршрута
  не более `routeGraphMaxWp` (дефолт 6). Больше — идём legacy-петлёй.
* Kill-switch: `useRouteGraph` (дефолт **true**, fallback — старая
  цепочка peak/bypass бит-в-бит при пустом результате графа).
* Hotspot-штрафы учитываются в весе рёбер (память заторов работает
  и на графе, не только в `PickBypass`).

## 3. Что НЕ трогаем

* Прямой `Rigidbody`-контроль; `ShipController`; `EnterDocked`/`ExitDocked`;
  `detectCollisions=true`; NGO/RPC/NetworkTransform.
* `WallFollow`/лидар/scatter/divert/retreat — остаются страховкой
  (граф уменьшает входы, а не заменяет выход из клина).
* `AltitudeCorridorData` (SO) — только чтение.
* `Core/NavMode.cs` — мёртв, не трогаем.
* Вертикаль: все гейты на `ProfileY` (лор D2, перелётов нет).

## 5. Проверка (делает пользователь, Play Mode, NOT RUN агентом)

1. Маршрут через хребет из 3+ пиков: `nav-plan` с `how=graphN`, пролёт
   по гейтам без входов в `WallFollow`; лог `graph-wp` по точкам.
2. Регресс флага: `useRouteGraph=false` = поведение NAV11/NAV16 бит-в-бит.
3. `mountain-home`: план `how=mountain-home`, заход напрямую в `Berthing`,
   нет вечных `nav-plan → возврат`.
4. F8 во время leg'а с графом: цели не протухли, 0 errors.
5. Console → 0 errors после compile (CS0618 по PeacefulShip — 0).
