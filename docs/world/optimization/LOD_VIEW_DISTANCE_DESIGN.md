# Дальность прорисовки и LOD — дизайн (4 уровня)

**Статус:** дизайн к реализации | **Дата:** 2026-09-20
**Требование (слова пользователя):** удалённые террейны выглядят очень хорошо — нельзя просто выключать их; снизить нагрузку, сделав их «фоном». 4 уровня: ближнее / среднее / дальнее / ультрадальнее окружение. Игра рассчитана на очень большие масштабы. Ультрадальнее пока выключать — 2+ игровых сцен нет; когда появятся — учесть и ввести.
**Управление:** ESC → Настройки → Видео → Дальность прорисовки.

---

## 1. Идея одной фразой

Один пресет «Дальность прорисовки» управляет четырьмя кольцами вокруг камеры. Далёкий террейн **никогда не выключается** — он переходит в дешёвый режим «фон» (тот же 1 draw call террейна: грубая геометрия + basemap + туман), а экономия берётся из **камеры (far), теней, мелких пропсов и LOD‑смещения**, а не из отключения гор.

## 2. Четыре кольца

| Кольцо | Дистанция* | Что видно | Режим отрисовки |
|---|---|---|---|
| **L0 Ближнее** | 0–3 км | Террейн в деталях, руины, поселения, корабли, эффекты | Полная геометрия террейна (`pixelError` малый), тени вкл, все пропсы |
| **L1 Среднее** | 3–12 км | Силуэты хребтов, снег, крупные постройки | Террейн упрощён (`pixelError` средний), мелкие пропсы скрыты, тени только ближние |
| **L2 Дальнее — ФОН** | 12 км — край сцены | Весь `Terrain_0_0` как панорама | **Basemap‑фон**: `pixelError` большой, 1 draw call, без попиксельных деталей; читаются силуэт + снег + туман. **Выключать запрещено** |
| **L3 Ультрадальнее — резерв** | Соседние `WorldScene_X_Z` | Пока не существует (в фокусе только `WorldScene_0_0`) | **Forced OFF**, кодовый хук + пункт UI в disabled. Ввести, когда сцен станет 2+ |

\* Точные метры колец — калибруются замерами Phase 0 (высота полёта 600–5000, сцена 80 км). Значения ниже — стартовые.

### Почему «фон», а не off

1. Пользователю нравится вид удалённых террейнов — off убьёт визуальный якорь и навигацию по ориентирам (пиллар «Навигация по ориентирам», `docs/world/WorldLandscape_Design.md` §8).
2. Террейн — это **один объект на всю сцену** (`Terrain_0_0`), его «выключение» дёшево по CPU, но дорого по картинке; а «удешевление» (pixelError + basemap + туман) почти бесплатно и сохраняет силуэт.
3. Фон‑режим не трогает геймплей: коллайдер террейна остаётся (физика не зависит от LOD), стриминг чанков не зависит от визуального culling.

## 3. Пресеты для игрока (один контрол — один пресет)

Игрок выбирает **один** пресет, движок раскладывает его на все кольца. Три активных + четвёртый зарезервирован.

| Пресет | Камера far | `lodBias` | Террейн pixelError / basemap | Тени (shadowDistance) | Мелкие пропсы (руины/детали) | L2‑фон до |
|---|---|---|---|---|---|---|
| **Близкая** (Performance) | 30 000 | 0.7 | 150 / 12 000 | коротко (~500) | скрыты дальше ~4 км | ~25 км |
| **Средняя** (Balanced, дефолт) | 60 000 | 1.0 | 100 / 20 000 (= текущее) | средне (~1500) | скрыты дальше ~8 км | ~45 км |
| **Дальняя** (Cinematic) | 120 000 | 1.3 | 40 / 40 000 | далеко (~3000) | скрыты дальше ~12 км | край сцены (80 км) |
| **Ультра** (резерв) | — | — | — | — | — | **disabled**, хинт «появится с новыми сценами» |

Замечания:

- Текущий `far=1000000` (обе камеры) уходит в прошлое: даже «Дальняя» 120 000 покрывает сцену 80 км с запасом и резко улучшает точность глубины (шаг глубины на 4 км сейчас ≈10 м — см. `DESIGN_farfocus.md` §1; меньший far = меньше z‑fighting на склонах).
- `basemapDistance` больше `far` не имеет смысла — в таблице значения согласованы (basemap ≤ far).
- Тени и пропсы — главные рычаги FPS; террейн‑фон сам по себе почти бесплатен.
- `DistantFocus` (`FarStart=800/FarEnd=4000`) живёт внутри L0/L1 — его пороги при смене пресета не трогаем, только проверяем, что размытие не спорит с новым far.

## 4. Что входит в каждый рычаг (технически)

| Рычаг | Как крутится | Где применяется |
|---|---|---|
| Camera far | `camera.farClipPlane = preset.far` для риг‑камеры (`SpringArmCamera.CameraComponent`) + `WorldCamera` | `ViewDistanceApplier` |
| LOD‑смещение | `QualitySettings.lodBias = preset.lodBias` | `ViewDistanceApplier` |
| Террейн‑деталь | `terrain.heightmapPixelError`, `terrain.basemapDistance` на `Terrain_0_0` (поиск разовый, кэш ссылки — не мировых координат) | `ViewDistanceApplier` |
| Тени | `QualitySettings.shadowDistance` (и/или URP‑ассет, что уже используется качеством) | `ViewDistanceApplier`, согласовано с `QualityLevel` |
| Мелкие пропсы | Дистанционный culling `RuinsValleys`‑детей и будущих деталей **только визуально** (`Renderer.enabled` / слой), без выгрузки и без разрушения инстансинга | `ViewDistanceApplier` или отдельный `DetailCuller` (решение на Phase 2) |
| Туман/фон | Не трогаем (атмосфера и так даёт перспективу); проверяем, что туман не съедает L2‑силуэт раньше `far` | Проверка, без кода |

## 5. Поведение и UX (ESC → Видео)

- Секция «Дальность прорисовки» в `GraphicsSettingsSection` (рядом с «Качество», до/после «Эффектов»).
- Виджет: **Dropdown из 4 пунктов** (переиспользовать `SettingsWidgets.CreateDropdown`):
  1. «Близкая — максимум FPS» → `ViewDistance.Near`
  2. «Средняя — баланс» → `ViewDistance.Medium` (дефолт)
  3. «Дальняя — кинематографично» → `ViewDistance.Far`
  4. «Ультра (скоро)» → `ViewDistance.Ultra` — **disabled**, хинт: «Появится, когда откроются соседние регионы».
- Применение **мгновенное** (как громкость/тумблеры эффектов), без рестарта; значение persists в PlayerPrefs (`Settings.ViewDistance`).
- Продвинутый слайдер far в эту итерацию **не делаем** — один пресет проще для игрока и проще тестировать. Отдельный слайдер — кандидат на Phase 5, если попросят.
- Локализация: новые ключи `ui.esc_menu.section.view_distance`, `ui.esc_menu.label.view_distance`, `ui.esc_menu.view_distance.near/medium/far/ultra`, `ui.esc_menu.view_distance.ultra_hint` — в `UI_Table` (ru+en минимум, остальные — следующим LOC‑проходом как уже делалось для «Эффектов»).

## 6. Связи с существующими системами

| Система | Связь | Решение |
|---|---|---|
| Floating Origin | `ViewDistanceApplier` не хранит мировые `Vector3` между кадрами (только настройки + дистанции) | 🟢 Хуков сдвига не надо. Запрет: не кэшировать мировые позиции пропсов без `ApplyRebaseTranslation`; дистанционный culling считать каждый кадр от текущей позиции камеры. См. `AGENTS.md` §Floating Origin |
| `WorldStreamingManager` | Стриминг грузит чанки, LOD прячет пиксели — разные слои | Culling только визуальный; чанки не выгружаем. `loadRadius/unloadRadius` не трогаем |
| `WorldSceneManager` (24 сцены 6×4) | L3‑хук | `ViewDistance.Ultra` применяется только если загруженных игровых сцен >1, иначе ранний return + лог. UI disabled независимо |
| `QualityLevel` (пресеты URP) | Два измерения: «красивость» vs «дальность» | Ортогональны: `QualityLevel` — шейдеры/AA/VSync, `ViewDistance` — far/LOD/террейн/тени. `ApplyAll()` применяет оба |
| `DistantFocusRenderFeature` | Средний план 0.8–4 км | Не меняем; после смены пресета — визуальная проверка, что фокус не плывёт |
| Сейвы | Только индекс пресета (int) | Паттерн сейвов мировых координат не затрагивается |

## 7. Что НЕ делаем (не‑цели)

- Не делим `Terrain_0_0` на тайлы и не пишем свой quadtree‑LOD для террейна — хватает связки `pixelError + basemap + far + fog` на масштабе 1 активной сцены.
- Не трогаем `ClientSceneLoader`/`NetworkSceneManager`, не добавляем `NetworkManager`, не удаляем `ScenePlacedObjectSpawner` (запреты `AGENTS.md`).
- Не пишем `.meta`/`.asmdef` руками; конфиг пресета — обычный `ScriptableObject`, создаётся через `CreateAssetMenu` в Editor.
- Не запускаем Play‑тесты и билды сами (по `AGENTS.md` — это делает пользователь); даём чек‑лист ручной проверки.

## 8. Риски

| Риск | Митигация |
|---|---|
| Pop‑эффект при смене pixelError/basemap | Гистерезис не нужен (смена только по действию игрока в меню, не каждый кадр); в будущем для авто‑LOD — двухпороговая схема |
| Туман съедает L2‑фон раньше far | Подобрать `far` после замера тумана; проверка скриншотами 3 пресетов с одной точки |
| Конфликт с `QualityLevel` (кто владеет shadowDistance) | Владение фиксируем: `shadowDistance` — за `ViewDistance`, остальное качество — за `QualityLevel`; задокументировать в коде обе стороны |
| Руины: отключение `Renderer` ломает инстансинг‑батчи | Куллить целыми хамлетами (60 групп), не отдельными инстансами; замерить draw calls до/после |
| Depth precision на дальних склонах | Уменьшение far с 1M до 30–120K само лечит; при необходимости поднять `near` 0.1→0.3 на «Близкой» (согласовать с `SpringArmCamera` zoomMin) |
