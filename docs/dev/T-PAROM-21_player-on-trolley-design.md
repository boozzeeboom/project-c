# T-PAROM-21 — игрок на тележку при ресторре (дизайн)

> Статус: дизайн. База: T-PAROM-20 (персистенция ветки), `WaitForShipAndBoard`
> (паттерн), carry re-init (`platform != _currentPlatform` — без рывка).

## 1. Цель

Игрок, сохранившийся на кабинке, после рестарта/перезахода появляется
НА ЖИВОЙ кабинке (текущая позиция по восстановленному `s`), а не в старых
мировых координатах (кабинка уже уехала — падение в пустоту).

## 2. Сейв: platformRouteId (server-side probe)

Carry считается на owner-стороне — сервер про remote-клиентов опоры не знает.
Поэтому сервер сам определяет ветку под ногами: SphereCast вниз от позиции
игрока (5-с тик, дёшево) → `attachedRigidbody` → `ParomTrolley` → `RouteId`.
Нашли — пишем `platformRouteId` в `PlayerPositionSaveData` (аддитивно).
Не нашли — старое поведение (мировая позиция). Ветка `inShip` — раньше
(пилот в кресле, не пассажир).

## 3. Ресторр: телепорт на живую крышу

В `PlayerPositionServer.RestorePlayer`, после ветки `inShip`, до фолбэка
на позицию: `platformRouteId` задан → ищем spawn-нутую ветку по `RouteId` →
точка `ParomRoute.GetBoardingPoint()` (верх коллайдера + 0.3) → телепорт
(тот же `TeleportPlayer`) → `NetworkPlayer.BindRiddenPlatform()` (кэш carry
на текущую позицию кабинки — иначе догоняющий рывок). Нет ветки —
фолбэк на сохранённую позицию (как раньше).

Клиентская сторона отдельно не нужна: у клиента `_currentPlatform == null`,
первый детект — чистая привязка через существующую re-init ветку (без рывка).

## 3b. T-PAROM-21b: global-путь пилота (наш случай!)

Лог показал: игрок идёт через `PilotSpawnRestored` (`UsesGlobalCoordinates`),
legacy-`RestorePlayer` у него НЕ выполняется — ветка из §3 молча не стреляет.
Поэтому дубль в global-ветку `RestorePlayerPositionCoroutine` (рядом с
`WaitForShipAndBoard`): `TryLoadPlayerPlatform` (только ID, без сдвига —
как `TryLoadPlayerShip`) → `WaitForRouteAndPlace` (ждёт `RestoreCompleted`,
телепорт на живую точку + bind + сброс fall-таймера/порога). Нет ветки —
остаться на pilot-точке (старое поведение).

## 4. Порядок

Ресторр парома (T-PAROM-20, ~3.5 с) раньше ресторра игроков (спавн + 5 с):
точка берётся с живой кабинки, которая уже на восстановленном `s`.
При живом сервере (просто перезаход) сейв вообще не читается — только живая.

## 5. Не входит

- T-PAROM-22 (platform-rescue при падении).
- NPC на пароме.

## 6. Проверка (пользователь)

1. Console → 0 errors.
2. Встать на кабинку, дождаться автосейва (5 с), ребутнуть сервер →
   игрок на крыше движущейся кабинки (лог restore с routeId), без рывка.
3. Удалить ветку из сейва (или переименовать routeId) → фолбэк на позицию,
   без ошибок.
