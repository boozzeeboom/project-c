# 01 — Дизайн генератора вариаций

Тикет: **T-VAR01**. Документ описывает модель, формулы и контракт детерминизма.

---

## 1. Цель и границы

Цель — получать из одного базового `ItemData` много **инстансов** с разными статами,
не создавая по `.asset` на каждый вариант:

- **профиль** описывает, какие статы и в каких диапазонах могут крутиться;
- **seed** выбирает конкретный ролл;
- **инстанс** (`instanceId`) хранит результат и может быть отправлен клиенту.

Не входит в T-VAR01:

- изменение `InventoryItemDto`/слотов инвентаря;
- автоматическая выдача в `LootTable`/`PickupItem`;
- визуальные эффекты редкости, UI-карточка, звук;
- персистентность профилей в базе данных (сейчас — JSON).

---

## 2. Статы и канонические единицы

Все статы хранятся как `int` в канонических единицах. Это убирает платформенные
различия float-математики и делает ролл воспроизводимым.

| `ItemStatId` | Отображение | Масштаб | Каноническая единица | Источник базового значения |
|---|---|---:|---|---|
| `Damage` | Урон | 1 | ед. | `WeaponItemData.baseDamage` |
| `CritChance` | Крит | 1 | % | `WeaponItemData.critModifier` |
| `Range` | Дальность | 1000 | м | `WeaponItemData.range` или `throwRange` для `Thrown` |
| `Weight` | Вес | 1000 | кг | `ItemData.weightKg` |
| `Price` | Цена | 1 | CR | `ItemData.basePrice` или оценка |
| `Durability` | Прочность | 1 | ед. | пока 0 (резерв) |
| `Armor` | Броня | 1 | ед. | `ClothingItemData.armorDefense` |
| `StrengthBonus` | Сила | 1000 | ед. | бонусы `ClothingItemData`/`ModuleItemData` |
| `DexterityBonus` | Ловкость | 1000 | ед. | бонусы `ClothingItemData`/`ModuleItemData` |
| `IntelligenceBonus` | Интеллект | 1000 | ед. | бонусы `ClothingItemData`/`ModuleItemData` |
| `StackSize` | Стек | 1 | шт. | `ItemData.maxStack` |
| `MoveSpeed` | Скорость | 1 | % | пока 0 (резерв) |

Примеры: `weightMilli = 1500` → 1.5 кг; `rangeMilli = 2500` → 2.5 м;
`strengthMilli = 250` → +0.25 силы.

`DamageDice` оружия **не** входит в статы: генератор меняет `baseDamage`/проценты,
а кубик остаётся частью класса оружия.

## 3. Структура профиля

`ItemVariationProfile` (в редакторе — `ItemVariationProfileAsset.profile`):

| Поле | Смысл |
|---|---|
| `schemaVersion` | версия формата (сейчас 1) |
| `profileId` | стабильный id, по нему сервер ищет профиль |
| `displayName` | имя профиля для редактора |
| `baseItemId` | id предмета в `ItemRegistry` (0 = не задан) |
| `baseItemName` | имя базового предмета |
| `seedSalt` | соль, чтобы одинаковый seed на разных профилях давал разные роллы |
| `nameStyle` | `PrefixSuffix` или `BaseWithAffixList` |
| `minRolls` / `maxRolls` | сколько аффиксов до бонусов тира |
| `tiers` | список редкостей |
| `modifiers` | список аффиксов |
| `baseStats` | снапшот базовых статов (серверу не нужен `ItemData`) |

### 3.1 Тиры

`ItemVariationTier`:

| Поле | Смысл |
|---|---|
| `tierId` / `displayName` / `colorHex` | идентичность и цвет |
| `weight` | относительный вес выбора; 0 = выключен |
| `extraRolls` | дополнительные аффиксы сверх `minRolls..maxRolls` |
| `valueMultiplierBps` | множитель силы роллов, basis points (10000 = ×1) |
| `priceMultiplierBps` | множитель итоговой цены |
| `qualityBase` | база качества 0..100 |

Дефолтные тиры (`ItemVariationProfileFactory.BuildDefaultTiers`):

| Тир | Вес | extraRolls | value × | price × | qualityBase |
|---|---:|---:|---:|---:|---:|
| Обычный | 60 | 0 | 1.00 | 1.00 | 5 |
| Необычный | 25 | 1 | 1.10 | 1.25 | 25 |
| Редкий | 10 | 2 | 1.25 | 1.60 | 50 |
| Эпический | 4 | 3 | 1.45 | 2.10 | 70 |
| Легендарный | 1 | 4 | 1.70 | 2.80 | 88 |

### 3.2 Аффиксы

`ItemVariationModifier`:

| Поле | Смысл |
|---|---|
| `affixId` | стабильный id (ASCII) |
| `affixName` | слово для названия предмета |
| `isSuffix` | `true` — после имени, `false` — перед |
| `stat` | какой стат меняется |
| `flatMin..flatMax` | плоский диапазон в канонических единицах (0/0 = не роллить) |
| `percentMinBps..percentMaxBps` | процент от базы в bps (500 = +5%) |
| `weight` | вес выбора |
| `minTierIndex..maxTierIndex` | на каких тирах доступен |
| `unique` | запрет двух одинаковых аффиксов в одном инстансе |

Аффикс может роллить **и flat, и percent одновременно** — тогда применяются оба.
В дефолтных профилях используется один тип на аффикс, чтобы карточка читалась проще.

## 4. Алгоритм ролла

`ItemVariationGenerator.TryRoll(profile, baseStats, seed, out result, out error, luckBps)`:

1. Проверить профиль: есть тиры, есть модификаторы, у тиров есть вес.
2. Создать `DeterministicRandom` из `Derive(seed, profileId, seedSalt)`.
3. Выбрать тир взвешенным роллом (с учётом удачи).
4. Выбрать `rollCount = rand(minRolls..maxRolls) + tier.extraRolls` (максимум 64).
5. Выбрать аффиксы взвешенно без повторов для `unique=true`, с учётом `minTierIndex`.
6. Для каждого аффикса бросить flat и/или percent в его диапазоне.
7. Умножить каждый ролл на `tier.valueMultiplierBps`.
8. Сгруппировать роллы по стату и посчитать итоговые статы.
9. Посчитать качество, цену, имя.

Порядок потребления RNG (тир → количество → выбор аффиксов → значения) — часть
контракта seed'а. Менять его можно только с повышением `schemaVersion`.

### 4.1 Формулы

**Ролл с множителем тира:**

```text
scaled = round_half_away_from_zero(raw * valueMultiplierBps / 10000)
```

**Итоговый стат:**

```text
final = max(0, base + trunc(base * sumPercentBps / 10000) + sumFlat)
```

Проценты суммируются по всем роллам одного стата и применяются один раз, поэтому
порядок аффиксов не влияет на результат.

**Цена:**

```text
finalPrice = round_half_away_from_zero(finalStats.price * priceMultiplierBps / 10000)
finalStats.price = finalPrice
```

**Качество:**

```text
strength_i = normalized position of roll inside its (scaled) affix range
quality    = clamp(tier.qualityBase + round(avg(strength) * 12), 0, 100)
```

### 4.2 Удача (`luckBps`)

Удача не меняет seed, но сдвигает веса тиров:

```text
weight_i' = weight_i * clamp(10000 + luckBps * tierIndex, 0, 40000) / 10000
```

- `luckBps = 0` — базовые веса;
- `+1000` — +10% к весу каждого следующего тира (легендарка становится заметно вероятнее);
- `-1000` — наоборот;
- если все веса обнулились, используется исходный вес тиров.

Удача сохраняется в `ItemVariationResult.luckBps` для аудита.

## 5. Детерминизм

Одинаковый предмет получается при совпадении **всех** пунктов:

1. `profileId`, `seedSalt`, `minRolls`, `maxRolls`, `nameStyle`;
2. порядок и содержимое `tiers` (индекс тира входит в удачу и `minTierIndex`);
3. порядок и содержимое `modifiers` (индекс аффикса пишется в `ItemStatRoll.modifierIndex`);
4. `baseStats` (снапшот);
5. `seed` и `luckBps`.

Практические правила:

- не переставляйте существующие тиры/аффиксы после выдачи предметов;
- новые аффиксы добавляйте **в конец** списка;
- если нужно поменять порядок — поднимите `schemaVersion` и не пересчитывайте старые
  инстансы: они хранят уже посчитанные `finalStats`.

PRNG — SplitMix64 (`VariationRandom.cs`), только целочисленная арифметика. `seed`
смешивается с `profileId` и `seedSalt` через FNV-1a, поэтому один seed на разных
профилях даёт разные роллы.

## 6. Имя, тир, качество

### 6.1 Имя

`nameStyle = PrefixSuffix` (по умолчанию):

- первый prefix-аффикс + базовое имя;
- первый suffix-аффикс — через `·` после имени.

Пример: `Закалённый Стальной клинок · Лёгкий`.

`nameStyle = BaseWithAffixList`:

- `Стальной клинок [Закалённый, Лёгкий]`.

Этот вариант нейтрален к языку базового имени (в базе есть английские названия).
Остальные аффиксы не попадают в имя, но видны в списке роллов и карточке.

### 6.2 Цвет

`tierColorHex` — цвет для UI/подсветки. Генератор его не парсит и не валидирует;
редактор показывает цвет, клиент может использовать как есть.

### 6.3 Качество

Качество — не отдельный стат, а агрегат: база тира + насколько «хорошо» выпали роллы
внутри своих диапазонов. Оно годится для сортировки/подписи, но не влияет на статы.

## 7. Ограничения и крайние случаи

- Пустой профиль (нет тиров/аффиксов) → `TryRoll` возвращает `false`; редактор и
  сервис не регистрируют такой профиль.
- Если у аффикса `flatMin > flatMax` или `percentMin > percentMax`, генератор
  нормализует диапазон; валидатор выдаёт предупреждение.
- Если аффиксов с диапазонами меньше, чем `rollCount`, инстанс получит меньше роллов
  (не ошибка).
- Отрицательный flat (например, «Лёгкий» на вес) может обнулить стат — это допустимо.
- `StackSize` сейчас не используется дефолтными аффиксами: менять размер стека у
  инстанса без изменения модели инвентаря опасно.
- `finalPrice` может быть 0, если у тира `priceMultiplierBps = 0`; валидатор это
  предупреждает.

---

## 8. Рекомендации по балансу

- Держите 5–10 аффиксов на профиль: этого достаточно для 2–6 роллов у высоких тиров.
- Суммарный процент одного стата лучше держать ≤ 25–30%, иначе высокий тир ломает
  баланс оружия/брони.
- Для оружия: `Damage` — проценты, `Crit` — flat, `Range` — проценты.
- Для одежды: `Armor` и бонусы характеристик — flat.
- Для расходников (еда/медицина/ресурсы): цена и вес; не добавляйте боевые статы.
- `seedSalt` должен быть уникальным на профиль (фабрика делает это автоматически из
  `profileId`).
