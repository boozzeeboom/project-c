# 03. Правила группировки дверей — v13.8 (финальные)

**Файл скрипта:** `Q:\…\New Folder\_work\run_all_doors_v13.py`
**Статус:** проверено на всех 23 чанках; гейты зелёные; город подменён.

---

## 1. Задача

Исходные модели PRIMUM хранят дверь и её части **по-разному** в разных чанках:

| Тип чанка | Как устроены двери | Пример |
|---|---|---|
| «узловой» | узел `<дом>_DOOR_<слот>` + дети | `RES_TN_01_DOOR2_LEAF`, `..._DOOR2_HANDLE` |
| «плоский» | отдельные объекты, полотна названы с `_LEAF` | `TRD_ES_01_DC1_LEAF`, `..._DIN_LEAF` |
| «склады» | фурнитура дома слита по материалу | `RES_RG_E_21_DRS_M_BRONZE`, `RES_S2_02_TQ_DTL_DOOR_OAK` |
| арки/проходы | `..._ARCH...` — **без дверей** (по слову заказчика) | `N1_GATE_N_GUILD_ARCH_*` |

Нужно: на выходе каждой двери → **один объект** (полотно + его фурнитура/накладки/петли),
пивот — низ по центру, имя содержит размер; всё остальное (стены, мебель, витрины) остаётся в батчах.

## 2. Правила (в порядке применения)

1. **Склады** (`*_DRS_*`, `_DOOR_HARD`, `_DOOR_PANELS`, `TQ_DOOR`, `TQ_DTL`) и любые `_DOOR`-объекты
   площадью > 4 м² → **режутся на острова** (связные компоненты).
2. **Острова собираются по КАСАНИЮ** (зазор ≤ 0.10 м): касающиеся острова одного дома = одна дверь.
   Сборка принимается дверью только если её габарит дверной: **h 1.6–3.2, w 0.35–4.5**.
   (Иначе дверь+фрамуга сливались в «дверь 7 м».)
3. **Якорь полотна** = объект/остров с именем `_DOOR`/`GATE`/`_LEAF` и профилем:
   * высота **1.6–3.2 м**, ширина (max горизонтали) **0.35–4.5 м**;
   * толщина **≤ 0.55 м** и толщина/ширина **≤ 0.55** (толстые полотна `VER_DOOR` 0.46 м — валидны);
   * ворота (`GATE`): h ≤ 3.6, w ≤ 6.0, толщина ≤ 0.70.
4. **Части** приклеиваются к **БЛИЖАЙШЕЙ двери мира** (не «своего дома» — ключи домов в исходниках
   неоднозначны: `TRD` vs `TRD_ES_21`):
   * имя содержит `_DOOR`/`GATE` **или** токен фурнитуры:
     `KEY, BOSS, FIT, KNOB, HND, HANDLE, LEVER, LEV, LVR, HNG, HINGE, LOCK, ROS, PLAQUE, KICK, SILL,
     STOP, TRIM, CASING, PANEL(S), PAN, CASE, PLATE, PULL, BRACE, DTL, JAMB, THRESH`;
   * площадь ≤ 1.0 м², зазор ≤ **0.15 м**, материал **не конструктивный**;
   * острова складов — зазор ≤ 3 м (с проверкой габарита).
5. **Конструктив никогда не вклеивается** (иначе при выключении двери в стене дыра):
   `LIME, BRICK, PLASTER, STONE, MARBLE, GRANITE, TIMBER_FRAME, CONCRETE, ROCK, TERRAZZO, P_*`
   (краски), `SAND, DIRT, SNOW, PLINTH`.
   *Исключение:* дверная **стойка/косяк** — конструктив, но тонкий столбик (≤0.20×0.20 м) → приклеивается
   при зазоре ≤ 0.05 м.
6. **Защита габарита**: привязка не должна **увеличивать** габарит двери (h ≤ max(2.9, h_двери+0.05),
   w ≤ max(4.5, w_двери+0.05)). Иначе дверь обрастала длинными планками и превращалась в «монстра».
7. **Добор мельчайшего**: объекты ≤ 0.12 м без токена, стоящие у двери (≤ 1 м) → в дверь.
8. **Улетевшие** (центр вне горизонтального робастного bbox чанка +15 м) → узел `OUTLIERS` (выключен).
   Гигантские кольца ADMIN (`RING_F4`, 80–130 м) → туда же **до** классификации светильников
   (они попадали в `LAMPS` по материалу `M_EMIT_LAMP` и висели над аллеей).
9. **Светильники** (имя/материал `LAMP/EMIT`) → узел `LAMPS` (включён).
10. **Арки** (`ARCH` в имени) → остаются в батчах (это проходы, не двери).
11. **Остальное** → батчи `<чанк>_M_<материал>` (оболочка) / `<чанк>_INT_<материал>` (интерьер),
    бюджет 55 000 вершин на меш.
12. **Масштаб k = 1.07** — только на меш-объекты; **пивот двери = низ по центру**;
    имя = `<исходное>_<W>x<H>_X`.

## 3. Гейты (проверяются ДО подмены в Unity)

| Гейт | Норма | Как проверяется |
|---|---|---|
| Грани | до == после | счёт `polygons` до/после |
| Утечки `_DOOR` | **0** | не-конструктивные дверные объекты вне узлов `DOORS/DOORS_BIG/LAMPS/OUTLIERS/DOOR_PARTS_UNASSIGNED` |
| Высокие двери | **0** (допустим 1 широкий проём) | h > 2.9 м = в дверь вклеена стена |
| Улетевшие | в `OUTLIERS` | центр вне bbox+15 |
| Полотна | манифест ±5% | `data/doors_manifest.csv` |

Гейт «высокие двери» — главный индикатор регрессии: ровно он поймал катастрофу v11 (медиана 3.5 м).

## 4. Запуск (параллельные воркеры)

```powershell
$base = 'Q:\Yandex.disk\Yandex.Disk\Project-C\models\primum\New Folder'
$lists = Join-Path $base '_work\lists'
'PRIMUM_HOUSES_S9_RING_P1_22H' | Set-Content "$lists\w1.txt" -Encoding UTF8   # по одному чанку на файл
$env:DOORS_WORKER = 'w1'; $env:DOORS_LIST = "$lists\w1.txt"
& 'W:\SteamLibrary\steamapps\common\Blender\blender.exe' -b --factory-startup `
  --python "$base\_work\run_all_doors_v13.py"
```

* Воркер пишет `_work/logs/run_v13_<id>.log`, FBX — в `_deliver_doors/`, бленд — в
  `PRIMUM_chunks_reimport_doors/`.
* Рабочие копии — в `%TEMP%\primum_doors\<id>\` (не на Яндекс.Диске — иначе синк тормозит).
* 4–6 воркеров на i7-8700 / 64 ГБ — нормально: 23 чанка ≈ 45–60 мин.

## 5. Аудит остатков (чтение, без экспорта)

`_work/audit_batch_islands.py` — по стейджинг-блендам считает, что осталось в батчах:
острова «дверного» профиля и мелкие детали у дверей. Важно: **часть находок — ложные**
(мебельные ручки у дверей, куски штукатурки, ставни), поэтому аудит — карта, а не приговор.

## 6. Известные ограничения

* Двери с нераспознанным полотном (нет подходящего объекта) остаются «пустыми» — их детали уходят
  в `DOOR_PARTS_UNASSIGNED` (активны, видимы) либо в батчи.
* В `TRD-S2` (TQ-квартал) часть `TQ_*`-геометрии — мебель/задние части, она остаётся видимыми
  отдельными островами (это не двери).
* Точные правила и история итераций — `05_HISTORY/05_DOORS_JOURNAL.md`.
