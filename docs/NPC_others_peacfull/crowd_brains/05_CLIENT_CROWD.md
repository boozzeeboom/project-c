# 05 — Клиент: толпа, которую видит игрок

> Сервер ничего не тикает за толпу. Значит, вся «живость» 150 тел — задача клиентского `CrowdManager`: пул тел, петли, LOD, реакции-заглушки. Этот файл — его поведение.

## 5.1 Принципы

1. **Толпа детерминирована сидом.** `appearSeed` из ростера → тело, цвета (`NpcVisualApplier`-подход), имя, голос, походка. Один `crowdId` — один облик везде и у всех наблюдателей (иначе «у меня докер лысый, у тебя — с бородой» и пинок не тому).
2. **Толпа живёт на якорях, не на NavMesh.** Петли и посты: `Work/Sit/Sleep/Socialize`-якоря (T-NPC-S23), патрульные маркеры (`NpcSpawner.patrolWaypointMarkers`-подход), очередь у лотка. Переходы — по прямой с `separation` (расталкивание), не `SetDestination` через весь отсек.
3. **Видимых меньше, чем существующих.** Пул тел на клиента: 40–60 («Гигант»), 50–80 (квартал). Остальные слоты ростера в этой зоне — «за стеной»: известны поименно (табличка, список), но не инстанцированы. Приоритет слотов: герои (всегда) → герои-на-день → ближние → по курсу взгляда.
4. **LOD обязателен.** shared меши/материалы (3–5 тел × вариации цветом, а не 150 уникальных префабов — тот же анти-паттерн из `npc_ship/02 §9`); `LODGroup` (LOD0 5–8k → LOD1 3k → LOD2 1k + импостор, по `ART_BIBLE`); `Animator.cullingMode=CullUpdateTransforms`; за 30–50м — без лицевых/пальцевых костей и без теней; дальний план — плоские импосторы/силуэты.
5. **Реакции без сервера.** Удар/крик/тревога — мгновенная локальная реакция (flinch, отшаг, крик через пул `NpcVocalCue`, разбегание), не дожидаясь `HERO_UP`. Серверная правда догонит дельтой и скорректирует (кто герой, кто убежал). Рассинхрон на 100–200 мс незаметен, а «отзывчивость» — решает ощущение.

## 5.2 Откуда клиент знает, кого рисовать

Источники (по приоритету):

1. `HERO_UP/DOWN` активных героев в AOI — рисовать всегда, поверх пула.
2. `heroUntil`-список зоны («знакомые») — держать в пуле приоритетно.
3. Ростер-сводка зоны: `[{crowdId, appearSeed, homeAnchorId, alive}]` — редко (при входе в зону / по запросу), не тик. По ней CrowdManager раскладывает тела по якорям.
4. Сценарный модификатор: `density + scenario {обед/тревога/ночь}` — сколько из приписанных реально на улице/палубе, остальные «в каютах» (не рисовать вообще).

Позиции толпы сервер не шлёт (см. `01 §1.6`). Клиент ставит тело на `homeAnchor + slotOffset(seed)` и гоняет по локальной петле. Серверная `coarsePos` для проверок вычисляется из того же правила детерминированно — обе стороны сходятся без трафика.

## 5.3 Петли и смена картинок (чтобы не палилось)

- Петля = 3–6 якорей + активности на них (`workAnim 5–15с`, `socialize 3–6с` — числа уже есть в `NpcSocialBrain.cs:111–120`). Обход со случайным пропуском (не синхронно всей толпой!).
- Стаггер фаз: при входе в зону петли стартуют со случайным сдвигом, иначе 40 тел шагнут одновременно.
- Смена вахты/ночь: часть тел уходит «за стенy» (деспавн вне взгляда — GTA-приём), часть приходит. Никогда не деспавнить в конусе взгляда ближе 15м (палится).
- Корабль: петли — в ship-local координатах (см. §5.5). Качка корабля не должна качать петли — только базовый фрейм.

## 5.4 Пулинг и память

- Тела — пул `GameObject` (без `NetworkObject`! иначе NGO попытается их спавнить/синкать). Переиспользование: сменить `appearSeed` → перекрасить/переодеть через `VisualApplier`, не пересоздавать.
- Аудио — пул голосов (2–4 одновременных крика на зону, не 40). Толпа-гул — один loop-`AudioSource` с громкостью от плотности.
- Тени/пост-эффекты — только герои + ближние 10м. Остальные — `castShadow=false`.

## 5.5 Корабль везёт толпу бесплатно (ключевой приём)

Вся толпа корабля — **дети `ShipRoot`** (тот же приём, что `ShipCrewSpawner.AttachMemberToShipDeck` + `TrySetParent`, только без сети). Следствия:

- Корабль летит — толпа летит (0 сетевого трафика, 0 тиков).
- Ребейз Floating Origin двигает корень — толпа едет вместе с ним, **участия в FO-протоколе не требует** (в отличие от `NpcBrain` как `IGlobalMotionActorParticipant` с `ApplyRebaseTranslation + Warp` на каждого). Это снимает главный риск F8-фриза на 150 участниках.
- Бой/разговор на палубе считаются в ship-local (дистанции, LOS-лучи — от корня). Допуски те же, что в `02–03`.
- Герой, сошедший с корабля на причал, — это смена `zoneId` + смена родителя (шип → мир) в момент `HERO_UP/DOWN` или по трапу-скрипту. Пограничный случай — в `07`.

## 5.6 Что клиент показывает про героев

- Бейдж/поза: герой-боец — стойка + (опционально) HP-пипка только ему; герой-разговорник — поворот к собеседнику + bubble; герой-на-день — именной бейдж вместо «Докер».
- Хит-флеш по дельте HP (тонко, без чисел урона толпе — числа только героям).
- «Занят» — честная индикация отказа (`03 §3.6`), а не молчание.

## 5.7 Числа для калибровки (стартовые, не догма)

- AOI толпы: 80–120м (дальше — только сводка, не тела). Совпадает с `NpcSpawner.activationRadius=80` — reuse порога.
- Пул тел: 40–60 (корабль), 50–80 (квартал). Остальное — сводка.
- Аниматор: полный апдейт ≤12 ближних; остальные — `CullUpdateTransforms` + редкие переключения петлевых клипов.
- Плотность: палуба «Гиганта» 273×107м позволяет 40 тел без давки (∼700 м² на тело при равномерной — на деле кучкуются у якорей, поэтому separation-радиус 0.6–0.8м обязателен).
