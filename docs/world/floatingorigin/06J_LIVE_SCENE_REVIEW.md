# T-FO06J — живой осмотр сцен пилота и блокер удаления

Дата: 2026-09-09. Предыдущий этап: T-FO06I, `8cb102e5` / `5540d1bb`.

## 1. Что сделано

`WorldScene_0_0` загружена дополнительно к `BootstrapScene`, обе сцены осмотрены живьём. Уточнены реальные цифры и найден блокер, который нельзя обойти публичными API Unity.

Ни одна сцена не изменена по содержимому: обе побайтово совпадают с зафиксированными версиями.

## 2. Живой осмотр опроверг оценку по YAML

| Показатель | Оценка по YAML (06I) | Живой осмотр |
|---|---:|---:|
| Корней в `WorldScene_0_0` | 26 | **58** |
| Корней в `BootstrapScene` | 55 | **56** |
| Мёртвых компонентов в `WorldScene_0_0` | 1 | **3** |
| Observations всего | 95 | **150** |

Причины расхождения:

- **prefab-инстансы.** Их корни в YAML сцены представлены блоками `PrefabInstance`, а не обычными объектами, поэтому разбор текста их не увидел.
- **пустая ссылка на скрипт.** У двух мёртвых компонентов `m_Script` вообще не содержит GUID, а мой парсер пропускал записи без GUID.

**Авторитетная цифра — 150 проверенных записей**, полученная собственным аудитом проекта на двух загруженных сценах. Оценка 95 из отчёта 06I занижена, и это исправление зафиксировано здесь.

## 3. Три мёртвых компонента в WorldScene_0_0

| Объект | Класс из файла | Ссылка |
|---|---|---|

`PoleBlockerComponent` не найден нигде в проекте. Дополнительно он объявлен в **Editor-сборке**: такой компонент в рантайм-сцене неработоспособен по определению, даже если бы класс существовал.

Все три — обычные объекты сцены, не prefab-инстансы, поэтому исправление относится к сцене, а не к префабам.

## 4. Блокер: удалить нельзя публичными API

Испробовано:

1. `GameObjectUtility.RemoveMonoBehavioursWithMissingScript` — для двух объектов не удаляет ничего: у них нет ссылки на скрипт, поэтому компонент не считается «со сломанным скриптом».
2. `SerializedObject` → `m_Component` → `DeleteArrayElementAtIndex` — первое удаление лишь обнуляет элемент, повторное не уменьшает массив.
3. `MoveArrayElement` + присваивание `arraySize` — массив компонентов GameObject не даёт изменить размер.

Все попытки завершились отказом **до** сохранения, поэтому сцена не пострадала: проверка подтвердила побайтовое совпадение с диском.

## 5. Почему это блокирует каталог

В аудите `inspectedComplete` вычисляется как «во время осмотра этой сцены не возникло ошибок», а отсутствующий компонент **в поддереве наблюдаемого корня** даёт ошибку. Оба проблемных объекта лежат внутри поддеревьев корней `WorldRoot_0_0` и `[Ship_Key_Container]`.

Компилятор каталога отвергает источник с `inspectedComplete = false`. Значит `WorldScene_0_0` нельзя внести в каталог, пока эти три ссылки не удалены.

## 6. BootstrapScene готова

- ошибок осмотра: `0` — уборка этапа T-FO06H подтверждена живым аудитом;
- безобидный флаг «изменена» сброшен сохранением идентичного содержимого; байты файла не изменились, что проверено хешем;
- флаг был важен не косметически: аудит выводит `saved` из него, а компилятор требует `saved = true`.

Отдельно установлено, что флаг поднимается перезагрузкой домена при компиляции скриптов, а не правками содержимого: сравнение живой сцены с файлом давало полное совпадение.

## 7. Три варианта для решения

1. **Точечная правка YAML** `WorldScene_0_0`: удалить два блока `MonoBehaviour` и соответствующие записи в `m_Component`. Минимальное и проверяемое изменение, но это прямая правка файла сцены, которую я не делаю без разрешения.
2. **Удаление вручную в Inspector.** Инспектор Unity умеет убирать такие слоты через контекстное меню компонента; это несколько кликов на двух объектах.
3. **Каталог только для `BootstrapScene`** в первом пилоте, с добавлением `WorldScene_0_0` позже. Противоречит заявленной области пилота, поэтому предлагается последним.

Рекомендую вариант 2: он выполняется средствами редактора и не требует правки файла сцены.
