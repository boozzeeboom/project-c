# Паром — гражданский тросовый транспорт (T-PAROM-01)

> Статус: дизайн + реализация v1. Код: `Assets/_Project/Scripts/World/Parom/`.

## 1. Лор

Гражданский транспорт между фермерскими поселениями. Кабинка на **двух протянутых
антигравиевых тросах** движется вперёд-назад как паромная переправа. Лопастные
двигатели + машинист. Маршрутный транспорт по подвесным тросам, до **40 км/ч**
(~11 м/с) — см. `docs/gdd/GDD_24_Narrative_World_Lore.md`, `GDD_02_World_Environment.md`.
Ранний концепт: `docs/world/Landscape_TechnicalDesign.md` §3.4 (`FerryCableSystem`,
catenary, 50 units/sec — устарело, заменяется этим документом).

## 2. Что строит пользователь (без хардкода)

1. Ставит в мире **якоря-пустышки** (анкоры): начальная точка, массив промежуточных,
   конечная точка. Например ветка `0-1 → … → 0-10` через все фермы.
2. Создаёт объект **ParomRoute** (потомок корня `WorldScene_*`) и перетаскивает
   якоря в поля: `Start Anchor`, `Intermediate Anchors[]`, `End Anchor`.
3. Настраивает в инспекторе (всё — поля, никакого хардкода):
   - `Trolley Prefab` — кастомная модель кабинки (любой FBX). Если пусто —
     строится fallback-примитив для прототипа.
   - `Cable Material` — материал тросов. Если пусто — дефолтный материал линий.
   - `Speed` (м/с, дефолт 9 ≈ 32 км/ч, потолок 11 ≈ 40 км/ч по лору).
   - `Dwell Seconds` — ожидание на каждой станции + опциональный массив
     `Station Dwell Overrides[]` (по одному значению на станцию, `-1` = дефолт).
   - `Cable Lateral Offset` — разнос двух тросов в стороны (дефолт 0.6 м).
   - `Sag Ratio` — провисание троса, доля от длины сегмента (дефолт 0.05 = 5%).
   - `Cabin Hang Depth` — насколько кабинка висит ниже тросов (дефолт 1.2 м).
   - `Propeller Rpm` — скорость вращения винтов (визуал, дефолт 240).
4. Веток может быть **несколько** — каждая ветка = свой объект ParomRoute
   со своей тележкой. Одна ветка = **одна челночная кабинка**: идёт от начальной
   через все промежуточные к конечной (остановка на каждой), затем назад.

## 3. Архитектура v1

```
ParomRoute (NetworkBehaviour, scene-placed, под корнем WorldScene_*)
├── _CableL / _CableR (LineRenderer, useWorldSpace=false, локальные точки)
├── _TrolleyRoot (инстанс Trolley Prefab или fallback, + ParomTrolley)
└── якоря — ВНЕШНИЕ scene-объекты (ссылки), живут под корнями сцен
```

- **Маршрут = полилиния** по живым позициям якорей:
  `[start, ...intermediates, end]`. Длины сегментов кэшируются (инвариантны
  к сдвигу мира), мировые позиции **никогда не кэшируются** — читаются
  с трансформов каждый кадр. Поэтому FO-хук `ApplyRebaseTranslation` НЕ нужен.
- **Сервер считает — клиенты видят.** Симуляция (скаляр `s` — метры от старта,
  направление `dir`, таймер стоянки) идёт только на сервере (`IsServer`).
  Синхронизация — три `NetworkVariable` (Server-write): `_netS`, `_netDir`,
  `_netDwelling` + `_netStation` (индекс станции для UI/дверей).
  Клиенты каждый кадр ставят кабинку из тех же живых якорей → геометрия
  идентична,carry-формула даёт тот же результат на всех пирах
  (тот же подход, что `PickupDeckRide`: каждый пир считает локально).
- **Без сети (превью):** пока объект не заспавнен (`!IsSpawned`) — симуляция
  идёт локально, чтобы маршрут можно было проверить без запуска сети.
- **Пассажир стоит на тележке.** Кабинка имеет кинематический `Rigidbody` +
  коллайдер пола → `NetworkPlayer.ApplyPlatformCarry` / `NpcBrain` /
  `PickupDeckRide` везут райдера автоматически (дисциплина:
  только translation + yaw, pitch/roll игнорируются — см. `PlatformRideHelper`).
  Требование: слой кабинки должен входить в `_platformMask` игрока/NPC.
- **Винты и машинист:** `ParomTrolley` крутит дочерние объекты с именем
  `*Prop* / *Винт* / *Rotor*` со скоростью `Propeller Rpm`; пустой
  `Driver Anchor` — место под модель машиниста (логики нет, v1 — визуал).

## 4. Floating Origin

🟢 **Едет бесплатно:** весь объект ParomRoute — под корнем `WorldScene_*`.
Тросы и кабинка — дети в **локальных координатах** (`useWorldSpace=false`,
`trolley localPosition`), якоря — тоже под корнями сцен.

- Кэшируются только **длины** сегментов (числа, не позиции) → сдвигать нечего.
- `ApplyRebaseTranslation` у ParomRoute **намеренно отсутствует** (нечего сдвигать).
- Перестройка тросов триггерится **движением якорей** (>1 мм), поэтому сдвиг
  мира F8/авто сам обновляет геометрию следующим кадром.
- Проверка: F8 → `runtimeRebase.Completed` + кабинка на месте + тросы целы
  + 0 errors; F9 → возврат. Маршрут НЕ должен пересекать границы сцен
  (все якоря одной ветки — в пределах одного `WorldScene_*`).

## 5. Состояния кабинки (пинг-понг)

```
Dwelling(станция i, таймер) → Moving(dir) → прибытие (s == рубеж станции)
→ Dwelling → … → на терминале dir = -dir
```

Старт: `s = 0`, стоянка на начальной. Рубежи станций = кумулятивные длины.
Скорость постоянная (`Speed`), без разгона/торможения в v1 (дешёвый lerp
по дуге; разгон — отдельной задачей при необходимости).

## 6. Настройка сцены (пошагово)

1. В `WorldScene_0_0` (или другой) создать пустые GameObject-якоря в точках
   станций: `Parom_A`, `Parom_B1`, `Parom_B2`, `Parom_C`.
2. Создать `ParomRoute_01` **под корнем сцены** (`WorldScene_0_0` root):
   `Add Component → ParomRoute` (+ `NetworkObject` подтянется сам).
   Объект автоматически зарегистрируется спавнером сценовых объектов
   (`ScenePlacedObjectSpawner`, как `DockStation`/`NpcShipController`).
3. Заполнить якоря, префаб кабинки (FBX с полом-коллайдером), материал тросов,
   скорость, ожидание. Нажать `Rebuild Cables` (контекстное меню / кнопка
   в инспекторе) для превью в редакторе.
4. Слой кабинки (напр. `Default`) проверить против `_platformMask` префаба
   игрока, иначе carry не подхватит.
5. Play: кабинка едет. F8/F9 — контроль сдвига мира.

## 8. Регистрация в closed-world каталоге пилота (T-FO06L, обязательно!)

Пилот (`GlobalMotionPilotRuntime` → `GlobalSceneNativeExecutor`) работает в
fail-closed режиме: **любой scene-placed `NetworkObject` без записи в каталоге
роняет старт хоста** (`uncontrolled_network_source_before_native_sweep`).
Поэтому `ParomRoute_01` зарегистрирован как все корабли/станции:

- `GlobalSceneSourceMarker` на корне ветки
  (`sourceId = {guid сцены}:{targetObjectId}:0`, `frameId = 0`,
  `activateWhenReady = false`);
- observation + entry в `GlobalMotionPilotSceneCatalog.asset`:
  `treatment = Unmanaged (5)`, `ownership = ShipOrRigidbodyRoot (4)`
  (на кабинке висит кинематический `Rigidbody` — без него ownership не сойдётся),
  `spatial = false`, `poseKind = None`, нулевая поза,
  `parentSourceId` = sourceId `WorldRoot_0_0`;
- `layoutHash` пересчитан тем же алгоритмом, что `AuditGlobalSceneCatalog`
  (включая обновлённый хэш `WorldRoot_0_0` — ветка добавила потомков),
  `dependencyHash` сцены обновлён, `SceneLayoutDigest` в
  `GlobalMotionPilotProfile.asset` пересчитан (`TryCompile` + `TryMatchDigest`).

Что можно свободно, а что требует перерегистрации:

- ✅ **Двигать якоря** — они лежат сиблингами под `WorldRoot_0_0` (не дети
  маршрута, без `NetworkObject` и маркеров): каталог их не видит, хэши не
  меняются. Тросы перестраиваются сами.
- ✅ Менять скорость/ожидание/провисание/материал тросов — сериализованные поля
  в хэш не входят.
- ⚠️ **Менять структуру ветки** (другая кабинка-FBX, добавить/убрать детей,
  переименовать/сдвинуть сам корень): меняется `layoutHash` маршрута
  (Host при этом НЕ падает — хэш сверяется только будущими аудитами).
  После таких правок — пересчитать хэши и digest (повторить процедуру выше).
- ⚠️ Новая ветка = новая запись в каталоге (маркер + observation + entry +
  digest), иначе Host упадёт на том же гейте.
- ℹ️ Несвязанный дрейф: в `BootstrapScene` есть 3 незакаталогизированных
  plain-корня (`DistantFocus`, `ChartWindow`, `VeilController` — без NO
  и маркеров): Host не блокируют, но аудит `AuditGlobalSceneCatalog`
  помечает каталог stale. Отдельная задача, не трогать здесь.

## 7. Что НЕ входит в v1 (следующие итерации)

- Посадка по кнопке E / двери / расписание-табло (игрок запрыгивает сам).
- Разгон/торможение, качание кабинки, звук винтов и двигателя.
- Несколько кабинок на ветке / разъезды / грузовые платформы.
- Сетевая интерполяция (сейчас — прямое применение `_netS`, скорости низкие).
- Сейвы позиций парома (кумулятив сдвига не нужен — всё локальное, но точка
  `s` после рестарта начнётся с начальной станции).
- Валидация длины троса (концепт §3.4 давал макс. 1500 units) — добавить при нужде.
