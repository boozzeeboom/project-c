## 1. Главная причина: Linear против гаммы (`678b136d`, `3e0813a9`)

`PlayerSettings.colorSpace = Linear`. Мод — гамма-пространство целиком:

- three.js `ShaderMaterial` пишет **сырые** sRGB-значения из `palette.js` (`v3(RGB.skyHorizon)`,
  без color management), а `clouds.js` собирает цвета вуали тоже из сырых массивов;
- браузер смешивает полупрозрачные CSS-слои в sRGB.

В Unity при Linear: `Material.SetColor` линеаризует цвет, GPU смешивает в линейном свете, а
UI Toolkit смешивает так же. Одна и та же альфа даёт другой результат:

| Слой | В браузере (sRGB) | В Unity (Linear) | Как это выглядело |
|---|---|---|---|
| `#e9f2ec` @ 0.26 над чёрным | 0.26 | ~0.55 | жёсткое белое пятно |
| `#070a09` @ 0.6 над небом 0.93 | 0.37 | ~0.62 | пересвеченный фон |
| `col * 0.36` (ночь неба) | ×0.36 | ×0.63 визуально | ночь не наступает |

### 1.1 Формула

`ProjectCMainMenuGamma.Alpha(a, tint, backdrop[, opacity])` (C#) и `PcmmGammaAlpha` в
`PCMM_Gamma.hlsl` (шейдеры) — одна формула: для слоя яркости `tint` с альфой `a` над подложкой
`backdrop` (всё в sRGB-яркости) ищется альфа `a'`, при которой **линейное** смешивание даёт то же
значение, что sRGB-смешивание мода:

```
g  = lerp(backdrop, tint, a)                 // что получил бы браузер
a' = (lin(g) - lin(backdrop)) / (lin(tint) - lin(backdrop))
```

Для тёмного слоя формула точна при любой подложке (≈ `1 - (1-a)^2.2`), для светлого — точна над
той подложкой, что передана. Поэтому у каждого слоя своя подложка:

| Подложка (`ProjectCMainMenuGamma`) | sRGB-яркость | Что на ней лежит |
|---|---|---|
| `Sky` | 0.80 | скрим меню, мист карточки, облака карточки, тёмные пуфы |
| `Scrim` | 0.42 | ореол и блобы кнопок, линия под вордмарком |
| `Cloud` | 0.30 | светлые ободки облаков |
| `Mist` | 0.07 | всё внутри карточки: ряды, пилюли, свечения, волоски |
| `0.18` | — | светлые пуфы переходов (над тёмными облаками) |

Перегрузка с `opacity` запекает текстуру так, чтобы `тексель × opacity элемента` попадал в
правильное значение при авторской opacity из USS.

### 1.2 Атмосфера (`678b136d`)

- `Shaders/PCMM_Gamma.hlsl` (новый): `PcmmToGamma`, `PcmmToLinear`, `PcmmLuma`,
  `PcmmGammaAlpha`; глобал `_PCMM_Backdrop`.
- `PCMM_Sky` — входные цвета переводятся в sRGB, вся математика (смешивание, шум, `_Dim`)
  в sRGB, как в моде, на выходе — обратно в линейный.
- `PCMM_Veil`, `PCMM_Gas`, `PCMM_Rope`, `PCMM_Hull` — цвет в sRGB, альфа через `PcmmGammaAlpha`.
- `PCMM_Stars`, `PCMM_Glow` — аддитивные, не тронуты.
- `ProjectCMainMenuAtmosphere` каждый кадр ставит `_PCMM_Backdrop` = яркость неба
  (`lerp(SkyMid, SkyLow, 0.35)`) с учётом ночного затемнения.

> Файлы `*.shader` / `*.hlsl` в `.gitignore` (контент в Lore VCS) — в git-коммиты не входят.

Проверка: `ShaderUtil.CompilePass` по 5 шейдерам — 0 сообщений, `ShaderHasError = false`,
`Editor.log` без ошибок шейдеров.

## 2. Подложки, контролы, текст (`3e0813a9`)

### 2.1 Тона мода вместо инвертированных

Ранее ради читаемости на тёмной атмосфере угольные слои были перекрашены в светлые. Вместе с
линейным смешиванием это и дало белые пятна. Возвращены токены `ui.js applyPalette`:

| Элемент | Было | Стало (как в моде) |
|---|---|---|
| `.pc-btn-cloud` (ореол) | `#e9f2ec` 0.26 | `--pc-cloud-base` = `veilDark` 0.34 |
| ободки облаков | `ink` 0.30 / 0.26 | `--pc-cloud-rim` = `skyHorizon` 0.24 |
| `.pc-cld` (облака карточки) | `SmokeTextures.Light` (светлый `smokeImage`, 5/11/23 ячеек) | `SmokeTextures.CardCloud` — угольный `smokePuff` 22,28,23 (`--pc-smoke-cloud`) |
| `.pc-switch` / `.pc-select` / `.pc-kbd` | светлая пилюля `SoftPill` | `--pc-track-2` = `veilDark` 0.55 |
| вкл. переключатель / hover селекта | — | `--pc-accent-soft` 0.16 + свечение `--pc-glow` |
| свечение вкладки | accent 0.34, stop 80% | accent 1.0, stop 72%, элемент 0.5 (как в CSS) |

`ProjectCMainMenuRamps.cs` переписан целиком: каждый тексель проходит гамма-коррекцию. Новые
рампы: `RowHover`, `RangeThumb`, `ThumbGlow`, `SwitchOn/Off`, `SwitchGlow`, `SelectIdle/Hover`,
`SelectGlow`, `KeyCap`, `CloseHaloHover`; `SoftPill` удалён.

### 2.2 Мист карточки без жёсткого эллипса

CSS: три радиальных градиента в `border-radius ~50%` + `filter: blur(18px)`. В UI Toolkit
`border-radius` обрезает фон чёткой кромкой — это и был эллипс. Теперь `Stacked()` композитит
три слоя и запекает эллиптический спад (`rimStart = 0.62` → 0 на вписанном эллипсе),
`border-radius` снят. Альфа по горизонтали `0.00 … 0.98 … 0.00`, угол — 0.

`border-radius` также снят у `.pc-blob`, `.pc-cld`, ободков и `.pc-tab__glow` — их текстуры сами
уходят в ноль внутри бокса.

### 2.3 Фокус

USS не знает `:focus-visible`, а `:focus` срабатывает и на клик. Правило с рамкой 1px рисовало
зелёный прямоугольник вокруг вкладки, селекта, переключателя и сдвигало содержимое. Рамка
оставлена только у `.pc-proj-input:focus`; у вкладки фокус — цвет (`ink-dim`, у активной `ink`).

### 2.4 Ряды и контролы

- `.pc-row-text { flex-grow: 1; flex-shrink: 1 }` — колонка занимает всю ширину до контрола.
  Раньше она ужималась до собственной измеренной ширины и на масштабированной панели
  переносила последнее слово («Общая / громкость»). Сейчас подпись 353.7 × 23.1 — одна строка.
- Полосы рядов (`RowWash`) получили мягкое перо сверху/снизу (16 px текстура, 22%) —
  соседние ряды больше не читаются как вырезанные плашки.
- `Row()` создаёт `.pc-row__wash` (дым слева на hover — его элемента раньше не было).
- `ProjectCMainMenuWindow.Controls.cs` (новый):
  - **слайдер** — трек, свечение и бегунок абсолютно позиционированы по `userData` (0–100);
    перетаскивание с захватом указателя, ←/→ (±5), Home/End; подпись `%` следует.
    Бегунки стоят на 77.7 / 54.9 / 83.5 / 69.4 % при 78 / 55 / 84 / 70;
  - **переключатель** — фон `SwitchOn/Off` по `.is-on`, свечение `.pc-switch__glow`;
  - **селект** — `SelectHover` + свечение на hover/focus; клик/Enter/→ — следующее значение,
    ← — предыдущее;
  - **крестик** — `CloseHaloHover` на hover/focus.
  Инлайн-фон всегда сильнее USS-правила, поэтому смена фона по состоянию сделана в C#.

### 2.5 Текст

- Размытие `text-shadow` в UI Toolkit не может быть шире паддинга SDF-атласа. Атлас, который
  UI Toolkit строит из `Font` сам, — 9 px при 90 pt, т. е. ~1.4 px на 13–15 px кегле: ореолы
  9–16 px превращались в плотный тёмный контур вокруг букв.
- `ProjectCMainMenuFonts.BodyAsset / DisplayAsset` строят свои SDF-атласы
  (`FontAsset.CreateFontAsset`, 90 pt, **паддинг 24**, SDFAA, 1024², dynamic, multi-atlas).
- Тени текста карточки убраны (в моде их нет). У кнопок оставлена та из двух теней мода, что
  реально видна на угольном облаке, — `0 1px 4px rgba(4,8,6,0.75)`; у вордмарка — мягкое
  свечение `0 0 3px --pc-glow`.
- Исправлен неверный комментарий: мод шрифт объявляет (`palette.js FONT`:
  `Inter, Segoe UI, Helvetica Neue, Arial`).

## 3. Второй запуск, вспышка, альтиметр (`10eebf00`)

### 3.1 Второй Play без меню

В проекте Enter Play Mode Options = `DisableDomainReload, DisableSceneReload` — статика и
`[NonSerialized]`-поля ScriptableObject переживают Stop. Атлас шрифта, закэшированный на
`PCMM_Fonts`, пережил Stop, а его **материал** — нет. Первая же отрисовка текста:

```
MissingReferenceException: The object of type 'UnityEngine.Material' has been destroyed
  Material.get_mainTexture ← TextUtilities.GetTextCoreSettingsForElement ← RepaintPanels
```

Исключение посреди `RepaintPanels` оставляло панель в состоянии «идёт рендер», и всё дальше
сыпалось каскадом `InvalidOperationException: VisualElements cannot change their render data …`
плюс `Assertion failed` — меню не появлялось.

Исправление: `ProjectCMainMenuFonts.Alive()` переиспользует кэш, только если живы материал и все
текстуры атласа, иначе строит атлас заново; материалу и текстурам ставится `HideFlags.DontSave`.
Остальные кэши (`ProjectCMainMenuRamps`, `ProjectCMainMenuSmokeTextures`) уже проверяли
`hit != null` и пересобираются сами.

### 3.2 Варнинг курсора

`Runtime cursors other than the default cursor need to be defined using a texture` — любой
курсор, кроме стандартного, в рантайме требует текстуры, а USS `cursor: link` её не даёт. Все 8
деклараций убраны из `PCMM_Menu.uss`. Тот же `cursor` есть в `CustomisationWindow.uss`,
`CharacterWindow.uss`, `MarketWindow.uss` — **не тронуты** (не меню).

### 3.3 Вспышка на наведении

Три источника:

1. ободок кнопки (`.pc-btn-cloud__rim`) прыгал 0.55 → 1 **за один кадр** — transition не было.
   Теперь transition 0.6 с `ease-in-out`, до 0.85;
2. облако раздувалось до 1.06 × 1.3 за 0.38/0.46 с и меняло `filter` (`contrast(1.24)`) —
   анимируемый фильтр, та же опасная динамика, что ломает перерисовку
   (`ProjectCMainMenuTextBlower.BlurFiltersEnabled`). Теперь 1.05 × 1.2, opacity/scale
   0.6/0.75 с `ease-in-out`, `filter` убран из transition и из hover-правил (кнопка, крестик,
   селект, ручка переключателя);
3. светлые пуфы `Field.Gather` на hover (`bright = y > 0.44·viewH`, как в моде) были запечены
   под подложку 0.42 и над тёмным облаком выходили ~на 40% ярче — теперь подложка 0.18.

### 3.4 Альтиметр

`ProjectCMainMenuAltimeter`: ход ленты 13 → **44 px** по всей высоте указателя, демпфирование
6.2 → 3.4 (лента догоняет указатель с инерцией), наклон 0.022 → 0.018°/px, тихое покачивание
±3.5 px (две синусоиды), деления продлены на 900 м за крайние кнопки (40 делений) — конец ленты не
открывается. Замер: за 2 с лента доходит до −41.5 / +46.3 px.

## 5. Проход «шрифт / свёртка / пыль / сутки»

### 5.1 Шрифт — Inter, как в моде

Мод объявляет `FONT = "Inter", "Segoe UI", …` и `FONT_DISPLAY` того же семейства; вордмарк —
`font-weight: 300`. Пара Roboto Regular + Northwest Bold давала тяжёлый широкий заголовок
другого семейства, «несовместимый» с кнопками.

- `Assets/Aura/Mods/ProjectCMainMenu/Fonts/Inter/` — `Inter-Regular.ttf`, `Inter-Light.ttf`
  (Inter 4.1, rsms/inter, лицензия SIL OFL 1.1 — `OFL.txt` рядом; распространение в игре
  разрешено).
- `Resources/PCMM_Fonts.asset`: `Body = Inter-Regular`, `Display = Inter-Light`. Обе гарнитуры
  с кириллицей. Атласы — те же SDF с паддингом 24 (§2.5).
- Размер вордмарка остаётся 78 px, как в CSS (`clamp(34px, 7.4vw, 78px)` при 1920). Широкие
  тяжёлые буквы Northwest делали его зрительно крупнее; лёгкий Inter того же семейства, что и
  кнопки, — это то, как он выглядел в моде.

### 5.2 Свёртка [Debug] и «Изменения»

`ProjectCMainMenuProjectPanels.cs`: у блока сбросов сохранений `[Debug]` появилась шапка
(`.pc-proj-admin-head`: заголовок + кнопка), у списка изменений (гит-лог) — кнопка рядом с ↻.
`CollapseToggle()` переключает `.is-collapsed` на панели, «−» / «+», всплывающая подсказка, и
запоминает состояние в `PlayerPrefs` (`PCMM.Admin.Collapsed`, `PCMM.Changelog.Collapsed`).
Свёрнутый блок показывает только шапку; у «Изменений» снимается `bottom: 15%`, и панель
сжимается до шапки. Замер: [Debug] 290.6 × 392.2 → 290.6 × 50.2, «Изменения»
408.9 × 762.6 → 408.9 × 57.9.

### 5.3 Пыль ветра

Мод (`wind.js`): 280 крапинок, при плотности 1 рисуется ~62%; размер
`uPixel · (0.65 + 1.5·size)` px, `uPixel = frameH / 300`, `size` 0.35–1.4; своя альфа
0.26–1 × `uAmount`; мягкая точка `smoothstep(0.5, 0.06, d)²`, аддитивно, по **всему кадру**.

Порт эмитировал из бокса 24 × 14 на расстоянии 1 перед камерой, где видимый кадр ~1.66 × 0.93 —
в кадр попадал ~1% частиц; материал — URP `Particles/Unlit` по умолчанию **непрозрачный**, поэтому
видимые единицы были белыми квадратами.

- `Shaders/PCMM_Dust.shader` (новый): процедурная мягкая точка из UV билборда (тот же
  `smoothstep(0.5, 0.06, d)²`), `Blend SrcAlpha One`, цвет/альфа — из вершинного цвета.
- `Resources/PCMM_WindDust.mat` — материал на этом шейдере (в `Resources`, чтобы шейдер попал в
  билд).
- `ProjectCMainMenuWindDust` переписан: бокс = видимый кадр × 1.08 (`SetView` из
  `ProjectCMainMenuAtmosphere.Layout`), размер по формуле мода, скорость — по `wind.js`,
  `speedModifier = 1 + 0.9·gust`, альфа — случайная между 0.26·amount и amount,
  `prewarm` (кадр сразу заполнен), население = `Count / lifetime`.
- Замер при 1080p: кадр 1.658 × 0.933, бокс 1.791 × 1.007, размер 4.2–9.9 px (как в моде),
  174 крапинки, 19.3/с, альфа 0.043–0.165.

### 5.4 Сутки

Мод крутит цикл за 190 с — на меню это читалось как небо, которое не меняется. Новое поле
`ProjectCMainMenuAtmosphere.cycleSeconds = 72` (в 2.6 раза быстрее), нижняя граница с учётом
ускорения на вкладках 12 с. Поле новое намеренно: префаб `ProjectCMainMenu.prefab` сериализует
старое `dayCycleSeconds = 190`, которое иначе перебило бы новое значение, а префаб агент не
сохраняет. Ускорение на вкладках/настройках (`PulseDaySpeed`) работает как прежде.

### 5.5 Каскад «Attempted to get a texture (index=27) that is not allocated»

После этого прохода на старте Play каждый кадр сыпалась ошибка

```
TextureRegistry.GetTexture ← TextureSlotManager.Bind ← UIRenderDevice.EvaluateChain
  ← RenderTreeManager.RenderSingleTree ← RenderTreeCompositor.RenderNestedPasses
```

то есть из **вложенных проходов** UI Toolkit — именно так рисуется каждый элемент с
`filter:` (поддерево в пульную RenderTexture, потом фильтр). Вложенный проход
ссылался на уже освобождённый id текстуры. В edit mode ошибка не воспроизводится, какая именно
текстура под id 27 — **не установлено**. Это вторая поломка того же механизма после
известного обрыва перерисовки при динамическом `filter` (`BlurFiltersEnabled = false`).

Исправление убирает весь путь: из `PCMM_Menu.uss` удалены все 9 статических `filter: blur()`
(облако кнопки 4 px, его ободок 2 px, банк карточки 2.5 px и его ободок 4 px, свечение вкладки
3.5 px, два волоска 0.7 / 0.8 px, крестик 0.3 px и его линии 0.45 px). Остался только
`filter: none` у `.pc-ghost`. Мягкость, которую давали блюры, уже запечена в рампы (smoothstep-спад)
и в дымовые листы (рваный прозрачный край); кадр заодно дешевле — нет десятков вложенных
RT-проходов. Если края облаков покажутся жёстче — смягчать текстуры, а не возвращать `filter`.

### 5.6 Белые облака на нажатии кнопки

Замечание: облака, которые сдувает при нажатии любой кнопки, слишком белые и контрастные —
нужна прозрачность.

Замер (`Tools/PCMMPuffProbe.cs`, 1920 × 1089, кнопка `host` 140.2, 500.3, 403.8 × 64.3). Все четыре
кнопки лежат ниже 0.44 высоты кадра (порог 479.3, пуфы кнопки `host` на sy 506.7–558.1), поэтому
все 13 пуфов нажатия берут **светлый** лист (`smokeImage` 233,242,236), а не угольный: размеры
40–149 px, элементная непрозрачность в пике 0.550. Ядро светлого листа (альфа текселя 0.557) в
линейном блендинге читается как 0.570 sRGB над телом облака кнопки (0.18) и 0.641 над скримом
(0.42) — 145/255 поверх тёмной подложки, то есть белое пятно, а не дым.

`ProjectCMainMenuSmokeField.PalePeak = 0.5` — светлые пуфы рисуются на половине своей авторской
непрозрачности (ключи умножаются в `AddPuff`; массивы ключей создаются на каждый пуф, поэтому
правка на месте безопасна). Пик падает 0.550 → 0.275, ядро читается как 0.432 sRGB над облаком
кнопки и 0.545 над скримом — полупрозрачный дым. Угольные пуфы не затронуты (у них пик 0.550 и
ядро 0.290 на скриме); `Gather`/`Disperse`, keyframes, направление ветра, количество и размеры
пуфов — без изменений. Пуфы от взлетающих букв (`BlowTextOf` → `onPuff`) тоже светлые, поэтому
получают ту же поправку.

### 5.7 Неактивные вкладки и крестик в настройках

Замечание (со скриншотом): «графика / звук» и «закрыть» плохо читаются в определённое время суток.

Причина — геометрия карточки: туман карточки (`CardMist`) — вписанный эллипс с `rimStart 0.62`,
поэтому верхняя полоса карточки (y ≈ 6% высоты) и её углы попадают *вне* плотной части тумана, и
на дневном небе заголовок, вкладки и крестик лежат прямо на светлом фоне (0.6–0.8 sRGB). Вторая
часть — тон `--pc-ink-faint` (#71806f): это средний тон (0.44 sRGB), у которого контраст ~2:1 и с
тёмным, и со светлым фоном; тень его не спасает — тень `0.82` над небом даёт всего 0.36 sRGB, всё ещё
рядом с самим глифом (замер: 2.61:1 на 0.80, **1.25:1** на 0.55, 2.04:1 на 0.30).

Что сделано:

- `.pc-tab` — неактивная вкладка берёт `--pc-ink-dim` (0.699 luma), `:hover` и `:focus` — `--pc-ink`;
  активная остаётся `--pc-ink` и по-прежнему помечена дымным мазком `pc-tab__glow`.
- `.pc-tab__label` и `.pc-card-title` — тёмная кромка `text-shadow: 0 1px 3px rgba(4,8,6,0.9)`,
  то же устройство, что уже работает у `.pc-btn-label` над облаками; на тёмном тумане она не видна.
- `.pc-close-line` — две полоски 1.5 px переведены с `--pc-ink-dim` на `--pc-ink`, а под крестиком
  теперь тёмное основание: `CloseHalo` / `CloseHaloHover` собираются через `Stacked` из
  прежнего светлого кольца (`--pc-hair` 0.16 / accent 0.16) и угольного диска `VeilDark 0.70`
  (радиус 0.62, stop 0.86, выпечено против `Sky`). Крестик — это две заливки, а не текст, тень к ним
  не применяется; диск даёт то же «маленькое тёмное облако», из которого сделаны кнопки.

Контраст (WCAG, по замеру `Tools/PCMMContrastProbe.cs`; фон 0.80 — дневное небо за тонкой частью
тумана, 0.30/0.12 — ночной туман):

| элемент | было | стало |
|---|---|---|
| неактивная вкладка (`ink-faint` × фон) | 2.61 / 1.25 / 2.04:1 | 4.43 / 6.36 / 8.40:1 (`ink-dim` + кромка) |
| крестик (`ink-dim` на светлом кольце) | ≈0.8:1 (кольцо на небе невидимо) | 5.63 / 7.66 / 9.58:1 (`ink` на угольном диске, центр 0.375 / 0.298 / 0.242 sRGB) |
| заголовок карточки | 2.61 / 1.25 / 2.04:1 | 4.43 / 6.36 / 8.40:1 |

USS импортируется без ошибок и предупреждений (213/213 скобки, 0 настоящих `filter:` кроме `none`).
