# T-FO06G — осмотр под каталог и опознание отсутствующих скриптов

Дата: 2026-09-09. Предыдущий этап: T-FO06F, `634e4500`.

## 1. Почему начал с осмотра, а не с профиля

Зависимости однонаправленные: профиль требует `SceneCatalog` и `SceneLayoutDigest`, который обязан совпасть с компиляцией каталога. Каталог нельзя составить, не осмотрев сцены. Поэтому профиль без осмотра был бы либо неполным, либо содержал бы недостоверные данные.

Результат этапа — установленные факты и два конкретных блокера, а не готовый каталог.

## 2. Жёсткое требование компилятора каталога

Из исходников компилятора: каждый источник каталога обязан иметь `inspectedComplete == true` **и** `saved == true`, валидный путь и 32-символьный `dependencyHash`. Иначе — отказ `missing_uninspected_dirty_or_invalid_scene_source`.

Следствие: **каталог нельзя честно составить для несохранённой сцены.** `dependencyHash` считается по содержимому на диске и не описывает живую несохранённую сцену.

## 4. Опознание трёх отсутствующих скриптов

Ранее эти компоненты числились как `identity=UNRESOLVED`, и я отказывался их удалять по имени GameObject. Теперь личность установлена по GUID из YAML сцены плюс подтверждение в коде.

| GameObject | Script GUID | Статус в коде |
|---|---|---|
| `[ShipKeyToast]` | `7e4592bffcae97841b2e9d1893479783` | помечен DEPRECATED в `QuestToast.cs`, класс удалён |
| `[ShipKeyServer]` | `d915eb76076361f4bad13b481fe4c1cc` | `CanPlayerBoard` DEPRECATED в `NetworkPlayer.cs`, заменён `MetaRequirementRegistry` |
| `[ShipOwnershipRegistry]` | `75a1a6152c04c0040b2c48c6fe27c18b` | «ShipOwnershipRegistry удалён (дублировал KeyRodInstanceWorld)» в `ShipTelemetryClientState.cs` и `NetworkManagerController.cs` |

Ни один из трёх классов не найден в коде проекта, и ни один GUID не найден ни в одном `.meta`.

**Вывод: это мёртвые ссылки на намеренно удалённые классы, а не потерянная функциональность.** Соответственно их удаление из сцены — уборка, а не потеря поведения. Само удаление в этом этапе не выполнялось.

## 5. Исправленная ложная диагностика

Первый прогон диагностики показал 21 «отсутствующий» компонент. 18 из них оказались ложными: ссылки вида `{fileID: 19102, guid: 0000000000000000e000000000000000}` — это встроенные объекты движка, у которых закономерно нет пути ассета, а не отсутствующие скрипты.

Инструмент исправлен: ссылкой на скрипт считается только `fileID 11500000`, остальные учитываются отдельно. После исправления результат — ровно 3 отсутствующих скрипта, что совпадает с 3 ошибками собственного аудита проекта. Совпадение двух независимых источников подтверждает цифру.

Итог по сохранённому файлу: 136 MonoBehaviour, 118 ссылок на скрипты, 18 ссылок на встроенные объекты, 84 различных GUID, 3 неразрешённых.

## 6. Два блокера, требующие решения

1. **Несохранённая сцена.** В редакторе есть изменения, предшествующие этой работе. Их авторство не подтверждено, поэтому я их не сохранял и не отбрасывал. Пока сцена не сохранена, `saved = true` заявить нельзя, и каталог для неё недопустим.
2. **Три мёртвых компонента.** Их удаление требует изменения и сохранения сцены, то есть упирается в первый блокер: сохранение зафиксирует и посторонние несохранённые изменения.

Эти два пункта связаны: любая правка сцены приведёт к сохранению всего её текущего состояния.

## 7. Проверки

- Использован собственный read-only аудит каталога проекта; сцены не загружались и не сохранялись.
- Диагностика отсутствующих скриптов выполнена по сохранённому YAML, без изменения сцены и без удаления компонентов.
- Перекрёстная сверка: 3 отсутствующих скрипта по обоим независимым источникам.
- Unity: **No compile errors**. Runtime C# не изменялся.
- Play Mode, physics, сетевые сессии, screenshots, builds, auth и save-файлы не использовались.
