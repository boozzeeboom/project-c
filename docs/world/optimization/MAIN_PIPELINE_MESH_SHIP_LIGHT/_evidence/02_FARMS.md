### 2.4. Что ломается под GRD и почему двери не мерджатся

1. **`layerCullDistances` игнорируется** → до Stage 8 двери рисовались на любой дистанции: ~25k инстансов / ~137 DC / ~1M тр (HO §8.4).
2. **Per-renderer opt-out из GRD не существует** (проверено рефлексией: только `forceRenderingOff`, `allowOcclusionWhenDynamic`, `renderingLayerMask`) → вариант «исключить двери из инстансинга» невозможен без отключения GRD целиком (R8 §1.2).
3. **Мерджить двери нельзя** [M]: (а) створка анимируется (`Open/Close`, `OpenProgress`), мерж убивает пивот; (б) каждая дверь — `DoorController` + триггер-коллайдер зоны; (в) политика 135/150 м требует **по-объектного** `forceRenderingOff`; (г) под GRD 2 598 дверей уже стоят 72 пары `(mesh,material)` → 1 DC на пару, мерж **добавит** слоты, а не уберёт (2.11 MR на инстанс уже минимум по материалам).

### 3.3. Конфликт двойного владения тенями ферм [F]/[M]

`FA §6.4` фиксирует: `Primum_farms.shadowCastingMode` пишут **оба** компонента (`DIRECTOR;ownershipConflicts` с Stage 6, не исправлялось). Механика:

| | `CityShadowBudget` | `ShadowBudget` |
|---|---|---|
| Кого берёт | все рендереры, включая фермы (не корабль, не слой 10) | только дети `Primum_farms` |
| `baseMode` | снят один раз в своём `Build()` | снят в своём `Build()` |
| Порог | 180 / 200 м | 50 / 60 м |
| Тик | 0.33 с (свой таймер) | 0.33 с (свой таймер) |

Полоса **60–200 м от камеры** — прямое противоречие: `SB` хочет `Off` (дальше 60 м), `CDB` хочет `baseMode` (ближе 180–200 м). Каждый пишет только при смене `want`, поэтому в этой полосе два таймера гоняют одно и то же свойство туда-обратно: **мигание теней ферм ~3 Гц** и лишние `shadowCasters`. Вне полосы (ферма в 1 км) оба согласны — поэтому дефект не виден на текущих дистанциях.

**Как не усугублять:** (1) не добавлять третьего писателя; (2) не расширять `farRootNames` на корни, которые и так покрывает `CDB`; (3) выбрать одного владельца — либо убрать `Primum_farms` из `farRootNames` (тогда 200/180 от `CDB`), либо выделить фермам отдельный слой и исключить его в `CDB` (`skippedLayer` — одно поле) и вести их только `SB`; (4) не трогать `QualitySettings.shadowDistance`/каскады — URP их игнорирует (J §6.3).

## 4. Коллайдеры: правила (из `FC` + код)

| Правило | Число/значение | Источник |
|---|---|---|
| Форма | **примитивы BoxCollider**, не один concave-меш: sphere-vs-box дешевле sphere-vs-triangles | FC §«Вариант B», `BSC` (шапка) |
| Мин. размер объекта | **0.25 м** (max сторона world AABB меньше — пропуск) | `BSC:61` |
| Мин. толщина бокса | **0.5 м** по каждой оси, расширение **вниз** (топ заподлицо) — лечит проваливание кораблей | `BSC:63` |
| Исключения по имени | `BOLT,SCREW,RIVET,NUT,WASHER,PIN,WIRE,CABLE,HOSE,PIPE,RAIL,LAMP,LIGHT,GLOW,GLASS,WINDOW,DECAL,MARKER,REFERENCE,TRIGGER,VOLUME,LOD1..3` | `BSC:66-69` |
| Круглые бары | `PIPE,REBAR,TUBE` → CapsuleCollider вдоль длинной оси (только длина ≥ 2 диаметров) | `BSC:72` |
| Кривые меши | slab-нарезка `sliceStep 1.0 м`, `sliceAdaptTol 0.05 м`; полости не заливаются | `BSC:74-79` |
| Слияние соседних боксов | `mergeGap 0.1 м`, `MergeScope` (гориз./верт./всё) — плиты с плитами, стены со стенами | `BSC:2491`, §«Merge» |
| Иерархия | отдельный `<Root>_Colliders/<здание>` в сцене, `static` для поселений (`shipMode=false`) | `BSC` (шапка) |
| MeshCollider (редко) | `convex=false`; cooking = CookForFasterSimulation + EnableMeshCleaning + WeldColocatedVertices + UseFastMidphase | `CMC:171-177` |
| Сколько на дом | **≈21** BoxCollider (диапазон чанков 13.5–52.8) | [M] §1.4 |

**Что нельзя:** `convex=true` на статике ради Rigidbody (дороже + ломает `CharacterController`, `CMC:172`); один гигантский concave-меш на всё поселение (дороже narrowphase, FC §B); per-triangle mesh-коллайдеры (в сцене их всего **7** — норма); удалять коллайдеры фермы без проверки геймплея (FC §B); ставить коллайдеры на FBX-узлы (переимпорт их снесёт — `BSC`).

**Почему это важно для ферм:** пилы 50–100 мс/0.25 с давали `OuterCommZone`/`MarketZone` с `OverlapSphere(r=1000, ~0)`: на «Ферма Примума 0_1» **82.93 мс и 136.6 КБ GC** за полл против 0.1–0.3 мс у остальных; виновата не PhysX (вся физика ~2.8–3 мс/кадр), а C#-обход хитов с `GetComponentInParent` (`FC` §«Что есть сейчас», `CAP` §1, §5). Лечение — сузить `pollLayerMask` (вариант A), а не число боксов.

## 8. Расхождения / риски

1. **`layerCullDistances` мертв под GRD** — в трёх документах он всё ещё описан как рабочий механизм дистанции (R2 §2, HO §4.3, J §5.3 п.1). Фактически работает только `VD`. Любой новый контент, полагающийся на `layerCullDistances`, будет рисоваться на всех дистанциях.
2. **«Гистерезис 130–150»** из брифа ≠ кода: `VD` даёт **off 150 / on 135**; R8 §4 измерял полосу 130–165 м (574 рендерера в смешанном состоянии). Числа «130» в документах — от Stage 7, не от текущего кода.
3. **Двойное владение тенями ферм** (§3.3) не исправлено с Stage 6, зафиксировано в `FA §6.4` как «вне тикета». Мигание в полосе 60–200 м; при полёте к ферме это видно.
4. **Две дистанции ферм**: R2 §3 — «5.7–6.0 км от P1» (из-за этого ожидался выигрыш ≈0); J §5.1 и `04_OCCLUSION §33` — «963–1 051 м». Одна из цифр устарела; от неё зависит, работает ли `ShadowBudget` вообще.
5. **Ферма ≠ «5/250 домов»**: системы домов-ферм нет; «Ферма Примума» — станция с merged-визуалом (145 MR) и 270 дверными рендерерами. Любая оценка «ферма на N домов» — только экстраполяция §5.
6. **Мёртвые ассеты**: `Colliders/PRIMUM_BC_*.prefab` (18 файлов, **12 111** боксов) и `Colliders/Houses/PM_HOUSE_*` (100 мешей) — **0 ссылок** в сценах и префабах. Риск: их примут за «текущий пайплайн домов» и будут править. Живые коллайдеры — inline `HOUSE_*_BOX` в сцене (12 299).
