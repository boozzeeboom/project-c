## 1. Задачи

1. **A/B-матрица поверх принятого L4 (только память, сцена не грязнится):** добавить в пул
   `ApplyTuneConfig(radiusMeters, maxActive, hysteresis, coneMarginDeg, conePreActivationDeg,
   rearMeters, penaltyPerDeg)` и в бенч `RunMode.L5` + меню `Project C/Lighting/T-LIGHT20 tune/Run|Abort`,
   тег `[T-LIGHT20]`, CSV-префикс `T-LIGHT20`. Варьировать **по одной оси** от базы L4:
   - `activeRadius` — **100 / 120 / 140** (70 уже отклонён в L2, не повторять);
   - `maxActive` — **96 / 128** (128 включать, только если GPU-гейт ниже проходит; 160/192 не трогать);
   - `hysteresis` — 0.10 / 0.20;
   - `coneMarginDeg` — 6 / 10; `conePreActivationDeg` — 0 / 5 / 8;
   - `rearRadius` — 20 / 28 / 35 (кламп `min(radius, 30)` уже в коде — проверить, что 35 реально даёт 30);
   - `anglePenaltyPerDeg` — 0.5 / 1.2 / 2.0.
2. **Замер в одном прогоне, одни и те же позы:** точки P1 / STREET / ADMIN / FARM, часы **12 / 18 / 20**
   (вечер 17–20 — исходная жалоба). Для каждого конфига: `dc`, `spc`, `gpuMs` (FrameTiming),
   `fps`, `active`, сплит OUT/IN/FARM, `inFrustum` и его доля, `behindOutsideRear`, `turn setChanged` +
   кадры реакции, `capCut`, `capSaturated`, `intensityZeroActive`, `checkMarkerMsAvg`, `poolCheckMs`.
3. **Выбрать один финальный конфиг** и обосновать числами; зафиксировать его **дефолтами в коде**
   (сериализованные инициализаторы, сцену не пересохранять) + строкой в `ConfigLine`/`ConeConfigLine`.
   Если финал совпал с L4 — так и записать, ничего не менять.
4. **GPU-гейт cap 128:** поднимать, только если во всех позах `gpuMs` ≤ базового 96 **+2.0 мс**
   и `fps` не ниже базового (медианы по 3 сэмплам, шаг 8 кадров; сравнивать пары в одном прогоне).
   Иначе cap остаётся 96 и это фиксируется в отчёте как отклонённый вариант.
5. **`range` INLIGHT 48.3 м:** измерить вклад косвенно — доля активных IN-ламп с `range > 20`
   в слотах и поведение `gpuMs` при `radius 100` vs `140` (если `gpuMs` растёт только с IN — это сигнал).
   **Ничего в сцене/префабах не менять**; предложение по `range` — отдельным пунктом в отчёте, не код.
6. **Визуальный риск-чек (для пользователя):** тюнинг не должен вернуть засветку за спиной, pop-in
   или «дыры» в веере; `rearRadius` не опускать ниже 20 м.
7. Не менять: владение `enabled`/`intensity`, `dayGate`/`split`/`outMin`, `checkInterval`,
   логику фокуса (L3) и веера (L4) — только значения.

## 3. Жёсткие правила

1. Только значения конфига пула; fade (L6), интерьерная окклюзия, LOD/HLOD, URP, `ProjectSettings`,
   `VisibilityDirector`, корабли, двери — не трогать.
2. `Light.enabled` пишет пул, `Light.intensity` — ALIC; пул `intensity` только читает.
3. `maxActive` 160/192 не рассматривать (риск тихого переполнения 256 лимита камеры без GPU-замера
   lights-per-tile); 128 — только через GPU-гейт.
4. FO-safe: никаких кэшированных мировых `Vector3`; после F8/F9 поведение идемпотентно.
5. Play Mode — только по разрешению; сцену не сохранять; push не делать; `.meta`/`.asmdef` руками не писать.
6. Известные артефакты бенча: `NOTE;farm_cluster` в FARM-позе пишется каждый кадр (растягивает кейс,
   секунды нерепрезентативны — опираться на кадры и медианы); `probeTurnSec` при просадках fps не годен.
7. `range`/`intensity`/`shadows` ламп в сцене не менять — только читать (владелец intensity — ALIC;
   scene-правки требуют отдельного одобрения).
