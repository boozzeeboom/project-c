**Поправка по ходу сборки (замер, не предположение):** пивот всех 106 моделей лежит **внутри голеней** —
низ меша на `−0.313…−0.075` м относительно пивота. Без правки NPC стояли бы по колено в мостовой, а
фиксированный нейм-плейт на y = 2.1 оказался бы **в груди** у моделей выше 2.1 м. Поэтому в
`PrimumCrowdNpc` добавлены `AlignVisualToGround()` (подъём `Visual` по низу меша) и
`PlaceNameplateAboveHead()` (плейт = верх меша + 0.35), повторно применяемые через 1 с уже по позе Idle.

**DoD (T1):**
1. В сцене существует ровно один `PRIMUM_NPC_CROWD`; NPC создаются только в рантайме внутри него.
2. На старте появляется 100 NPC, каждый — на навмеше, у каждого свой дом и **в доме не больше 4**.
3. NPC ходят (Idle ↔ Wander), не проходят сквозь стены (двигает только `NavMeshAgent`).
4. У каждого виден нейм-плейт в радиусе и `E` открывает его личный диалог (при поднятом хосте).
5. При сдвиге `WorldRoot_0_0` (тест: подвинуть корень руками в инспекторе в Play) NPC остаются на местах
   относительно города, не улетают и не теряют маршрут.
6. Ни одного `NetworkObject`/`Rigidbody`/`CharacterController` на NPC.

## Риски и заготовленные решения

| Риск | Решение |
|---|---|
| `FindWorldRoot` возьмёт `Mountains`, город не сдвинется | NPC не зависят от FO: локальные якоря + детект дельты своего корня |
| Навмеш не покрывает интерьеры | на T1 проверяется сэмплом; при провале — T5 отдельно (двери + интерьерный навмеш) |
| 100 уникальных моделей = 100 материалов/текстур | на T1 допустимо; на T3+ — атлас/общие материалы/импостеры |
| `NpcController` создаёт заглушку-куб | в шаблоне есть TMP-плейт → ветка заглушки не срабатывает |
| `NpcController` насильно делает коллайдер триггером | принимаем: NPC не блокируют игрока, стены держит навмеш |
| 1000 `NpcDefinition`-ассетов замедлят авто-скан базы | на T3 перейти на рантайм-провайдер (описано в `04_ASSETS_AND_DATA.md §5`) |
