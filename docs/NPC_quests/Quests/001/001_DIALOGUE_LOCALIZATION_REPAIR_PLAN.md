# Q001 — План проверки и исправления диалоговой локализации

> **Квест:** Q001 — «Пепел под стеклом»
> **Связанный draft:** `001_ASH_UNDER_GLASS_DRAFT.md`
> **Статус:** implementation in progress
> **Дата начала:** 2026-08-25
> **Область:** только Q001 DialogTree и необходимые RU/EN записи `Dialogue_Table`

## Цель

Исправить отображение Q001 диалогов, чтобы вместо строк вида `dialog.dlg_lyra_q001...` показывались локализованные тексты, не нарушив существующую локализацию проекта.

## Подтверждённая причина

Q001 DialogTree используют ключи с префиксом `dialog.dlg_...`, например:

```text
dialog.dlg_lyra_q001.node.greeting
```

`ProjectC.Localization.Loc.ParseKey()` распознаёт для диалогов только префикс `dialogue.` и направляет его в `Dialogue_Table`. Поэтому ключи `dialog.dlg_...` не маршрутизируются в `Dialogue_Table` и возвращаются на экран буквально.

`QuestServer` и `DialogWindow` уже вызывают `Loc.Get()` для текста узлов, вариантов ответа и имени говорящего. Первичный фикс должен выполняться в Q001 asset keys и таблицах, без изменения общей runtime-схемы.

## Жёсткие ограничения безопасности

1. Не выполнять полный rebuild локализации.
2. Не очищать ни одну таблицу.
3. Не удалять и не пересоздавать `SharedData`.
4. Не перезаписывать существующие значения.
5. Не изменять `Static_Table`, `UI_Table` и `System_Table`.
6. Не запускать `LocalizationTableRepair.cs`.
7. Не использовать текущий `AddDialogueEntries.cs` как массовый источник: он содержит неполный старый набор и RU-only записи.
8. Изменять только Q001 DialogTree и отсутствующие Q001 записи `Dialogue_Table`.
9. Перед каждым изменяющим этапом сохранять baseline и проверять область изменения.
10. При любом несоответствии количества/ID/таблиц отменять этап до сохранения.

## Этапы

### Этап 0 — Зафиксировать baseline

- Снять список ключей и SharedData ID для `Static_Table`, `UI_Table`, `Dialogue_Table`, `System_Table`.
- Зафиксировать количество записей в каждой таблице для RU и EN.
- Снять список всех Q001 ключей из шести DialogTree.
- Сохранить baseline в отдельный отчёт рядом с этим планом.
- Ничего не изменять.

**Приёмка:** baseline создан; все четыре таблицы доступны; существующие ключи и ID сохранены.

### Этап 1 — Статический аудит Q001

- Проверить все `displayName`, `node.text` и `edge.label` шести Q001 DialogTree.
- Найти ключи с неправильным префиксом `dialog.`.
- Найти отсутствующие ключи в `Dialogue_Table Shared Data`.
- Проверить наличие RU и EN значений.
- Отдельно проверить имена Q001 NPC и связанные квестовые/предметные строки.
- Составить точный список исправлений без изменения ассетов.

**Приёмка:** полный список Q001 ключей и проблем получен; неизвестных массовых изменений нет.

### Этап 2 — Нормализация ключей только в Q001

Заменить только в шести Q001 DialogTree:

```text
dialog.dlg_...
```

на:

```text
dialogue.dlg_...
```

Суффиксы ключей не менять.

**Приёмка:** все Q001 диалоговые ключи начинаются с `dialogue.`; ключи других диалогов не изменены.

### Этап 3 — Аддитивное добавление RU/EN

Создать отдельную узкую процедуру для Q001:

- добавлять только отсутствующие ключи через `SharedData.AddKey()`;
- добавлять значения в `Dialogue_Table_ru` и `Dialogue_Table_en`;
- сохранять существующие SharedData ID;
- не изменять существующие значения;
- не затрагивать другие таблицы;
- повторный запуск не должен создавать дубликаты.

Значения RU/EN подготовить для всех Q001:

- displayName DialogTree;
- тексты всех nodes;
- labels всех choices;
- имена NPC;
- сообщения ошибок и провальных веток;
- финальные реплики.

**Приёмка:** добавлены только ожидаемые новые ключи; существующие значения и ID не изменились.

### Этап 4 — Пост-изменительный статический контроль

Проверить:

- каждый Q001 ключ имеет префикс `dialogue.`;
- каждый ключ существует в SharedData `Dialogue_Table`;
- RU и EN значения существуют и не равны самому ключу;
- 42 Q001 nodes достижимы;
- dangling edges отсутствуют;
- object references не изменены;
- остальные три таблицы и не-Q001 ключи не изменены;
- проект компилируется без ошибок.

**Приёмка:** все статические проверки проходят, изменения ограничены Q001 Dialogue_Table.

### Этап 5 — Ручной Play Mode-прогон

Проверить вручную:

1. Подход к каждому из шести Q001 NPC.

4. Локализованные варианты ответа.
5. Скрытые и недоступные варианты.

**Приёмка:** Q001 не показывает ключи; существующая локализация не имеет регрессий.
