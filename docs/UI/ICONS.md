# UI Icons — регистр (батчи B1 + B2 + B3 + B4 + B5 + B6)

Регистр иконок интерфейса: что сгенерировано, где лежит, в каком состоянии.
Каталог: `Assets/_Project/UI/Icons/`. Правила нэйминга и импорт-настройки — `Assets/_Project/UI/Icons/README.md`.

**Итого: 168 иконок — батч B1 (40) + батч B2 (34) + батч B3 (22) + батч B4 (25) + батч B5 (22) + батч B6 (25).** Статус на 2026-10-29: `IMPORTED / PLACED PARTIALLY` — все 168 импортированы как `Sprite` с размером по роли, расставлено 1116 ссылок в восьми Sprite-полях, задействовано 45 иконок. Остальные 123 ждут поля в коде или данных — см. «TODO: расстановка» ниже.

Стиль батча: стимпанк + дизельпанк, западный комикс, тонкий тёмный контур, эмаль по тёмной стали, латунная окантовка, потёртости по кромкам, без встроенного текста. Свечение только функциональное (антиграв, мезий, ядро техники).

## Известные замечания батча

1. **`Villagers` перегенерирован.** Первая версия была зелёной и конфликтовала с палитрой `GuildOfCreation`; принята вторая версия — дерево, солома, лён, железо, без зелёного. В каталоге лежит только итоговая версия.
2. **`Icon_Damage_Ballistic`** — самая слабая иконка набора по силуэту: горизонтальная композиция занимает малую часть кадра. Нужна перегенерация с более компактной/наклонной компоновкой или кадрирование перед даунскейлом.
3. **`Icon_Cat_Fuel`** — зелёный корпус баллона colour-конфликтует с медициной и Созиданием; рассмотреть оливковый/серый вариант.
4. **`Icon_Damage_Antigrav`** — дуги читаются как «энергия/излучение», что близко к запрещённому «декоративному свечению»; при несоответствии канону перегенерировать с более тонкими и короткими дугами.
5. **`Icon_Faction_Guards`** — мелкая детализация (рифление рукояти, спицы фонаря) не выживет на 24 px; для 24 px понадобится упрощённый вариант.
6. **Даунскейл факций не выполнен.** Исходники 1024 px; при 24–32 px позолота и потёртости исчезнут — требуется контролируемый downsample и проверка читаемости.
7. Иконки категорий сделаны в более «объёмном» рендер-ключе, чем плоские метки карты и целей квестов. Внутри каждой группы стиль единый; смешение ключей между группами терпимо, но при сборке одного экрана (инвентарь + карта) разница будет заметна.

1. **`Icon_Cat_Key` — исправление пропуска B1.** В `ItemType` девять членов, включая `Key = 8` (ключи-стержни кораблей, R2-SHIP-KEY-003); в батче B1 было сгенерировано только восемь.

### Чего в B3 нет и почему

- **`CombatSubtype`** (`None`, `Throwables`, `Traps`, `Bows`, `Crossbows`) — в самом коде помечен «Виден только дизайнеру в инспекторе. Игроку не показывается», поэтому игровых иконок не требует.
- **`WeaponHandling`** (`Melee`, `Ranged`, `Thrown`, `Placed`) — три из четырёх значений дословно совпадают с дисциплинами (`Melee` / `Ranged` / `Placed`); отдельный набор дал бы две почти идентичные группы глифов на одном экране. Осознанно не генерировался.
- **`WeaponClassMask`** — flags-зеркало `WeaponClass` (`1 << WeaponClass.*`); своих иконок не нужно.
- **По-навыковые иконки отдельных `SkillNodeConfig`** (в коде упоминаются 27+ `.asset`) — это строковые `skillId`, а не члены enum, поэтому правило «имя файла == имя enum-члена» для них не работает. Отдельный батч, когда будет утверждён список `skillId`.
- **Валюты и статусы/эффекты** — по-прежнему заблокированы (причины в разделе B2).

## Известные замечания (батч B3)

1. **Кости различаются только формой** (`d4…d20`), цифры не запекались. `d10` и `d20` на 32 px сольются; в UI нужна текстовая подпись рядом.
2. **`Icon_Discipline_Melee` и `Icon_SkillCat_Combat`** оба построены на «меч + защита» (наруч vs щит) — на одном экране (дерево навыков) проверить, что не читаются как одна иконка.
3. **`Icon_Discipline_Combat` и `Icon_Skill_Combat`** (B2, `SkillType` крафта) — оба «скрещённое оружие» в разных доменах; в одной панели различаются только контекстом.
4. **`Icon_WeaponClass_Sword` (горизонтальный меч) vs `Icon_Slot_WeaponMain` (вертикальный)** — осознанно: класс оружия ≠ слот экипировки.
5. **`Icon_WeaponClass_MesiumRifle`** — единственный глиф B3 с настоящим свечением (зелёная жидкость), разрешено каноном.
6. **`Icon_WeaponClass_AntigravBlade`** — единственный, где зазоры читаются как «парящие сегменты»; свечения нет по канону (пассивный антиграв).
7. **`Icon_WeaponClass_Throwable`** — две фигуры в кадре (граната + нож); на 32 px станет мешаниной, использовать при 64 px.
8. **Широкие композиции** (`Sword`, `Spear`, `Crossbow`, `Pneumatic`, `MesiumRifle`) занимают почти всю ширину кадра — тот же риск, что у wide-группы B2: читаемость на 64 px, не ниже.

## Известные замечания (батч B5)

1. **`Icon_Crew_Passenger` перегенерирован.** Первый проход ушёл в полный рост (вся фигура с ног до головы), что ломало единый поясной кадр с остальными пятью ролями; принята вторая версия — тот же поясной бюст.
2. **`Icon_Relation_Allied` перегенерирован.** В первой попытке массив вышел со сдвигом: под именем `Allied` сохранилась картинка пассажира. Из-за этого набора пришлось чинить две позиции; текущие файлы правильные (кольца), но при ручном аудите стоит открыть именно эти два файла.
3. **`Icon_Relation_*` — самая минималистичная группа каталога**: два плоских латунных кольца выживут на 24 px, но при этом визуально беднее всех остальных иконок; в панели репутации они должны стоять рядом с эмблемой фракции, иначе экран будет выглядеть пустым.
4. **`Icon_Relation_Neutral` vs `Icon_Relation_Allied`** — различие только в том, касаются ли кольца. На 32 px и меньше разница читается плохо; минимум — 48 px, либо цветовая подложка.
5. **`Icon_Relation_Hostile`** — единственная иконка батча с крупной ржаво-красной зоной; при сборке панели следить, чтобы красный не спорил с цветами репутационных tier'ов (`ReputationTier.color`).
6. **`Icon_Hull_Operational` / `Icon_Hull_Broken`** — секция обшивки с манометром читается и как щит с циферблатом; это не мешает паре (состояние считывается по трещине), но рядом с эмблемами фракций-щитов может путать.
7. **`Icon_Hull_*` шкала без цифр** — намеренно (общий запрет на цифры в иконках); стрелка даёт состояние только относительной позицией, поэтому в HUD нужна ещё текстовая/цветовая полоса прочности корпуса.
8. **`Icon_Service_Trade` и `Icon_Skill_Trading`** (B2) оба построены на весах — один и тот же мотив в двух доменах. Различаются деталями (у `Service` ярлык и монеты у основания), но в одной панели (диалог торговца + экран навыков) их лучше не ставить рядом.
9. **`Icon_Service_Restock`** — внутри ящика оливково-зелёный брезент; это не зелёный Созидания, но близко к нему — тот же риск, что у `Icon_Cat_Fuel`, при сборке торгового экрана.
10. **`Icon_Station_*` и `Icon_Know_Station`** (B2) — оба про «станок/верстак». `Icon_Know_Station` — это способ открытия знания, `Icon_Station_*` — конкретная станция; на экране крафта рядом держать не стоит.
11. **`Icon_Station_Loom` и `Icon_Station_CraftingTable`** — обе деревянные рамы; на 32 px силуэты похожи, держать 64 px.
12. **Ноль свечения в батче B5** — намеренно: ни один из пяти доменов не имеет функционального источника света по канону (сервисы, станции, экипаж, отношения, корпус).

### C. Требует отдельного решения

1. **`ItemData.icon` на 1049 предметах — категорийный плейсхолдер.** Настоящая иконка предмета требует отдельного арта на каждый предмет; текущая расстановка заменяется полностью, а не дополняется.
2. **`TradeItemDefinition.icon` (113 ассетов) не расставлен.** У `TradeItemDefinition` нет ни категории, ни типа предмета — только `itemId`/`displayName`/цена. Детерминированного маппинга нет. Варианты: добавить поле категории (код), маппинг по префиксу `itemId` (код) или отдельный арт на каждый товар.
3. **`NpcDefinition.portrait` (30 ассетов) не расставлен.** Это портреты, а не иконки: в каталоге подходящего арта нет, нужен отдельный батч портретов.
4. **`.meta` в `.gitignore`** (правило `*.meta`, строка 182): настройки импорта не переносятся через git. На чистой копии их нужно применять заново, либо снять правило для `Assets/_Project/UI/Icons/**/*.png.meta`.
5. **Max Size 48 не поддерживается.** Для `Quests/Objectives` в README стояло 48 px, `TextureImporter.maxTextureSize` принимает только степени двойки — применено 64. Либо принять 64, либо пересмотреть запись.
6. **`Skill_Social_BasicTalk` имеет `category = Combat` при `discipline = None`** — получил `Icon_SkillCat_Combat`. Похоже на ошибку данных: социальный навык помечен боевым. Правка в ассете, но это решение владельца данных, а не расстановки.
