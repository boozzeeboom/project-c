# T-SHIP-DOC08 — перепроверка: Bootstrap трогать / не трогать (RepairManagerWindow)

> Тикет: `T-SHIP-DOC08`. Дата: 2026-09-18. Статус: **ПОДТВЕРЖДЕНО ЧАСТИЧНО (снимается вариантом «или»)**.
> Scope: только перепроверка + уточнение гайда. Кода/сцены нет.

## Что проверяли

Утверждение ревью (§9 несостыковок): `Modul_system/02_REPAIR_MANAGER.md §1.3` —
создать `[RepairManagerWindow]` в `BootstrapScene/DontDestroyOnLoad`;
`ITERATIONS.md T-ENG02` — `BootstrapScene 🚫 НЕ ТРОГАТЬ, залочена`.

## Факт (сверено чтением)

- Гайд `02 §1.3` (строка 28): «**В BootstrapScene или DontDestroyOnLoad**» —
  альтернатива заложена в сам гайд, прямого требования править Bootstrap нет.
- `RepairManagerWindow.cs:30,96-99`: синглтон с duplicate-destroy в `Awake`,
  `DontDestroyOnLoad` в коде **нет** — персист должен дать сцена/порядок создания.
- Запрет `T-ENG02` (Bootstrap залочена) подтверждён `ITERATIONS.md`.
- Вывод: противоречие снимается выбором второго варианта («или DontDestroyOnLoad»),
  но гайд не задаёт приоритет — читатель может выбрать запрещённый путь.

## Решение

Статус ПОДТВЕРЖДЕНО ЧАСТИЧНО. Фикс docs-only: уточнение в `02 §1.3` —
приоритет: runtime/DDOL (или размещение в WorldScene) по умолчанию;
правка BootstrapScene — только с отдельного аппрува. Добавление `DontDestroyOnLoad`
в код окна — НЕ этот тикет (кандидат в `T-SHIP-FIX15`, вместе с дубль-синглтонами).

## Проверка

- Читать `02 §1.3`: приоритет вариантов зафиксирован.
- Compile: не требуется (docs only).
