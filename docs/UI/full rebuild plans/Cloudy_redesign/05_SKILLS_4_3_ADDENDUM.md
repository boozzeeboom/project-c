# 05 — Дополнение 4.3: навыки и шесть боевых слотов

> **Статус:** проработка мода **4.3**. Экспорт в игру **не выполняется** (как и в 4.2).
> **Область:** только то, чего нет в 4.2. Документы `01`…`04` описывают мод **v4-2** и остаются в силе целиком.
> **Дата:** 2026-10-28
> **Источник визуала:** `.Aura/Mods/v4-2/` (активный мод; в `mod.json` имя всё ещё `v4.1` — файл управляется Aura).

## 1. Что добавляет 4.3

Окно персонажа в легаси (`P`, `CharacterWindow`, вкладка `knowledge`) содержит то, чего в облачной раскладке
не было вовсе: **навыки**. 4.3 добавляет три вещи и ни одной новой системы данных:

1. **Шесть боевых слотов** в левой панели — 2 ряда по 3, компактно под модулями.
2. **Полноразмерный граф навыков** — по тому же жесту и той же вёрстке, что граф отношений
   (`src/rel-graph.js`): полоса-шапка со сворачиванием, панорама, зум, облачные пласты, кабели предпосылок.
3. **Кнопка «Социальные навыки»** под слотами — тот же граф, но только социальная категория и без слотов.

Репутация при этом **опускается в самый низ** панели: под ней больше ничего нет.

## 2. Левая панель: что меняется и какими числами

Порядок блоков `#home` в 4.2 (`src/home.js`):

```
шапка (ДОМАШНЯЯ СТАНЦИЯ + имя) → календарь → характеристики STR/DEX/INT →
кольцо: слоты 5 | ниша 3D + кредиты | слоты 5 → модули (3 × 36 px) →
репутация (.hm-mast, flex:1) → альтиметр
```

Порядок в 4.3:

```
шапка → календарь → характеристики → кольцо →
модули (3 × 36) → БОЕВЫЕ СЛОТЫ 2 × 3 → «СОЦИАЛЬНЫЕ НАВЫКИ» →
спейсер (flex:1) → альтиметр → репутация (последний блок)
```

Почему так: репутация сейчас `flex:1` и поэтому «съедает» всю свободную высоту, прижимая альтиметр к низу.
В 4.3 гибким становится **спейсер**, репутация получает фиксированную высоту и встаёт последней — так
шесть слотов получают место без сжатия кольца и без обрезки станции на низких окнах.

### Числа (взяты из `src/style.css`, не придуманы)

| Что | Значение | Откуда |
|---|---|---|
| Ширина колонки персонажа | 200 px | `--homeW, 200px` в `#ui` |
| Слот кольца / модуля | 36 × 36 px | `.hm-slot`, `#home .hm-mods .hm-slot` |
| Зазор модулей | 6 px → ряд 3 × 36 + 2 × 6 = **120 px** | `.hm-mods { gap: 6px }` |
| Слот навыка 4.3 | 36 × 36 px, зазор 6 px → сетка **120 × 78 px** | та же геометрия, что у модулей |
| Кнопка «Социальные навыки» | 120 × 32 px, капс 10.5 px, `.12em`, радиус ≤ 2 px | правило приборных бирок мода |
| Ниша 3D (ступени подгонки) | 200 → 188 → 176 → 160 → 144 → 132 px | `STAGES` в `home.js` |

Бюджет высоты: блок навыков добавляет **78 px** (сетка) + **6 px** (зазор) + **32 px** (кнопка) + **6 px** =
**≈ 122 px**. Ступени `STAGES` отдают максимум 68 px, значит 4.3 обязана либо добавить ступени ниже 132 px
(ниша 120 / 108), либо включать компактный режим слота 30 × 30 при `hm-cmp2`. Решение фиксируется числом в
`v43-panel-fit`, а не «на глаз».

## 3. Почему слотов именно шесть

Шесть — это ровно перечисление `ProjectC.Skills.SkillInputSlot`, ничего не добавляется на клиенте:

| Слот в сетке | `SkillInputSlot` | Биндинг по умолчанию (`InputBindingsConfig.combatSkills`) |
|---|---|---|
| 1 | `Primary` = 1 | ЛКМ (fallback `K`) |
| 2 | `Secondary` = 2 | ПКМ |
| 3 | `Slot1` = 10 | `Ctrl+ЛКМ` |
| 4 | `Slot2` = 11 | `Ctrl+ПКМ` |
| 5 | `Slot3` = 12 | `Shift+ЛКМ` |
| 6 | `Slot4` = 13 | `Shift+ПКМ` |

Следствие для подписи: боевые слоты **не нумеруются 1–4** — они висят на мыши с модификатором. Подпись слота
берётся из `InputBindingsRuntime.Instance.GetSkillDisplayName(slot)` (тот же источник, что в
`SkillTreeWindow.RebuildSlotOverview`), fallback — `slot.ToString()`.

## 4. Поведение слота

**Наведение.** Карточка-подсказка (`.tip-card`, как у слотов экипировки):

- занятый слот — название навыка, тип (**активный / пассивный**), дисциплина, эффекты
  (`SkillEffect`: `statType +floatValue`, `x multiplier`), `cooldownSeconds`, маска оружия
  (`requiredWeaponMask` словами — готовая `SkillInputService.DescribeMaskShort`), «требует:» из `prerequisites`;
- пустой слот — «слот пуст» и **список выученных боевых навыков, которые ещё не висят ни на одном слоте**
  (источник: `SkillsClientState.CurrentSkills` ∩ `isActive == true`, минус уже привязанные из
  `SkillInputService.GetAllBindings()`);
- пассивные навыки в этот список не попадают никогда: `SkillInputService.TryActivate` их отклоняет
  («passive — can't activate»), поэтому вешать их на слот бессмысленно и в UI их предлагать нельзя.

**Клик.** Разворачивает полноразмерный граф навыков с фокусом на привязанном навыке (для пустого слота — граф
без фокуса). Выход — клик по полосе-шапке или Esc, как у графа отношений.

**Назначение.** Внутри графа: выбранный навык → ряд из шести кнопок привязки, ровно как `btn-bind-*` в
`SkillTreeWindow`. Привязка идёт через публичный `SkillInputService.BindSlot(slot, skillId)`; если навык уже
висит на другом слоте — сначала `BindSlot(oldSlot, "")` (та же логика, что `SkillTreeWindow.OnBindSlotClicked`).
Отвязка — `BindSlot(slot, "")`. Сохранение делает сам сервис в
`Application.persistentDataPath/Skills/slot_bindings_{clientId}.json`; **мод своих привязок не хранит.**

## 5. Полноразмерный граф навыков

Вёрстка повторяет граф отношений (`src/rel-graph.js`), это не новый язык интерфейса:

| Элемент графа отношений | В графе навыков 4.3 |
|---|---|
| `.rp` — полноэкранная секция, `.rp-head` со сворачиванием по клику и Esc | то же; заголовок «НАВЫКИ» / «СОЦИАЛЬНЫЕ НАВЫКИ», в шапке счётчик «выучено N из M · известно K» |
| `.rp-stage` + `.rp-view`: один трансформ двигает узлы, кабели и подписи | то же; панорама драгом пустого места, зум колесом 0.4…2.2, двойной клик — вписать |
| `cloudClip(id)` — рваный облачный край узла, детерминированный от id | то же (id = `skillId`) |
| кабели-квадратики с провисанием и «подписями-глаголами» | предпосылки: кабель от `prereq` к навыку, подпись «требует» / «открывает» |
| фокус по клику: `.focus`, `.dim`, подсветка своих кабелей | то же |
| `aside.rp-leg` — легенда: типы связей, раскладка, шкала тиров | легенда: дисциплины (Combat / Melee / Ranged / Defense / Placed / None), цвета, «активный/пассивный», кнопки «Сохранить раскладку / Вернуть мою / Упорядочить» |
| ПКМ по пустому — меню «заметка / вписать / упорядочить», стикеры-заметки | меню «вписать / упорядочить»; заметки — **не нужны** (не переносим) |
| раскладка «подсолнух» + `localStorage 'v4.relations.layout'` | своя раскладка `v4.skills.layout`; координаты `treeX/treeY` — только стартовый «упорядочить по автору» |

Источник узлов в моде — не выдуманные данные: `TreeX/TreeY` из `SkillNodeConfig` (см. `03_DATA_CONTRACT.md` для
остальных доменов), поэтому «Упорядочить по автору» даёт ту же схему, что легаси-окно (`treeX * 2.5 + 10`,
`treeY * 2.5 + 10`, узел 140 × 28).

## 6. Кнопка «Социальные навыки»

Тот же граф, отличия — ровно как между `SkillTreeWindow` и `SocialSkillTreeWindow`:

- фильтр `category == SkillCategory.Social` (в ассетах это **3 навыка**: `social_barter`, `social_persuasion`,
  `social_leadership`; см. находку **D6** про четвёртый);
- все социальные навыки **пассивные** → в графе нет шести слотов, нет кнопок привязки, нет чипов дисциплин
  (легаси просто скрывает эти блоки: `stw-slot-overview-col`, `stw-chip-row`, `btn-bind-*`);
- заголовок «СОЦИАЛЬНЫЕ НАВЫКИ» (`ui.skill.social_tree_title`).

Кнопка в панели — единственный вход в социальный граф; наведение на неё поднимает карточку «3 навыка ·
все пассивные · выучено K».

## 7. Контракт данных 4.3

| Значение в моде | Источник в игре (проверено по коду) |
|---|---|
| Выученные навыки | `SkillsClientState.Instance.CurrentSkills` (`HashSet<string>`), событие `OnSkillsUpdated` |
| Известные (но не выученные) | `SkillsClientState.Instance.KnownSkillIds` |
| Каталог навыков | `Resources/Skills/Skill_*.asset` (`SkillNodeConfig`), кэш `SkillsClientState.TryGetSkillConfig(skillId, out cfg)` |
| Название / описание / иконка | `SkillNodeConfig.displayName` / `.description` / `.icon` (**иконок нет ни у одного навыка — D11**) |
| Тип, дисциплина, подтип | `.isActive`, `.discipline` (`CombatDiscipline`), `.subtype` (`CombatSubtype`) |
| Эффекты | `.effects[]` (`SkillEffect.Type.StatMod`: `statType`, `floatValue`, `multiplier`; `stringParam` для unlock'ов) |
| Кулдаун | `.cooldownSeconds` (у сервера свой, клиентский — локальный для отзывчивости) |
| Требования | `.prerequisites[]`, `RequiredStrengthTier / DexterityTier / IntelligenceTier`, `requiredWeaponMask` |
| Стоимость изучения | `.LearnXpCost` (0 = бесплатно) |
| Знание о навыке | `.knowledgeUnlockType` / `.knowledgeUnlockId` / `.knowledgeUnlockDescription` |
| Позиция в графе | `.treeX`, `.treeY` |
| Привязки слотов | `SkillInputService.Instance.GetAllBindings()` → `IReadOnlyDictionary<SkillInputSlot, string>` |
| Подпись слота | `InputBindingsRuntime.Instance.GetSkillDisplayName(slot)` |
| Привязка / отвязка | `SkillInputService.Instance.BindSlot(slot, skillId)` (`""` = отвязать) |
| Выученные для биндинга | то же событие `OnSkillsUpdated` → `SkillInputService.SetKnownSkills(learned)` |

Кнопки «Изучить» / «Забыть» в 4.3 **не реализуются**: легаси делает это reflection-вызовом
`ProjectC.Skills.SkillsServer.RequestLearnSkillRpc` / `RequestForgetSkillRpc`, то есть прямого публичного API нет.
Граф 4.3 — просмотр + привязка на слот; изучение остаётся за легаси-окном `[ИЗУЧИТЬ НАВЫК]` до отдельного решения.

## 8. Действия и запреты (наследуются из `README` и `02`)

- Ни одна сигнатура игры не правится: чтение `SkillsClientState`, `SkillInputService`, `InputBindingsRuntime`,
  `SkillNodeConfig` — только существующие публичные члены.
- `SkillTreeWindow`, `SocialSkillTreeWindow`, `CharacterWindow` не трогаются; их UXML/USS читаются как эталон
  поведения, не как код для правки.
- Одновременно с легаси окно не открывается (`CharacterWindow.IsVisible()`); Esc остаётся за `UIManager`.
- Взаимоисключение графов: в один момент открыт либо граф навыков, либо граф отношений, либо окно корабля —
  тот же `rel-open`-подобный флаг на `#app`.

## 10. Что в 4.3 не переносимо в USS (предупреждение до порта)

Новые блоки приносят свой список «браузерного», его надо снять **до** порта, как сделано в `01` §3:

| Приём в 4.3 | Где | Замена в USS |
|---|---|---|
| `clip-path` облачного края узла и стикера | переиспользуется из `rel-graph` | нет `clip-path`: рваный край — только `Texture2D`-маска/SVG-подобный `VectorImage` |
| `radial-gradient` / `linear-gradient` в узлах и заметках | `rel-graph` стили | нет градиентов: плашка + отдельный слой полупрозрачности через `ProjectCMainMenuGamma.Alpha` |
| `@keyframes ntpulse` (пульс свёрнутой заметки) | `rel-graph` | заметки не переносятся; любой пульс → `opacity` по кадрам из C# |
| `box-shadow` карточек-подсказок | `.tip-card` | inset-рамка через `border` + второй `VisualElement` |
| `transform: translate/scale` одним трансформом | `.rp-view` | лонгхенды `translate`/`scale` на `VisualElement.style` |
| `font-size` в долях от контейнера, `calc/clamp` | `fitCredits`, подгонка подписей | px на опоре 1920 × 1080 |
