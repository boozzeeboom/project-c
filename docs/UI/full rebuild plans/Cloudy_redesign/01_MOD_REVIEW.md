## 1. Что было до прохода полировки

### 1.1 «Cloudy style» почти отсутствовал

Облачность жила **только в фоне** (`sky.js`: дрейф вуалей, газ, тросы, `setWindScale`). У окон и панелей дыма не было:

| Где | Было | Почему не «cloudy» |
|---|---|---|
| Открытие попапов (`style.css` `rise`, `grow`, `rel.css` `rwfly`) | `translateY` + opacity за 0.12–0.22 с | обычное desktop-появление карточки |
| Подсветки (`calendar.js` `calpulse/calhl`, `rel.css` `rwpulse/rwtier`, `style.css` `won`) | пульсы `box-shadow` | кольца-рамки, не дым; в USS `box-shadow` не существует |
| Смена вкладок | мгновенный своп | нет растворения подписей, которое есть в главном меню |
| Поле дыма, gather/disperse, общий порыв | **нет** (в меню — `smoke.js`, `wind.js`) | — |

Совпадения по `smoke|puff|dissol|gust|wind`: в `v4-2` только декоративный `puff` вагонетки (`lines.js`, `style.css`) и
плоские пуфы за фигурой (`character.js`). В `projectc-main-menu` те же ключи встречаются 78 раз в `smoke.js` и 176 в `ui.js`.

### 1.2 Смешанная модель времени

Большинство модулей уже жили по кадровому времени (`update(dt)` из `main.js`), но таймеры `setTimeout` оставались в
`calendar.js` (раскрытие/свёртка 60/250 мс), `rel-widget.js` (180/250 мс), `rel-graph.js` (сброс transition 260 мс),
`ui.js` (задержка подсказки). В Unity это два разных механизма (`schedule.Execute` против `Update`) и источник гонок.

### 1.3 Расхождения правил с игрой (найдены сверкой с кодом, см. `03_DATA_CONTRACT.md`)

| В моде | В игре | Источник |
|---|---|---|
| Перенос в трюм любого количества, остаток «по курсу» | сервер **отклоняет** количество, не кратное `ExchangeRateEntry.inventoryQty` («Количество должно быть кратно N») | `ShipCargoServer.RequestStoreToCargoRpc` |
| Перенос доступен из окна всегда | в игре перенос делается в `ShipCargoConsoleWindow` (консоль трюма); серверная проверка — только владение (`KeyRodInstanceWorld.IsOwnerOfShip`), дистанции нет | `ShipCargoServer.cs`, `ShipCargoConsoleWindow.cs` |
| Кнопка «СДАТЬ» квест | у клиента нет обёртки сдачи; сдача идёт через диалог NPC (`QuestServer.RequestTurnInQuestRpc(questId, toNpcId)`) | `QuestClientState.cs`, `QuestServer.cs` |
| Журнал «последние поступления» | такого журнала в игре нет | поиск по `InventoryClientState` |

## 2. Что исправлено в проходе полировки (2026-10-28)

Отчёт агента мода, замеры из его тестов:

- **`src/motion.js`** — один модуль движения по образцу `smoke.js` + `wind.js` меню: пул 48 пуфов (создаётся один раз,
  текстура дыма запекается в canvas), операции **gather → проявление → disperse** и **swap** вкладок; анимируются только
  `opacity`, `translate`, `scale`; один общий порыв читают пуфы, подписи и небо (`sky.js setGust`, снос вуалей ≈10 px).
- Подключено к: ЗАДАНИЯ, окно КОРАБЛЬ и его hover-попап, багаж, календарь, граф, hover-подробности строки, раскрытие
  репутации, карточка шага, вкладки ЗАДАНИЯ|КОНТРАКТЫ и ОБЗОР|МОДУЛИ|ГРУЗ, дымная кромка дока при изменении высоты ≥24 px.
- Длительности: gather 260 мс, проявление 220 мс после задержки 120 мс, disperse 320 мс, вкладка 220 + 240 мс, кромка дока
  300 мс; reduced-motion — fade 150 мс без пуфов. Easing — только `ease/ease-in/ease-out/ease-in-out`.
- Пуфов на переход: полноэкранные окна 12, попапы 5–6, вкладки 4–5, док 4; одновременно в обычной работе до 24,
  на стресс-тесте упор в пул 48 без создания новых элементов.
- `setTimeout` снят из `calendar.js`, `rel-widget.js`, `rel-graph.js`, `ui.js` (подсказка получила `update(dt)`).
- `filter: saturate` у приглушённых строк ленты заменён на `opacity`; `cubic-bezier` нигде не осталось; keyframes
  `rise/grow/rwfly` удалены.
- Исправлена ошибка: карточка шага ленты заново анимировалась при каждой пересборке строки.
- Правила игры перенесены в модель мода: кратность курса в обе стороны, флаг «в зоне обменника» (рынок или консоль трюма; по умолчанию
  выключен — кнопки переноса неактивны с причиной «подойди к обменнику»; уточнено решением пользователя), «СДАТЬ» → информационная бирка «сдать у {NPC}», журнал поступлений помечен
  как вычисленный, добавлен источник «неизвестен».
- Производительность: fps 59.9–60, frameMsP95 16.8–16.9 мс; `motion.js` в покое 0.1 мс, на переходах 0.2–0.6 мс;
  20 циклов открытия/закрытия всех окон — DOM 1154 → 1154.

**Не проверено в моде:** системный `prefers-reduced-motion` (проверен принудительный режим), анимация в движении
(смотрелся замороженный кадр середины открытия).
