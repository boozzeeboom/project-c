# T-FO09K — Rollback возвращает книги: фантом кумулятива сейва

Date: 2026-09-14. Жалоба (ф8_34): циклы «вышел в городе → заход в городе»
иногда дают спавн в пустоте; в пойманном случае global 80035 против города
40000 (40км).

## Диагноз

1. Сейв атомарен (синхронный `SaveCurrentState`), Bootstrap чист
   (только wind-твик), стриминга нет, fallback 09G-фикс уже в билде
   (1 маркер). Дело не в них.
2. Корень: `Rollback` (`restored==true`) возвращал контент через
   `TryAbort`, но `_frame`/`CumulativeRebaseOffset` оставались
   «сдвинутыми». Каждый F9 растил кумулятив сейва фантомом при net-zero
   мире. Свежий старт вычитает фантом из координат → спавн смещён на
   накопленный фантом (здесь ~40км) → пустота. Интермитентность: баг
   проявляется, только если в сессии жали F9.
3. Дизайн `PERSIST01_REBASE_AWARE_RESTORE.md:42-43` требовал
   «rollback при restored −= T» — реализация отсутствовала
   (в плане осталась рационализация «никогда не вычитает»).

## Решение (slice, ветка `restored`)

- `_frame = request.Plan.Before` (контент тоже вернулся — книги обязаны
  совпасть);
- `CumulativeRebaseOffset -= request.Plan.LocalTranslation`;
- `_frameGeneration` НЕ трогаем (монотонность, lineage 07B);
- broadcast 08D без изменений.
Только при `restored`; `RollbackFaulted` книги не трогает.

## Проверка

1. Compile: `refresh_unity` (force + compile) — PASS; `read_console` —
   0 errors, 0 CS; скобки 168/168.
2. Play Mode (user): F8 → F9 → F8 → ... → выход → заход → спавн в городе
   (фантом не копится). В логе после каждого F9 книги возвращены
   (следующий F8 у origin честно `no_rebase_plan`). Лог — мне.
