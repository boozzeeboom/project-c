# T-UI10 — План ввода контекстных подсказок взаимодействия

**Дата:** 25 августа 2026 года  
**База:** рабочая ветка после отката, описанного в `docs/world/Localization/06_POSTMORTEM_T-UI09_Localization_Blast_Radius.md`  
**Цель:** вернуть минорную UI-фичу без повторного повреждения локализационных ассетов.
**Статус:** выполнено; Play Mode и screenshots подтверждены пользователем.

## Правила выполнения

1. Каждый шаг — маленький независимый diff.
2. Сначала проверяется состояние проекта и локализации, затем изменяется только нужный scope.
3. Полный `LocalizationTableRepair` запрещён для этой задачи.
4. Никаких ручных правок YAML локализационных `.asset`.
5. После C#-изменений обязательна проверка компиляции.
6. Play Mode и screenshots выполняет пользователь; без них этап не считается завершённым.
7. При отказе любого localization-checkpoint работа останавливается и откатываются только изменения T-UI10.

## Phase 2 — Runtime-resolver без изменения input-flow

- [ ] 2.1 В `NetworkPlayer` определить компактное состояние подсказки: `None`, `Talk`, `Use` либо эквивалентный enum/struct.
- [ ] 2.2 Резолвить состояние на owner-клиенте по тем же объектам и условиям, которыми пользуются реальные обработчики:
  - `TryInteractNearestNpc` для NPC;
  - `FindNearestShip` для посадки;
  - `InteractableManager.FindNearestPickup`/`FindNearestNpcLoot` для pickup;
  - `FindNearestResourceNode` для сбора;
  - `FindNearestCraftingStation` для крафта;
  - `FindNearestShipCargoConsole` для cargo console;
  - текущий door-flow для двери.
- [ ] 2.3 Не считать target валидным только по collider или наличию компонента. Учитывать активность объекта, `_inShip`, spawn/state guards и фактический радиус текущего обработчика.
- [ ] 2.4 Не добавлять новый `InputAction`, RPC, сетевое поле или изменение `IInteractable`.
- [ ] 2.5 Вызывать обновление UI только при изменении состояния/target-kind. Не выполнять `Loc.Get` и не менять TMP-текст на каждом кадре.
- [ ] 2.6 При одновременных кандидатах сохранить порядок текущего Update-flow: действительный F-candidate имеет приоритет над NPC E; внутри F сохраняется существующий порядок `PickupItem` → gathering → crafting → cargo console → door → ship.
- [ ] 2.7 Не показывать `Press F to use` для существующих E-only non-NPC flow, пока они не получили отдельный input-контракт.

**Gate 2:** по нажатию клавиши фактическое действие должно остаться тем же, что и до T-UI10. Hint является наблюдением, а не источником выбора target.

## Rollback criteria

Немедленно остановить этап и откатить только T-UI10, если произошло хотя бы одно из условий:

- SharedData изменился больше чем на две новые записи;
- изменился ID существующего ключа;
- изменились Static/System/Dialogue таблицы;
- `UI_Table` потеряла старые строки;
- EN/RU lookup возвращает ключ вместо fallback/перевода;
- hint показывает F для NPC или E-only non-NPC объекта;
- runtime action после нажатия клавиши отличается от baseline;
- появились compile errors.

**Никогда не исправлять эти симптомы запуском полного `LocalizationTableRepair`.** Для проблем самой локализации нужен отдельный, изолированный тикет с backup, проверкой полноты источников и явным rollback-планом.
