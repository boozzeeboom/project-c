# 02. Блоки и геометрия (фаза 2)

Дата: 2026-10-17. Цель фазы: превратить **147 715 объектов / 4.49 млн треугольников** в **20–60 блоков**
так, чтобы город можно было и редактировать, и рисовать, и объединять без потери кварталов.

---

## 1. Что такое блок

**Блок** — пространственная группа города (квартал или участок улицы) размером ~**100–300 м**, которая
является единицей:

* объединения мешей (draw calls),
* коллайдера,
* LOD-переключения (L1 HLOD),
* и рабочей единицей редактирования (Prefab Stage).

Блок **не** равен чанку поставки: чанк — это партия домов (18–45 домов), блок — квартал внутри неё.
Блоки нарезаются по геометрии: улица/аллея, площадь, кольцо, торговая аркада, гильдейская аллея, фермы-админ.

## 3. Правила нарезки и объединения (Blender)

1. **Join по «блок × материал».** Внутри блока объекты одного материала склеиваются в один меш.
   Материалов в чанке 16–38 — это и задаёт число подмешей на блок.
2. **Флэтнить иерархию.** Пустые родители, промежуточные группы, `E_*`-маркеры внутрь меша не идут:
   маркеры вынести в блок как пустышки (для Unity-иерархии), остальное — плоско.
3. **Глобальные координаты не трогаем** (правило проекта): геометрия остаётся в мировых координатах,
   корень блока в файле — в (0,0,0). В Unity блоки ставятся в (0,0,0) под `WorldRoot_0_0/PRIMUM`.
4. **Имена:** корень блока `PRIMUM_BLK_<zone>_<NN>`, меши `PRIMUM_BLK_<zone>_<NN>_M<материал>`.
   Для будущих ферм — тот же шаблон с префиксом `FARMS_BLK_…`.
5. **Не склеивать через улицу**: блоки обязаны иметь обособленные границы, иначе рушится отсечение (culling).
6. **Сохранять UV/нормали** (материалы в проекте без текстур, но UV нужны под будущие атласы).
7. **Что не склеивать:** стеклянные/эмиссивные элементы, окна-витражи, воду, всё, что должно иметь свой
   материал/шейдер (иначе потеряется вид).

## 4. Интерьеры

Мебель и внутренняя отделка — основная масса **объектов** (пример: RES-ALLEY 9 698 мешей на 18 домов),
но меньшая доля треугольников. Два пути:

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Включить интерьеры в меш блока | один код-путь, ничего не грузится в рантайме, draw calls не растут | интерьеры рисуются всегда (overdraw внутри стен), нельзя выгрузить |
| B. Интерьеры отдельными наборами по требованию | экономия треугольников/памяти вдали, гибкость для геймплея | нужен спавнер/триггер, второй набор префабов |

**Рекомендация:** начать с **A** (быстро, безопасно, проверяемо), а на фазе 5 перейти к **B** для
кварталов с геймплеем (или если профилировщик покажет overdraw). Паттерн спавна уже есть в проекте —
`docs/world/PLACEMENT_SCRIPTS/…` (скрипты создания контента по ID).

## 5. Перевыгрузка FBX из Blender

Настройки — те же, что отработаны (см. `farm_catalog/PRIMUM/115_CITY_FBX_EXPORT.md`):
глобальные координаты, `Apply Transform = OFF`, Y-up, масштаб 1.0, без анимации, MESH+EMPTY,
только свои объекты (линки BASE в экспорт не попадают).

**Проверка после каждой перевыгрузки** (обязательна):

1. в Blender: габарит и число мешей/треугольников блока снимаются и записываются в таблицу;
2. в Unity: после импорта — те же числа из модели (меши, треугольники, габарит), расхождение ≤ 0.02 м;
3. сверка «до/после» с таблицей §2: объекты упали, треугольники остались те же (±1 %).

## 6. Критерии приёмки фазы 2

- [ ] город нарезан на 20–60 блоков; у каждого корень и имя по конвенции
- [ ] ни один меш блока не превышает 65 535 вершин
- [ ] суммарные треугольники города = 4.49 млн ± 1 % (ничего не потеряно)
- [ ] объекты в файлах: ≤ 1 500 на весь город (было 148 178)
- [ ] все 18 исходных чанков остаются в проекте как «источник» (не удаляем) — блоки собираются из них
- [ ] таблица «блок → меши → треугольники → габарит → материалы» заполнена и лежит рядом с этим документом
