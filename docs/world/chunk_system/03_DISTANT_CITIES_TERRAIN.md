# 03. Видимые города вдали и террейн/горы без чанк-лоадера

Дата: 2026-09-27. Тезис: **сейчас хорошо, потому что дальнее не выключается; задача —
сохранить это свойство при росте мира и добавить города-силуэты тем же приёмом.**

## 1. Почему сейчас хорошо (разбор кадра)

1. `Terrain_0_0` — один объект 80×80 км (`docs/world/terrain/README.md:7-16`): на любой дистанции
   это 1 draw call; `heightmapPixelError = 200` + `basemapDistance = 20000` дают «грубая геометрия +
   запечённый цвет» вместо попиксельных деталей — ровно режим «фон».
2. Пресет Medium = текущий вид (`ViewDistanceConfig.cs:46-56`): far 60 000 покрывает сцену с запасом,
   `fogScale = 1.0` — туман DayNight топит даль раньше far (exp 0.0003 топит всё дальше ~10 км —
   `LOD_VIEW_DISTANCE_DESIGN.md:57`), силуэты читаются, срез far спрятан.
3. Камеры far 1M → 60K (T-LOD01) резко улучшили depth precision (шаг 10 м на 4 км при far 1M —
   `DESIGN_farfocus.md:20-23`); меньше z-fighting на склонах.
4. `DistantFocus` (800–4000 м, `AfterRenderingOpaques`) работает в среднем плане и не спорит
   с фоном: блюрит L0/L1, горы-фон за 12 км — вне его диапазона (`DESIGN_farfocus.md:36-56`).

Вывод: «хорошую картинку» даёт связка **монолитный террейн + туман + умеренный far**, а не детализация
каждого склона. Любой чанк-лоадер, режущий террейн на куски или выключающий даль, эту связку ломает.

## 2. Четыре кольца — канон (из LOD_VIEW_DISTANCE_DESIGN, с привязкой к городам)

| Кольцо | Дистанция | Террейн/горы | Города/поселения | Техника |
|---|---|---|---|---|
| **L0 Ближнее** 0–3 км | Детали склона, снег 2200–3000 м абс. (`terrain/README:16`) | Полные здания, огни, NPC | Полная геометрия, тени ближние |
| **L1 Среднее** 3–12 км | Силуэты хребтов, снег пятнами | Крупные постройки, башни | Упрощённые меши, мелкие пропсы скрыты (`DetailDistanceCuller`) |
| **L2 Дальнее-фон** 12 км — край сцены | **Basemap-фон**: грубая геометрия + запечённый цвет + туман; выключать запрещено | **Силуэт-фон**: 1–2 draw calls на город (см. §3) | pixelError большой, 1 draw call террейна; импосторы городов |
| **L3 Ультра** соседние сцены | Пока OFF (сцен 2+ нет) | OFF + хук | `ViewDistance.Ultra` disabled, ранний return (`LOD_VIEW_DISTANCE_DESIGN.md:77`) |

Точные метры колец — калибруются с высоты 600–5000 (`LOD_VIEW_DISTANCE_DESIGN.md:22`).
Правило: L2 **никогда не off** — только дешевле.

## 3. Города-силуэты: конкретная конструкция (чего нет сейчас)

Проблема: горы имеют LOD-план (LOD0 1500–2048 tri → LOD1 512–768 → LOD2 билборд 2 tri —
`Landscape_TechnicalDesign.md:369-407`), а города — нет. На 12–80 км полный город рисовать
нельзя (сотни draw calls), выключать нельзя (убьём навигацию по ориентирам —
пиллар `WorldLandscape_Design.md` §8, цит. в `LOD_VIEW_DISTANCE_DESIGN.md:24-28`).

Решение — **городской импостор** (evolution LOD2 гор, не чанки):

- **L0 (0–3 км):** полные префабы города под своим корнем сцены (см. `05_*` про корни/каталог).
- **L1 (3–12 км):** HLOD-коробки кварталов: 1 меш на квартал (bake в Editor, не в рантайме),
  окна — emissive-текстура, мелкие детали скрыты `DetailDistanceCuller`-логикой.
- **L2 (12–80 км):** 1 квад-билборд на город (camera-facing, pre-rendered силуэт с альфой,
  как уже запроектировано для гор — `Landscape_TechnicalDesign.md:404-407`) + отдельный
  аддитивный квад ночных огней (дешёвый, читается сквозь туман лучше геометрии).
  Переключение — `LODGroup` (два уровня + cull), дистанции согласовать с `ViewDistance`-пресетами.
- **Ночь:** силуэт + огни важнее геометрии; огни — всегда поверх тумана (emissive, без теней).
- **Навигация:** каждый город-фон обязан иметь уникальный силуэт (башня/шпиль/трубы) —
  требование геймдизайна, а не графики.

Что НЕ делать: не генерировать импосторы в рантайме из сида (ошибка legacy
`GenerateCloudsAsync`/`CreateFarmPlaceholder`); bake один раз в Editor (RenderCamera →
RenderTexture → Sprite, как в техдизайне гор), хранить как ассеты рядом со слоями террейна
(пути вне `*Textures*` — иначе не попадут в git, `terrain/README.md:54`).

FO-класс импосторов: 🟢 (как `DistantFocus`, `distantfocus/README.md:66-69`) при условии:
билборд-скрипт хранит только скаляры (дистанция, текущий LOD), позицию пересчитывает каждый кадр
от камеры, мировых `Vector3` между кадрами не кэширует; сам квад — ребёнок корня сцены → едет бесплатно.
Проверка: F8/F9 + смена LOD на сдвинутом мире.

## 4. Террейн-горы на 12–80 км: что крутить (и что не трогать)

Крутить (всё — в `ViewDistanceConfig`, без перекомпиляции — `ViewDistanceConfig.cs:1-6`):

| Ручка | Near (FPS) | Medium (= сейчас) | Far (cinematic) | Комментарий |
|---|---|---|---|---|
| `cameraFar` | 30 000 | 60 000 | 120 000 | Far покрывает 80 км с запасом; 1M не возвращать |
| `terrainPixelError` | 300 (код) / 150 (дизайн) | 200 / 100 | 50 / 40 | Расхождение код/дизайн — калибровать по скриншотам |
| `terrainBasemapDistance` | 12 000 | 20 000 | 80 000 | Всегда ≤ far |
| `fogScale` | 1.3 (прячет срез) | 1.0 | 0.6 (панорама) | Владение плотностью — у фаз DayNight, пресет — множитель |
| `shadowDistance` | 500 | 1500 | 4000 | Главный FPS-рычаг, не картинка дали |
| `detailCullDistance` | 4 000 | 8 000 | 12 000 | Руины/детали только визуально (`Renderer.enabled`), без выгрузки |

Не трогать:

- Не делить `Terrain_0_0` на тайлы, не писать quadtree-LOD (`LOD_VIEW_DISTANCE_DESIGN.md:83-84`).
- Не выключать террейн на любом пресете (запрет L2-off, `LOD_VIEW_DISTANCE_DESIGN.md:19`).
- Не поднимать `near` без согласования с `SpringArmCamera.zoomMin` (риск клиппинга персонажа —
  `LOD_VIEW_DISTANCE_DESIGN.md:98`).
- Не менять пороги `DistantFocus` (800/4000) при смене пресета — только визуальная проверка.

Связь с туманом (критично): без `fogScale` связка far/basemap не видна — exp-туман топит даль раньше.
Калибровка — тремя скриншотами с одной точки (3 пресета) + профайлер (чек-лист в `06_*`).

## 5. Анти-паттерны дали (из крови ITERATIONS и terrain-запретов)

- ❌ Потолки `min(h, ceiling)` для «ровной дали» — дают меза-плато (`terrain/README.md:50`).
- ❌ Пики по origin инстансов — только по истинным вершинам max-vertex (`terrain/README.md:51`).
- ❌ Цепи ближе 3 км к поселениям (`terrain/README.md:52`).
- ❌ Точечные правки высот полной регенерацией — только `GetHeights/SetHeights` по bbox
  (`terrain/README.md:45,49`).
- ❌ Чанк-выгрузка террейна/фона ради «оптимизации» — убивает якорь и навигацию.
- ⚠️ `TerrainData.GetHeight` возвращает единицы `size.y`, не 0..1 (`terrain/README.md:53`) —
  любой будущий LOD-код, сэмплящий высоты, обязан это учитывать.

## 6. Что это даёт без чанк-лоадера (итоговая таблица)

| Требование | Чанк-лоадер 2K | Предлагаемое (без чанков) | Выигрыш |
|---|---|---|---|
| Горы видны на 80 км | Режет на 1600 кусков, pop на границах | Монолит + basemap + туман | 1 draw call, нет pop |
| Города видны вдали | Спавн/деспавн префабов с фризами | Импосторы L1/L2 + огни | 1–2 draw calls/город, нет спавна |
| FPS на слабом ПК | Фризы генерации каждые 0.5 с | Пресет Near: far 30K + тени 500 + fog 1.3 | Гладко, предсказуемо |
| Память | Пики генерации (меши+материалы в рантайме) | Bake в Editor, ~26.5 МБ мир (оценка техдизайна §5.3) | Нет рантайм-аллокаций |
| FO | Не покрыт вообще | Корни сцен + 🟢-класс | F8/F9 бесплатно |

`NOT VERIFIED` (за пользователем): скриншоты 3 пресетов с одной точки (высота ~2000, дистанция
до Main ~30 км), F8/F9 на каждом пресете, профайлер кадра с/без `DistantFocus`.
