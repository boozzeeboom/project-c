# Броня: парные детали, зеркалирование и посадка на кости

> **Дата:** 2026-11-27 · **Тикет:** T-ARM01 (анализ)
> **Статус:** только анализ. Кода, префабов и ассетов не создано.
>
> Связано: `docs/dev/ARMOR_KITS_PICKABLE_ITEMS.md` (инвентаризация 93 моделей),
> `docs/lore_summary_context/02_MODULAR_CLOTHING.md` (концепт),
> `Assets/_Project/Scripts/Equipment/Visual/EquipSlotToBone.cs`,
> `Assets/_Project/Scripts/Equipment/CharacterEquipmentVisualApplier.cs`.

---

## 1. Ответ коротко

**Плечи — да, зеркальные дубли. Перчатки и башмаки — не использовать готовую пару: отделить одну деталь и зеркалить так же, как наплечники.**

Причина не в красоте, а в технике: один предмет надевается в один слот и вешается на **одну** кость.
Пара, лежащая в одном меше, физически не может оказаться на двух руках/ногах — она прицепится целиком
к одной кости, и вторая половина будет висеть в воздухе у первой.

Правило для всех парных слотов (плечи, руки, ступни, бёдра, колени):

> один меш = одна деталь → на персонаже спавнится **дважды**: слева как есть, справа — зеркалом.

Исключения — детали, которые по смыслу охватывают обе стороны тела и зеркалить их нельзя:
мантия (`ACC_MANTLE_11_RANGER`), пояс, нагрудник, шлем, ранец/баллон.

## 2. Что показала проверка геометрии

Проверка только на чтение: bounds, распределение вершин, силуэт по проекциям X-Y и X-Z,
доли вершин слева/справа от центра. Play Mode не запускался, ассеты не менялись.

### 2.1. Все модели нормализованы

У **всех 93** FBX максимальный габарит ровно **0.9980** — без исключений. Это значит:

- Tripo нормализовал каждый меш в единичный куб; реальных метров в файлах нет;
- сравнивать «на глазок» размеры разных деталей нельзя — шлем и баллон в файлах одинаковые;
- **каждому префабу нужен свой `attachScale`**, иначе шлем будет размером с нагрудник.

Внутренние пропорции детали при этом сохранены, так что масштаб подбирается один раз на деталь.

### 2.2. Пары есть не везде

Генератор выдал смесь: в одной линии одна деталь, в соседней — две. Примеры, проверенные по силуэту:

| Модель | Что в меше | Уверенность |
|---|---|---|
| `ACC_PAULDRON_01_STEEL` | **одна** деталь: асимметричный колпак + ремни в одну сторону | высокая |
| `ACC_MANTLE_11_RANGER` | **одна** мантия на оба плеча | высокая |
| `ACC_PAULDRON_09_SUPERHEAVY_v3b` | **две** симметричные половины, шов по центру | высокая |
| `LEGS_THIGH_09_SUPERHEAVY_v3b` | **две** пластины, зазор по центру | высокая |
| `LEGS_THIGH_11_RANGER` | **две** пластины, зазор по центру | высокая |
| `LEGS_KNEE_13_RUNIC` | **две** чашки | средняя |
| `HANDS_BRACER_11_RANGER_v2` | **одна** деталь, диагональная труба | высокая |
| `HANDS_BRACER_13_RUNIC` | **одна** деталь | высокая |
| `HANDS_GAUNTLET_09/10` | **одна** перчатка | высокая |
| `HANDS_BRACER_12_CHROME`, `BRACER_14_KORU` | похоже на **две** штуки рядом: плоские, X = 1.0 при Y = 0.36–0.40 | средняя |
| `FEET_BOOT_01/03/09/12` | похоже на **два** ботинка (два голенища + две подошвы) | средняя |
| `FEET_BOOT_11/13/14`, `BOOT_07` | **один** ботинок | средняя |
| `LEGS_KNEE_05`, `LEGS_KNEE_05_FIELD` | **одна** чашка | высокая |

Вывод: **полагаться на «сгенерировано парой» нельзя**. Даже внутри одной категории правило разное,
поэтому пары надо не «использовать», а приводить к единому виду.

> Точная граница «одна деталь / две» в спорных случаях видна только в рендере. Список выше — по
> геометрии; финальную проверку делает человек в редакторе (агент Play Mode не запускает).

## 3. Почему готовую пару нельзя надеть как есть

1. **Один слот — одна кость.** `CharacterEquipmentVisualApplier` инстансит **один** `visualPrefab`
   под **одну** кость из `EquipSlotToBone`. Все дочерние меши наследуют эту кость.
2. **Пара в меше = двойная геометрия на одной стороне.** Вторая половина не попадёт на вторую руку
   или ногу — она останется висеть рядом с первой.
3. **Выставочная поза.** Зазор и наклон в сгенерированной паре рассчитаны на картинку, а не на
   скелет персонажа: у него другая ширина плеч, длина рук и стоп.
4. **Нельзя настроить offset каждой стороны.** Один `attachPositionOffset` на предмет — общий.
5. **Асимметрия генерации.** Левая и правая детали могут отличаться формой и толщиной; на персонаже
   это читается как брак.

Отсюда правило: **одна деталь — источник истины, вторая сторона всегда получается зеркалом.**

---

## 4. Как отделить одну деталь из меша

Порядок для каждой парной модели:

1. Импортировать FBX, работать с мешем в его локальных координатах (ось X — поперёк тела).
2. Разрезать по плоскости `X = центр bbox`.
3. Посчитать долю треугольников слева и справа:
   - обе доли **≥ 30 %** → в меше пара: оставить одну половину (ту, что больше), вторую удалить;
   - одна доля **< 30 %** → деталь одиночная, резать нечего.
4. Мелкие оболочки (заклёпки, ремни, пряжки) отнести к ближайшей половине по X, чтобы не потерять.
5. Pivot перенести в точку крепления на кости (плечо, кисть, стопа, бедро, колено), а не в центр
   габарита — иначе посадка будет «плавать».
6. Одиночную деталь не резать: она уже готова к зеркалированию.

## 5. Как зеркалить (важно для Unity)

- `localScale.x = -1` у дочернего объекта **переворачивает winding**: отсекаются задние грани,
  ломаются нормали, тени и освещение. Для брони это заметно сразу.
- Правильный путь: **испечь зеркальный меш** — вершины `x → -x`, треугольники в обратном порядке,
  нормали и тангенты пересчитать. Один раз на предмет, кэшировать.
- Обходной путь через negative scale + материал `Cull Off` допустим только как временный: дороже,
  даёт артефакты теней и не годится для финального вида.

## 6. Кости: сейчас одна сторона, нужна пара

Текущий `EquipSlotToBone` даёт **одну** кость на слот, причём левую:

| Слот | Сейчас | Нужно для пары |
|---|---|---|
| `Feet` | `LeftFoot` | `LeftFoot` + `RightFoot` |
| `Hands` | `LeftHand` | `LeftHand` + `RightHand` |
| `Accessory1/2` | `Spine` | `LeftShoulder` + `RightShoulder` (для наплечников) |
| `Legs` (набедренник) | `Hips` | `LeftUpperLeg` + `RightUpperLeg` |
| `Legs` (наколенник) | `Hips` | `LeftLowerLeg` + `RightLowerLeg` |

Пара не требует новых слотов: предмет по-прежнему один, просто его визуал спавнится два раза.
Но требует поддержки **двух точек крепления** в визуальном аппликаторе — это отдельный маленький
тикет (см. §8), без него парные руки/ступни на персонажа не надеть.

---

## 7. Что это меняет в модели предметов

- **Плечи:** один предмет на пару, слот `Accessory1`; `Accessory2` остаётся свободным под пояс/сумку.
- **Руки, ступни, бёдра, колени:** один предмет на пару, визуал спавнится L/R.
- **Количество предметов не меняется** — те же 76 из `ARMOR_KITS_PICKABLE_ITEMS.md` §6.1.
- `attachBoneOverride` для пар не используется: кости задаёт парный режим, а не одно поле.
- Мантия, пояс, нагрудник, шлем, ранец — **без зеркала**, как обычный одиночный визуал.

## 9. Что проверить руками (после сборки)

- [ ] На персонаже обе половины на своих костях, зазор по центру симметричный.
- [ ] Нет двойной геометрии на одной стороне (не осталась вторая половина из меша).
- [ ] Нормали не вывернуты: при взгляде сзади броня не «просвечивает».
- [ ] Масштаб детали соответствует телу (все меши пришли нормализованными).
- [ ] При анимации рук/ног половины не расходятся и не проваливаются в тело.
