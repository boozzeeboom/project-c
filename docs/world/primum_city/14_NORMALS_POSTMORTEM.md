# 14. Постмортем: вывернутые нормали города — причина, фикс, профилактика

Дата: 2026-10-18 (ночь). Связанные документы: `13_RECOVERY_RESEARCH.md` §7–9, `ITERATIONS.md`.

---

## 1. Симптом

В Unity (Scene view и Play) у домов и боксов **видны только внутренние поверхности**: снаружи бокс
«прозрачный», видна его обратная сторона (то, что должно быть скрыто). Пользователь описал как
«вижу 50 % плейнов, обратную сторону» и «оптимизация работает наоборот». В Blender при этом всё
выглядело нормально.

## 2. Корневая ошибка

**Скрипты-строители домов PRIMUM создавали боксы с инвертированным виндингом (нормали внутрь).**
Ошибка возникла в самом начале моделирования и тянулась через всё создание города (подтверждено
пользователем по оверлею Face Orientation в Blender).

Почему не замечали:

| Маскирующий фактор | Суть |
|---|---|
| Blender не кулит обратные грани | в viewport/Eevee/Cycles меш с вывернутыми нормалями рисуется «нормально» (страдает только свет), поэтому на этапе моделирования дефект невидим |
| Приёмка считала ЧИСЛА, а не ориентацию | сверялись меши/грани/треугольники/габариты — все совпадали; ориентация не проверялась ни разу |
| Скриншоты были обзорными | `unity_1_overview.png` — город крошечным пятном на фоне плиты; по такому кадру дырки не увидеть |
| Ассеты-соседи собраны другим инструментарием | фермы 42 %, блок-аут 59 % нормалей наружу — смесь, где дефект размазан и потому не бросался в глаза |
| Ложные следы | сначала винили лимит 16-битных индексов, потом GPU Resident Drawer/шейдеры (откат GPU-путей дефект не лечил — он был настоящей причиной только для *другого* симптома) |

## 3. Диагностика (повторяемая методика)

1. **Тест выпуклого бокса.** Взять меш с 8/24 вершинами, посчитать долю нормалей, смотрящих от центра
   bbox наружу. У исправного бокса — 24/24 наружу.
2. **Знаковый объём — главный критерий:** `V = Σ det(a, b, c) / 6` по треугольникам (веерная
   триангуляция n-гонов). `V > 0` — нормали наружу, `V < 0` — вывернут.
3. ⚠️ **Считать объём ТОЛЬКО по связным островам (компонентам), не по мешу целиком.** Склеенные
   меши содержат десятки независимых островов; их объёмы взаимно гасятся, знак суммы случаен —
   именно на этом сломалась первая правка (часть островов развернулась наизнанку).
4. **В Unity топология утеряна** — FBX-импорт разбивает вершины по граням. Чтобы применить критерий
   3 к тому, что реально рендерится, восстановить топологию **склейкой вершин по позициям**
   (квантование 1 мм), затем union-find и объём по компонентам.

## 4. Фикс (рецепт)

`_work/fix_normals2.py` (Blender, headless):

1. открыть рабочий чанк (`PRIMUM_chunks/<BASE|HOUSES>/<чанк>.blend`);
2. для каждого меша: BFS по рёбрам bmesh → связные острова;
3. объём каждого острова; `V < 0` → `bmesh.ops.reverse_faces` **только по этому острову**;
4. `save_mainfile`, удалить линкованные BASE-объекты, экспорт FBX канонически
   (`FBX_SCALE_NONE, axis_forward='-Z', axis_up='Y', global_scale=1.0`);
5. контрольный проход: островов с `V < 0` остаться не должно.

**Результат:** развёрнуто **542 043 грани** (18 чанков), 1 687 512 оставлено как есть;
18 FBX перевыгружены и переимпортированы (MD5 `_deliver` ↔ `Assets` = 18/18).
Бэкап до правки: `_versions\PRIMUM_chunks_pre_fix_normals_2026-10-18`.

**Верификация в Unity** (склейка по позициям): объёмных мешей чисто **493**, с вывернутым островом
**0**; островов 126 584, вывернутых **0**. Габарит 1717.3 × 103.9 × 1095.7 и 14 339 коллайдеров
не изменились (правка трогает только ориентацию, не геометрию).

## 5. Как не повторять (правила и гейты)

1. **Гейт ориентации в приёмке КАЖДОГО чанка** (обязателен, до статуса «done»):
   знаковый объём по островам → **0 вывернутых**. Скрипт есть (`fix_normals2.py` + контрольный
   проход); прогонять также на FBX-поставке.
2. **В генераторах домов** завести один хелпер создания бокса, который сразу гарантирует `V > 0`
   (или после каждой генерации прогонять `fix_normals2.py` как штатный шаг пайплайна — дешевле,
   чем ловить в Unity).
3. **Editor-автотест в Unity** после импорта партии: тот же критерий со склейкой позиций, порог
   0 вывернутых островов, отчёт в лог. Визуальная проверка — только ПОСЛЕ него.
4. **Скриншоты для приёмки — крупные** (с уровня улицы, 20–50 м), а не только обзорные с километра:
   дефекты ориентации и дыры видны только вблизи.
5. **RAW остаётся вывернутым** (не трогали сознательно): при работе с RAW-исходниками — прогонять
   фикс после склейки, иначе дефект вернётся в новый экспорт.
6. Фермы (42 %) и блок-аут (59 %) — тот же дефект в меньшем масштабе; при желании чинятся тем же
   скриптом (отдельной задачей, чтобы не смешивать с городом).
