Как работает (контракт §2/§7.1):

* цели ищутся по имени в `Assets/_Project/Materials/**`, папки `archive*` исключены; дубль имени цели — ошибка;
* подстановка только через `sharedMaterials`, **в тот же индекс слота**; `Undo.RecordObject` +
  `PrefabUtility.RecordPrefabInstancePropertyModifications`; одна Undo-группа на прогон; на диск
  ничего не сохраняется;
* идемпотентность: слот, уже стоящий на любой цели таблицы (или `PM_LAMP_GLOW_WARM`), — `already`;
* `DONE` / `HOLD` / `GAP` не трогаются (`skip_<kind>`);
* двери пропускаются (`skip_doors`): имена `PM_DOOR_*` **и** все рендереры внутри префабов

### Б. Боковые части домов — не face orientation, а объектное пространство мешей (диагностика, не исправлено)

Замер по `PRIMUM` (19 944 меша) и по `S9_TRD-S2` (6 388):

| Факт | Значение |
|---|---|
| Поворот объекта X = 270° (Blender Z-up, `bakeAxisConversion = false`) | **19 221 / 19 944** |
| `lossyScale` ≈ 100 (`useFileScale`, `fileScale = 0.01`; часть — 107) | **19 141 / 19 944**, единичного масштаба — 0 |
| Габарит детали в object space (`|extents|`, медиана) | 0.00–0.01 ед. (≈ 0–1 м в мире) |
| Центр меша от пивота (`|bounds.center|`, медиана) | 0.2–0.3 ед. (≈ 20–30 м) — пивот не в детали, а у дома/чанка |

Процедурные графы проекта построены под другой контракт (`docs/Materials/*/README.md`): локальная
**Y — верх**, пивот **внутри объекта**, единица object space ≈ размер объекта («единичный габарит
2×2×2» для кромочных масок). На городских мешах это нарушено во всём:

* `Wood` (семь вариантов, большинство боковых деталей квартала): кольца `r = length(p.xz)` считаются
  вокруг локальной Y = **мировой горизонтали** и вокруг пивота в 20–30 м от детали; волокно
  (сжато по Y) ложится не вдоль доски;
* частоты всех семейств заданы в единицах object space → рисунок в мире в ~100× крупнее
  задуманного, на метровой детали стоит кусок одной полосы/пятна;
* кромочные маски по `|x|,|y|,|z|` и «вертикальные» эффекты (потёки грязи, трещины вверх,
  bias налёта) смотрят по локальной Y, то есть вбок.

Поэтому на вертикальных боках домов рисунок выглядит «вывернутым». Это свойство связки
«импорт FBX × объектные шейдеры», а не нормалей: на флет-цветных FBX-плейсхолдерах это было невидимо.
Агент квартал глазами не смотрел — связь симптома с этой причиной **NOT VERIFIED** визуально.
