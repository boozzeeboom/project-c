# 05 — Бюджеты производительности

Целевая платформа пилота — ПК, текущая сцена `WorldScene_0_0` (64.3 МБ YAML, 4 907 prefab-инстансов,
город ≈1.55 км² по HLOD-манифесту). Замеры — на машине пользователя, Play Mode, Profiler.

## Что чем платим

| Механизм | Цена | Когда включаем |
|---|---|---|
| `NavMeshAgent` (движение+avoidance) | ~0.03–0.1 мс/агент в типичном кадре, avoidance дороже | T1, T2, «горячие» T3 |
| `Animator` (humanoid retarget, 50 костей) | самая дорогая часть на NPC | всегда, но `CullCompletely` |
| SkinnedMeshRenderer | 100 уникальных мешей ≈ 100 DC | T1 ограниченно, T3+ атлас/импостер |
| Тик FSM | ничтожен (0.2–0.7 с на NPC, без аллокаций) | всегда |
| `NavMesh.SamplePosition` | микросекунды, но не в цикле каждый кадр | только при выборе цели |
| `FindObjectsByType<NpcController>` на `E` | O(n) по 100–1000, разово | всегда (существующий код) |

## Целевые значения по тирам

| Тир | NPC | Агентов одновременно | Активных аниматоров | Доп. DC | Цель по CPU толпы |
|---|---|---|---|---|---|
| T1 | 100 | 100 | ≤100 (cull по видимости) | ≈100 | ≤ 2.0 мс |
| T2 | 300 | 300 | ≤120 (LOD по дистанции) | ≤120 | ≤ 3.5 мс |
| T3 | 1000 | ≤120 | ≤60 | ≤60 | ≤ 4.5 мс |
| T4 | 10000 | ≤120 | ≤24 | ≤24 + импостеры | ≤ 5.0 мс |

Числа — **цели**, а не измерения. Фактические замеры вписываются сюда по мере этапов (T7).

## Обязательные правила, чтобы не «утонуть»

1. **Никаких аллокаций в тике.** Ни `LINQ`, ни `foreach` по интерфейсам на горячем пути, ни
   `new List<>` в кадре; дома/модели — массивы, индексы.
2. **Тик разнесён по фазе.** `offset = i * 0.137 % period` — 100 NPC не решают в одном кадре.
3. **Аниматор за кадром не считается.** `CullCompletely` + отключение `SkinnedMeshRenderer` за
   `visualRadius`.
4. **`NavMeshAgent.updateRotation`** оставляем только у ближних на T3+; у дальних вращение по `velocity`.
5. **Спавн батчами**: ≤10 объектов/кадр (T1), ≤20 (T2), ≤40 (T3/T4) — иначе фриз на старте.
6. **Никаких `NavMeshObstacle` на NPC** до T4-обсуждения: carve-пересчёт дороже, чем польза.
7. **Никаких `Rigidbody`**: физика не должна участвовать в движении толпы.

## Как мерить

- Profiler → CPU: маркер `PrimumCrowd` (спавн/тик/FO) + `BehaviourUpdate`/`Animators.Update` до/после.
- `Stats`: Batches/Tris до и после включения толпы.
- Консоль: `[PrimumCrowd] spawned=100 agents=100 animators=… houses=… maxPerHouse=4`.
- FO-проверка: подвинуть `WorldRoot_0_0` в Play на ±50 м и убедиться, что NPC не «отстали».
