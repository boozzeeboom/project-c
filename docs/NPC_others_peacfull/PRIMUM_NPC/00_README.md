# PRIMUM NPC CROWD — пилотный стресстест (100 / 300 / 1000 / 10000)

Статус: **в работе**. Текущий инкремент — **T1 = 100 NPC**.
Сцена: `Assets/_Project/Scenes/World/WorldScene_0_0.unity` (единственная рабочая, дублей не создаём).
Play Mode запускает **пользователь**; агент play-режим не стартует.

## Цель пилота

Проверить, что на подготовленном навмеше PRIMUM можно держать город, населённый NPC, которые:

1. ходят по улицам и внутрь домов, понимают стены (навмеш + `NavMeshAgent`);
2. **не более 4 NPC «заякорены» на один дом**;
3. каждый имеет **своё имя и свой диалог**;
4. позже — открывают двери (отдельный этап);
5. живут «отдельной коллекцией» в сцене и **корректно переживают Floating Origin**;
6. масштабируются батчами: 100 → 300 → 1000 → 10000.

Каноничность (лор, квесты, серверная авторитетность, нетворк-репликация каждого NPC) в пилоте **не** делается.

## Границы (что НЕ делаем в пилоте)

- Не трогаем `ProjectC.Ship.DoorController`, `PM_DOOR_*` и навмеш-печь (двери — этап T6).
- Не включаем `GlobalMotionControlledRebaseSlice`/`GlobalMotionPoseAdapter` на NPC: этот слой отвергает
  объекты с `NavMeshAgent` (см. `01_AUDIT.md §6`), а в сцене он не установлен.
- Не реплицируем NPC по сети (каждый NPC — локальный, без `NetworkObject`). Для 100+ объектов
  `NetworkTransform` неприемлем по стоимости; серверный роуминг — отдельный трек (`crowd_brains/`).
- Не восстанавливаем `PRIMUM_HLOD` / `VisibilityDirector` в сцене — коллекция NPC по имени попадает
  в `GroupClass.Misc` (observed-группа), директирования рендереров не получает.
- Не перепекаем навмеш и не правим YAML сцены rebase-ом.
