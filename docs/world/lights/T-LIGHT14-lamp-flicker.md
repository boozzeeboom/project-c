# T-LIGHT14 — случайное мерцание ламп по группе

**Статус:** реализовано; Play Mode-приёмка за пользователем
**Дата:** 2026-10-23
**Файл:** `Assets/_Project/Scripts/Core/Lighting/AdditionalLightIntensityController.cs`
**Связанные:** `T-LIGHT13` (переопределения группы), `PrimumLightPool` (Э3, бюджет источников)

## 1. Задача

Мерцание «как старые лампочки», но **не синхронное по группе**: каждая лампа мерцает сама по себе, со своей частотой. Управляющие параметры — границы случайной частоты (Гц) и булев выключатель.

## 2. Анализ выполнимости

**Выполнимо в текущей архитектуре без новых компонентов и без правок сцен.**

| Вопрос | Ответ |
|---|---|
| Чем мерцать? | Множителем к `Light.intensity`, который уже принадлежит этому контроллеру. `Light.enabled` принадлежит `PrimumLightPool`, `Light.color`/`range` — переопределениям `T-LIGHT13`. Конфликта владения нет. |
| Как не получить синхронную пульсацию? | У каждого источника собственное состояние (`LightState`) и собственный ГПСЧ, засеянный хешем имени + ID сущности. Общего источника случайности нет, поэтому события не совпадают. |
| Куда применять множитель? | **Поверх** сглаженной интенсивности, после `Mathf.Lerp`. Если умножать до сглаживания, `transitionSpeed = 4` съедает провал длиной 40–120 мс: лампа визуально «не мерцает». |
| Что если время суток заморожено? | `Update()` раньше выходил из `ApplyIntensity`, когда `timeOfDay` не менялся. Добавлено условие `_anyFlickerEnabled`: при включённом мерцании пересчёт идёт каждый кадр. |
| Как вести себя с выключенными пулом лампами? | При `light.enabled == false` планирование событий сбрасывается, множитель = 1. Иначе накопившийся «провал из прошлого» сработал бы в момент включения источника. |
| Стоимость | На источник в кадре: 1 сравнение флагов, 2–4 сравнения времени, на событие — 3 вызова ГПСЧ (~10 инструкций). Для ~2 000 источников это доли микросекунды; рескан и `FindGroup` уже выполняются в том же цикле. |
| Нужны ли правки сцен/префабов? | Нет. Мерцание — поля группы в инспекторе; `flickerEnabled` по умолчанию `false`, поведение существующих групп не изменилось. |

## 3. Модель мерцания

Провал — короткий треугольный импульс яркости, а не синусоида: синус читается как «дыхание», импульс — как контакт/износ.

1. Пока событий нет: `nextTime = now + 1/Hz`, где `Hz = Random[hzMin…hzMax]` — **своё** значение на каждое событие и на каждый источник.
2. Событие: `duration = Random[durationMin…durationMax]`, `depth = Random[depthMin…depthMax]`.
3. Внутри провала: `u = (now − start) / duration`, `shape = 1 − |2u − 1|`, `factor = 1 − depth · shape`.
4. Следующее событие: `nextTime = end + 1/Hz'` — пауза тоже случайная, поэтому ровного ритма нет.
5. Итог: `light.intensity = smoothedIntensity × factor`.

Диапазон частоты трактуется как **события в секунду**. `0.5…3 Гц` — заметное неисправное мерцание; `0.05…0.3 Гц` — редкие «моргания» умирающей лампы.

## 4. Параметры группы

| Поле | Смысл | По умолчанию |
|---|---|---|
| `flickerEnabled` | Мерцание включено для этой группы | `false` |
| `flickerHzMin` | Нижняя граница частоты событий, Гц | `0.5` |
| `flickerHzMax` | Верхняя граница частоты событий, Гц | `3` |
| `flickerDepthMin` | Минимальная глубина провала (доля яркости) | `0.15` |
| `flickerDepthMax` | Максимальная глубина провала (`1` = гаснет полностью) | `0.6` |
| `flickerDurationMin` | Минимальная длительность провала, с | `0.04` |
| `flickerDurationMax` | Максимальная длительность провала, с | `0.12` |

Взаимодействие с остальными ручками:

- `intensityMultiplier` и `intensityByHour` задают базу; мерцание — множитель `0…1` к ней. Днём (`кривая = 0`) мерцание невидимо, потому что база нулевая.
- Переопределения `T-LIGHT13` (`range`, `color`, …) мерцанием не затрагиваются: цвет и радиус стабильны, меняется только яркость.

## 5. Санитайз

Поля добавлены после первой сериализации сцен, поэтому `SanitizeFlicker()` в `Awake` восстанавливает осмысленные значения, если в сцене лежат нули или границы перевёрнуты: `hzMin > 0`, `hzMax ≥ hzMin`, длительности `> 0`, при нулевой глубине обе границы ставятся `0.15/0.6`.

## 6. Ограничения

| Ограничение | Причина |
|---|---|
| Мерцают только включённые источники | Дальние лампы выключены пулом по бюджету 96; невидимый свет не тратит кадр на планирование событий. |
| Мерцание не меняет цвет и радиус | Это множитель интенсивности; для «цветового» мерцания нужен отдельный слой. |
| Мерцание не влияет на тени | `Light.shadows` стабилен; при `shadows = None` (текущие `PM_LIGHT_*`) эффекта теней нет в принципе. |
| `Time.time` (scaled) | При `Time.timeScale = 0` мерцание замирает вместе с игрой. |
| Время жизни состояния | `LightState` живёт в словаре по `Light`; при выгрузке сцены ключ становится `null`-объектом и просто пропускается в цикле, при повторной загрузке состояние снимается заново. |

## 7. Проверки

- `refresh_unity` (`scope: scripts`, `compile: request`) — компиляция запрошена.
- `check_compile_errors` — `No compile errors`.
- Сцены не изменялись; `flickerEnabled` = `false` у всех существующих групп.
- Play Mode, визуальная оценка частоты/глубины мерцания — **NOT RUN**, выполняется пользователем.

## 8. Приёмка (Play Mode)

1. `BootstrapScene` → `AdditionalLightIntensityController` → `PRIMUM_INLIGHT` → включить `Flicker Enabled`.
2. Ожидаемо: в интерьере разные лампы моргают вразнобой, одновременной вспышки всей группы нет.
3. Проверить диапазон частот: `0.5…3` → частое мерцание; `0.05…0.2` → редкие моргания.
4. Проверить выключение: `Flicker Enabled = false` → яркость становится ровной, без «хвоста» провала.
5. Проверить, что при выключении мерцания в инспекторе в Play Mode эффект снимается не позже `rescanInterval` (2 с).

## 9. Откат

Снять `Flicker Enabled` у групп — код остаётся, поведение возвращается к `T-LIGHT13`. Полный откат — вернуть файл контроллера к версии коммита `T-LIGHT13`.
