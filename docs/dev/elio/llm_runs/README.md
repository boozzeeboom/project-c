# LLM-прогоны — архив экспериментов

> Здесь лежат **сырые логи, промпты, конфиги и анализы** LLM-игр. Формат — по одной папке на эксперимент, чтобы потом строить графики прогресса.

> ⚠️ **2026-11-08:** P0-баги движка v1.3 (уход за доску, порча при оттеснении, оттеснение нулями) **исправлены в v1.3d**. Игры, собранные до фиксов, помечены `contaminated`; v2.1 — первый чистый прогон. Подробности: `../AUDIT_V13D.md`. Для графиков используйте поле `clean` в `summary.json` / `progression.json`.

## Структура

```
llm_runs/
  README.md
  _tools/              — скрипты аудита (unit-баги, replay-аудит, частота багов)
  YYYY-MM-DD_<эксперимент>/
    README.md          — что проверяли, гипотеза, итог
    PROMPT_DESIGN.md   — разбор промпта до игры
    prompt.txt         — фактический ZERO_DOCTRINE / system prompt
    config.json        — модель, режим, лимит, число игр
    matches/           — сырые JSON логов (по одной игре)
    audit.json         — машинный аудит логов (replay/целостность/осцилляции)
    analysis.md        — анализ после игр
    summary.json       — машинно-читаемая сводка (для графиков)
```

## Как строить прогресс

- `progression.json` — сводный машинно-читаемый файл по всем Zero-прогонам.
- `summary.json` каждого прогона содержит: win/draw/loss, moves, center ticks, supports, line deaths, fallbacks, ошибки, `clean`-флаги.
- Для графиков: собирать `summary.json` из всех папок, ось X — дата/номер прогона, оси Y — winrate (только clean), средняя длина, center ticks, доля убийств Линейного.
- **Contaminated-игры не смешивать с чистыми**: на графике — отдельная серия/пометка.
- Не смешивать разные режимы/лимиты в одном графике без пометки.
