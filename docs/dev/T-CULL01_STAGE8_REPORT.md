### 1.2. Почему не вариант B (opt-out дверей из GRD)

Проверено рефлексией по живому API (`UnityEngine.Renderer`, 6000.5.2f1): per-renderer opt-out из GRD
отсутствует — доступны только `forceRenderingOff`, `allowOcclusionWhenDynamic`, `renderingLayerMask`.
Двери выпадают из GRD лишь при отключении GRD целиком (Stage 4 принят пользователем, откат вне scope)
либо при замене материала/шейдера на не-DOTS — правка материалов дверей запрещена брифом.
Поэтому вариант B как контрольная ветка не реализуем без выхода из scope; контрольной веткой стал
**тот же рендерер с `DoorCullEnabled = false`** — batching, инстансинг и материалы идентичны, разница
только в политике. Это чище, чем opt-out: A/B изолирует ровно одно изменение.
