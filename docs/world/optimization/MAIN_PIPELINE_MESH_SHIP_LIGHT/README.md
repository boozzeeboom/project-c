### 1.2. Формула DC — главное, что определяет все правила

Проверена на 7 независимых замерах (`_evidence/05_MATERIALS_DC.md` §1.1), ошибка ≤1 DC:

```
DC(L0) ≈ 2 × P + C + O
P = число уникальных троек (mesh, material, renderer-settings) в кадре
C = число shadow-кастеров в кадре        (1 DC на кастер)
O = 106…155 DC постоянной добавки        (небо, UI, TMP, террейн, руины)
```

**Следствия (запомнить):**
- **Одна уникальная пара = 2 DC.** Уникальный материал на каждый дом/проп = `+2 DC` за объект.
- **Один сабмеш = ещё одна пара = +2 DC.** Дом 12 материалами = 24 DC; тот же дом 1 мешем/1 материалом = 2 DC.
- Число **рендереров почти не влияет** на DC (GRD инстансит одинаковые пары); влияет число **пар**. Город: 1 207 MR
  → 1 806 слотов → 1 806 пар → весь город в кадре дал бы ≈3 612 DC, поэтому и существует HLOD (23 пары → 46 DC).
- Кастеры: каждая тень = 1 DC. Кастомные бюджеты теней (`CityShadowBudget`, `ShadowBudget`, `ShipShadowBudget`,
  `DoorVisibilityBudget`) — единственный способ их ограничить.
- **Пропы = 95 % слотов, но 25 % треугольников.** Мелочь <0.25 м = 16.4 % тр. города, скрытые интерьеры = 78.6 % —
  всё это платится слотами. Поэтому «оптимизировать треугольники» ≠ «оптимизировать кадр».

## 2. Двенадцать золотых правил (нарушение = регресс)

1. **Всё новое — под активный корень своей `WorldScene_*`.** Дети корней едут с Floating Origin бесплатно;
   объекты вне корней/неактивные корни — ломают F8/F9 (`_evidence/03_CITY_HLOD.md` §1.3).
2. **`NetworkObject` в сцене → обязательна регистрация** через `ProjectC → World → Floating Origin → Bake Pilot
   Catalog (Preview + Apply)` (маркер + observation + entry + `layoutHash`/`dependencyHash` + digest + непустой
   `reviewNote`). Без неё Host падает: `uncontrolled_network_source_before_native_sweep`.
3. **Никаких static-флагов, Batching, ContributeGI, Occluder** — мир двигается под FO, baked world-space ломается.
   Static-флаг есть только у `Terrain_0_0`.
4. **Не писать чужие свойства** (§1.3): `forceRenderingOff`, `shadowCastingMode`, `enabled`, `intensity`.
5. **Мержить только статику и только edit-time**, результат — коммитируемые `.asset` в git. Runtime `CombineMeshes`
   запрещён (хитч + недетерминизм). Мерж через scene-overrides — запрещён (хрупко: reimport/Apply сносит).
6. **Ключ мержа** = `(ячейка/юнит, материал, renderer-settings)`. Настройки рендерера (`layer, shadows, receive,
   lightProbes, reflectionProbes, motionVectors, renderingLayerMask`) должны быть одинаковы у копий, иначе группы
   дробятся (`ShipVisualMerger.AddToGroups`).
7. **Двери, створки, интерактив, коллайдеры, VFX — никогда не мержить.** `DoorController` требует `Collider`;
   створка едет с узлом модели; коллайдеры — compound из примитивов.
8. **Уникальный материал = +2 DC.** Палитра: 49 `M_PC_*`/`PM_*`; 1 материал на проп; ≤12 на дом; ≤24 на статик-визуал
   корабля; сабмешей ≤4. Никаких `MaterialPropertyBlock`/`.material` на массовом контенте.
9. **Интерьеры — отдельно от экстерьера.** 78.6 % тр. города — скрытые интерьеры; не класть их в общий батч,
   не моделить мелочь <0.25 м (16.4 % тр.).
10. **Свет — только на реальные приборы.** Point, `range` 3.5–14 м (никогда >20), `shadows=None`, `enabled=false`
    в префабе, имя с префиксом группы (`PRIMUM_OUTLIGHT_/INLIGHT_/FARMLIGHT_`), точка — центр стекла прибора.
11. **Новый блок в `PRIMUM` → перепечь HLOD** (`Stage 7 HLOD → Bake All Blocks + L2` + `Rebake Determinism Check`).
    Не перепечь = новый контент живёт только <3 км.
12. **Имя = контракт.** `PRIMUM`, `Primum_farms`, `Secund/Tertius/Quartus`, `WorldRoot_0_0`, `PRIMUM_DOORS/<блок>`,
    `PRIMUM_LIGHTS/<чанк>`, `PRIMUM_HLOD` — переименование молча ломает директор/HLOD/FO.

### 4.3. Как прикинуть DC нового ассета (до замера)

```
DC ≈ 2 × (число различных (mesh,материал,настройки)-слотов в кадре) + (сколько из них кастует тень)
```
- Дом 12 материалов, 1 меш на материал: `2×12 + 12 = 36 DC`. Тот же дом 1 мешем/1 материалом: `3 DC`.
- HeavyII в кадре 555 слотов: `2×555 + 60 = 1 170 DC` — совпало с замером.
- Весь город (1 806 слотов) дал бы 3 612 DC — поэтому нужен HLOD (23 пары = 46 DC).

Полосы ниже — рабочее предложение (помечено [E] в `_evidence/01_SHIPS.md` §5), используй их как бюджет.

| Полоса | Длина | Пример | Шаги | Бюджет DC (в кадре) | LODGroup | ShadowBudget | Двери / коллайдеры |

### 6.3. Пошаговый пайплайн нового корабля

1. **`Tools → Project C → Create Ship Preset`** — выбрать класс (Light/Medium/Heavy/HeavyII), получить префаб
   со всеми компонентами (Rigidbody, NetworkObject, ShipController, ShipDeckNav, 11 ModuleSlot и т.д.).
2. **Заменить `MainVisual`** на свою модель (root scale = 1, `MainVisual` ребёнком).
3. **Вынести коллайдеры и двери из FBX** (по образцу `ShipPrefabRepair`): коллайдеры — в `SHIP_COLLIDERS`
   как отдельные дети префаба; двери — `DoorController` + `Collider` на узлах створок, иначе reimport FBX их снесёт.
4. **Мерж greebles** (только статика, только если класс M/L/XL): dry-run → apply → verify; Σtris должна совпасть.
5. **LODGroup** для M/L/XL: пороги от `worldSize` (не ближе 0.866×worldSize), LOD1 — без мелкой greeble,
   LOD2 — 1 меш × ≤5 материалов.
6. **`ShipShadowBudget`** для L/XL (и если корабль попадает в гейт DC): Apply → Verify (9/250/11/616 MR, LOD 300/900,
   `Off` в префабе = 0, расхождений с FBX = 0).
7. **Сцена:** инстанс **в корне сцены** (как `Ship_havyII_base`), tag `Ship`, `ShipRootReference`,
   `NetworkObject`; далее **FO-каталог** (`Bake Pilot Catalog`) — корабли вне `WorldRoot` → ветка B обязательна.
8. **Замер** (Play Mode, пользователь): `Project C → Culling → Stage 3 Ship Bench → Run`: 80/200/200-repeat/300/400/1200 м,
   `lodBias 1.3`, shadow 400/4/soft; гейты: 200 м ≤1 300, 300 м ≤1 300, повтор ±5 %.
9. **Целостность:** 9 `DoorController` (open/close), 250 `BoxCollider`, 11 `ModuleSlot`, `PilotSeat`, `CargoVisual`,
   `ContrailVFX`, 2 `EngineThrusterVisual`; F8/F9.

### 6.4. Что нельзя

- Мержить двери/створки/коллайдеры/интерактив/VFX (§4.2).
- Пытаться задать LOD0→LOD1 ближе 281.6 м для heavy (упрётся в `screenRelativeTransitionHeight ≤ 1`).
- Писать `shadowCastingMode` в edit-mode без `Application.isPlaying`-guard и `RestoreShadows()`
  (дефект Stage 2 оставил 5 346 `m_CastShadows: 0` — образец, как делать нельзя).
- Забыть `ShipContrailVfx.UseShipBounds=false` + `ManualBoundsSize` после мержа — след прилипнет к новому bounds.
- Править medium/light/NPC «на всякий случай»: если мешают в кадре — выключать `MeshRenderer` runtime-ом,
  префабы не трогать (решение Stage 3b).
- Менять `ShipPositions.json` с сохранённой позицией падения (телепорт на −41 570 м, каждая сессия перезаписывалась).

### 6.5. NPC-корабли и масштаб флота

- 20 NPC-шаблонов: 6 MR / 820 тр. каждый; **LODGroup нет**. Это нормальный «дальний» профиль.
- При ×100: NPC-корабли не должны быть LOD0-тяжёлыми — держи их в «6 MR» профиле, без динамических материалов;
  если NPC-корабль подходит к игроку ближе ~150 м — ему нужен LOD0-визуал (тогда это уже класс L).
- Одновременно видимых тяжёлых кораблей: **не больше 1** (один heavy = 1 170 DC). Второй — за границей кадра/дистанции.

  либо повтори по образцу с собственным отчётом и инвариантами (абсолютные пороги MR не переноси).

### 7.3. Математика масштаба: 5 домов vs 250 домов

Экстраполяция по одному дому (`_evidence/02_FARMS.md` §5), калибровка — 576 домов = 1 949 DC города при P1,
т.е. **3.4 DC/дом** в текущей гранулярности [E]:

| Величина | 1 дом | **5 домов** | 25 домов | **250 домов** |
|---|---:|---:|---:|---:|
| Двери (инстансы / MR / слоты) | 4.65 / 9.8 / 24 | **23 / 49 / 121** | 116 / 245 / 603 | **1 163 / 2 454 / 6 036** |
| Коллайдеры (двери + дом) | 31 | **157** | 784 | **7 841** |
| Визуальные слоты | 3.1 | **16** | 78 | 783 |
| Entry теней | 2.3 | **11** | 57 | **565** |

| Дверных рендереров в кадре (150 м) | ≤2 | ≤10 | ≤50 | ≤300 (потолок города 419) |

**Где предел.** Один кластер — **≤150–200 DC** (≈**45–60 домов**) и **≤600 entry теней**. 250 домов = **≈850 DC**:
это **43 % всего города** и **36 % бюджета кадра** — это уже отдельный «город/район», а не ферма.

**Правило:** ферма >60 домов **не строится одним объектом** — она нарезается на блоки по **25–45 домов**

свои entry теней и свой бюджет света.

### 7.5. Коллайдеры: правила

- **Примитивы `BoxCollider`**, не один concave-меш и не per-triangle: sphere-vs-box дешевле sphere-vs-triangles.
- Мин. размер объекта **0.25 м** (меньше — пропуск), мин. толщина бокса **0.5 м** по каждой оси,
  расширение **вниз** (верх заподлицо) — лечит проваливание кораблей.
- Исключения по имени: `BOLT, SCREW, RIVET, NUT, WASHER, PIN, WIRE, CABLE, HOSE, PIPE, RAIL, LAMP, LIGHT, GLOW,
  GLASS, WINDOW, DECAL, MARKER, REFERENCE, TRIGGER, VOLUME, LOD*`.
- Круглые бары (`PIPE, REBAR, TUBE`) — `CapsuleCollider` по длинной оси (если длина ≥ 2 диаметров).
- Кривые меши — slab-нарезка `sliceStep 1.0 м`, `sliceAdaptTol 0.05 м`; полости не заливаются.
- Слияние соседних боксов `mergeGap 0.1 м`; иерархия — отдельный `<Root>_Colliders/<здание>`,
  **не на узлах FBX** (переимпорт снесёт).
- `MeshCollider` — редко, `convex=false`, cooking: `CookForFasterSimulation + EnableMeshCleaning +
  WeldColocatedVertices + UseFastMidphase`. `convex=true` на статике — запрещён.
- На дом: **≈21 бокс** (≤30 — норма); на 250 домов — ≈7 841 бокс, но **не число боксов** тормозит зоны:
  `OuterCommZone/MarketZone` с `OverlapSphere(r=1000, маска ~0)` давали **82.93 мс и 136.6 КБ GC** на полл.
  Перед масштабированием ферм — сузить `pollLayerMask` зон (вариант A из `25092026/02_FARM_COLLIDERS.md`).

### 8.3. Что никогда (проверено кодом URP, не только докой)

- **Тени на доп. лампах** — `m_AdditionalLightShadowsSupported: 0`, тени не рисуются.
- **`range > 20 м`** для интерьера/фасада: доминирующий дефект — ALIC-оверрайд `INLIGHT range=48.3`;
  100 % активных IN «длинные», свет проходит сквозь стены (теней нет), интерьеры конкурируют с улицей.
- **`cullingMask` / light layers / per-object limit 4** — инертны: `m_SupportsLightLayers: 0`, в Forward+ карта
  per-object не строится (`ForwardLights.cs:744-745`).
- **`maxActive 96 → 128`** «чтобы стало видно»: L5 показал cap 128 — GPU-гейт пройден, но доля в кадре 73 % vs 80 %,
  FPS не выше; 96 оставлено, 256 — жёсткий потолок.
- **fade-out** писать: L6 — удержание `enabled` до **75** источников против гейта ≤16 → `fadeOutSeconds=0`
  (мгновенное гашение — принятое ограничение).
- **HDR/bloom от emissive**: HDR off, `_BaseColor 2.4` клипается; ореола не будет.
- Ожидать, что emissive слушает день/ночь: **не слушает** — горит и в полдень.

### 8.4. Масштаб ×100 (2 238 → ~224 000 ламп) — что резать и в каком порядке

| N | чек пула | амортизация (4 Гц) | `FindFocusCamera` | вердикт |

| 2 238 | 1.5–3.2 мс | 0.23–0.39 мс/кадр | 2.4–3.6 мс | текущее, принято |

| 224 000 | 150–310 мс | — | — | **невозможно** одним массивом |

Порядок:
1. **emissive-корпус** для всего, что >100 м (уже есть, HDR off — дёшево);
2. **HLOD ночной атлас** `PRIMUM_L2_Night.asset` (2 DC, ноль источников) — дальний город светится без ламп;
3. **чанк-локальный пул**: регистрировать 1–3 чанка вокруг камеры (~2–5 тыс. ламп), инкрементальное обновление;

Пока этого нет — **не превышать ~4–5 тыс. ламп в мире**: иначе чек пула выходит за бюджет 0.5 мс/кадр

| Метрика | Сейчас | Предел/формула | ×10 | ×100 |

### 9.5. Правила «новый квартал = …»

1. **Новый квартал = новый ребёнок `PRIMUM`** (= блок = чанк директора), имя
   `PRIMUM_<TYPE>_S<n>_<ZONE>_P<m>_<NN>H`, совпадающее с `PRIMUM_DOORS/<то же имя>`.
   Футпринт 26–228 × 156 м, ≤80 k тр., ≤65 535 верт./меш, join «блок × материал».
2. **1 блок ≈ 2 DC в L1 ≈ 1.27 МБ ассетов.** Бюджет мира: **≤200–250 блоков** (иначе L1 ≤500 не выполняется).
3. **≤~100 корней сцены** (FO-участники) и **≤4 загруженных `WorldScene_*`** — кварталы раскладывать по сценам сетки.
4. **Регион больше сцены = отдельная сцена + свой HLOD-манифест** (сейчас манифест один и жёстко привязан к `PRIMUM`).
5. **Фермы/спутники/руины в HLOD не входят** — при ×100 они дают L0-DC на всех дистанциях; сначала сделать им L1
   по шаблону (бейкер знает только `PRIMUM`).
6. **L2 пересматривать при футпринте >≈5 км** (один квад + атлас перестаёт читаться): 2–4 региональных импостора
   или тайловый атлас.
7. **Каждый новый блок = перепечь L1+L2 + F8/F9 + `Rebake Determinism Check`.**
