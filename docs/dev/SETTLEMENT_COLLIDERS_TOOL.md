# Settlement Colliders Tool — дизайн-нота

**Дата:** 2026-09-23
**Контекст:** `WorldScene_0_0`, `Project-C_primum_farm_x_1_2_GameReady` (фермерское поселение, ~2к мешей).
**Prior art:** `Assets/_Project/Editor/CombineMeshesToCollider.cs` + `docs/world/COMBINE_MESHES_TO_COLLIDER.md`,
`Assets/_Project/Editor/GenerateSimpleCityColliders.cs`.

## 1. Проблема

- Старый тул `CombineMeshesToCollider` клеит **один concave MeshCollider** на выбранный корень.
  По факту им пользовались **поштучно**: выбирали отдельный меш внутри FBX и гнали скрипт —
  иначе один гигантский меш на всё поселение (долгая варка, тяжёлый broadphase, одна точка отказа).
- `GenerateSimpleCityColliders` ставит BoxCollider'ы, но фильтры имён захардкожены под город
  (`FLOOR/SLAB/...` + русские `НИЖНЯЯ ПАНЕЛЬ` и т.д.) — для фермы не подходит.
- Кейс `MD2_Deck_Blockout`: плоская палуба получила тонкий коллайдер (миллиметры в локальных
  единицах). Игрок (`CharacterController`) стоит, а корабль (`Rigidbody`, Continuous) туннелит
  сквозь неё и «падает». Город сейчас перестраивается — его не трогаем, но класс ошибки фиксируем.

## 2. Решение

Новый Editor-тул `BuildSettlementColliders` (`Assets/_Project/Editor/BuildSettlementColliders.cs`,
меню `Tools/ProjectC/Build Settlement Colliders...`):

- **Один клик по корню FBX → по одному `BoxCollider` на каждый значимый меш внутри** (рекурсивно).
- Box достаточен и игроку (`CharacterController` сталкивается с чем угодно статичным),
  и кораблю (`Rigidbody` дружит со статичными боксами; с concave-мешем тоже, но боксы дешевле
  и не требуют варки). Лестницы — бокс на ступеньку, проверяется тестом в игре.
- **Фильтр мелочи** (болты и т.п.): пропуск по имени (токены) + по мировому размеру
  (`max(worldSize) < minWorldSize`). Для ферм на 2к мешей это срезает сотни бесполезных боксов.
- **Мин. толщина 0.5 м (world)** по каждой тонкой оси, расширение **вниз** (топ остаётся заподлицо
  с визуалом) — лечит туннелинг кораблей сквозь палубы/настилы класса MD2.
- Коллайдеры живут в **отдельной иерархии** `<Root>_Colliders/<Группа>/BC_xxxx_<имя>` в сцене
  (не на самих FBX-узлах): переживает переимпорт FBX, идемпотентный перезапуск, Undo-friendly.
- Группировка по прямому ребёнку корня (обычно = отдельное здание/двор) — порядок в Hierarchy.
- Опциональный repair-проход: утолщает уже существующие тонкие боксы внутри корня (не трогая город).
- **Dry Run**: посчитать, сколько будет создано/пропущено, без создания объектов — для подбора порогов.

## 3. Что осознанно НЕ делаем

- Не один общий combined-меш: для поселений боксы быстрее и надёжнее для кораблей.
- Не `convex MeshCollider` на плоскость: выпуклая оболочка плоскости — бумага, корабли проваливаются.
- Не трогаем `WorldScene_0_0` городские `SC_*`/CITY_SIMPLE_COLLIDERS (город перестраивается).
- Не кэшируем мировые позиции, не храним состояние между запускам — floating origin 🟢:
  коллайдеры — дети корня сцены, едут бесплатно. F8/F9 — штатная проверка.
- Нет `.asmdef`/`.meta` руками, нет изменений `ProjectSettings`, нет Play Mode (тесты — пользователь).

## 4. Проверка приёмки

1. Console → 0 errors после создания скрипта.
2. Выбрать `Project-C_primum_farm_x_1_2_GameReady` → Tools → ProjectC → Build Settlement Colliders →
   Dry Run (оценить created/skipped), затем Build.
3. Игрок ходит по ферме, не проваливается; лестницы — тест ступенек.
4. Корабль садится на палубы фермы, не падает сквозь.
5. F8 → `runtimeRebase.Completed`, коллайдеры на месте; F9 → возврат.
