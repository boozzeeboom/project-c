# T-CAM25 — Камера на высокой скорости: не отстаёт и не «прыгает»

> **Файл:** `Assets/_Project/Scripts/Core/SpringArmCamera.cs`
> **Репорт:** «если ускоряться с большой скоростью (админский бег) — камера не успевает
> за персонажем, прыгает». Паром после T-CAM22/23 и T-PAROM-25/27 — ок.

## 1. Почему на скорости камера «не успевает» и «прыгает»

Отставание камеры складывалось из трёх слоёв, и каждый масштабируется со скоростью:

| Слой | Вклад | На 48 м/с |
|---|---|---|
| задержка интерполяции цели (T-CAM22) | `v × targetSignalDelay` | 3.4 м |
| лаг (exp, `lagHorizontalTime`) | `v × 0.15` | 7.2 м |
| сглаживание позиции | `v × positionSmoothTime` | 1.9 м |

Итого ~12.5 м. Дополнительно в `LateUpdate` стоял «снап по дистанции»:
`Distance(_lagTargetPos, target) > 10 м → SnapCameraToPosition()`. На скорости лаг
честно превышал 10 м, и снап срабатывал **каждый кадр, телепортируя лаг-цель** — это
и есть «прыгает». Плюс в `UpdateLag` был похожий клэмп `delta > 10 м`, который тоже
телепортировал.

## 2. Что изменено (все пороги — поля в инспекторе)

1. **`maxLagDistance` (2.5 м)** — потолок отставания лаг-цели от цели **по дистанции**,
   а не по времени. На walk/run (0.75–1.2 м) не срабатывает; на 30–50 м/с не даёт
   камере уехать на метры. `0` = без потолка (старое поведение).
2. **Снап — только на телепорт** по **кадровому шагу цели** (`> 10 м за кадр`), а не по
   дистанции лага. Быстрое движение больше не триггерит снап.
3. **Задержка интерполяции гасится со скоростью**: `10 → 25 м/с` линейно до 0
   (`targetDelayFadeStartSpeed` / `targetDelayFadeEndSpeed`). Интерполяция нужна против
   ступенек сети на обычной скорости; на 90+ км/ч она только добавляет отставание.
4. **Сглаживание позиции ужимается со скоростью**: `10 → 30 м/с` до
   `positionSmoothTime × smoothTightenMinFactor` (0.25). Убирает хвост `v·0.04`.
5. Удалён старый клэмп `10 м` в `UpdateLag` (он телепортировал лаг-цель).

Скорость цели берётся из **сырого** кадрового шага (сглажено 0.15 с), поэтому не зависит
от лага и от platform-follow.

## 3. Замер (модель, `docs/dev/tools/cam_highspeed_sim.js`)

| Скорость | Было: отставание / разброс шага камеры / снапов | Стало |
|---|---|---|
| 12 м/с (43 км/ч) | 6.54 м / 0 мм / 0 | 6.47 м / 0 мм / 0 |
| 25 м/с (90 км/ч) | 8.45 м / 0 мм / 0 | 6.47 м / 0 мм / 0 |
| **48 м/с (173 км/ч)** | **12.88 м / 3842 мм / 9 снапов** | **6.43 м / 0 мм / 0** |
| 120 м/с (432 км/ч) | 11.95 м / 3560 мм / 71 снап | 6.56 м / 0 мм / 0 |

(6.4–6.5 м — это спроектированное плечо 5.845 м, т.е. собственное отставание ≈0.5–0.7 м.
«Разброс шага 0 мм» = камера идёт ровно, без рывков.)

## 4. Тюнинг

| Поле | Дефолт | Смысл |
|---|---|---|
| `maxLagDistance` | 2.5 | потолок отставания, м (0 = выкл) |
| `targetDelayFadeStartSpeed` / `EndSpeed` | 10 / 25 | с какой по какую скорость гасить задержку сэмпла |
| `smoothTightenStartSpeed` / `EndSpeed` | 10 / 30 | с какой по какую скорость ужимать сглаживание |
| `smoothTightenMinFactor` | 0.25 | предел ужатия |

Откат: `maxLagDistance = 0`, `targetDelayFadeStartSpeed = 999`, `smoothTightenMinFactor = 1`
→ точное старое поведение.

## 5. Проверка (Play Mode — пользователем)

1. Админ-бег/noclip на x1 (12 м/с), Shift (48 м/с), максимум мультипликатора — камера
   едет ровно, персонаж не убегает из кадра, нет рывков при разгоне и торможении.
2. Обычная ходьба/бег — ощущение не изменилось (порог 10 м/с не задет).
3. Разгон в транспорте/на корабле — без регрессий.
4. Телепорт админкой — камера по-прежнему мгновенно переезжает (снап по шагу).
