# T-FO09C — «Спасение» возвращает на корабль, а не в пустоту

Date: 2026-09-13. Жалоба: Esc-спасение возвращает на точку спавна (пустота
после 06K); раньше падение с корабля возвращало на корабль.

## Диагноз

`PlayerRespawnTracker.PerformDefaultRespawn` (кнопка «СПАСЕНИЕ»,
`ForceDefaultRespawnServerRpc`) шёл «ТОЛЬКО на дефолтную точку
RespawnManager, без ship-проверок» — намеренный обход ship-цепочки
автореспавна (текущий → последний → ближайший owned). Пока дефолтная точка
была на земле, обход был незаметен; после удаления граунда (06K) и переноса
спавна это возврат в пустоту. `RespawnManager.GetEffectivePosition` читает
live `spawnPoint.position` — сам по себе сдвиги переживает, виноват только
обход.

## Решение (`PlayerRespawnTracker.cs`)

- Новый `TryResolveShipRescuePosition` — общая ship-цепочка, единый источник
  (позиции live: `GetExitPosition`/поиск → сдвиги мира переживают).
- `PerformDefaultRespawn`: сначала цепочка (`Rescue-to-ship (источник)`),
  дефолтная точка — только fallback.
- `PerformRespawn`: три дублирующих блока заменены вызовом общей цепочки
  (поведение то же, дрейфа реализаций больше нет).

## Проверка

1. Compile: `refresh_unity` (force + compile) — PASS; `read_console` —
   0 errors, 0 CS; скобки 115/115; висячих `np` нет.
2. Play Mode (user): упасть с корабля → автореспавн на корабль (как раньше);
   Esc-«Спасение» в пустоте → корабль (`Rescue-to-ship`), а не точка спавна;
   без кораблей рядом → дефолтная точка (сibling перенёс на землю).
