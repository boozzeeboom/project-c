## 3. Иерархия (одинаковая)

```
PM_DOOR_SINGLE_<ID>          (pivot: низ по центру проёма, слой PRIMUM, static)
├── Frame                    — рама: 2 стойки + перекладина (статика)
├── Sill                     — порог (статика)
├── Leaf                     — ПОЛОТНО, pivot на петлях (левый край), static=false
│   ├── LeafWood             — полотно/доски/филёнки
│   ├── LeafIron             — петли / железные полосы
│   └── LeafBronze           — ручка (кольцо или рычаг)
└── ArchTrim                 — только ARCH_C: навершие арки
```

`Leaf` — отдельный узел, его можно вращать вокруг локального Y (открывание). Пивот Leaf:
* PLANK_A: local x = **−0.36**
* PANEL_B: local x = **−0.39**
* ARCH_C: local x = **−0.44**
(y = 0.04, z = 0)

## 5. Как ставить в проёмы (черновик; полный алгоритм — `01_PREFAB_PLAN.md`)

1. Взять строку из `registries/doors_registry_<чанк>.csv` (`pos_*`, `rot_y`, `w`, `h`).
2. Выбрать вариант по ширине: ≤1.00 → `PLANK_A`; 1.00–1.10 → `PANEL_B`; >1.10 → `ARCH_C`
   (дворцы/администрация — отдельные наборы, будут позже).
3. Поставить как ребёнка чанка: `local = parent.InverseTransformPoint(world_pos)`,
   `localRot = Quaternion.Inverse(parent.rotation) * Quaternion.Euler(0, rot_y, 0)`.
4. Подогнать под проём: **масштаб** `scale = (w_registry / w_prefab, h_registry / h_prefab, 1)`
   (допустимо ±12 %; иначе — другой вариант).
5. Оригинальную группу `DOORS/<имя>` оставить выключенной (заглушка).

## 6. Код-генератор (воспроизведение 1:1)

Всё строится в редакторе Unity (MCP `execute_code`) из единичного куба 24 вершины:
рама/порог/полотно/фурнитура — наборы боксов, склеенные `Mesh.CombineMeshes`; каждый меш сохраняется
как ассет (иначе префаб сохраняет пустую ссылку!), материалы — URP Lit.

Ключевые параметры (см. §2): `jamb` 0.08 (PLANK) / 0.10 (остальные), `lintel` 0.10 / 0.12,
толщина полотна 0.05, глубина рамы 0.16, выступ порога +0.06, для ARCH — навершие +0.08/+0.06.

> Если префабы потеряны — их можно пересоздать этим же подходом: логика описана выше дословно
> (размеры, смещения, материалы). Полный код генератора — в истории чата/у исполнителя;
> при необходимости вынести в `Assets/_Project/Editor/Primum/DoorPrefabBuilder.cs`.

### 7.1 Постмортем: вывернутые меши (исправлено 2026-10-21)

Диагноз заказчика подтвердился измерением: **13 из 16 мешей имели отрицательный знаковый объём**
(порядок треугольников шёл против заданных нормалей — с ряда ракурсов дверь не рендерилась).

Исправлено двумя мерами (защита в глубину):

1. **Разворот веток** у всех мешей `Prefabs/City/Doors/Meshes` → знаковый объём положительный
   у 16/16 (контроль после правки: 0 вывернутых).
2. **`_Cull = 0` (Cull Off, двусторонняя)** на всех 5 материалах `PM_DOOR_*` — тонкие дверные
   поверхности читаются с любой стороны; класс «не видна изнутри» снят целиком.

> Правило: при ручной сборке мешей из примитивов проверять `SignedVolume > 0` — та же семья
> ошибок, что и с нормалями PRIMUM (`../05_HISTORY/06_V11_WALL_REGRESSION.md`).

## 8. Коллайдер + скрипт двери (сделано 2026-10-21)

На каждый префаб установлено:

| Компонент | Где | Настройка |
|---|---|---|
| `BoxCollider` (триггер) | корень | зона взаимодействия (0.90/1.00/1.10 × H × 0.20) |
| `BoxCollider` (не триггер) | узел `Leaf` | блокирующий объём створки (0.74–0.88 × 1.96–2.04 × 0.07), **едет со створкой** при открытии |
| **`DoorController`** (`ProjectC.Ship` — скрипт корабельных дверей) | корень | `doorType=HingedSingle`, `hingePivot=Leaf`, `hingePanel=LeafWood`, `hingeSide=Left`, `openAngle=90°`, `openDuration=1.2с`, `startOpen=false`, `autoCloseDelay=0` |

* `Leaf` — одновременно пивот и контейнер полотна: `DoorController` вращает `Leaf`, коллайдер и меши едут вместе.
* Петли слева (лицевая сторона +Z); если открывается не туда — поменять знак `openAngle` (−90).
* Диагностика `GetSetupIssues()` на всех трёх префабах: **0 ошибок, 0 предупреждений**.
