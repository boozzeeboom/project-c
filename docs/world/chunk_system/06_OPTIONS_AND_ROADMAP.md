## 2. Почему не E (формальный отказ — для истории решений)

1. Противоречит трём действующим решениям: authored `Terrain_0_0` (`terrain/README`),
   GlobalPilot + каталог 151 (`floatingorigin/README`, `09S`), NGO 2.13 `[Rpc(SendTo.X)]` (`AGENTS.md`).
2. Не в сценах (0 ссылок в `*.unity`), помечен legacy (`FloatingOriginMigrationCensus.cs:49`),
   retired-паттерн уже применён к соседям (`ClientSceneLoader.cs:92-111`, `WorldSceneManager.cs:76-91`).
3. Дефекты §5 `02_*` (fade через alpha, on-demand бесконечность, бродкаст-RPC, `FloatingOriginMP`
   split-brain) — архитектурные, не баги; чинить нечего, проектировать заново дешевле.
4. Решение зафиксировано здесь; повторное предложение E обязано приложить профайлер,
   опровергающий `02_*` §3, иначе закрывается ссылкой на этот документ.

## 3. Критерии возврата к чанкам D (числа, а не ощущения)

Открывать D только если **все** выполнены (замеры — Profiler + Memory Profiler, делает пользователь):

1. В кадре типичного геймплея (полёт 100 м/с, высота 600–5000) render/culling > 10 мс
   при пресете Medium **после** калибровки T-LOD01 (т.е. far/тени/туман уже ужаты).
2. Виновник — именно количество уникальных объектов/текстур (draw calls > ~1000 или
   текстуры > ~1 ГБ VRAM), а не шейдеры/overdraw/тени (иначе лечится не чанками).
3. Объекты кластеризуются пространственно (кварталы, фермы, флоты) — т.е. выгрузка куском
   реально убирает сотни draw calls, а не 5–7 (как руины сейчас).
4. Сцен 2+ (иначе чанки внутри одной 80-км сцены — это снова сетка 2K поверх сцены 80K,
   т.е. ошибка §2 `02_*`).
5. `NetworkPrefabsList` починен и динамический спавн работает (иначе чанки только визуальные —
   а это уже опция B/D-визуальная, без сети).

Если хоть один пункт не выполнен — оставаться на B.

## 4. Роадмап B (фазы, без дат — по готовности приёмки)

- **Фаза B0 — калибровка (пользователь, Play):** чек-лист §5A; числа — в `ViewDistanceConfig`-ассет
  (`Assets/_Project/Resources/Config/ViewDistanceConfig.asset`, fallback — кодовые дефолты
  `ViewDistanceConfig.cs:86-98`). Без B0 дальше не идти (иначе проектируем вслепую).
- **Фаза B1 — импосторы городов (Editor bake, без сети):** L1-HLOD кварталов + L2-билборд +
  ночные огни (§3 `03_*`); корни под `WorldRoot_*`; FO-класс 🟢; приёмка §5B.
- **Фаза B2 — scene-interest hardening (сеть, без визуала):** автореестр
  (`ScenePlacedObjectSpawner` → `ServerSceneManager.RegisterSceneObject`), ACK-цикл вместо
  `WaitForSeconds(1f)`, дерегистрация при unload; приёмка §5C (2 клиента минимум).
- **Фаза B3 — L3-хук (когда 2-я сцена):** разблокировать `ViewDirection.Ultra` по условию
  `loadedScenes > 1` + билборды соседних городов; каталог/digest на 2 сцены через Bake-тулзу.
- **Фаза D0 (условная) — профайлер-триггер §3:** только при выполнении всех 5 критериев.

Каждая фаза — маленьким диффом, без посторонних рефакторингов (`AGENTS.md`);
сейвы координат — паттерном `ShipPositionServer` + кумулятив; `.meta`/`.asmdef` руками не писать.

## 5. Чек-листы ручной проверки (пользователю, NOT RUN агентом)

### 5A. B0 — калибровка ViewDistance (1 клиент, Host, `WorldScene_0_0`)

1. Compile: Console → 0 errors.
2. Одна точка (высота ~2000, вид на Main ~30 км): скриншоты Near / Medium / Far
   (агент скриншоты не делает — пользователь).
3. На каждом пресете: F8 → `runtimeRebase.Completed` + объект на месте + 0 errors; F9 → возврат.
4. Profiler кадра на каждом пресете (с/без `DistantFocus`): render, culling, shadows, tris, draw calls,
   VRAM. Записать в `docs/world/optimization/ITERATIONS.md` + откалибровать `ViewDistanceConfig`.
5. Пороги `DistantFocus` (800/4000) визуально не спорят с новым far/fog — да/нет.

### 5B. B1 — импосторы (1 клиент)

1. L0→L1→L2 переходы без pop (допустим 1-кадровый dissolve, недопустим скачок силуэта).
2. Ночь: огни читаются на 30+ км сквозь туман; день: силуэт уникален (навигация).
3. F8/F9 на каждом LOD: импостор на месте, LOD не залипает, 0 errors.
4. Draw calls/трисы до/после (ожидание: −сотни на город в L2, +1–2).
5. `AuditGlobalSceneCatalog`: без новых расхождений (несетевой контент каталог не трогает —
   `09S_NEW_CONTENT_PIPELINE.md:59-73`).

### 5C. B2 — interest (2 клиента: host + гость)

1. Гость join → сцена + ACK → объекты видны; до ACK — невидимы (нет NRE `__endSendRpc`).
2. Гость в соседней сцене: `NetworkHide` старой + `NetworkShow` новой; хост не дёргается.
3. F8 на хосте → гость получает `FO06_REBASE_SHIFT`, `ActorRebound(ok=True)`, объекты на месте.
4. Disconnect гостя → сервер чистит карты (`_clientSceneMap/_clientLoadedChunks/_playerTransforms`);
   reconnect → шаги 1–3 заново.
5. UTP-профайлер: число RPC на транзишен ~ O(1), а не O(чанки × клиенты).

### 5D. Выход на C (2 сцены)

1. `loadedScenes > 1` → Ultra разблокирован; иначе disabled + хинт (уже в дизайне).
2. Билборды соседней сцены видны сквозь границу; выгрузка дальней сцены не гасит фон.
3. Каталог/digest на 2 сцены: `TryCompile=True` + `TryMatchDigest=True`.
