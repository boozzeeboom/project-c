## Что взято у бронзы (и что — нет)

`Assets/_Project/Materials/Bronze/BronzeEdgeNoise_forTEST.shadergraph` —
**read-only**. Он читается сборщиком только как источник формата документов узлов и
слотов. Логики бронзы в бетоне нет: ни патины, ни вертикального bias, ни
«износа до металла», ни `Metallic`.

| Соблазн «взять у бронзы» | Что сделано в бетоне | Почему |
|---|---|---|
| Патина + вертикальный bias | Нет вообще | Бетон не «течёт» как бронза: вертикальность есть только в слое высолов (`_Bloom_Stretch`), и это единственный слой, привязанный к Y |
| `Metallic`, `_Patina_*`, `_Tone_*` | Отсутствуют (`Metallic` блок мастер-стека не подключён) | Диэлектрик. Проверено: `_Metallic present = False` в пресете |
| Маска кромок: `Absolute → Split → 3 Smoothstep → попарные × → 2 Add → Saturate` | **Взята** структура 1:1 (прямое указание задачи) | Кромка бетона — это заглаженная/затёртая зона (цементное молочко + песок), а не металл; структура годится, меняется только трактовка |
| Три набора царапин + гасящая маска (`ScratchA/B/C` + `ScratchMask`) | **Взяты** механизм и сигнатуры 1:1, своя HLSL-реализация с префиксом `PCConc_` | Документированный механизм; царапины на бетоне матируют и светлеют, рельефа не дают |
| Светлые зёрна как отдельный слой | Появился `ProceduralConcreteAggregate` + второй `Smoothstep`-порог на светлые кварцевые зёрна (порог 0.55…0.95 — **константы на слотах**, не свойства) | Это то, по чему бетон опознаётся на расстоянии: крупа разного тона, а не гладкая серая масса |

## ⚠ Отличие от бронзы: порядок входов `Smoothstep`

ShaderGraph собирает `SmoothstepNode` в
`Out = smoothstep(Edge1, Edge2, In)`, где слот `0 = Edge1` — **нижний** порог,
`1 = Edge2` — **верхний**, `2 = In` — значение
(источник: `Library/PackageCache/com.unity.shadergraph@2df19e8719bc/Editor/Data/Nodes/Math/Interpolation/SmoothstepNode.cs:28`).

Бронза — и, унаследовано, Wood и IronRust — провода держит наоборот: в `Edge1` уходит
**изменяющийся сигнал**, а в `In` — **константа**. Из-за этого каждый порог выходит
обращённым:

- маска кромок бронзы = `smoothstep(|x|, E−W, E)` = 1 там, где `|x| < E−W`,
  то есть потёртость садится на **середину граней**, а настоящие рёбра остаются
  чистыми (задумано было `smoothstep(E−W, E, |x|)`);
- порог царапин бронзы = 1 там, где `scratch < threshold`, то есть чисто **ровно на
  линиях царапин**;
- то же у гасящей маски царапин.

Само по себе это не «сломано» — рисунок получается, но полярность обратная авторскому
замыслу (в `Wood/README.md` механизм описан в естественной форме
«`Smoothstep(_Scratch_Threshold, +_Scratch_Band)` → `Add` → `× Smoothstep(mask)`»).

**В бетоне значение всегда подаётся во вход `In`, а пороги — в `Edge1`/`Edge2`.**
Это зафиксировано хелпером сборщика `Smooth(inR, e1, e2)` и проверено на графе:
`Smoothstep = 10`, из них со значением в `In(2)` — **10 из 10**.

Проверяемая по коду разница формулируется так:

| Слой | Бронза (как есть) | Бетон (естественный порядок) |
|---|---|---|
| Кромка | `smoothstep(\|coord\|, E−W, E)` → 1 в середине грани | `smoothstep(E−W, E, \|coord\|)` → 1 на кромке |
| Царапины | `smoothstep(scratch, thr, thr+band)` → 1 вне линий | `smoothstep(thr, thr+band, scratch)` → 1 на линиях |
| Гасящая маска | `smoothstep(mask, thr, thr+band)` → 1 в тёмных пятнах | `smoothstep(thr, thr+band, mask)` → 1 в светлых пятнах |
| Пятна/высолы | — (нет слоя) | `smoothstep(thr, thr+soft, fbm)` → 1 в пятне |

Бронза, Wood и IronRust **не правились** — это их собственный вид, и он вне задачи.

## Слои бетона (что делает его бетоном, а не серым камнем)

```
Position (object-space, m_Space = 0)
 ├─ ЗАПОЛНИТЕЛЬ    ProceduralConcreteAggregate  (Worley F1 + тон ячейки) → крупа разного тона
 ├─ РАКОВИНЫ        ProceduralConcretePores      (Worley F1, радиус) → редкие ямки
 ├─ ТРЕЩИНЫ         ProceduralConcreteCracks     (ridged fbm + warp + пятно-маска) → сеть линий
 ├─ ТЕСТО           ProceduralConcreteBlotch #1  (fbm, Stretch = 1)  → облачность
 ├─ МОКРЫЕ ПЯТНА    ProceduralConcreteBlotch #2  (fbm, Stretch = 1, свой сид) → пятна
 ├─ ПОТЁКИ/ВЫСОЛЫ   ProceduralConcreteBlotch #3  (fbm, Stretch = 9)  → вытянуто вдоль локальной Y
 ├─ КРОМКА          |x|,|y|,|z| → 3 Smoothstep → попарные × → Add×2 → Saturate (структура бронзы)
 └─ ЦАРАПИНЫ        ScratchA/B/C (ridged fbm) → Saturate(сумма) → × Smoothstep(ScratchMask)

BaseColor  = Lerp(Lerp(Lerp(Lerp(Lerp(Lerp(Lerp(Lerp(_Concrete_Color, _Mottle_Color, облачность),
                                                  _Aggregate_Color, заполнитель),
                                                  _Aggregate_Light_Color, светлые зёрна),
                                                  _Pit_Color, раковины),
                                                  _Crack_Color, трещины),
                                                  _Stain_Color, мокрые пятна),
                                                  _Bloom_Color, высолы),
                                                  _Wear_Color, кромка + царапины)
Smoothness = Saturate( Lerp( Lerp(_Smoothness − раковины×_Pores_Matte,
                                  +_Stain_Gloss в пятнах),
                              +_Edge_Gloss на кромке) )
NormalTS   = Normal From Height( заполнитель×_Aggregate_Bump
                               + раковины×_Pores_Bump
                               + трещины×_Crack_Bump ,
                                 Strength = 0.01 — слот не подключён, значение узла)
Metallic / Emission / Occlusion — не подключены (диэлектрик, свечения нет)
```

### Пояснение по каждому слою

- **Заполнитель.** Бетон = крупный заполнитель в цементном тесте. Узнаётся он именно
  по **крупе разного тона**, а не по «шумной серости». Реализация: Worley **F1** даёт
  ячейку зерна (`shape = saturate(1 − smoothstep(0.20, 0.58, d))` — плато в центре),
  а **хеш выигравшей ячейки** даёт тон зерна, постоянный внутри ячейки и скачком
  меняющийся на её границе. `_Agg_Tone` управляет разбросом: 0 — все зёрна одного
  тона (0.85), 1 — от 0.25 до 1.0 (от почти невидимого зерна до светлой кварцевой
  крупинки). Второй слой — **светлые зёрна**: `smoothstep(0.55, 0.95, Aggregate)`,
  пороги вынесены **константами на слоты**, а не свойствами: это не ручка художника,
  а разделение «песок/щебень» и «кварц».
- **Воздушные раковины.** Ямки от пузырьков воздуха у опалубки — самый «бетонный»
  дефект поверхности. Радиус задаётся `_Pores_Size` в долях ячейки Worley, покрытие
  растёт как `1 − exp(−4.19·r³)`: `0.30 ≈ 11 %` площади, `0.45 ≈ 30 %`.
  Раковины работают **вниз** по рельефу (`_Pores_Bump = −0.55`) и матируют глянец
  (`_Pores_Matte`).
- **Трещины.** Усадочные трещины — это **сеть тонких линий с изломом**, а не шум.
  Реализация: ridged-fbm (`1 − |2·fbm − 1|` — 1 на линии), домен предварительно
  **искривлён** (`_Crack_Warp`, три value-noise по `p×0.45`), иначе линии читаются
  как регулярная рябь. Второй, более крупный fbm решает, **где вообще есть трещины**
  (`smoothstep(0.30, 0.72, fbm(p×0.35 + 13.9))`): сплошная сеть по всей поверхности
  выглядит как шум — трещины живут участками. В альбедо идут тёмным тоном, в рельеф —
  вниз (`_Crack_Bump = −0.45`).
- **Тесто (облачность).** Цементное тесто неоднородно: крупные, мягкие, изотропные
  пятна другого тона. Это `ProceduralConcreteBlotch` с `BlotchStretch = 1`, и вклад —
  прямое умножение сырого fbm на `_Mottle_Amount` (без порога): пятна должны быть
  мягкими, а не «включёнными».
- **Мокрые пятна.** Тот же примитив, другой масштаб и сид, но **с порогом**
  (`_Stain_Threshold` / `_Stain_Softness`) — это не полутон, а локальные зоны намокания
  и вымывания. Добавляют глянец (`_Stain_Gloss`), потому что смытая/заглаженная
  поверхность светлее лощится.
- **Потёки и высолы.** Единственный «гравитационный» слой и главная вертикаль бетона:
  тот же fbm, но с `BlotchStretch = 9` домен сжат по **локальной Y** → пятна
  вытягиваются в вертикальные языки. Порог — `_Bloom_Threshold` / `_Bloom_Softness`,
  цвет — светлый `_Bloom_Color` (известь, выцветшие соли).
- **Кромка.** Структура бронзы 1:1: `Absolute → Split` по модулям координат, три
  `Smoothstep` (в естественном порядке! см. выше), попарные произведения, два `Add`,
  `Saturate`, умножение на `_Edge_Wear`. На кромке габарита две координаты близки к
  максимуму одновременно, поэтому произведение по парам даёт 1 именно у рёбер.
  Кромка светлеет (`_Wear_Color` — высохшее цементное молочко и песок) и чуть лощится
  (`_Edge_Gloss`).
- **Царапины.** Механизм бронзы 1:1: три ridged-fbm в сжатой (вытянутой) системе
  координат — A и B под общим углом `_Scratch_Angle`, C под своим углом в собственной
  повёрнутой системе, — суммируются и `Saturate`-ятся, затем гасятся маской
  (`ProceduralConcreteScratchMask`, тот же примитив `Blotch` с `Stretch = 1`) и
  умножаются на `_Scratch_Amount`. Царапина на бетоне — **светлая матовая дорожка**
  (песчаная пыль в борозде), поэтому слой влияет на альбедо и `Smoothness`, а рельефа
  не даёт: жёсткий рельеф царапин на бетоне читается как царапины на металле.
  Роль `_Scratch_Mask` двойная (как в бронзе: тот же трюк) — это и **порог** гасящей
  маски, и **сид** её шума.

## Ядро шума — `Assets/_Project/Shaders/ProceduralConcreteNoise.hlsl`

Правило проекта **T-BRONZE01** соблюдено: все экспонированные функции —
**одно-выходные** (File-режим), их сигнатуры совпадают с порядком слотов CF-нод
в графе. Новое поведение — **новой** функцией; существующие сигнатуры не менять
(слоты связываются по номеру).

| Функция (имя CF-ноды) | Входы | Выход | Что считает |
|---|---|---|---|
| `ProceduralConcreteAggregate` | `ObjectPos, AggScale, AggTone, AggSeed` | `Aggregate` | Worley F1 + тон ячейки: `shape = saturate(1 − smoothstep(0.20, 0.58, d))`, `tone = lerp(0.85, lerp(0.25, 1.0, cellHash), saturate(AggTone))`, выход `saturate(shape × tone)` |
| `ProceduralConcretePores` | `ObjectPos, PoresScale, PoresSize, PoresSeed` | `Pores` | `r = clamp(PoresSize, 0.04, 0.90)`, `saturate(1 − smoothstep(r×0.40, r, d))` |
| `ProceduralConcreteCracks` | `ObjectPos, CrackScale, CrackWidth, CrackWarp, CrackSeed` | `Cracks` | ridged-fbm + домен-warp (3 value-noise при `p×0.45`, сдвиги 9.1 / 23.7 / 51.3, под `if (CrackWarp > 0.0001)`) × пятно-маска `smoothstep(0.30, 0.72, fbm(p×0.35 + 13.9))` |
| `ProceduralConcreteBlotch` | `ObjectPos, BlotchScale, BlotchStretch, BlotchSeed` | `Blotch` | `p.y /= max(0.05, BlotchStretch)` → сырой `saturate(fbm)`. `Stretch = 1` — изотропно, `> 1` — вытянуто вдоль локальной Y |
| `ProceduralConcreteScratchA` | `ObjectPos, ScratchScale, ScratchStretch, ScratchDetail, ScratchSeed` | `Scratch` | механизм бронзы/дерева 1:1 |
| `ProceduralConcreteScratchB` | `ObjectPos, ScratchScale, ScratchStretch, ScratchDetail, ScratchSeed` | `ScratchB` | то же, сид `+17.3`, сжатие по другой оси |
| `ProceduralConcreteScratchC` | `ObjectPos, ScratchScale, ScratchStretch, ScratchDetail, ScratchSeed, ScratchAngle` | `ScratchC` | то же, сид `+41.1`, собственный угол поворота |
| `ProceduralConcreteScratchMask` | `ObjectPos, ScratchMaskScale, ScratchMaskSeed` | `ScratchMask` | гасящая маска: `PCConc_Blotch(..., Stretch = 1, ...)` |

Внутренние хелперы (на них граф не ссылается): `PCConc_Hash13` (хеш без `sin`),
`PCConc_ValueNoise3`, `PCConc_Fbm3` (3 октавы), `PCConc_Ridge`, `PCConc_WorleyF1`
(3×3×3, отдаёт ещё и хеш выигравшей ячейки — «тон зерна»), `PCConc_ScratchDir`.

Три экземпляра CF-ноды `ProceduralConcreteBlotch` отличаются только проводкой:
у облачности и мокрых пятен `BlotchStretch` **не подключён** (значение слота
принудительно = 1, это константа, а не свойство), у потёков он подключён к
`_Bloom_Stretch`.

## Требования к геометрии

1. **Единичный локальный масштаб** (габарит ≈ 2×2×2): маска кромок сравнивает
   `|x|,|y|,|z|` с `_Edge_Position`. Для меша другого размера либо нормализовать
   габарит, либо задать `_Edge_Position` равным половине наибольшего размера
   (для куба 1×1×1 — 0.5).
2. **Локальная Y — «вверх» детали**: по Y вытягиваются потёки и высолы
   (`_Bloom_Stretch`). Стена/плита/фундамент должны стоять в своей локальной
   системе координат «как в жизни», иначе высолы пойдут вбок.
3. **Локальный масштаб влияет на частоту.** Всё процедурное считается в object-space,
   поэтому масштабирование объекта в сцене масштабирует и рисунок. Это осознанный
   компромисс FO-safe шума, а не баг: для мелкой детали поднимать `_Pores_Scale` /
   `_Agg_Scale`, а не масштабировать объект.
4. **Фаски не нужны.** Кромка считается по координатам, а не по геометрии, поэтому
   низкополигональный меш без фасок тоже получает полосу кромки.
5. **UV не нужны вообще.** Ни один слой не читает UV.

## Рельеф: у каждого вида свой коэффициент и свой знак

`Normal From Height` считает
`Out = SafeNormalize(T − Strength · surfGrad)`, где `surfGrad` линейно по входу,
а вход собран как `заполнитель×_Aggregate_Bump + раковины×_Pores_Bump + трещины×_Crack_Bump`.
Значит каждый вид входит в градиент ровно со своим коэффициентом, а **знаки** задают
направление: зерно выпуклое (плюс), раковины и трещины — впадины (минус).

`_Aggregate_Bump` / `_Pores_Bump` / `_Crack_Bump` — это амплитуды **высоты**
(они уходят в `ddx`/`ddy`), а **не** сила рельефа. Общий множитель рельефа один:
слот `Strength` **не подключён**, поэтому берётся `m_Value` шаблонного слота —
`0.009999999776482582`, то есть `float(0.01)` в сгенерированном шейдере. Из
материала эта величина **не настраивается**.

Проверено в сгенерированном HLSL (`Temp/concrete_generated.txt`):

```hlsl
float3x3 _NormalFromHeight_<guid>_TangentMatrix =
    float3x3(IN.WorldSpaceTangent, IN.WorldSpaceBiTangent, IN.WorldSpaceNormal);
Unity_NormalFromHeight_Tangent_float(_Add_1b180cae2ad34cceb097ef688fde9dab_Out_2_Float,
    float(0.01), <Position>, <TangentMatrix>, <Out>);
surface.NormalTS = _NormalFromHeight_<guid>_Out_1_Vector3;
```

Тело функции там же (строка 475) подтверждает роль `Strength`:

```hlsl
float3 surfGrad = surface * (dHdx*crossY + dHdy*crossX);
Out = SafeNormalize(TangentMatrix[2].xyz - (Strength * surfGrad));
```

### Открытый вопрос: сила рельефа

`0.01` — значение по умолчанию узла, унаследованное из шаблона бронзы. Строка
сборщика `// Strength не подключён -> 1.0, общего множителя нет` **неверна**
(исправлена). Читается ли рельеф при множителе `0.01` — **`NOT RUN`** (визуал за
пользователем). Если не читается, правильное лечение — не менять
`_*_Bump` на порядок, а **подключить** в слот `Strength` (id `2`) Vector1-свойство,
чтобы силу рельефа можно было настраивать из материала.

Кромка и царапины в рельеф **не входят** — только альбедо и глянец.

## Инцидент: потерянная цепочка рельефа (`NormalTS`)

**Симптом.** Ребро `NormalFromHeight → NormalTS` в файле графа было, а в
сгенерированном шейдере цепочки рельефа не было вообще:
`surface.NormalTS = IN.TangentSpaceNormal;`, ни одного упоминания
`NormalFromHeight` и ни одного использования `_Aggregate_Bump` / `_Pores_Bump` /
`_Crack_Bump`.

**Причина.** У `NormalFromHeightNode` рантайм-id слотов **не последовательны**:
`In = 0`, `Strength = 2`, `Out = 1`. Сборщик перенумеровывал `m_Id` слотов в номер
позиции в массиве `m_Slots` → `0 / 1 / 2`. Ребро с `"m_SlotId": 2` стало указывать
на **вход** `Strength`, импортёр такое ребро **отбросил без предупреждения**,
`NormalTS` остался неподключённым, а `Normal From Height`, два `Add` и три
`Multiply` вырезались как неиспользуемые.

**Диагностика — три независимых источника.**

| Источник | До правки | После правки |
|---|---|---|
| `Temp/ConcreteEdges.cs` — рёбра в **файле** | 174 | 174 |
| `Temp/GraphAudit.cs` — рёбра в **импортированном** `GraphData` | **173**, ребра `NFH → Block` нет | **174**, есть `NormalFromHeightNode[1] -> BlockNode[0] (NormalTS)` |
| `Temp/DumpConcreteShader2.cs` — сгенерированный текст | 233 160 символов, `Unity_NormalFromHeight_Tangent_float` **отсутствует** | 248 935 символов, функция и `surface.NormalTS` **присутствуют** |

Расхождение «174 в файле против 173 при импорте» и было уликой.

**Правка.** Три значения в `Concrete.shadergraph`: у ребра от `a7d1428c…`
`"m_SlotId"` `2 → 1`; у слота `Strength` `"m_Id"` `1 → 2`; у слота `Out` `"m_Id"`
`2 → 1`. Плюс исправлено правило в `Temp/ConcreteGraphBuilder.cs` (перенумерация
`m_Id` по индексу убрана), чтобы повторная генерация графа не вернула баг.

## Грабли формата `.shadergraph` (для будущих правок)

1. `.shadergraph` — поток JSON-документов, разделитель — `}` + пустая строка + `{`.
   **Пустая строка внутри документа обрывает документ.**
   Проверено на этом графе: `blankLineDocs = 0`.
   ⚠ **Переводы строк по проекту разные.** Замер (подсчёт байтов `CR`/`LF` по всем
   `*.shadergraph`): `Concrete.shadergraph` — **чистый CRLF** (`CR = LF = 18235`),
   `Bronze.shadergraph` — преимущественно CRLF (`CR = 15844`, `LF = 15900`),
   `BronzeEdgeNoise*.shadergraph` — LF плюс один одиночный `CR`,
   `Glass`, `IronRust`, `Plastic`, `Wood`, `Steel*` — LF (`CR = 0`).
   При сборке бетона файл был LF: сборщик и `ConcreteEdges` резали его по
   литералу `"}\n\n{"` и находили 508 документов. **После точечной правки
   `Concrete.shadergraph` стал CRLF**, то есть разделитель в нём теперь
   `}\r\n\r\n{`. Инструмент, режущий по литералу `"}\n\n{"`, увидит **один**
   документ вместо 508 и не найдёт ни одну ноду (именно так и вышло при аудите
   `Temp/NfhStrengthAudit.cs`). Перед текстовым разбором нормализовать переводы
   строк или резать по регулярке `}\s*\n\s*{`. Для импорта Unity это безразлично:
   граф с CRLF импортируется без замечаний (проверено).
2. Последний документ в потоке сохраняет свою закрывающую `}` — при сборке файла
   из списка документов её нужно дописать.
3. Свойства блэкборда адресуются по `m_ObjectId` (32 hex); `PropertyNode` ссылается
   на свойство через `"m_Property": {"m_Id": "<m_ObjectId свойства>"}`.
4. Блоки мастер-стека входят в `m_Nodes` корня и дополнительно перечислены в
   `m_VertexContext.m_Blocks` / `m_FragmentContext.m_Blocks` (проверено:
   `blocksInBronzeNodes = True`).
5. Слот `m_SlotId` ссылается на **числовое** `m_Id` слота, а оно **не всегда равно**
   позиции в массиве `m_Slots`: у `NormalFromHeightNode` бронзы порядок
   `In(0), Strength(2), Out(1)`. **Перенумеровывать `m_Id` в позицию массива нельзя** —
   импортёр резолвит ребро по значению `m_SlotId`, и после перезаписи `"m_SlotId": 2`
   начинает указывать на вход `Strength` вместо выхода. Ребро **молча выбрасывается**,
   ноды рельефа вырезаются как неиспользуемые, `NormalTS` остаётся неподключённым.
   Именно так был потерян весь слой рельефа (см. «Инцидент: потерянная цепочка
   рельефа»). Перенумерация по индексу допустима только там, где **один и тот же**
   шаблон слота переиспользуется для нескольких входов (CF-нода: `ObjectPos = 0`,
   входы `1…N`, выход `N+1`) — у `NormalFromHeightNode` каждый слот свой, поэтому
   его шаблонные `m_Id` сохраняются как есть.
6. Значение по умолчанию входа правится в `"m_Value"` слота (`{x,y,z,w}` у
   `DynamicValueMaterialSlot`); **`"m_DefaultValue"` не трогать**.
7. Целевой рендер — URP Lit (`UniversalTarget` + `UniversalLitSubTarget`), Forward.
8. Инцидент этого материала: правка сборщика через `replace_in_file` с завершителем
   `>>>>>>> REPLACE` вместо `+++++++ REPLACE` вписала текст диффа **внутрь** файла
   (`Temp/ConcreteGraphBuilder.cs`), а исправление «вставленных не туда» строк
   `defs` дало ошибку компиляции Roslyn. Лечение — правка с корректным завершителем
   и повторная сверка файла чтением. При правках сборщиков **всегда перечитывать
   результат**, а не верить отчёту тула.
