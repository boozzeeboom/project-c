# Материалы ProjectC — генеративный подход без текстур

> Статус: каркас. Первый материал в работе: `SteelRust/`.

## Цель

95% объектов игры — без текстур. Только процедурные адаптивные материалы
(шум в object-space + маски + vertex colors как арт-дирекшн).
Текстуры — только главный герой и ключевые персонажи (исключение, не правило).

## Почему так

- Память: MMO-sandbox, сотни пропсов. Текстуры на каждый ящик/панель/трубу —
  это гигабайты стриминга и вечная боль с атласами.
- Стиль: постапокалиптическая небесная цивилизация — потёртый металл,
  ржавчина, пыль. Всё это хорошо ложится на шум + правила размещения
  (верх/низ, стыки, кромки), а не на уникальные развёртки.
- Масштаб мира (`SCENE_SIZE = 79999f`, Floating Origin): материалы обязаны быть
  FO-safe — см. раздел ниже.

## Железные правила

1. **Никакого `AbsoluteWorld`-шума без компенсации.** Ребейз (F8/авто/F9)
   сдвигает корни сцен целиком. Шум, привязанный к мировым координатам,
   «поплывёт» относительно объекта после сдвига. База — **object-space**
   позиция + стабильный сид (свойство материала, а не мировая позиция).
   Мировые координаты — только для эффектов, где поплытие допустимо
   (далекие облака), либо через глобальный uniform сдвижка (пока не вводим).
2. **Forward-совместимость.** Рендер `ProjectC_URP_Renderer` — Forward
   (`m_RenderingMode: 0`). Никаких GBuffer-трюков из Deferred-гайдов.
   Проверено через unity-mcp `mcpforunity://pipeline/renderer-features`
   (04.10.2026): EdgeDetection + VolumetricClouds + DistantFocus, все Forward.
3. **Vertex colors — главный канал арт-дирекшна.** Шейдер даёт правила,
   художник — маски. Договор по каналам единый для всех процедурных
   материалов (см. ниже). Красить — в Blender (bake Pointiness/AO) или
   ProBuilder/Polybrush прямо в редакторе.
4. **SRP Batcher friendly.** Один шейдер — много материалов-пресетов.
   Вариативность — через свойства материала, не через отдельные шейдеры.
   Ключевые слова (`shader_feature`) — минимум, только качество Near/Far.
5. **Два качества.** `Near/Hero` (полный шум, 3 октавы) и `Far/Low`
   (1 октава, без bump). LOD-переключение — материалами или ключевым словом,
   не дублированием шейдеров.

## Договор по vertex colors (единый)

| Канал | Смысл | Кто пишет |
|---|---|---|
| R | Полость/стык: куда садится ржавчина, грязь, пыль (вогнутое) | Bake AO / Pointiness concave, ручная докраска стыков |
| G | Выпуклая кромка: сколы, потёртость до металла (выпуклое) | Bake Pointiness convex / Curvature, фаски обязательны |
| B | Крупная вариация: оттенок панелей, тон, выцветание | Художник / рандом по деталям |
| A | Резерв: пыль сверху, потёки, мокрота | По материалу |

Низкополигональный меш без фасок кромку не удержит: G-канал требует
дополнительных edge loops у кромок. Куб без фаски = нет кромочной маски,
это нормально и документируется, а не чинится шейдером.

## Известная ошибка сборки: рельеф (`Normal From Height`) не работает с первого прогона

**Симптом.** Цепочка высоты в JSON графа есть, ребро `NFH[1] → NormalTS` есть,
`ShaderHasError = false`, и `surface.NormalTS = _NormalFromHeight_…_Out_1_Vector3;`
в сгенерированном шейдере тоже есть — **а рельефа на объекте нет**. Проверка
«цепочка на месте» этот дефект не ловит, поэтому он повторялся в каждом
материале и каждый раз «лечился» вручную после первой сборки.

Причин две, обе — в builder'ах, которые клонируют `NormalFromHeightNode` из
бронзового шаблона.

### Причина 1 (системная): `Strength` остался шаблонным и равен 0.01

Слот `Strength` **не подключается**, поэтому нода берёт значение по умолчанию,
а оно приходит из шаблона бронзы и равно **0.01**, не 1.0. `Strength` — прямой
множитель силы рельефа (`Out = normalize(T − Strength·∇In)`, где `∇In` уже
приведён к мировому масштабу), поэтому 0.01 гасит рельеф в **100 раз**. При
коэффициентах вида ~0.5–1.6 эффективная сила выходит ~0.005–0.016 — визуально
это ноль.

Замер по сгенерированным шейдерам (`ShaderGraphImporter.GetShaderText`),
по всем 15 графам `Assets/_Project/Materials/`:

|---|---|---|
| Wood | `float(1)` | рабочий |
| IronRust | `float(1)` | рабочий |
| Bronze | `_Property_…` (отдан свойству) | рабочий |
| Glass | `_Property_…` (отдан свойству) | рабочий |
| **Brick** | `_Property_…` (отдан свойству `_Bump_Strength`, дефолт 1.0) | рабочий — эталон лечения: второй аргумент вызова равен свойству, `float(0.01)` в тексте — 0 вхождений |
| **Plate** | `_Property_…` (отдан свойству `_Bump_Strength`, дефолт 1.0) | рабочий — второй материал без дефекта: второй аргумент вызова равен свойству, `float(0.01)` в тексте — 0 вхождений |

Никакой «калибровки под 0.01» нет: 0.01 — это незакрытый дефолт шаблона.
Материалы, где рельефом реально занимались, стоят на `1.0` (Wood, IronRust),
а Bronze/Glass вообще отдают `Strength` свойству материала. Формулировка
«коэффициенты откалиброваны под Strength = 0.01, рабочий диапазон −2…+2»,
попавшая в ранние README, была **рационализацией этого дефекта** и снимается.

### Причина 2 (терминальная): слоты `NormalFromHeightNode` нумеруются нативными id

`m_Slots` ноды лежат как `[In, Strength, Out]`, но рантайм-идентификаторы —
**`In = 0`, `Strength = 2`, `Out = 1`** (не по порядку массива). Если builder
проставил id по позиции (`0, 1, 2`), ребро «выход NFH» уходит на слот **2**,
который выходом не является. Импортёр молча выбрасывает такое ребро, у ноды
`Normal From Height` не остаётся потребителя, и генератор не emit'ит её вызов
**вообще**. Ровно это сейчас в `Plastic/`: узел в графе есть, а
`Unity_NormalFromHeight_Tangent_float` в сгенерированном шейдере не вызывается
ни разу.

### Обязательная проверка после каждой сборки графа

Наличия ребра в JSON и `ShaderHasError = false` **недостаточно**. Минимум три пункта:

1. В файле графа у трёх слотов `NormalFromHeightNode` `m_Id` должны быть
   `In = 0`, `Strength = 2`, `Out = 1`, а `m_SlotType` у `Out` — `1`.
2. В сгенерированном тексте должна быть строка `Unity_NormalFromHeight_Tangent_float(`
   и **второй аргумент** в ней должен быть задуманным значением, а не `float(0.01)`
   по наследству от шаблона.
3. В том же тексте — `surface.NormalTS = _NormalFromHeight_…_Out_1_Vector3;`.

Пункт 1 ловит причину 2, пункт 2 — причину 1. Пункт 3 сам по себе бесполезен:
он проходит и при погашенном рельефе.

### Как починить

- Слоты — `FixNfh` (id по имени слота), выход брать **по id 1**.
- `Strength` — не оставлять шаблонный дефолт. Правильно **подключить слот к
  свойству материала** (`_Bump_Strength`), как в Bronze/Glass: тогда сила
  рельефа настраивается из пресета, а не только правкой графа. Альтернатива —
  проставить дефолт слота `1.0`, как в Wood/IronRust, но тогда все `*_Bump`
  надо пересчитать: они подбирались под эффективный множитель 0.01.
