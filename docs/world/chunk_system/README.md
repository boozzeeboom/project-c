# Chunk System — ресёрч: нужен ли клиентский чанк-лоадер

**Дата:** 2026-09-27. **Статус:** ресёрч завершён, кода нет, решений по сценам/префабам не меняет.
**Вопрос пользователя (дословно, сжато):** нужен ли нам клиентский чанк-лоадер, поможет ли он в оптимизации,
сможем ли мы с ним сделать видимые города вдали и террейн/горы (сейчас картинка хорошая);
как это будет работать на host-client / server-client среди нескольких клиентов; как ляжет на FO-архитектуру.
**Ранние прототипы чанков:** игнорировать как действующую систему — они зафиксированы как deprecated в §2 и `01_CURRENT_STATE.md` §6.

## Короткий вердикт (TL;DR)

1. **Полноценный клиентский чанк-лоадер в смысле «грузить/выгружать куски мира 2×2 км с генерацией геометрии» — НЕ нужен.**
   Текущая картина хорошая именно потому, что мир — это **один authored `Terrain_0_0` 80×80 км** (1 draw call в фоне),
   а не набор процедурных чанков. Воскрешение legacy-прототипов (`WorldStreamingManager` + `ChunkLoader` +
   `ProceduralChunkGenerator`, сетка 2000) **ухудшит** картинку и перф, а не улучшит (§2, `01_CURRENT_STATE.md` §6).
2. **Что действительно нужно для «видимых городов вдали и гор» — это не чанк-лоадер, а три другие системы, две из которых уже есть:**
   - (а) **дальность прорисовки как «фон, а не off»** — уже реализована `T-LOD01`
     (`ViewDistanceConfig` / `ViewDistanceApplier` / `DetailDistanceCuller`, пресеты 30K/60K/120K);
   - (б) **LOD/HLOD + импосторы/билборды для городов и пиков** — частично есть (`LOD Group` в дизайне ландшафта),
     для городов отсутствует и является следующим шагом (`03_DISTANT_CITIES_TERRAIN.md`);
   - (в) **серверный per-client interest (кому что видно)** — зачаток есть (`ServerSceneManager` + `NetworkShow/Hide`),
     но требует hardening, а не чанк-RPC (`04_NETWORK_TOPOLOGIES.md`).
3. **Оптимизация:** чанк-лоадер почти ничего не даёт на масштабе 1 активной сцены, где доминируют
   террейн-фон + туман + тени + мелкие пропсы. Главные рычаги — `camera.far`, `shadowDistance`, `fogScale`,
   визуальный culling пропсов, LOD-смещение. Выгрузка геометрии чанками даёт выигрыш только когда
   в кадре реально тысячи объектов/гигабайты текстур — у нас этого нет (замеры и бюджет — в §3 и `02_*`).
4. **Сеть:** legacy-схема «сервер шлёт каждому клиенту `LoadChunkClientRpc` на каждый чанк» не масштабируется
   на N клиентов и конфликтует с NGO-авторитетом и scene-placed спавном. Правильная топология:
   **сервер владеет interest/видимостью, клиент автономно владеет визуальным LOD**; чанки как сетевые сущности отсутствуют.
   Детали по host / dedicated / late join — в `04_NETWORK_TOPOLOGIES.md`.
5. **Floating Origin:** любой чанк-контейнер обязан жить **под корнями `WorldScene_*`** и участвовать в транзакции
   `GlobalMotionControlledRebaseSlice` как явный participant с маркером/каталогом/digest; кэши `Vector3` —
   через `ApplyRebaseTranslation` на обоих путях (success + rollback); `FloatingOriginMP` (legacy) воскрешать запрещено.
   Полный разбор — в `05_FO_INTEGRATION.md`.

## Правила чтения этого ресёрча

- Все пути к коду — относительно корня репозитория. После пути указано `:строка` для навигации
  (например `Assets/_Project/Scripts/World/Scene/ClientSceneLoader.cs:92`).
- Факты о рантайме, не подтверждённые кодом/сценой, помечены `NOT VERIFIED` — их проверяет пользователь в Play Mode
  (агент Play Mode не запускает, скриншоты не делает — см. `AGENTS.md` и скиллы `dont-start-play` / `manual-playtest-only`).
- Тикеты вида `R2-003`, `T-FO06Z` сохраняются в тексте — это трекер проекта.
- Этот ресёрч не меняет сцены, префабы, каталог FO, `ProjectSettings`, `Packages` — только документы здесь.
