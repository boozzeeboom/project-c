## 2. Что изменено в коде

### 2.1 `AdditionalLightIntensityController.cs` (владелец `Light.intensity`)

- `LightState` получил `fadeWeight` (0…1), `fadeTarget`, `fadeInStartTime`, `fadeOutStartTime`, `fadeOutActive`.
- Запись яркости только в одном месте: `value = smoothedIntensity * flicker * fadeWeight` (`ApplyActiveCore`);
  вес идёт `Mathf.MoveTowards` со скоростью `1/fadeInSeconds` вверх и `1/fadeOutSeconds` вниз.
- `BeginFadeIn` (из `ApplyImmediate`): цель 1; при `fadeWeight > 0.001` переход **не перезапускается**
  (resync/возврат уже горящей лампы), при `!fadeEnabled || fadeInSeconds <= 0` вес сразу 1 (поведение L5).
- `ShouldHoldEnabledForFade(Light)` — контракт для пула: `true` только если fade включён, `fadeOutSeconds > 0`,
  источник в `_activeLights`, `fadeWeight > 0.001` и не вышел дедлайн `fadeOutSeconds + 0.05`.
- `ApplyIntensityCore` на immediate-путях (`forceApply`, загрузка сцены) ставит вес активным лампам в 1 —
  тёмного кадра на старте нет.
- Диагностика: `FadeEnabled/FadeInSeconds/FadeOutSeconds/FadeActiveCount/FadeInCount/FadeOutCount/
  FadeMaxWeightError/LastFadeMs`, `FadeConfigLine`, `ApplyFadeConfig(bool,float,float)`, `ResetFadeProfile()`,
  `GetFadeProfileSample(...)`, `FadeProfileT90Sec/T90Frames/MaxJumpRatio`.
- **По итогам гейта** дефолт `fadeOutSeconds` изменён `0.3 → 0` (см. §4.2) с комментарием в `Tooltip`.

### 2.2 `PrimumLightPool.cs` (владелец `Light.enabled`)

- `gateGraceSeconds = 0.4`; `emitting` в `CheckCore` теперь `gateEps < 0 || intensity > gateEps ||

**Причина пика.** `HeldForFade` — число источников, удержанных в одном чеке пула. Максимум совпадает с
моментом, когда после разворота камеры на 180° набор возвращается к базовой позе: `CONEPROBE` в STREET/12 ч
показывает `active = 85` в развороте против 42 в базе, и при возврате разом выходят 75 источников. В обычном
установившемся режиме удержание равно 0 во всех кейсах. Тем не менее по правилу брифа (§2, §3 п.6)
превышение >16 — основание отклонить fade-out, поэтому `fadeOutSeconds` по умолчанию `0`.

**Что это значит на практике:** появление света плавное (причина «щелчка» при развороте и беге вечером),
исчезновение — мгновенное, как в L5. Механизм fade-out сохранён и включается одним значением
(`fadeOutSeconds > 0` или `ApplyFadeConfig(true, 0.15, 0.30)`), чтобы вернуться к нему отдельной итерацией,
например с понижением `hysteresis` на возврате или ограничением числа удерживаемых источников.

## 6. Ограничения и оговорки

- **`t90` ниже нижней границы ±20 % в трёх кейсах** (0.107/0.118/0.118). Это квантование кадра: вес считается
  `MoveTowards` с шагом `dt/0.15`, и при 28–36 fps 90 % достигается за 3–4 кадра. Полный ramp до 1.0 занимает
  0.15 с; кривая линейна (`FadeMaxWeightError` ≈ один шаг).
- **`FadeMaxWeightError` 0.18–0.23 не является ошибкой формы кривой** — это расхождение первого записанного
  кадра с идеалом: `MoveTowards` уже сработал до записи сэмпла.
- **`fadeMaxJumpRatio` считается по записанной яркости**, поэтому flicker-провал профильной лампы попадает в
  метрику (ADMIN/интерьеры — 0.22–0.24 при flicker). Для ламп без мерцания метрика чистая.
- **`HeldForFade` — это последний чек пула, а не накопительный счётчик**; пик за кейс включает переход позы и
  разворот камеры на 180°, установившееся значение равно 0 во всех кейсах.
- **`LastFadeMs`** измеряет весь покадровый проход активного набора (fade + мерцание), а не только блок веса;
  CPU-гейт считается по `alicMs` (`ProfilerRecorder`).
- **Дедлайн удержания** отдаёт `enabled = false` на ближайшем чеке пула (≤0.25 с) после достижения веса 0,
  поэтому фактическое удержание `enabled` может превышать 0.30 с, но `intensity` в это время уже 0 —
  невидимо.
- **FARM-позы**: `NOTE;farm_cluster` пишется каждый кадр, секунды/FPS там нерепрезентативны; выводы — по
  структурным метрикам.
- **`gpuMs` шумный** (6.25–12.30 мс на одном конфиге) — для выводов не использовался.
- **`SetVersion`** в CSV кумулятивный по прогону; приращения по окнам кейсов посчитаны вручную (§4.2).
- Замер — единственный прогон; повтор выполнен только для P1/18 ч и совпал по `dc` и `active`.

## 8. Что осталось

- **Визуальный sign-off L6** — плавность появления, отсутствие «щелчка» на гашение, flicker, переходы часа.
- **Fade-out** — вернуться отдельной итерацией, если «щелчок» на выключение будет мешать: нужен способ
  ограничить число одновременно удерживаемых источников (например ≤16 с приоритетом по близости/B≥1) или
  сглаживать массовый выход через `hysteresis` на возврате, не ломая `cap`.
- **Input-flake F9** (`no_rebase_plan`, 2 нажатия) — отдельный тикет; световую политику ради этого не менять.
