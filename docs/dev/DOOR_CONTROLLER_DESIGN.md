# DoorController v2 — дизайн-нота

## Проблема (v1)

`DoorController` был затычкой: голый `Vector3 slideDirection` + `float slideDistance`
в метрах. Чуть ошибся осью/дистанцией — дверь «улетает фиг пойми куда»,
подбор параметров занимал много времени. Типа двери не было в принципе
(только слайдер), все поля всегда в куче.

## Решение

### Типы дверей (`DoorType`)

| Тип | Панели | Для чего |
|---|---|---|
| `SlidingSingle` | 1 (`doorModel`) | Обычная сдвижная дверь каюты |
| `SlidingDouble` | 2 (`leftPanel`/`rightPanel`, разъезд) | Широкие проёмы, **ангарные ворота** |
| `HingedSingle` | 1 пивот + панель | Распашная дверь, петли слева/справа |
| `HingedDouble` | 2 пивота + панели | Двустворчатая распашная, ворота |
| `LiftUp` | 1 (`doorModel`, едет вверх) | **Ангарная шторка**, гаражный подъём |

Ангар = `SlidingDouble` (разъезд в стороны) или `LiftUp` (шторка вверх),
подсказка продублирована в инспекторе.

### Направление — словами, не вектором

- Сдвижная: `SlideSide` — Влево / Вправо / Вверх / Вниз / Вперёд / Назад
  (**в осях РАМКИ** — объекта двери, стрелки видно в Scene View).
- Распашная: `HingeSide` — петли слева / справа + подписанный угол
  −180…180 (знак разворачивает сторону, если открылась не туда).
- Двустворчатые направления зеркалятся автоматически.

Важно: оси рамки ≠ оси корабля, если корень повёрнут (heavyII: 270/90, ×180).
Поэтому в инспекторе есть кнопка «🧭 Оси рамки = мировые»,
а валидация ловит отъезд в тонкую сторону панели и створки поперёк оси.

### «На свой объём» по умолчанию

`OpenDistanceMode.AutoBySize`: дистанция = габарит створки вдоль оси сдвига
× `sizeFactor` (1.0 = ровно на свою ширину). Габарит меряется по
Renderer/Collider-потомкам, в локальных единицах родителя.
Ручной режим остался (`Manual`), рядом кнопка «📐 Подставить габарит»
и предупреждение, если ручная дистанция > 3× габарита («улетит»).

### Анимация без дрейфа

- Длительность в секундах (`openDuration`), а не скорость м/с — время
  открытия предсказуемо при любой дистанции.
- Поза всегда вычисляется от закэшированной закрытой (`closed + offset`),
  а не от текущей — накопления ошибки нет, дверь не может «улететь».
- Тоггл во время анимации разворачивает её с текущего места
  (раньше ввод просто игнорировался).
- Кривая easing (`openCurve`), автозакрытие по таймеру, события
  `onOpened`/`onClosed`.
- Всё в **локальных** координатах → безопасно для Floating Origin
  (ребейз двигает корни сцен, локальные позы не меняются).

### Совместимость

- Публичный API сохранён: `Toggle()`, `Open()`, `Close()`, `IsOpen` —
  `NetworkPlayer.TryInteractNearestDoor()` не меняется.
- Старые сериализованные поля (`slideDirection`, `slideDistance`,
  `slideSpeed`) оставлены скрытыми, при первой загрузке мигрируют
  в новые поля в режиме `Manual` — старые двери ведут себя 1:1 как раньше.
- `ShipPresetCreator` переведён на новый API.
- Свежий компонент (`Reset()`) стартует с `AutoBySize` — новые двери
  из коробки отъезжают на свою ширину.

### Редактор

`DoorControllerEditor` показывает только поля выбранного типа + общие
(тайминг, события). Кнопки: превью открыть/закрыть в Edit Mode,
создание пивотов петель по габариту, подстановка габарита.
Ошибки/предупреждения собираются методом `GetSetupIssues()` рантайма.

## Проверка (пользователем, NOT RUN агентом)

1. Console → 0 errors после компиляции.
2. Открыть префаб корабля с дверью → инспектор показывает новый редактор,
   старая дверь мигрировала (режим «Вручную», поведение прежнее).
3. Новая дверь: тип → панели → «По габариту» → превью → F8/F9 сдвиг:
   дверь на месте, 0 errors.
4. F → дверь открывается/закрывается, повторный F mid-animation разворачивает.
