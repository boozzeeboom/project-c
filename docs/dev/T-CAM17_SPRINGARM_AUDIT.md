# T-CAM17 — Полный аудит SpringArmCamera

> **Статус:** дизайн-нота → реализация
> **Дата:** 2026-09-28
> **Файл:** `Assets/_Project/Scripts/Core/SpringArmCamera.cs` (+ префаб `ThirdPersonCamera.prefab` без изменений)
> **Контекст:** жалобы — камера прыгает при pitch вниз «к полу» (тянется к персонажу и назад),
> падение — рывки («тошнота»). Эксперимент пользователя: `adaptiveDistanceEnabled=false` → прыжки
> исчезают; `dynamicLagEnabled=false` + adaptive вкл → прыжки остаются. Диагноз подтверждён: adaptive.

## 2. Корневая причина F1 (подробно)

Контур: `T` (`_targetDistance`) → `C` (`_currentDistance`, SmoothDamp 0.5 с) → desired →
`SphereCast` → `A` (`actualDist`, камера прибита к стене = const, пока `C` за стеной).

- Shrink активен при `A/U < 0.7 && colliding` и тянет `T → A−0.7`, что **меньше** расстояния
  до стены → `C` следует ниже стены → луч короче стены → `colliding=false`.
- Recovery тянет `T → U=5`, что **больше** расстояния до стены → `C` уезжает за стену →
  `colliding=true`. Цикл замкнулся. Период задают `adaptiveSpeed 3` + `recoverySpeed 2` +
  SmoothDamp 0.5 с ≈ 1–2 с — наблюдаемое «туда-сюда».
- F2 снимает единственное демпфирование (задержка 0.5 с открывается один раз и навсегда),
  F4 превращает качание в прыжки (ступенька замороженной точки).

## 3. Решение (реализация в этом тикете)

1. **Adaptive → 3 состояния (SHRINK / REST / RECOVER)** — REST и есть точка покоя:
   shrink только если «не влезает» (`_wasColliding && T > A + fitDeadband 0.3 м`);
   если у стены, но влезает — держать `T`, таймеры в ноль; recovery — только после
   устойчивого просвета (`recoverDelay` 0.3 с, таймер копится каждый кадр, `_lastClearTime`
   удаляется). Shrink тоже за задержкой (`shrinkDelay` 0.2 с). Переключение на ratio
   больше не используется → F10 закрывается структурно.
2. **Stale-guard anti-pop (F4):** запоминать `_lagTargetPos` в момент коллизии
   (`_collisionLagPos`); замороженную точку отдавать, только если лаг-цель ушла < 0.35 м.
   Новое поле сдвигать в `TryApplyGlobalMotionCameraTranslation` (рядом с `_lastCollisionPos`,
   контракт T-FO06DD), на restore — консервативно приравнять к текущей (без изменения
   структуры снапшота). Плюс то же для новой сглаженной точки взгляда.
3. **Гистерезис vert-boost (F5):** вкл > 6.5 м/с, выкл < 3.5 м/с (`_vertBoostActive`).
   Петлю F6 полностью не рвём (нужен velocity цели — нет в API), гистерезис + существующее
   сглаживание `_lagSpeed` достаточно гасят охоту.
4. **Сглаживание точки взгляда (F7):** exp-Lerp `lookSmoothTime` 0.03 с (~2 кадра —
   1-кадровые щелчки убиты, отзывчивость сохранена). Снап состояния в `Snap/SetTarget/
   SetShipMode/Initialize/restore`, сдвиг при ребейзе.
5. **Зум (F8+F9):** нормировка скролла на нотчи (`/120`: 1 нотч ≈ 1.5 м при sens 3);
   быстрое следование дистанции `zoomFollowTime` 0.15 с, медленное `modeSwitchSmoothTime`
   0.5 с — только в окне `modeSwitchWindow` 1 с после `SetShipMode`.
6. **F11:** игнорить `CharacterController` в `ShouldIgnoreCollision` (чужие игроки;
   NPC уже covered через NavMeshAgent). Камера проходит сквозь персонажей вместо упора.
7. **F12:** дефолты кода = значениям префаба (0.5/50, корабль 2/350).

API-контракт не меняется (публичные сигнатуры те же; только новые `[SerializeField]`
с дефолтами и одно приватное поле в rebase-сдвиге).

## 4. Риски и откат

- Feel-изменения: более отзывчивый зум, чуть инертнее взгляд (0.03 с), камера проходит
  сквозь игроков. Всё крутится инспектором; откат — префаб-оверрайды или revert коммита.
- FO-ребейз: новые поля участвуют в сдвиге/ finite-check; снапшот-структура не тронута.
- Ручная проверка (Play Mode — пользователем, NOT RUN агентом):
  1) pitch в пол и держать — встала и стоит, поднял — отъехала (~0.3 с);
  2) стена: подошёл — поджалась и стоит, отошёл — вернулась;
  3) падение/прыжок — без брыков; 4) колесо — ~1.5 м/нотч; 5) walk↔ship — мягкий переход;
  6) F8/F9 — без попа камеры; 7) толпа игроков — камера не упирается в чужих.
