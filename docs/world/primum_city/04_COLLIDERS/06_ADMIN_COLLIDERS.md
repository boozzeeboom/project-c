## 2. Замер против первой посылки: у ADMIN **есть** перекрытия как объекты

Первая редакция этого документа утверждала: «14 плит — это ноль, `SLAB`/`FLOOR` в чанке нет,
перекрытия надо синтезировать по этажам». **Это неверно.** Перепроверка по именам и габаритам
показала, что все 14 — настоящие конструктивные плиты, и каждая ушла в бокс 1:1:

| Объект | Габарит (м) | z, м |
|---|---|---|
| `ADM_F1_FLOOR` … `ADM_F4_FLOOR` | 66.80 × 62.80 × 0.40 | 24.45…24.85 / 28.45…28.85 / 32.45…32.85 / 36.45…36.85 |
| `ADM_ROOF_SLAB` | 69.20 × 65.20 × 0.70 | 40.45…41.15 |
| `ADM_SLAB_DOME` | 24.00 × 24.00 × 0.70 | 40.45…41.15 |
| `ADM_LIB_GALLERY` | 21.00 × 22.00 × 0.40 | 28.45…28.85 |
| `ADM_WING_N/S_F1_FLOOR`, `_F2_FLOOR` | 30.00 × 32.00 × 0.40 | по этажу крыла |
| `ADM_WING_N/S_ROOF_SLAB` | 31.20 × 32.60 × 0.40 | по кровле крыла |
| `ADM_ROT_APRON` | 7.20 × 4.00 × 0.30 | (по габариту, форма не плита) |

Уровни этажей подтверждаются окнами — центры лент ровно **26.700 / 30.700 / 34.700 / 38.700**,
разброс внутри этажа **0.000** (ленты F4 доходят до 40.700, высота 6.50).
То есть шаг 2.50 м на этаж, и синтез уровней из §2.1 старого плана **не нужен** — он уже есть в объектах.

**Ошибка была не в отсутствии плит, а в их форме:** плиты не сплошные. Поэтому бокс по габариту
залил бы лестничные клетки, атриум и библиотечный void, то есть ровно тот дефект, из-за которого
в домах игрок не мог пройти (`05_HOUSES_BOXES.md` §7).

### 2.1 Плиты с дырками → резка лучевой сеткой

Замер площади меша против площади габарита и доля пустых ячеек (сетка 56 × 40):

| Плита | Пусто | Что это |
|---|---|---|
| `ADM_F1_FLOOR` | 0.4 % | почти сплошная, небольшая выборка у фасада |
| `ADM_F2_FLOOR` | 26.8 % | атриум / void, форма буквой Г |
| `ADM_F3_FLOOR`, `ADM_F4_FLOOR` | 1.4 % | лестничная клетка точно под маршем |
| `ADM_ROOF_SLAB` | 23.0 % | кольцо под барабан + углы террасы |
| `ADM_SLAB_DOME` | 76.8 % | только обод кольца |
| `ADM_LIB_GALLERY` | 70.1 % | галерея вокруг void в два света |
| `ADM_WING_N_F2_FLOOR` | 3.3 % | угловая лестничная клетка |

Резка — `plate_boxes()` в `houses_boxes.py`: сетка `PLATE_STEP = 0.40`, один луч на ячейку сверху
вниз, покрытие маской `greedy_rects()`, боксы с `th = 0.0`.
Пустая доля < 0.2 % (`PLATE_HOLE_SHARE`) — плита считается сплошной и остаётся одним боксом.
Резка включается только когда в группе дома ровно **один** плитный объект; все 14 плит ADMIN —
каждая своя группа, поэтому режутся все 14.

**`PLATE_ERODE = 0`** (было 1). Эрозия на ячейку ошибается в ДРУГУЮ сторону: она **расширяет**
настоящую дыру на 0.40 м в сторону, а закрыть ею проход шириной больше игрока нельзя — ошибка
шага 0.40 м может только запечатать щель уже игрока. Теперь маска эродируется «в ноль»
(`er = [row[:] for row in mask]`), а не на клетку.

```
плит: 14 → 132 боксов        (ADM_SLAB_DOME — 60 из них)
после добавления резки по пятну марша: 113 → 122 бокса
```

Резка консервативна по построению: одна проба на ячейку, без эрозии — ошибка может только **уменьшить**
плиту, но никогда не запечатать дырку.

### 2.6 Крыши и марши: две причины «перекрытия мешают»

**а) Синтетическая крыша на каждом этаже.** У большинства групп стен ADMIN нет объекта крыши,
поэтому срабатывает `synth_roof()`. Группы разбиты ПО ЭТАЖАМ (`ADM_F1_WALL`, `ADM_CORR_F2`,
`ADM_WC_F3`, `ADM_OFF_F1`…), и `_roof_box` давала бокс на каждую полосу высот облака стен:

```
синтетических боксов 42, из них крупных 68x64 м на уровнях 24.73 / 29.01 / 33.29 / 37.57 / 41.85
плита F2 — 29.16…29.56, то есть бокс 29.01…29.14 садится ровно в ПРОЁМ шахты
```

Исправление в два шага: `_roof_box(..., top_only=True)` для синтетики (берётся только верхняя
полоса — верх группы) и выбрасывание синтетического бокса, если сверху есть настоящая плита,
низ которой садится на его верх (−0.05…+0.60 м). Крыш в сборке: **47 → 18**.

**б) Марш проходит сквозь плиту, в которой нет дыры.** Растр плиты вырезает только настоящие
дыры меша; там, где их нет или они смещены, марш остаётся под плитой:

| Место | Замер |
|---|---|
| Крыло N/S | марш 27.40…29.55, плита F2 низ 29.16 → 1.3 м марша под плитой, игрок встаёт за 0.4 м до площадки |
| Главная | марш 40.25…42.70 сквозь синтетическую крышу 41.73…41.98 — выхода на кровлю нет |

Исправление — `carve_plates_by_stairs()`: пятно марша (+0.12 м) вычитается из плиты/крыши,
если верх марша попал в низ плиты (−0.60…+1.80 м); плита делится на до 4 прямоугольников.
Плит: 113 → 122, крыш: 12 → 18.

**в) Правило для простого бокса.** `ADM_WING_N/S_STAIR_LANDING` — обычный параллелепипед
(8 вершин, 3.4 × 4.6 × 2.0). По вершинам направление хода не определить, и такая «площадка»
раньше становилась наклонным боксом поперёк стены 25.01…29.01. Теперь объект с **< 12 вершин**
всегда идёт сплошным боксом: гадать нечем.

**г) Направление марша — только замером (25.10.2026).** Разбор всех 28 лестничных объектов ADMIN
лучом сверху по сетке 0.30 м (`_analysis/dbg_adm_stair_geo.py`):

| Марши | План | Ход | Ступени |
|---|---|---|---|
| Главные `ADM_STAIR_M1..M4_A/B` | **3.60 × 4.00** | вдоль **3.60** (длинная сторона — поперёк!) | 104 вершины, плоскость верха СКО 0.041 м, уклон 29.8° |
| Крылья `ADM_WING_N/S_STAIR_FLIGHT_A/B` | 3.60 × 2.30 | вдоль 3.60 | 104 вершины, СКО 0.038 м, 30.0° |
| Библиотека `ADM_LIB_STAIR_E/W_FLIGHT` | 7.80 × 2.20 | вдоль 7.80 | 208 вершин, СКО 0.000 м, 27.1° |
| Площадки/подиумы/входные ступени | — | нет хода | 8 вершин, верх плоский |

Старое правило «ось = длинная горизонтальная сторона» для главных маршей давало **поворот
диагонали на 90°**: рампа `3.6 × 4.77`, уклон `a = 0.000` по верхней огибающей, подъём 2.14 м на
поперечной оси — игрок шёл по ней боком к ступеням. Ровно те 8 боксов выглядели как
«перепутаны оси». Теперь `stair_top_cells()` + `stair_plane()` дают градиент верха, ось =
`atan2(B, A)`, а низ/верх остаются из габарита (`bb[4]`/`bb[5]`) — они и раньше совпадали с
плитой и площадкой (25.26 → 27.41 → 29.55 … → 42.70).

Проверка после правки (`_analysis/dbg_adm_stair_fit.py`): 14 наклонных боксов против меша
ступеней — **максимальное отклонение 0.131 м**, промахов нет; в сцене у каждого бокса
опора под низом и верхом в пределах **0.06 м**, перекрытий хода **0 из 14**.

   `c/s` бокса — фрагменты получали координаты, преобразованные дважды (верх −80.64 / −46.75 /
   −23.63 / 14.90 при верных габаритах 0.40 × 62.80). Отсюда «27 мусорных плит» и пропажа
   F2/F3/F4/крыши в JSON от 25.10. Теперь фрагменты собираются напрямую (`c/s/ry`), без
   `make_box`. Тот же дефект был в `add_threshold_steps` — исправлен там же.
2. **Порог не срабатывал:** в `add_threshold_steps` стояло `dt > STEP_RISE_MAX → continue`, то есть
   ровно те перепады 0.30..0.60, которые и надо дробить, отбрасывались (замер входа: 0.43 м).
   Условие стало `dt > 2 × STEP_RISE_MAX` (одна промежуточная ступень лечит до 0.60 м).

**Крыльцо (`fill_level_gaps`, новое):** ступени и подиум стоят на одном уровне 24.85, но
между ними была яма 2.5 × 17.2 м с полом 24.40 — игрок падал на 0.45 и опять лез на 0.45.
Правило: если плоская ступень/площадка и плита на одном уровне (±0.10), а в плане между ними
разрыв ≤ 3.0 м при перехлёсте ≥ 1.0 м по другой оси, полоса разрыва мостится на уровне верха
(толщина 0.60). Мостятся только ямы у ступеней; разрывы между двумя плитами (шахта, атриум)
не трогаются. Сработало 3 раза: вход главного корпуса `c=(77.74, 24.55, −21.06) s=(2.54, 0.60, 17.2)`
и по одному у крыльев N/S.

## 5. Жёсткие правила для ADMIN

1. **Плита — ОДИН крупный бокс на уровень и корпус** плюс по боксу на крыло (с 25.10 растр
   `plate_boxes` снят: он давал «пол с дырками»). Склейка плит одного уровня — union-find в
   плане с зазором `PLATE_CLUSTER_GAP 1.20`; дырки делает ТОЛЬКО `carve_plates_by_stairs` по
   пятну марша. Бокс «по габариту плиты с дырками» без резки запрещён по-прежнему.
2. **Любой бокс, собранный в локальных координатах, НЕЛЬЗЯ заворачивать в `make_box`:**
   `make_box` ждёт мировые координаты модели и сам зовёт `to_local()`. Двойное преобразование
   уже дало 27 мусорных плит и потерю F2/F3/F4 (см. §3.1). Локальный бокс собирается словарём
   `{"c": [x, y, z], "s": [sx, sy, sz], "ry": 0.0}`.
3. **`WALL_BLOB_T` не опускать к 0.60.** Типовая стена ADMIN — ровно 0.60 м, строгое `>` на этом
   значении теряет настоящие стены на шуме float.
4. **Классификация — только по имени.** Геометрические догадки в ADMIN уже давали и потерянные
   стены, и залитые помещения.
5. **«Скорлупа помещения» никогда не превращается в бокс** — `wall-blob` её отсекает.
6. **Оконные ленты (`ADM_F*_WINDOW_*`) — не проёмы в `doors[]`**: это участок стены, который держат
   сплошным либо режут по высоте ленты.
7. **`ADM_DOOR_PORTAL_*` — проём на всю высоту объекта**, не через `CLEAR_H`/`DOOR_MAX`.
8. **Купол, барабан, ротонда, венчающая группа — не бокс по габариту.** Только кольца/секторы или
   точный меш.
9. **Марши — побъектно, без кластеризации.** Кластеризация по касанию габаритов уже склеивала
   A + B + LAND + PODIUM в один бокс (уклон 12.6°, подъём 1.86 м вместо 4.00). Уклон берётся
   из габарита (`bb[4] → bb[5]`) по верхней огибающей, а НЕ из МНК по облаку и НЕ из `principal_theta`.
10. **Синтетическая крыша — только верхняя полоса группы и только если сверху нет настоящей плиты.**
   Иначе она садится в проёмы шахт: ADMIN был разбит по этажам и получал 68 × 64 на каждом этаже.
11. **Плита и крыша режутся по пятну марша** (`carve_plates_by_stairs`) — растр видит только дырки меша.
    Порог перед полом (`add_threshold_steps`) дробит перепад 0.30..0.60 на две ступени, а яма
    между ступенью и плитой на одном уровне мостится (`fill_level_gaps`).
12. **Play Mode запускает пользователь**; численные проверки — меню 363/364/367/368 и `tools/*.py`.
13. **Правка плит ещё не пригнана к домам:** `houses_boxes.json` (25 чанков) собран старой схемой,
    риском тем же (`carve_plates_by_stairs` + растр). Прогон по домам — отдельный шаг с полной
    перепроверкой меню 363/364.
