> История (коротко, чтобы не повторять ошибки):
> 1. **v1** — 8 больших боксов вместо платформ + спаны стен со сдвигом на пол-длины (залило дверные проёмы).
> 2. **v2/v3** — платформы стали `MeshCollider`'ами (вырезы сохранены), спаны стен — из габаритов,
>    перемычки над дверями исключены из слияния: **0 из 3 038 дверных проёмов перекрыто**.
> 3. **v3 «лестницы»** — марши подбирались наклонными боксами по кластерам ступеней: на внутренних
>    лестницах дало 2–3 наложенных бокса и неверные высоты. Внутренние лестницы переведены на **точную
>    геометрию** (`stairs.obj`, один `MeshCollider` на чанк); наклонные боксы остались только у BASE.
> 4. **проёмы (эта ревизия)** — бокс по bbox объекта не умеет дыр: слэб с проёмом лестницы, L-образные
>    ограждения, крыша-объединение по дому и арки-порталы «заваривали» марши (проверка лучей: 73 из 878
>    ступеней перекрыты, 40 лестниц недоступны). Добавлено **вырезание проёма лестницы из боксов**
>    (см. §3.1): 844 бокса разрезаны на 1 421 часть, перекрытых ступеней — 0.

## 2. Где это в сцене

```
WorldRoot_0_0
├── PRIMUM                 ← город (инстанс PRIMUM_CITY.prefab) — НЕ ТРОГАЕМ
├── PRIMUM_DOORS           ← 2 161 префаб двери
└── PRIMUM_COLLIDERS       ← ✅ трансформ = трансформ PRIMUM (едет с ребейзом), static = false
    └── <чанк>/
        ├── PLATFORM_<имя>     ← 9 MeshCollider'ов (BASE)
        ├── STAIRS             ← 1 MeshCollider на чанк (внутренние лестницы)
        ├── WALL               ← один GameObject, сотни BoxCollider (осевые)
        ├── FLOOR / ROOF
        └── STAIR              ← группы по (yaw,pitch): GameObject с поворотом + боксы
```

**Почему СОСЕД корня города, а не ребёнок:** всё, что добавлялось внутрь префаб-инстанса `PRIMUM`,
терялось при пересохранении префаба (так пропали `SLAB3` и старый `PRIMUM/COLLIDERS`). Корень
коллайдеров копирует трансформ `PRIMUM` и висит под `WorldRoot_0_0` → ребейз мира везёт физику
вместе с городом. `static`-флаги НЕ ставятся (правило Floating Origin). Если корень города сдвинут —
пересобрать (одно меню).

## 3. Откуда геометрия и как считается

Источник — **исходная (несклеенная)** геометрия `PRIMUM_chunks_RAW/*.blend` (23 чанка). Из склеенного
по материалу меша боксы получить нельзя: он охватывает чанк целиком.

* RAW — **пре-масштаба**, поэтому `s = C + (p − C)·1.07`, `C = (7.5, −148.0, 18.5)`;
* перевод в локальные координаты корня PRIMUM: `local = (−s.x, s.z, −s.y)`;
* повороты: `yaw` вокруг Y (0/90 у осевых), у лестниц ещё `pitch = −atan(подъём/забег)`.

Правила отбора:

| Класс | Отбор | Особенности |
|---|---|---|
| PLATFORM | объекты `DECK_*`, `PLATFORM_L*` из `20_PLATFORMS` | геометрия → `platforms.obj`, в Unity `MeshCollider` (вырезы под лестницы) |
| STAIRS | детали с `STAIR`/`STEPS` в имени/коллекции, без перил/ограждений/ковров (`RAIL/GUARD/HAND/FURN/RUG/CARPET`) | `stairs.obj` — точная геометрия, группировка по лестнице; в Unity один сводный меш на чанк |
| STAIR (BASE) | террасные марши BASE | наклонный бокс: кластеризация в марши, уклон по крайним ступеням |
| WALL | `10_WALLS` (+ `PART_*`, `ADM_SHELL`) | отсев «косяков» (тонкие < 0.35 и короткие < 0.85); спаны = `[min,max]` по оси стены; **перемычки, начинающиеся выше пола + 1 м, в слиянии НЕ участвуют** → окна заливаются, дверные проёмы остаются |
| FLOOR | `05_FLOOR` (без `STAIR`) | плита = бокс |
| ROOF | `50_ROOF` (+ `PARAPET`) | по дому; группы только из парапетов отбрасываются |
| **Пропуск** | `30_WINDOWS`, `40_INTERIOR`, `60_DECOR`, `20_ENTRANCE` (двери — свои коллайдеры), маркеры | |

### 3.1 Проёмы лестниц (вырезание в боксах)

Бокс по габариту не выражает дыру в слэбе, поэтому:

* в Unity при сборке читаются габариты **всех** лестниц из `stairs.obj` (по чанкам);
* каждый бокс класса `WALL/FLOOR/ROOF` (осевой, `pitch = 0`) проверяется на пересечение с габаритом
  лестницы: по XZ — любое перекрытие, по Y — «бокс ниже низа марша» и «бокс выше верха марша более
  чем на 0.6 м» отбрасываются (пол под лестницей и потолок высоко над ней не трогаем);
* задетый бокс разрезается на **2–4 бокса вокруг проёма** (слева/справа/до/после), проём = габарит
  лестницы + 0.08 м; резание идёт **по всем лестницам чанка** (один длинный слэб/крыша может
  перекрывать 16 лестниц подряд);
* повёрнутые боксы (`yaw` не кратен 90°) не режутся — в жилых чанках их на пути маршей нет.

Итог: 844 бокса → 1 421 часть (счётчик в отчёте сборки: `проёмов лестниц вырезано`).

## 6. Что осталось / известно

* **Интерьеры** (мебель, шкафы) не покрыты — по решению «мелочь не плодить».
* **Крыши — один бокс на дом**: скатные крыши аппроксимированы; если марш упирается в крышу, проём
  вырезается автоматически (см. §3.1).
* **26 лестниц** имеют 1 «спорную» ступень из 8: над ней на 0.34–0.38 м проходит следующая ступень
  **своей же** геометрии (марши смоделированы наложенными клиньями). Коллайдер = точная геометрия,
  поэтому игрок видит ровно то же, что в модели; это ограничение геометрии, не коллайдеров.
* **`S9_RING` — 3 крыши** (у круглых домов крыши не в `50_ROOF`).
* **Лестницы есть не во всех чанках**: 15 чанков без внутренних лестниц (в моделях их нет или они в
  интерьерных коллекциях).
* **`PAVING` MeshCollider** (39 166 верт.) **выключен** — низ города держат 9 платформ + рельеф.
* Двери: у префабов свои коллайдеры (рама — триггер `E`, полотно блокирует).
* Повёрнутые боксы (`yaw` не кратен 90°) проёмами не режутся — на пути маршей их нет; если появятся
  (новые чанки), для них нужен OBB-рез или перевод в точный меш.
