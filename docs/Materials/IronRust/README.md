## 1. Что это и зачем

Железо, собранное «как бронза, но ржавчина вместо патины» — та же нодово-процедурная
схема, что у `Assets/_Project/Materials/Bronze/BronzeEdgeNoise_forTEST.shadergraph`
(эталон не тронут), с ржавчиной и **с bump**. Ни одной текстуры, UV не нужны,
vertex colors не читаются.

Это **не** замена и не дубль `SteelRust/`: там другая школа (печёные R/G-маски
через `EdgeMaskBaker`, тумблер `_UseVertexColors`, debug-виды, ручной URP-шейдер).
Здесь — чистый Shader Graph, одним графом, без запечки.

## 2. Что изменилось реворком (v1 → v2)

Реворк снял вертикальный bias и развёл «мягкую» и «яркую» ржавчину на две разные маски.

| # | Что | Было (v1) | Стало (v2) |
|---|---|---|---|
| 1 | Вертикальный переход ржавчины | `Smoothstep(_Rust_Height → +_Rust_Softness, pos.y)` домножался на маску | **удалён** (ноды и свойства) — ржавчина больше не привязана к object-space Y |
| 2 | Двойное применение `_Rust_Amount` | величина входила в маску дважды (две ветви складывались в `4f036e21`) | **один раз**, ПОСЛЕ чего `Saturate` — рабочий диапазон стал ≈ 0…1, а не 0…3 |
| 3 | Пятна ржавчины | один порог `Smoothstep(_Rust_Threshold → +_Rust_Band)` | к нему добавлена **вторая маска пятен** `ProceduralIronRustPatch` со своими порогом, полосой, масштабом и сидом |
| 4 | Ядро/ржавчина в альбедо | тройной Lerp с «ядром» `_Rust_Core` | **тёмная → яркая** двухступенчатая модель: `_Rust_Deep_Color` как подложка и `_Rust_Bright_Color` поверх неё по маске пятен |
| 5 | Bump | сумма (царапины + вся ржавчина) в одну `Add`-ноду | **два независимых рельефа**: `царапины × _Scratch_Bump` и `ржавчина × _Rust_Bump`, складываются перед `Normal From Height` |
| 6 | Детализация ржавчины | зашита в HLSL (`detail = 2.0`) | выведена в свойство `_Rust_Detail` (новая функция `ProceduralIronRustD`) |
| 7 | Имена | `_Bump_Strength` управлял всем bump | `_Bump_Strength` → **`_Scratch_Bump`** (теперь только царапины) |

**Удалённые** из блэкборда свойства: `_Rust_Height`, `_Rust_Softness` (вертикальный переход),
`_Rust_Core` (переименовано — см. ниже).

**Решения, принятые по ходу реворка (не были отдельно согласованы):**

- `_Rust_Core` **переосмыслено и переименовано** в `_Rust_Patch_Band` (дефолт `0.12`) —
  это уже не «глубина ядра», а полоса порога для маски пятен.
- `_Rust_Height` / `_Rust_Softness` **удалены**. Само удаление вертикального перехода было
  авторизовано; удаление именно этих двух свойств — следствие.

Целостность v1 держится только в текстовых дампах в `Assets/_Project/Materials/Iron/dump_*.txt`
(папка не под git): сам файл графа версии v1 перезаписан и не восстанавливается.

## 3. Как работает (слои)

Позиция одна и та же для всех слоёв — нода `Position` в **object-space** (`m_Space = 0`),
`AbsoluteWorld` (`m_Space = 4`) в графе отсутствует.

```
Position (Object) 131f1a6f
  ├─► CF ProceduralIronBase(_Noise_Scale, _Noise_Detail, _Noise_Warp, _Noise_Seed)  — fbm + Worley, 3 октавы
  │        ├─► × _Tone_Gain → + _Tone_Base → × _Iron_Color                = тон металла (a7c05f68)
  │        └─► кромки: Abs(xyz) → Split(|x|,|y|,|z|)
  │                Smoothstep(_Edge_Position − _Edge_Width → _Edge_Position) по каждой оси
  │                → попарные × (x·z, y·z, y·x) → Add → Saturate
  │                → × Smoothstep(_Edge_Wear → _Edge_Wear + _Scratch_Band; In = тон)  = маска кромок
  │
  ├─► ржавчина:
  │     CF ProceduralIronRustD(ObjectPos, _Rust_Scale, _Rust_Seed, _Rust_Detail) → Rust   (da0ebae1, вых. слот 4)
  │       M          = Smoothstep(_Rust_Threshold 2c462b5a → dbb1568d = +_Rust_Band b2624cb1; In = Rust)   fb750d86
  │       rustCover  = M × _Rust_Amount (e21c4aea)                                        d9e448f6
  │       rustCoverSat = Saturate(rustCover)                                             39c53baa   ← подложка альбедо
  │
  │     CF ProceduralIronRustPatch(ObjectPos, _Rust_Patch_Scale, _Rust_Patch_Seed) → Patch (60f0c9ff, вых. слот 3)
  │       patchMask  = Smoothstep(_Rust_Patch_Threshold 7fda84f9 → 13cb9e0e = dbb1568d + _Rust_Patch_Band d78f98dd;
  │                              In = Patch)                                               10a4631e
  │       brightMask = rustCoverSat × patchMask                                          419b2bbd   ← яркая ржавчина
  │
  └─► CF ProceduralIronScratchA/B/C(_Scratch_Scale, _Scratch_Stretch, _Scratch_Detail, _Scratch_Seed;
          C дополнительно повёрнута на _Scratch_Angle)
          → Smoothstep(_Scratch_Threshold → +_Scratch_Band) → объединение
          → × CF ProceduralIronScratchMask(_Scratch_Mask_Scale, порог _Scratch_Mask)
          → × _Scratch_Amount (c7cadc8d)                                 = рельеф царапин / «wear» (6ff6bf81)

Albedo     53fa4006 = Lerp(тон a7c05f68, _Rust_Deep_Color eea3fad0, T = rustCoverSat s1)     ← тёмная подложка
           83c6e24d = Lerp(53fa4006,      _Rust_Bright_Color c3e27968, T = brightMask s2)   ← яркая поверх
           3aa3ef8f = Lerp(83c6e24d,      _Scratch_Color 639f0dc4,   T = wear s1)            ← зачистка
Metallic   = Lerp(Lerp(_Metallic, 0.05, RustSat), _Metallic, wear)
Smoothness = Lerp(Lerp(_Smoothness, _Rust_Smoothness, RustSat), _Scratch_Smoothness, wear)
Normal TS  = Normal From Height(In = царапины + ржавчина×(1 − wear), Strength = 1.0)         f5799910
Emission, Occlusion — не подключены (как в бронзе)
```

Смысл разделения: `_Rust_Deep_Color` — это **подложка под всей ржавчиной** (её видно
везде, где `rustCoverSat > 0`), а `_Rust_Bright_Color` ложится **поверх и только там,
где совпали обе маски** (`rustCoverSat` × `patchMask`). Отсюда «рыжие пятна на тёмной
коррозии» вместо плоской заливки.

## 4. Bump — что конкретно изменено

В бронзе `Normal From Height` кормился **только** рельефом царапин (`c7cadc8d`).
В v1 перед ним ставилась одна `Add`-нода, суммировавшая царапины и всю ржавчину.
В v2 рельефы разделены на два независимых множителя и только затем складываются:

```
c7cadc8d [рельеф царапин] ──× _Scratch_Bump (7060546e) ──► de62f085 ──┐
                                                                      ├─► Add 28e68538 ──► Normal From Height.In (f5799910.s0)
fb750d86 [M — маска ржавчины ДО _Rust_Amount] ──× [Multiply cd90057e: M × OneMinus e8c4995f ← wear] ──× _Rust_Bump (7a7332a9) ──► 3c48e3eb ──┘
```

Рёбра правки 2: `6ff6bf81.s1→e8c4995f.s0`, `e8c4995f.s1→cd90057e.s0`,
`39c53baa.s1→cd90057e.s1`, `cd90057e.s2→3c48e3eb.s0`; снято старое
`39c53baa.s1→3c48e3eb.s0`. **Правка 3** заменила источник входа `cd90057e.s1`:
ребро `39c53baa.s1→cd90057e.s1` снято, поставлено `fb750d86.s3→cd90057e.s1`.
`3c48e3eb.s1` по-прежнему `_Rust_Bump` (`7a7332a9.s0`).

Теперь царапины и ржавчина крутятся **независимо**: `_Scratch_Bump` — только царапины,
`_Rust_Bump` — только ржавчина, причём ржавый рельеф **снимается там, где металл на экране
зачищен до серебра**. Старая нода `Add` (`cd8e05f0`) и ее ребро в
`Normal From Height.In` удалены; вход `Strength` (`f5799910.s2`) **не подключён**,
`m_Value = 1.0`.

### Почему появился множитель (1 − wear)

Маска, которой кормился ржавый рельеф, была маской **подложки альбедо**, а не «где ржавчина
видна». `39c53baa = Saturate(M × _Rust_Amount)`, `M = Smoothstep(_Rust_Threshold 0.06 → 0.71,
RustD)`, `RustD` = `PCIron_Fbm3` со средним 0.5. При `_Rust_Amount = 2.47` единица достигается
уже при `M ≥ 0.405`, то есть при `RustD ≳ 0.35` — **≈1 на 80–85 % поверхности**. Значит
`_Rust_Bump` работал глобально, в том числе по серебру. Серебро же берётся из другой,
независимой цепи: `6ff6bf81 = Saturate(d6b8e464 + c7cadc8d.s2)`, где `d6b8e464` — кромочная
зачистка, в цепь рельефа не входящая вовсе, а `c7cadc8d` при `_Scratch_Threshold = 0.92` почти
пуст (редкие тонкие линии). Итог без правки: на серебре единственный видимый рельеф — ржавый
(0.05), против невидимых царапин (0.02). Множитель `(1 − wear)` приводит рельеф к тому же
«видимому» состоянию, что и цвет: он гасит ржавый рельеф ровно там, где верхний `Lerp`
(`3aa3ef8f`) перекрыл ржавчину серебром `_Scratch_Color`.

### Почему источник рельефа заменён на M (правка 3)

`39c53baa` — это **клипованная ступенька**, а не высота. Градиент у неё есть только там,
где она не заклипована, то есть на границе серых впадин ржавого шума, а не внутри ржавчины.
Отсюда и наблюдение: «ржавые шкварки» видны на серебристо-сером, а внутри ржавчины рельеф
плоский (константа `_Rust_Bump` = 0.05).

Важно и то, что серое в кадре — не обязательно `_Scratch_Color` (0.80/0.80/0.83): это ещё и
тон металла `_Iron_Color` (0.42/0.43/0.46), проступающий там, где шум ржавчины провалился.
При `_Rust_Amount = 2.47` маска ≈1 почти везде, поэтому движение `_Rust_Scale` / `_Rust_Seed`
видно **только** как перемещение этих впадин. Множитель `(1 − wear)` правки 2 до них не
достаёт: `wear` — цепь царапин и кромки, от `_Rust_*` не зависящая.

Правка 3 питает рельеф маской `fb750d86` = `M` (до `_Rust_Amount`): она реально меняется
0…1 вслед за шумом ржавчины, поэтому рисунок идёт по всей ржавчине, а во впадинах (`M → 0`)
рельеф снимается сам. Множитель `(1 − wear)` сохранён — он по-прежнему гасит ржавый рельеф
под зачищенным царапинами/кромкой серебром.

`Normal From Height` считает нормаль из производных по экрану. В проекте производные
`ddx`/`ddy` живы, а `fwidth` мёртв — история вопроса в `docs/Materials/SteelRust/README.md` §2.
Визуальный результат обоих рельефов — **NOT RUN**.

### Значения пресета и реворк

Пресет **не перетюнивался** под v2 — он несёт значения, набранные под v1. Два места, где
это точно заметно:

- `_Rust_Amount = 2.47` набиралось под модель, где величина входила в маску **дважды**
  (и где работал вертикальный bias). Теперь вход один и клиппинг наступает раньше —
  **ожидается заметно больше ржавчины**, вероятен перетюн вниз.
- `_Scratch_Bump = 0.02` перенесено переименованием из `_Bump_Strength` (дефолт графа 0.25).
  Значение сохранено намеренно: переименование свойства не должно молча менять облик пресета.

## 6. Floating Origin

Только object-space: в графе одна нода `Position`, и она в пространстве `Object`
(`m_Space = 0`); `AbsoluteWorld` (`m_Space = 4`) в файле графа не встречается — проверено
по всем пяти полям `m_Space` (значения только `0` и `3`). Сиды — это смещения, которые
прибавляются к object-space координатам, то есть тоже не зависят от мирового положения
объекта. Свойства материала — не мировые координаты.
Ожидание: после F8 (ребейз) и F9 (возврат) паттерн стоит на месте. **NOT RUN** (проверяет пользователь).

## 7. Известные ограничения и грабли

- **Дефолты блэкборда остались «бронзовыми» в цветах.** `_Rust_Bright_Color` по дефолту
  = 0.25/0.55/0.45 (**бирюзовая патина**), `_Iron_Color` = 0.50/0.32/0.16 (**бронза**).
  Значит: **новый материал из этого шейдера получит бирюзу вместо ржавчины.** Актуальная
  палитра живёт только в `M_PC_IronRust.mat`.
- `_Noise_Detail = 0` в пресете: шаг частоты октав упирается в минимум 1.1, три октавы
  идут почти на одной частоте — базовый тон почти без мелкой детализации. Унаследовано
  от бронзы, не поломка.
- Вертикальный переход ржавчины **удалён**: ржавчина теперь распределена по объекту
  равномерно, без «сверху ржавее». Если понадобится зональность — только через новый
  механизм, старого больше нет.
- `Emission` и `Occlusion` в графе не подключены (константы) — как в бронзе.
- **Формат файла `.shadergraph`**: это поток JSON-документов, разделённых ровно одной
  пустой строкой (`}\n\n{`). Любая пустая строка **внутри** документа режет его на части,
  а разделитель `\n` вместо `\n\n` склеивает соседние документы — импорт падает с
  `ArgumentException: JSON parse error: The document root must not follow by other values.`
  Править файл графа текстом можно, но только с сохранением границ документов (см. §9).
- Правки HLSL — уважать **T-BRONZE01**: `ProceduralIronNoise.hlsl` содержит только
  одно-выходные функции File-режима, **сигнатуры и порядок слотов CF-нод менять нельзя**
  (слоты привязаны по номерам). Поэтому детализация ржавчины добавлена **новой функцией
  `ProceduralIronRustD`**, а у CF-ноды ржавчины выход переехал со слота 3 на слот 4.
  Старая `ProceduralIronRust` в HLSL осталась, но графом больше не используется.
- В `Assets/_Project/Materials/Iron/` лежат рабочие текстовые дампы (`dump_*.txt`). Это
  **не ассеты**, а следы разбора; в них остался единственный уцелевший список рёбер v1.
  Папка не под git — при уборке дампы сначала скопировать наружу.
- `39c53baa` (`Saturate(rustCover)`) на пресете заклипован в 1 примерно на 80–85 %
  поверхности (см. §4), поэтому маска подложки ≠ «где ржавчина видна»: серо-металлические
  впадины в кадре — это провалы шума ржавчины, а не зачистка. Рельеф правкой 3 снят с
  клипованной маски на `M` (`fb750d86`) и по-прежнему гасится `(1 − wear)`; тёмная подложка
  альбедо ложится почти везде — перетюн `_Rust_Amount` / `_Rust_Band` за пользователем.

## 8. Требования к геометрии

Специальных нет: материал полностью попиксельный, из object-space координат.

- UV не нужны; развёртка меша шейдеру безразлична.
- Vertex colors **не читаются** (`VertexColor`-нод в графе нет) — договор R/G/B/A из
  `docs/Materials/README.md` этим материалом не используется, запекать нечего.
- Фаски/плотность вершин не нужны (в отличие от `SteelRust/`, где на этом всё держится).
- Нормали должны быть корректными (пересчёт, без перевёрнутых граней) — иначе bump поверх
  сломанной нормали даст грязь.
