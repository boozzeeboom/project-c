# Эльо — система координат доски (v40)

> Статус: **предложение / документация**, код не изменялся.
> Исторические ссылки в этом документе (ELIO_RULES_DETAILED, ANALYSIS_CENTER, UNIT_TYPES_PROPOSAL, BALANCE_ANALYSIS_100, ELIO_GAME_RULES_ANALYSIS) указывают на файлы в `archive/`. Актуальные правила — `ELIO_RULES_FINAL.md` v1.3.
> Цель: простая, запоминаемая, шахматно-подобная адресация каждой клетки без необходимости помнить осевые координаты.

---

## 1. Принципы

1. **Один код = одна клетка.** Никаких дублей и неоднозначностей.
2. **Коротко и читаемо.** Код помещается внутри гекса (9–10 px).
3. **Зона видна из кода.** По первому символу понятно: своё поле, спорная или центр.
4. **Человеческий слой поверх данных.** Внутри движка остаются глобальные осевые `(q,r)`; код — это «витрина» для игроков, UI и логов.
5. **Без отрицательных чисел и запятых в пользовательском коде.**

---

## 2. Рассмотренные варианты

### Вариант A — осевые `(q,r)` с префиксом поля: `P-0,-1`

- **Плюсы:** однозначно, легко считать соседей, совпадает с движком.
- **Минусы:** отрицательные числа и запятые плохо читаются; игроку приходится помнить осевую систему; код длинный.
- **Вывод:** хорош как внутренний формат, плох как пользовательский.

### Вариант B — локальные координаты поля (шахматный стиль): `P-C3`

- **Плюсы:** коротко, привычно (буква + цифра), каждое поле адресуется независимо, легко печатать и диктовать.
- **Минусы:** нужно один раз объяснить, что строки/колонки локальные и не все комбинации существуют.
- **Вывод:** лучший баланс простоты и однозначности.

### Вариант C — глобальные осевые с буквами: `E7`

- **Плюсы:** одна система на всю доску.
- **Минусы:** доска — разреженная сетка 11×11 с дырками; строки идут по диагонали, не по горизонтали; поля/спорные/центр не различаются кодом; много пустых адресов.
- **Вывод:** слишком абстрактно для «лепестковой» доски.

### Рекомендация

**Вариант B (адаптированный):** префикс зоны + локальная колонка (A–E) + локальная строка (1–5). Спорные и центр — отдельные короткие коды. Это сохраняет шахматную читаемость, прячет осевую математику и явно различает зоны.

## 3. Рекомендуемая схема

### 3.1 Коды зон

| Префикс | Зона | Цвет на доске |
|---|---|---|
| `P` | Поле Плюсов | синий `#5b9bd5` |
| `M` | Поле Минусов | красный `#e05a5a` |
| `Z` | Поле Нулей | серый `#9aa0a6` |
| `PZ/MZ/PM-1/2` | Спорные гексы (мосты) | пунктир `#8a8ab0` |
| `Ц` | Центральный гекс (победный) | золотой `#c9a227` |

> Латиница `C` допустима как машинный ключ центра; для игроков используем `Ц`.

### 3.2 Локальная сетка поля (5×5)

Каждое поле — гексагон радиуса 2 (19 клеток). Локальные осевые `(q,r)` переводятся в букву/цифру:

- **Колонки A–E** = `q + 2` (A…E при q = -2…2).
- **Строки 1–5** = `r + 3` (1…5 при r = -2…2).

Адрес: `<Поле>-<Колонка><Строка>`, например `P-C3`.

```
Строка 1 (дальний край)      . . C1 D1 E1
Строка 2                     . B2 C2 D2 E2
Строка 3 (центр поля)        A3 B3 C3 D3 E3
Строка 4                     A4 B4 C4 D4  .
Строка 5 (кончик к центру)   A5 B5 C5  .  .
```

Точка `.` — пустота (этой клетки в поле нет). Существуют только клетки с осевым расстоянием `( |q| + |r| + |q+r| ) / 2 ≤ 2`.

**Ориентация (одинаковая для всех полей):**

- Строка 1 — дальний край поля (внешний периметр).
- Строка 5 — внутренний кончик, ближайший к центру доски.
- Колонка A — левый край в локальной системе поля.

**Ключевые клетки полей (центры):**

| Поле | Код центра |
|---|---|
| Плюсы | `P-C3` |
| Минусы | `M-C3` |
| Нули | `Z-C3` |

### 3.3 Спорные гексы (по соседним полям)

Называются по паре соседних полей в порядке Плюсы–Минусы–Нули (P, M, Z), номер 1 = ближе к центру, 2 = дальше. Код `PM` использует порядок P→M (не алфавитный):

| Код | Глобальные `(q,r)` | Промежуток |
|---|---|---|
| `PZ-1` | (1, -1) | Плюсы ↔ Нули (ближний) |
| `PZ-2` | (2, -2) | Плюсы ↔ Нули (дальний) |
| `MZ-1` | (0, 1) | Минусы ↔ Нули (ближний) |
| `MZ-2` | (0, 2) | Минусы ↔ Нули (дальний) |
| `PM-1` | (-1, 0) | Плюсы ↔ Минусы (ближний) |
| `PM-2` | (-2, 0) | Плюсы ↔ Минусы (дальний) |

### 3.4 Центр

- `Ц` — центральный гекс (победный). Глобальные `(0,0)`.
- Внутренние жёлтые входные гексы (не центр, но ворота к нему):

| Поле | Код жёлтого гекса | Глобальные `(q,r)` |
|---|---|---|
| Плюсы | `P-C5` | (0, -1) |
| Минусы | `M-E1` | (-1, 1) |
| Нули | `Z-A3` | (1, 0) |

> Напоминание: вход на `Ц` разрешён **только** с этих трёх гексов (`P-C5`, `M-E1`, `Z-A3`). Спорные `PZ/MZ/PM-1/2`, хотя и соседствуют с `Ц`, входом не служат.

### 3.5 Примеры адресации

| Ситуация | Код |
|---|---|
| Центр поля Плюсов | `P-C3` |
| Жёлтый входной гекс Нулей | `Z-A3` |
| Дальний спорный в промежутке Плюсы–Нули | `S2` |
| Центральный победный гекс | `Ц` |
| Клетка на внешнем крае Плюсов (верх) | `P-C1` |

### 3.6 Полная карта кодов полей

Поле Плюсов (аналогично для M и Z, подставляя префикс):

```
        P-C1  P-D1  P-E1
     P-B2  P-C2  P-D2  P-E2
  P-A3  P-B3  P-C3  P-D3  P-E3
  P-A4  P-B4  P-C4  P-D4
  P-A5  P-B5  P-C5
```

(Для Минусов и Нулей — та же форма, префиксы `M-` и `Z-`.)

## 4. Таблица соответствия (концепт)

Внутренняя таблица `code ↔ (q,r)`:

| Код | Зона | Глобальные `(q,r)` |
|---|---|---|
| `P-C3` | центр поля Плюсов | (0, -3) |
| `P-C5` | жёлтый входной (Плюсы) | (0, -1) |
| `M-C3` | центр поля Минусов | (-3, 3) |
| `M-E1` | жёлтый входной (Минусы) | (-1, 1) |
| `Z-C3` | центр поля Нулей | (3, 0) |
| `Z-A3` | жёлтый входной (Нули) | (1, 0) |
| `PZ/MZ/PM-1/2` | спорные | см. таблицу 3.3 |
| `Ц` | центр | (0, 0) |

Полная таблица на 64 клетки генерируется из правил 3.2 (колонка = q+2, строка = r+3) и хранится в данных; в документации держим концепт + ключевые точки, чтобы не дублировать 64 строки.

## 5. Как рендерить подписи

1. **Внутри гекса**, по центру, шрифт 9–10 px, моноширинный/гротеск.
2. **Прозрачность:** 0.45 по умолчанию, 1.0 при наведении/выделении (переключатель «Показать координаты» может включать постоянно).
3. **Цвет:** белый для полей, серый для спорных, золотой для `Ц`; жёлтые входные гексы — жирный код.
4. **Инфо-панель** (как в `elio_game_v51.html`): показывать `Код: P-C3 · (q,r)=(0,-3) · зона: поле Плюсов`.
5. **Легенда** вне доски: `P/M/Z — поля, PZ/MZ/PM-1/2 — спорные, Ц — центр`.
6. **Не дублировать** полные коды в подписях полей («ПЛЮСЫ» остаётся как сейчас).

---

## 6. Правила валидности

1. Код вида `X-YZ` валиден только если клетка существует в поле X (расстояние ≤ 2).
2. `PZ/MZ/PM-1/2` и `Ц` — всегда валидны.
3. Невалидные комбинации (например `P-A1`) в UI не показываются и в логах не встречаются.
4. При сериализации/сетевой передаче использовать глобальные `(q,r)` как источник истины; код — для отображения и логов.
