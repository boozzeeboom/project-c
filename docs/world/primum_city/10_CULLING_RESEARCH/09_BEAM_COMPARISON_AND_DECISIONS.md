| 14 | «Baked occlusion для чанков» | Прямое нарушение FO-правил (world-space/static) | Внутреннее противоречие beam |

**Полезные идеи beam, которых у нас не было:** Precomputed Culling ($150, v1.3.0, Unity **6000.0.77**,
URP) — единственный найденный ассет с явным Unity 6, проверить механизм/FO как «измеритель потолка»
(не покупать без теста); MIT-импосторы (Abdns/ImpostorSystem, Rawteous) как альтернатива Amplify;
interest management (NGO `CheckObjectVisibility`/`NetworkShow`) на будущее MMO; калибровка «GPU occlusion
в indoor может дать ~5 % — не обещать без замера»; сжатый чёрный список ассетов.

## 6. ИТОГОВЫЕ РЕШЕНИЯ

### 6.1. Корабли: что клеить (ответ на «100500 объектов»)

**«100500» — не число из проекта, а оборот заказчика.** Реальный максимум: **936 узлов / 935 мешей в одном
FBX** → **973 MeshRenderer / 1 452 GameObject** на тяжёлый корабль после импорта. Это второй источник DC
после дверей (тяжёлый ~2 919 DC, все корабли ~4 917 DC по модели). Если появится модель на 100k объектов —
правило то же: **никогда не тащить 100k рендереров в сцену**.

**Что клеить:**
1. **P0 (0.5 дня, без риска, делать до всего):** вынести **250 BoxCollider** и **9 `DoorController`**
   (`Door_AftGate_Port`, `Door_Bridge_1/2`, `Door_Guest`, `Door_Landing`, `Door_Medbay`, `Door_Mess`,
   `Door_Nav`, `Ramp_Cargo`) из **инстанса FBX** в обычные дети префаба. Сейчас 238 из 250 боксов и все
   9 дверей лежат внутри FBX-инстанса — реимпорт модели их снесёт. Мерж визуала здесь не нужен.
2. **P1 (1–2 дня):** склеить **greeble** — `Bolt_*`, `UnderHull_*`, `Interior_*`, `Contour_*`, `Mess_*`,
   `Det_*` (359 объектов, ~8 % тр.) в 10 сабмешей по материалам: 973 → ~620 слотов. Без риска для
   интерактива.
3. **P2 (2–3 дня):** `LODGroup` на корабль: LOD0 полный, LOD1 без болтов/труб/`UnderHull` (decimate),
   LOD2 1 меш / 3–5 материалов; пороги 300/900/2500 м (согласовано с shadowDistance 1000).
4. **P3 (3–5 дней):** полный мерж **«ячейка разрушения × материал»** (8 ячеек: нос/корма/борта/палубы/
   надстройка/днище/интерьер/двигатели) → **973 → ~92 слота**, готово к pre-fractured. Не «всё в 1 меш»:
   один меш убивает разрушаемость, lightprobes и по-комнатную видимость.

**Что нельзя клеить:** 9 дверей + аппарель/ворота (`DoorController`), `PilotSeat` (посадка),
11 `ModuleSlot` + визуалы модулей, `CargoVisual`/грузовой консоль, винты/гондолы
(`EngineThrusterVisual`/`ShipPartShake`), `ContrailVFX`, 250 коллайдеров, будущие фрактуры.

**Как:** edit-time в Unity → **коммитируемые mesh-ассеты** `Generated/Ships/<Class>_VIS_<Cell>_<Mat>.asset`
(они в git; prefab/FBX — в Lore, `.gitignore:151–154`), prefab-ассет, а **не scene-overrides**; генератор
коммитится, dry-run обязателен. Runtime `CombineMeshes` запрещён (хитч и недетерминизм на клиентах).
Коллайдеры — compound 250 боксов, не одним `MeshCollider (convex=false)` (не поддерживается динамическим
Rigidbody). Сеть/FO не затрагиваются.

**Ожидание:** тяжёлый **973 slot / ~2 919 DC → ~92 slot / ~276 DC**; все корабли **~4 917 → ~480 DC**
(−4.4 тыс. DC). Проверять Frame Debugger на одном инстансе (40064, 2512, 39449).

**Правило на будущее:** FBX с 900+ объектами не принимается как есть; приёмка: ≤24 слота статик-визуала,
≤40 GO вне визуала, ≤120 примитивных коллайдеров, ≤60k тр. LOD0, 0 мешей ≤24 тр. в LOD0; модель проходит
мержер.

### 6.2. Фермы: дальше **не клеить**

- Сейчас: **142 MR / 150 slots**, 99 merged-ассетов, 116.6 МБ, ~1.27 млн тр., двери 270 MR, 963–1 051 м от города.
- «1 меш на все фермы» сэкономит ≤280 DC (1.3 % кадра), но заставит рисовать **1.27 млн тр каждый кадр**
  и убьёт culling внутри фермы. «По ферме 1–2 меша» — то же по тр., выигрыш мал.
- Правильные рычаги: **двери ферм (270 MR) на слой `PRIMUM_DOORS`** с дистанцией 120–150 м (из города
  исчезают ~270 рендереров/640 слотов), **`shadowCastingMode=Off` геометрии ферм** (1.27 млн тр в shadow
  pass), свет — вне пула; коллайдеры не трогать; HLOD L1 — позже, фермы идеальный первый кандидат.
- Гранулярность уже правильная; дальнейшая склейка ухудшает culling.

### 6.3. Город: **сейчас оставить «чанк × материал»**, не переклеивать

J посчитал 4 варианта на реальной геометрии (Monte-Carlo камер):

| **A. чанк × материал (сейчас)** | 698 (живых 761) | **1 656 (1 806)** | **129 м** | **2 292** | **1 647** |
| B. дом × материал (всё) | 1 234 | 6 214 | 3.8 м | 7 426 | 4 056 |

**Вывод:** A — минимум по DC (и цвету, и теням). Дробление умножает слоты быстрее, чем фрустум их
отсекает; тень — главный потребитель городских DC (1 656 из 2 292). «По блоку 100–300 м» — no-op: чанк
и есть блок (26–228 м). Ячейки 10–30 м режут дома и дают +16…+47 % видимых слотов.

**Порог перехода на B2** (только все три):
1. GRD-пилот зелёный (`BrgStripping=2`, `InstancedDrawing`, Hi-Z);
2. окклюзия снимает **≥35 %** видимых слотов B2 на 3 точках;
3. отдельный **бюджет теней** решён (иначе B2 даёт +40 % DC).
Пилот — `S9_TRD-S2` (104 рендерера → ~330 B2), затем решать.

**Как делать (когда решим):** edit-time Unity-тул `PrimumCityRebatch` + манифест в git; меши
`Assets/_Project/Art/.../Rebatched/<чанк>/<unit>_<MAT>.asset`; prefab-ассет на чанк; **никаких
scene-overrides** (текущий мерж — 174 001 override / 34.3 МБ / 54.6 % сцены и невоспроизводим: merge-тула
и входных FBX/prefab нет в git). Сохранить материалы/сабмеши/UV, не трогать коллайдеры/двери/интерьеры/лампы,
static не ставить. Первый шаг — **воспроизводимость** (тул + манифест + prefab в VCS), 1–2 дня.

3. **Не резать город на ячейки 10–30 м** — +16…+47 % видимых слотов, швы, новая сущность пайплайна.
4. **Не решать гранулярность слоями** — 21 свободный слой не заменяет 577 домов; слои — для классов/дистанций.
5. **Не покупать culling-ассеты без триала** — ни один не заявляет Unity 6.5/URP 17.5; Perfect Culling
   ($97.46) — только измеритель потолка, Precomputed Culling ($150) — проверить, не покупать.
6. **Не включать Mesh LOD «всем»** — несовместим с батчами/static/GRD LOD0; только для импортируемых мешей.
7. **Не считать `Camera-relative culling` рычагом** — уже включён и, вероятно, no-op в URP.
8. **Не тащить 100k независимых объектов с физикой** — PhysX/DOTS-миграция не в scope; визуал — мерж+GRD,
   физика — только игровые объекты.
9. **Не повторять scene-overrides** для мержа — хрупко и невоспроизводимо.
10. **Не запекать Umbra/PVS в world-space** — FO ломает; static-рендеры запрещены.

| Что сходится beam/наше? | Двери — 84 %; Umbra не путь; нужен runtime/GPU culling + LOD/HLOD; DOTS не нужен; ассеты не покупать. |

| Где истина? | Двери — первый DC; **корабли — второй** (973 MR тяжёлый); город склеен правильно для DC, крупно для окклюзии; фермы склеены правильно; Umbra/FO-bake закрыты. |
| Что клеить в кораблях? | **Пилот — только `Ship_havyII_base`:** P0 вынести коллайдеры/двери; P1 greeble (359 объектов → 10 сабмешей); P2 LODGroup; P3 полный мерж «ячейка разрушения × материал» (973→92). Medium/light/NPC в этих операциях **не трогаем** — future scale-out после зелёного пилота. Не клеить двери/кресло/модули/груз/винты/VFX/коллайдеры/фрактуры. |
| Фермы клеить дальше? | **Нет.** 142 MR/150 slots уже правильно; 1 меш = +1.27 млн тр каждый кадр за ≤280 DC. Рычаги — двери на слой, тени off, HLOD позже. |
| Город переклеить по дому? | **Не сейчас.** A (чанк×материал) — минимум DC. B2 (дом, только крупное ≥1 м) — только после зелёного GRD и если окклюзия снимет ≥35 % видимых слотов + отдельный shadow-бюджет. Полное «по дому» — ×3.8 слотов и +146 % DC. |
| По слоям? | Слои — для классов/дистанций (двери/пропсы/интерьеры/фермы/руины), не для ячеек. 21 свободный слой, а домов 577. |
| 100500 объектов? | Это оборот; реально 936 в FBX / 973 MR в префабе. На будущее: 100k объектов нельзя тащить как 100k рендереров — мерж по материалам/секциям, LOD/импостор, pre-fractured пулы, приёмка ≤24 слота. |
