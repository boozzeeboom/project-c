# Headless 100 × 18 — баланс на v1.3d

## 1. Что прогнали

- **1800 партий**: 100 на каждую из 18 вариаций (3 порядка хода × 2 типа игры × 3 варианта пешек).
- **Без LLM**: все три фракции играет встроенный ИИ v1.3c.
- Движок **v1.3d** (P0/P1-фиксы: доска, оттеснение, щиты, king/hold).
- Seeded RNG на каждую игру (`baseSeed=20261108`), integrity-guard после каждого действия.
- `passRule=random` (канон), `cycleDir=forward`; `repeat`/`back`/`reverse` не включены.
- 10 фигур — канон; **10+1 (p1)** и **15 (p5)** — тест-варианты.

- **Самый сбалансированный 10-фигурный вариант — Pass + Long: 34 / 33 / 32** (средняя 33.3, 9 побед по лимиту, 1 ничья).

**Осторожно:** 100 игр дают ±~5–10 п.п.; для канона нужен чистый 400-партийный перепрогон. Но старые 400 уже нельзя использовать как есть.

### 3.2. 10+1 и 15: пешки усиливают Нулей, особенно в Main

- **10+1 Arrow + Main: 31 / 41 / 27** — Нули 27 %, практически как старые 26 %.
- **10+1 Arrow + Long: 27 / 29 / 44** — Нули 44 %, как старые 42.5 %.
- **10+1 Pass + Main: 29 / 33 / 36** — Нули 36 %, как старые 37.5 %.
- **10+1 Pass + Long: 26 / 41 / 32** — Нули 32 %, минусы 41 %; много лимитов (24).
- **15 p5:** Нули 37 % (Arrow+Main), 50 % (Arrow+Long), 51 % (Pass+Main), 54 % (Pass+Long), 78–79 % (Cycle Main/Long).
- **15 p5 Cycle — сломанный вариант:** 78–79 % Нулей, средняя 17.6–17.9, 0 гибелей Линейного. Не канон.
- **Главный вывод:** пешка в `C1`/15 фигур сильно помогает Нулям; 10+1 Arrow+Main (27 %) — середина, 15 p5 Cycle (79 %) — край.

### 3.3. Main vs Long: Main структурно бьёт по Нулям

- В **Main** гибель Линейного = мгновенная победа военного; Нули не успевают. В **Long** партия продолжается, и Нули чаще доигрывают до Hold.
- Pass p0: Main 20 % → Long 32 % (+12).
- Arrow p0: Main 22 % → Long 28 % (+6).
- Arrow p1: Main 27 % → Long 44 % (+17).
- Cycle p1: Main 49 % → Long 69 % (+20).
- Исключения: Pass p1 36 → 32; Cycle p5 79 → 78.
- **Для теста DeepSeek выбран Main — самый тяжёлый для Нулей режим.** Это не ошибка модели: в Arrow/Pass Main база 20–28 %, в Cycle Main — 39 %.

### 3.4. Встроенный ИИ Нулей — измеримый ориентир для DeepSeek

- **10+1 Arrow + Main, ИИ за Нулей: 27 %** (31 / 41 / 27, 100 игр).
- **DeepSeek v2.1: 16.7 %** (1 / 6), **v2 clean: 20 %** (1 / 5).
- Разрыв **7–10 п.п.** в пользу встроенного ИИ. 725 — чистая победа и доказательство потенциала, но доктрина v2 в среднем **слабее ИИ Нулей**.
- Это ключевой ориентир: следующая цель — не «побить 0 %», а догнать/обогнать 27 % ИИ в том же сетапе.

### 3.5. Линейные и центр

- **Line deaths (Main, p0):** Arrow 23 %, Pass 18 %; в Long p0 — 3–16 %. В 10+1 Long Arrow — 32 %, Pass — 24 %. Пешка увеличивает число гибелей Линейного.
- **Center entered:** 85–100 % во всех вариантах — центр почти всегда кто-то занимает. Проблема Нулей не «дойти», а **удержать**: в 10+1 Arrow+Main центр занят в 85 % игр, а Нули выигрывают только 27 %.
- В 15 p5 Cycle — 0 гибелей Линейного и 78–79 % Нулей: военные просто не успевают/не мешают, Нули душат Hold.

## 4. Сравнение со старыми 400-партийными цифрами

- **10+1 старые цифры близки к новым** (Arrow+Main 26→27, Arrow+Long 42.5→44, Pass 37.5→36). Эти прогоны были относительно чистыми.
- **10-фигурные p0 старые цифры — нет.** Особенно Pass+Main: 31.2→20 у Нулей; Cycle: 25→15 у Плюсов; Arrow+Long: 33.4→41 у Минусов. Причина — P0-баги старого движка (нелегальное оттеснение нулями, порча доски, уход за доску).
- **Вывод:** `ANALYSIS_V13_400_GAMES.md` для 10 фигур нужно переписать после чистого 400-партийного прогона. 10+1-анализ можно оставить с оговоркой, что он совпал с чистым 100-игровым срезом.

## 5. Ограничения

- 100 игр на вариант — ±~5–10 п.п.; для тонких выводов нужна выборка больше.
- ИИ v1.3c — эвристика; после фиксов движка его оценка оттеснения/щитов могла стать неоптимальной. Минус-перекос p0 может быть частично артефактом ИИ, а не только правил.
- В `pass` передача случайная; стратегия передачи не тестируется.
- В `cycle` направление фиксировано `forward`; выбор Нулей не тестируется.
- `centerTicks` в `results.json` — число действий с занятым центром, не число тиков; для «дойти» используйте `centerEntered`.
- 10+1/15 — тест-варианты, не канон.
