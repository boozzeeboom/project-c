# 05. Рекомендуемая архитектура видимости для Project C

**Дата:** 2026-10-30 · **Статус:** предложение к решению (не реализовано; research-only)
**Основа:** `03_MERGE_VS_INDEPENDENT.md`, `04_ARCHITECTURE_OPTIONS.md`, отчёты A–F.
Все числа «после» — прогноз; критерии успеха/провала — в `06_EXPERIMENTS_AND_ROADMAP.md`.

---

## 1. Одним абзацем

Не откатывать склейку города и не покупать culling-ассеты. Сделать **Ф0 — дешёвый бюджет
дальности/теней дверей + P0/P1 кораблей** (3–5 дней суммарно), затем **Ф1 — встроенный GPU Resident
Drawer + GPU occlusion culling** (2–3 недели, цель 1.5–2.5 тыс. DC), а **свой код** писать не как
«свой окклюжн-движок», а как тонкий **Visibility/Budget Director** поверх engine-куллинга: иерархия
групп, мультикамерный union, бюджеты теней, двери/корабли, гистерезис, FO-safe обновление, ≤2 мс.
Пере-грануляцию города (A → **B2**, дом × материал только ≥1 м) делать только после Ф1, если GRD
снимет ≥35 % видимых слотов и решён бюджет теней; ячейки 10–30 м — не делать. Umbra и world-space PVS
не использовать — они несовместимы с FO.

## 2. Почему именно так (ключевые факты)

1. **Двери = 84 % кадра** (17 766 из 21 118 DC в конфиге B; 22 027 из 26 981 в A), при этом <10 %
   треугольников. Их стоимость — `material slots × проходы`, а не уникальные двери.
2. **Город уже склеен и это правильно** (1 207 рендереров вместо 16 470; 1 806 слотов вместо 20 694).
   Без склейки DC растут ×1.2–1.9; с GRD — падают до сотен, но GRD заблокирован шейдерами/настройками.
3. **Гранулярность AABB 129 м** — крупна для окклюзии/LOD, но **дробление стоит +40…+146 % DC**
   (J): A остаётся оптимумом, пока GRD/окклюзия не докажут ≥35 % выигрыша; B2 — условный следующий шаг,
   ячейки 10–30 м — нет.
4. **Корабли — второй источник DC после дверей:** тяжёлый **973 MR/973 slot**, light 428, medium 118;
   в сцене 23 корабля = **1 639 MR = 18.4 %** рендереров. **Пилот — только `Ship_havyII_base`**
   (973 MR): P1 greeble (973→~620), P2 LODGroup, P3 «ячейка разрушения × материал» (973→~92).
   Остальные корабли (medium/light/NPC) в этих операциях **не трогаем** — future scale-out после
   зелёного пилота.
5. **FO**: первый авто-ребейз ≈56 км, дальше 0.26–1.5 км каждые ~35 с; baked world-space данные
   умирают. Только frame-local (frustum, distance, Hi-Z, CullingGroup) или данные в локальных
   координатах ячейки. Static-рендеры/батчинг запрещены; 2 076 static GO (коллайдеры/холдеры) — есть.
6. **URP 17.5 уже умеет GPU-окклюзию** (Hi-Z → indirect), Forward+ уже включён; блокеры —
   `BrgStripping=KeepAll` и DOTS-инстансинг в шейдерах: город — 49 Shader Graph на 15 графах,
   двери — 6 на 5 графах; объём DOTS-настройки графов **[UNVERIFIED]** и может быть шире, чем
   «пара кастомных HLSL» (ProceduralSteel в сцене не используется — 0 ссылок).
7. **Стриминга контента нет**: 23 из 24 сцен пустые, пилот грузит одну `WorldScene_0_0`;
   объектный culling — отдельный слой, а не стриминг сцен.
8. **Бюджет culling ≤2 мс** (из дизайна мира), кадр 16.67 мс; всё, что дороже, — off by default.

## 3. Архитектура по слоям

```
┌─────────────────────────────────────────────────────────────────────┐
│ 0. Engine culling (Unity/URP)                                       │
│    frustum + layers + layerCullDistances + shadow cascades          │
│    + GPU Resident Drawer: BRG instancing + Hi-Z occlusion (Ф1)      │
└───────────────▲─────────────────────────────────────────────────────┘
                │ видимость/бюджеты (скаляры, гистерезис)
┌───────────────┴─────────────────────────────────────────────────────┐
│ 1. Visibility / Budget Director (наш C#, Ф0/Ф2)                     │
│    - реестр групп: doors / interior / lamps / ruins / ships / cells │
│    - правила: distance, shadowDistance, layer, importance           │
│    - мультикамерный UNION (какие камеры «настоящие»)                │
│    - применение: Renderer.enabled / forceRenderingOff /              │
│      shadowCastingMode; каденция 2–4 Гц; гистерезис 10–15 %         │
│    - бюджет 0.2–0.5 мс/кадр; O(групп), не O(объектов)               │
└───────────────▲─────────────────────────────────────────────────────┘
                │ события/скаляры
┌───────────────┴─────────────────────────────────────────────────────┐
│ 2. Данные мира                                                      │
│    - живые Transform/bounds (FO-safe), локальные координаты ячеек   │
│    - никаких мировых Vector3 между кадрами                          │
│    - пересборка на ребейзе: по запросу/поллингу CumulativeOffset    │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.1 Компоненты (что писать)

| Компонент | Ответственность | Срок |
|---|---|---|
| `DoorVisibilityBudget` (Ф0) | слой дверей + `layerCullDistances` + `shadowCastingMode` по дистанции/группе, гистерезис, 2–4 Гц | 1–2 дня |
| `ViewDistanceFixes` (Ф0) | `shadowDistance` → URP asset/свой бюджет; `Camera.main` → явный риг; `AtmosphereCamera` — не мировая | 1 день |
| `VisibilityDirector` (Ф2) | группы/ячейки, мультикамерный union, бюджеты теней, правила по классам, реестр владения renderer'ами | MVP 5–8 дн, прод 3–4 нед |
| `ForwardOriginAdapter` (Ф2) | пересчёт bounds/групп после ребейза; сброс кэшей; обработка rollback | 2–3 дня |
| `CullingDiagnostics` (Ф0/Ф2) | счётчики видимых/включённых групп, `ProfilerRecorder`, `UnityStats`, Frame Debugger-метки | 1–2 дня |
| GRD-настройка (Ф1) | `BrgStripping=2`, `GPUResidentDrawerMode=InstancedDrawing`, GPU occlusion, `smallMeshScreenPercentage`; пилот | 2–3 нед |

> Свой GPU-driven BRG (Hi-Z, indirect, `OnPerformCulling`) **не писать**: 80 % этого уже в engine,
> 6–10 недель дубля. Если GRD не подходит — сначала PVS/CPU-директор (Ф3/Ф4), потом думать.

### 3.2 Правила по классам контента

| Класс | Механизм | Дистанции/бюджет | Гранулярность | FO |
|---|---|---|---|---|
| Двери (интерактив) | слой + distance + shadow-only; при GRD — инстансы | цвет 0–150 м; тени 40–80 м; дальше off | префаб/группа дома | позиции живьём |
| Батчи домов | frustum + occlusion (GRD)/distance + LOD | L0 полный; L1 HLOD 3–12 км; L2 импостор >12 км | чанк → блок 10–30 м | bounds локальные |
| Интерьеры (`_INT_`) | сейчас в батчах: только LOD/HLOD; отдельные объекты — нельзя static | L0/L1 | батч/дом | — |
| Лампы/emissive | пул света (готово) + distance корпусов | свет 140 м; корпуса с батчем | группа/чанк | `Light.enabled` ≠ Renderer |
| Фермы/руины | frustum + distance + HLOD | руины 4/8/12 км (есть), фермы как город | ферма/хамлет | класс A |

| Дальние города | L2-импостор + CullingGroup | 12–80 км | город | только скаляры |
| Триггеры/коллайдеры/VFX | **не трогать** rендер-куллингом | — | — | — |

## 4. Фазы

### Ф0. Low-code бюджет дверей + фиксы (2–4 дня) — сделать первым

**Действия:**
1. Создать слой `PRIMUM_DOORS` (свободен, например 10); перенести 11 дверных префабов
   (`PM_DOOR_*`, `PM_ADM_ENTRANCE_PORTAL`) — инстансы наследуют слой.
2. `Camera.layerCullDistances[doors] = 120–150 м` на геймплейной камере; `layerCullSpherical = false`.
3. `shadowCastingMode = Off` дверям: (а) дальше 40–80 м; (б) либо сразу всем — решает заказчик по
   визуалу. Реализация — дешёвый менеджер групп с гистерезисом, не per-door каждый кадр.
4. Фиксы: `QualitySettings.shadowDistance` no-op → перенести в URP-ассет или в бюджет;
   `Camera.main` → явно брать rig-камеру; `AtmosphereCamera` (far 10, меню) — не включать в union.
5. A/B: центр/улица/крыша, реальный far 30 км, равный `frameCount`, `UnityStats`, Frame Debugger.

**Ожидание:** 26 981 → **5 000–9 000** DC (A), т.е. −67…−81 %; двери в кадре — сотни.
**Gate:** экономия ≥30 %, нет визуальных дефектов, F8/F9 без ошибок.

### Ф0-b. Корабли: **пилот `Ship_havyII_base`** (P0/P1/P2, 3–5 дней) — параллельно Ф0

**Scope:** только тяжёлый `Ship_havyII_base`. `Ship_medium_base`, `Ship_Light_root_fbx_test` и 20 NPC
в этих операциях **не трогаем**; если пилот зелёный — для них появляется рабочий пайплайн
(future scale-out, отдельный этап).

1. **P0:** вынести user-коллайдеры из nested FBX. **H1 уже сделан частично:** 240/250 снаружи,
   9 `DoorController` + 10 leaf-коллайдеров остались (reimport проверен, OK; H1-R1 — повторять после reimport).
2. **P1 (1–2 дня):** мерж greeble (`Bolt_*`, `UnderHull_*`, `Interior_*`, `Contour_*`, `Mess_*`, `Det_*`:
   359 объектов, ~8 % тр.) в 10 сабмешей по материалам → **973 → ~620 slot**.
3. **P2 (2–3 дня):** `LODGroup` + LOD1/LOD2 (300/900/2500 м) → на дистанции **40/5 slot**.
4. **P3 (3–5 дней, после плана разрушаемости):** мерж «8 ячеек разрушения × материал» → **~92 slot**;
   не «всё в 1 меш» (убьёт pre-fractured/lightprobes/покомнатную видимость).

Не клеить: 9 дверей+аппарель, PilotSeat, 11 ModuleSlot, CargoVisual, винты/гондолы, ContrailVFX,
250 коллайдеров, фрактуры. Как: edit-time Unity-тул → `.asset` в git (prefab/FBX — Lore), prefab-ассет,
**не scene-overrides**; runtime `CombineMeshes` запрещён.
**Ожидание пилота:** тяжёлый **973 slot → ~620 (P1) → ~92 (P3)**; DC ~2 919 → ~1 800 (P1) → ~276 (P3).
**Gate:** Frame Debugger на одном инстансе; реимпорт FBX не ломает; двери/слоты работают; FO/сеть ок;
**другие корабли — 0 изменений**.
**Future scale-out (не входит):** medium/light → все корабли 4 917 → ≤2 500 DC (P1/P2), после P3 — ≤480.

### Ф1. GPU-путь: GRD + GPU occlusion (2–3 недели)

**Действия:**
1. Аудит шейдеров: город — 49 Shader Graph (15 графов) + 1 Unlit, двери — 6 Shader Graph (5 графов);
   **настроить DOTS-инстансинг/инстанс-варианты в ~20 графах** (в текущих `.shadergraph` ключей
   instancing/DOTS нет — это и есть реальный блокер, а не 8 кастомных HLSL). Проверить, что материалы
   города не используют `ProceduralSteel` (0 ссылок — уже подтверждено).
2. `ProjectSettings/GraphicsSettings.asset → m_BrgStripping = 2 (Keep All)`.
3. URP: `GPUResidentDrawerMode = InstancedDrawing`, `GPUResidentDrawerEnableOcclusionCullingInCameras = 1`.
4. Пилот на одном чанке/материале → Frame Debugger: `Hybrid Batch Group`; сравнить DC/SetPass/тр.
5. Затем вся сцена: двери должны схлопнуться в десятки (≤~72) пар mesh×material; проверить тени, створки, F8/F9.
6. Fallback: исключить двери из GRD (`GPUDrivenProcessor`/opt-out), если створки/тени ломаются.

**Ожидание:** 26 981 → **1 500–2 500** DC (прогноз), GPU-окклюзия начинает работать.
**Gate:** DC ≤2 500; Hybrid Batch Group есть; визуал/тени/FO без регрессий; нет шейдерных ошибок.

### Ф2. Гранулярность (B2, условно) + VisibilityDirector (3–4 недели)

1. **B2-переклейка** (дом × материал, только геометрия ≥1 м; мелочь/интерьеры — чанк-батчи) — **только
   если** GRD-пилот зелёный и окклюзия снимает **≥35 %** видимых слотов B2, а рост теней закрыт
   отдельным бюджетом. J: A 1 656 слотов / DC_B 1 647; B2 3 182 слота / DC_B 2 302 (**+40 %**);
   ячейки 10–30 м — не делать. Пилот — `S9_TRD-S2` (104 рендерера → ~330 B2).
2. `VisibilityDirector`: группы/ячейки, мультикамерный union, бюджеты теней, корабли/интерьеры,
   гистерезис, обновление 2–4 Гц, ≤0.3–0.5 мс; FO-адаптер.
3. HLOD L1 (3–12 км) по блокам; L2-импостор (12–80 км) — отдельный трек Э6.
4. Воспроизводимый merge-тул + манифест в git (сейчас мерж невоспроизводим), prefab-ассеты, не scene-overrides.

**Ожидание:** B2 — только при выполнении условий; иначе остаётся A; L0 1–2k после GRD+директора.
**Gate:** нет регрессий DC, визуал без pop-in, culling ≤2 мс, Σtris ±0.1 %.

### Ф3. Опции (только по необходимости)

- Portal/PVS (6–10 недель) — если нужен L0 <1k и город заморожен.
- Свой BRG — только если GRD принципиально не подходит.
- HLOD/импостор — самостоятельный этап Э6; culling его не заменяет.

## 5. FO-контракт для системы видимости (жёсткие правила)

1. **Никаких мировых координат в данных между кадрами**: позиции/bounds читаются из Transform
   или пересчитываются из локальных координат ячеек.
2. **Ребейз**: первый авто-ребейз ≈56 км, дальше 0.26–1.5 км; после success и rollback — сброс
   кэшей/пересчёт bounds. Публичного события нет: использовать `TryRebuild`-хук (сейчас no-op) или
   поллинг `CumulativeRebaseOffset/FrameGeneration`.
3. **Static-флаги запрещены**; GRD/LOD/CullingGroup — можно (frame-local).
4. **Мультикамера**: `Renderer.enabled` глобален для всех камер → union только по «настоящим»
   камерам; `AtmosphereCamera` (far 10, слой 9) и статичная `BootstrapScene/MainCamera` — не включать.
5. **Состояние ≠ рендер**: не трогать `DoorController`, коллайдеры, `Light`-пул, сеть, физику, VFX;
   отключать только Renderer/тени.
6. **Стриминг**: одна мир-сцена; данные города строятся при загрузке `WorldScene_0_0` и не
   перестраиваются на ребейзе; выгрузки контента нет.
7. **Бюджет**: culling ≤2 мс; всё, что дороже, — off by default; обновление группами 2–4 Гц.

## 7. Что НЕ делать (анти-цели)

| Анти-цель | Почему |
|---|---|
| Возвращать 147k/16.7k независимых объектов | DC ×1.2–1.9, редактор/загрузка снова страдают; без GRD бессмысленно |

| Клеить фермы в 1 меш | −≤280 DC за +1.27 млн тр каждый кадр |
| Резать город на ячейки 10–30 м | +16…+47 % видимых слотов, швы, новая сущность пайплайна |
| Решать гранулярность слоями | 21 свободный слой не заменит 577 домов; `layerCullDistances` не влияет на тени |
| Писать свой GPU-куллер с нуля | 6–10 недель дубля engine; 80 % уже в GRD |
| Запекать Umbra/PVS в мировых координатах | FO ломает; static-рендеры запрещены; бейк падает |
| Покупать culling-ассеты «вслепую» | Unity 6/URP 17.5 не заявлены; боль не в готовых рендерерах |
| Склеивать двери/интерактив в батчи | потеря `DoorController`/коллайдеров/анимации |
| Менять `shadowDistance` через `QualitySettings` | URP его игнорирует — no-op |
| Трогать `Terrain`, коллайдеры, триггеры, VFX | вне задачи; риск сломать геймплей/физику |
