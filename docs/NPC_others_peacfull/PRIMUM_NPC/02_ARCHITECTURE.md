# 02 — ARCHITECTURE

## 1. Коллекция в сцене

```
WorldScene_0_0
└─ WorldRoot_0_0                      (корень мира; всё под ним FO-инвариантно)
   ├─ PRIMUM                          (город, слой 8)
   ├─ PRIMUM_DOORS
   └─ PRIMUM_NPC_CROWD   ← НОВОЕ      (только здесь живут NPC)
      ├─ Residents                    (резиденты с домом, ≤4 на houseId)
      └─ StreetCrowd                  (толпа без дома — включается с T4)
```

Почему именно так:

- `PrimumHlodManifest` фиксирует контракт «координаты в пространстве `WorldRoot_0_0` FO-инвариантны,
  ребаз переносит корень и всё под ним». Значит дети корня едут с миром бесплатно (см. `01_AUDIT §6`).
- Всё, что вне `WorldRoot_0_0`, при вертикальном/горизонтальном сдвиге «отстаёт» — так делать нельзя.
- `VisibilityDirector` (когда он есть) строит группы по именам детей `WorldRoot_0_0`; незнакомое имя
  попадает в `GroupClass.Misc` (observed-группа, без директирования рендереров). Мы это принимаем:
  NPC не должны попадать в HLOD-чанки города и не должны попадать под `DetailDistanceCuller`.
- Отдельный корень исключает конфликт с `HouseMarker`/`PRIMUM`/`PRIMUM_DOORS` и позволяет удалить/пересоздать
  всю толпу одним `Destroy` без риска зацепить город.

Внутри коллекции — **плоские списки детей** (никакой глубокой иерархии): 10 000 объектов с глубокой
иерархией замедляют `Transform` и события; группировка идёт по имени и по данным, а не по дереву.

Изменение канонического кода — **одно, аддитивное**: в `NpcController` добавляется
`public void SetDefinition(NpcDefinition, TextMeshPro)` (+регистрация в `Registry`). Причина: `definition`
приватный `[SerializeField]`, а NPC получают свой `NpcDefinition` в рантайме (100 разных личностей из
одного шаблона). Поведение существующих NPC не меняется.

## 3. Анимация

- Один `AnimatorController` на всех: `Base Layer` — 1D Blend Tree по параметру `Speed`
  (`0` → `Idle01`, `1` → `Walk01_Forward`), retarget с humanoid-паков Kevin Iglesias.
- `Animator` живёт **на инстансе модели** (в FBX он уже есть с валидным аватаром), контроллер
  проставляется рантаймом из конфига. 106 моделей ⇒ 106 разных аватаров, контроллер общий.
- `animator.cullingMode = CullCompletely` — за кадром анимация не считается (главный выигрыш на масштабе).
- Скорость клипа масштабируется: `animator.speed = speed / 1.4` (чтобы шаг не «ёхал» на медленных NPC).

## 4. Дома и правило «≤4 на дом»

1. Директор один раз собирает `HouseMarker` в сцене и группирует по `houseId` (замер: 534 маркера →
   362 дома). Центр дома = среднее `mapPoint` всех его маркеров.
2. Резидент получает дом по детерминированному порядку (сортировка по `houseId`), счётчик
   `residentsByHouse[houseId] < 4`. Исчерпали 4 — следующий дом. Исчерпали все дома — NPC уходит в
   `StreetCrowd` **без дома** (для T4 это норма, для T1–T3 недостижимо: 362×4=1448).
3. Точка спавна: `NavMesh.SamplePosition(center, out hit, 30 м)` → если не нашли, пробуем 60 м, затем дом
   пропускается и его ёмкость перераспределяется. Это же и есть проверка «дом стоит на навмеше».
4. Дом хранится **в локальных координатах `WorldRoot_0_0`** (`worldRoot.InverseTransformPoint`), чтобы
   ребаз не ломал якоря. Точки прогулки — тоже локальные.
5. Дом не «привязывает» NPC физически: он лишь центр его маршрутов. NPC может уйти на 60–120 м, но
   возвращается к дому (это и есть «заякорен»). При T6 (двери) дом станет точкой входа внутрь.

## 5. Поведение (FSM)

```
Spawn ──► Idle (1–4 c, случайный yaw)
            │
            ├─► Wander: цель = NavMesh-сэмпл в кольце 8…wanderRadius от дома
            │       (по умолчанию 45 м; 30 % — «прогулка» 80–120 м)
            │       скорость 0.6…1.4 м/с, Arrive → Idle
            └─► (T6) EnterHouse: дверь дома → интерьер → Idle → выход
```

- Решения тикают **не каждый кадр**: у каждого NPC свой фазовый офсет, интервал 0.2–0.5 с
  (`Time.time + offset`), поэтому 100 NPC не дают пиков в одном кадре.
- Валидация пути: `pathStatus == PathPartial/PathInvalid` или `IsPathStale` → пере-выбор цели;
  сэмпл вне `NavMesh` отклоняется до `SetDestination`.
- Вода/края: `NavMesh.SamplePosition` + `agent.isOnNavMesh` проверяются перед каждой выдачей цели.
- NPC-NPC: включаем `obstacleAvoidanceType = LowQualityObstacleAvoidance` на T1–T2 (качество), отключаем на
  T3+ (стоимость); тогда расталкивание — забота дистанций сэмпла, а не навмеша.

## 6. Идентичность и диалог

- На каждого NPC — свой `NpcDefinition` (`npcId = primum_crowd_XXXX`, `displayName` из пула имён,
  `greetingText` 2–4 фразы из ролевых шаблонов, `faction = Neutral`, `interactionRadius = 3`).
  Ассеты кладутся в `Assets/_Project/Quests/Data/Npcs/PrimumCrowd/`, `QuestDatabaseAutoDiscover`
  подхватывает их рекурсивно.
- На NPC висит `NpcController` (существующий) + триггер-капсула → `NetworkPlayer` по `E` находит ближайшего
  и вызывает `QuestServer.RequestTalkToNpcRpc` → сервер отдаёт fallback-дерево из `greetingText`.
  **Новый UI не нужен**, работает существующий `DialogWindow`.
- Нейм-плейт — TMP-ребёнок шаблона, `nameLabel` прокидывается в `NpcController` через `SetDefinition`,
  поэтому заглушка-куб из `NpcController.Awake` не создаётся.
- Диалог живёт на сервере: без поднятого `QuestServer` (например, сцена открыта одна, без хоста) `E`
  ничего не откроет. Это ограничение существующего пайплайна, а не пилота; нейм-плейт при этом виден.

## 7. Толпа на масштабе (тиры)

| Тир | NPC | Движение | Анимация | Рендер | Ввод в диалог |
|---|---|---|---|---|---|
| T1 | 100 | `NavMeshAgent`, avoidance Low, тик 0.2–0.5 с | `CullCompletely`, LOD по дистанции | все включены | все |
| T2 | 300 | то же, тик 0.35–0.7 с, avoidance Off | то же | renderer off > `visualRadius` | все |
| T3 | 1000 | агент только у «горячих» (≤`agentRadius` от игрока, бюджет ~120), остальные — движение по заранее снятым полилиниям улиц | ближние | ближние; дальние — без скелета | ближние |
| T4 | 10000 | без агентов: маршрутный граф улиц, шаг по полилинии, скорость из профиля | только «горячие» (≤60 м) | 3 уровня LOD/импостер | ближние |

T3/T4 строятся **поверх** T1-контракта: те же данные (дом/идентичность/диалог), другой драйвер движения.
Поэтому переход между тирами не ломает уже сделанное.

## 8. Floating Origin — контракт коллекции

1. Коллекция — ребёнок `WorldRoot_0_0`. Никаких NPC вне корня.
2. Директор в `LateUpdate` сравнивает `worldRoot.position` с сохранённым (как `VisibilityDirector.DetectFrameShift`).
3. На дельте `Δ` (порог 1e-3 м):
   - каждому NPC: `agent.ResetPath()`, `agent.Warp(transform.position)` (позиция уже сдвинута корнем),
     затем пере-выдача цели из **локальных** координат;
   - обнуляем кэш «текущая мировая цель»; якоря не трогаем — они локальные.
4. Никаких `Rigidbody`/`CharacterController` на NPC: `NavMeshAgent` сам двигает `Transform`, а
   `GlobalMotion*`-слой (если его когда-нибудь включат) такие объекты отвергает и не станет их ломать.
5. Если FO не сработал (см. `01_AUDIT §6`, `FindWorldRoot` может взять `Mountains`) — ничего не ломается:
   дельты нет, локальные якоря валидны, NPC едут с городом.

## 9. Что сознательно не делаем

- Нет `NetworkObject`/`NetworkTransform` на NPC: 100–10 000 сетевых объектов убьют и сервер, и полосу.
  Сетевая модель для толпы — отдельный трек (`docs/NPC_others_peacfull/crowd_brains/`).
- Нет `Rigidbody`: NPC не толкают игрока и не падают, ходят строго по навмешу.
- Нет `NavMeshObstacle` на NPC в T1 (это цена пересчёта для агентов); расталкивание — avoidance/сэмплинг.
- Нет HLOD/импостера для NPC в T1.
