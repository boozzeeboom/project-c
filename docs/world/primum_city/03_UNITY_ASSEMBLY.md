# 03. Сборка города в Unity (фаза 3)

Дата: 2026-10-17. Цель фазы: блоки стоят в мире, объединены, имеют коллайдеры, лежат на своём слое,
редактор работает быстро, а редактировать город можно по одному блоку.

---

## 1. Импорт: настройки, которые нельзя путать

Именно на них сломалась прошлая попытка (см. `PRIMUM_CITY` до 17.10: модели в 100× больше,
`globalScale` вручную 0.36…10.64):

| Параметр `ModelImporter` | Значение | Почему |
|---|---|---|
| `useFileScale` (Convert Units) | **true** | Blender отдаёт FBX в сантиметрах; без этого модель в 100× больше (админ: 17 565 м вместо 175.65 м) |
| `globalScale` | **1.0 у всех** | пофайловые «подгонки» дают кашу |
| `meshCompression` | Off | геометрия без компрессии |
| `animationType` | None | анимаций нет |
| `addCollider` | false | коллайдеры делаем осознанно (см. §5) |
| `isReadable` | false | доступ к вершинам не нужен |

Проверка после импорта: габариты моделей/блоков совпадают с Blender-таблицей (Δ ≤ 0.02 м).

## 2. Слои (поименно)

| Слой | Слот | Назначение |
|---|---|---|
| **`PRIMUM`** | **8** (создан 17.10) | весь контент города PRIMUM |
| `FARMS` | 9 (зарезервировать при работах по фермам) | портовые станции «Средняя» |
| … | 10…30 | следующие группы контента (по одной на группу) |

Правила:

* имя слоя = имя группы контента, **UPPERCASE**; слоты занимаем по порядку с 8 (свободны 9…30);
* слой — инструмент **скрытия/диагностики** (в том числе для скрытия в Scene View);
  основная рабочая видимость в редакторе — `Scene Visibility` (иконка глаза в Hierarchy), не слой;
* при назначении слоя проверить: **culling mask камер** (сейчас `MainCamera.cullingMask = Everything` → ок)
  и **матрицу физики** для пар «слой города × игрок/корабли/зоны» (по умолчанию новые слои сталкиваются
  со всеми — для статики это верно, но проверить после появления геймплейных объектов);
* слой задаётся на **корне группы** (`PRIMUM`) и наследуется детьми; отдельные исключения — только осознанно.

## 3. Размещение в мире

```
WorldScene_0_0
└── WorldRoot_0_0                     (ребёнок корня сцены → Floating Origin везёт бесплатно 🟢)
    ├── Terrain_0_0
    ├── Primum_farms  …              (существующий контент — не трогаем)
    └── PRIMUM                       ← слой PRIMUM, позиция (0,0,0), масштаб 1
        ├── PRIMUM_BLK_<zone>_01     (меш(и) блока + коллайдер)
        ├── PRIMUM_BLK_<zone>_02
        └── …
```

* **Корень всегда (0,0,0), масштаб 1, поворот 0.** Никаких «подгонок масштабом» (это и была ошибка 1.06).
* Вертикальная посадка: поверхность террейна в центре игровой области ≈ **2 199 м**, существующий блок-аут
  порта стоит на **2 500 м**, город нужно поставить **на поверхность** (или подрезать террейн по bbox
  через `GetHeights/SetHeights` — это разрешённый приём, полная регенерация запрещена).
* Горизонтальная посадка и разворот — согласовать с портом (по лору порт западный, с забором и 2 КПП),
  фермами и `CompassRose_North` (см. `05_FO_NETWORK_AND_GAMEPLAY.md` §4).
* **Старый блок-аут `Primum` (6 229 рендереров) снимается** после того, как новый город встанет на его место.

## 4. Объединение (combine) — по блоку, не по городу

Инструмент: `Assets/_Project/Editor/CombineMeshesToCollider.cs`, меню **Tools → ProjectC → Combine Children
Meshes → Collider**, программно `CombineMeshesToCollider.CombineInto(root, removeChildRenderers: true)`.
Документ: `docs/world/COMBINE_MESHES_TO_COLLIDER.md` (там же — критичное правило про пересчёт
`rootWorldToLocal * localToWorldMatrix`, иначе коллайдер уезжает).

* **Почему по блоку:** один меш на весь город = 1 draw call, но **нулевое отсечение** — рисуется всё.
  Блок даёт и малое число вызовов, и отсечение по кварталам.
* Комбинированный меш сохраняется ассетом в `Assets/_Project/Generated/<Root>_Combined.asset` — без этого
  он не переживёт перезапуск.
* Инструмент идемпотентен: повторный запуск пересобирает ассет (после переимпорта FBX — обязательный шаг).
* Ожидаемый эффект: 147 715 рендереров → **150–400**, draw calls → **40–120**.

## 5. Коллайдеры

| Что | Как | Почему |
|---|---|---|
| Экстерьер блока | `MeshCollider` из комбинированного меша, `convex=false`, `cookingOptions = CookForFasterSimulation \| EnableMeshCleaning \| WeldColocatedVertices \| UseFastMidphase` | `CharacterController` (игрок) работает с non-convex; Rigidbody (корабли) — нет, им нужен свой коллайдер |
| Провалы сквозь палубы/площадки | `BuildSettlementColliders` (Tools → ProjectC → Build Settlement Colliders), `Мин. толщина бокса = 0.5` | лечит класс ошибки «провал сквозь палубу» |
| Интерьеры | при варианте B — коллайдеры внутри интерьерного префаба | не тратим физику на то, что не загружено |
| Бюджет | **1 коллайдер на блок** (+ точечные боксы) вместо 147 715 | PhysX: сотни MeshCollider'ов = ×5–10 по времени |

Проверка: `Dry Run` у тулзы поселений (сколько боксов и что отсеяно) до `Build`.

## 6. Рабочая сцена и режим правок (главное для редактора)

| Приём | Как |
|---|---|
| **Рабочая сцена** | `Assets/_Project/Scenes/Test/PRIMUM_City_Work.unity` — **не в билде**, только для редактирования |
| **Prefab Stage по блоку** | правим один блок как префаб, не поднимая весь город |
| **Scene Visibility** | скрываем ненужные слои/группы в Scene View (не трогая слой-маску камер) |
| **Слой `PRIMUM`** | быстрый тумблер «город виден/скрыт» |
| **Правило** | **город не держим инстансом в `WorldScene_0_0`**: он лежит блоками-префабами и инстанцируется только для проверок (именно это вернуло сцену с 167 969 к 20 254 рендерерам) |

## 7. Критерии приёмки фазы 3

- [ ] корень `PRIMUM` под `WorldRoot_0_0`, позиция (0,0,0), масштаб 1, слой `PRIMUM`
- [ ] рендереров города в сцене ≤ 400 (было 147 715)
- [ ] объектов в сцене (город) ≤ 1 500
- [ ] draw calls города ≤ 120 (замер Frame Debugger / Profiler)
- [ ] у каждого блока есть коллайдер; PlayerController стоит на площади и на крышах (Play — пользователь)
- [ ] Scene View: скрытие города одним тумблером слоя работает
- [ ] редактор: вход в Play и открытие `WorldScene_0_0` без заметных задержек

## 8. Политика материалов (решение пользователя, 17.10)

* Материалы сейчас — **заглушки**. Важны только **имена** (`M_GRANITE`, `M_BRICK_YELLOW`, `M_BRONZE`, …):
  позже они подменяются **пулом материалов, сделанных в Unity**.
* Поэтому на фазах 2–4 не тратим время на вид/текстуры материалов. Что действительно важно:
  1. **не переименовывать** материалы при склейке мешей (имя = ключ для подмены);
  2. каждый меш должен иметь материал-заглушку (без «пустых» слотов);
  3. держать число разных материалов минимальным (это же требование Unity для батчинга).
* Позже понадобится: таблица соответствия «имя материала из Blender → материал Unity-пула» + скрипт
  подмены по имени (по всем моделям города и ферм разом).
