# 04. Двустворчатая дверь — префаб `PM_DOOR_DOUBLE_A` (2026-10-21)

**Статус:** собран, проверен, расставлен в **110** проёмов (торговая аллея + «дверь + неподвижная
панель» в жилых чанках). Скрипт-генератор — `Assets/_Project/Editor/Primum/DoorPrefabBuilder.cs`
(кнопка `ProjectC → World → PRIMUM → Двери: собрать двустворчатый префаб`).

Зачем понадобился: на визуальной приёмке выяснилось, что в торговой аллее одна двустворчатая дверь
была разложена конвейером v13 на **две отдельные группы** (`…_DOOR_LEAF` + `…_DOOR_LEAF_L`), и
расстановщик ставил в каждую по одиночному префабу — получались «две узкие двери подряд» или
«дверь в половину проёма» (вторая створка при этом отбраковывалась как узкая 0.56 м).

## 1. Спецификация

| Параметр | Значение |
|---|---|
| Общий габарит (по порогу) | **1.36 × 2.50 × 0.22** м |
| Проём по раме (= триггер взаимодействия) | 1.30 × 2.50 × 0.20 |
| Створка (одна) | **0.56 × 2.36 × 0.072** м |
| Стойка рамы / перекладина | 0.09 / 0.10 м |
| Глубина рамы / порога | 0.16 / 0.22 м |
| Материалы | рама `PM_DOOR_WOOD_DARK`, порог `PM_DOOR_STONE`, полотно `WOOD_DARK` + филёнки `WOOD_MID`, петли `IRON`, ручки `BRONZE` |
| Вершин (все части) | 72 (рама) + 24 (порог) + 2 × (24 + 96 + 72 + 48) = **600** |
| Пивот | низ по центру проёма, лицевая сторона **+Z** |
| Слой | `PRIMUM` (8), **static = false** (иначе отрывается при ребейзе мира) |

## 2. Иерархия

```
PM_DOOR_DOUBLE_A              (пивот = низ по центру; BoxCollider-триггер 1.30×2.50×0.20)
├── Frame                     (2 стойки + перекладина, WOOD_DARK)
├── Sill                      (порог, STONE)
├── LeafL  localPos (-0.56, 0.04, 0)   пивот = ЛЕВЫЙ край (петли слева)
│   ├── LeafL_Wood            (плита полотна, x 0…0.56)
│   ├── LeafL_Panels          (2 филёнки × 2 стороны, WOOD_MID)
│   ├── LeafL_Iron            (3 петли у левой кромки)
│   ├── LeafL_Bronze          (ручка у притвора)
│   └── BoxCollider           (блокирующий, 0.52×2.30×0.07 — едет со створкой)
└── LeafR  localPos (+0.56, 0.04, 0)   пивот = ПРАВЫЙ край (петли справа), меши зеркальны
```

Створки сводятся в середине; ручки — у притвора, петли — у внешних кромок.

## 3. Скрипт

`DoorController` на корне:

| Поле | Значение |
|---|---|
| `doorType` | `HingedDouble` (3) |
| `leftPivot` / `leftHingePanel` | `LeafL` / `LeafL_Wood` |
| `rightPivot` / `rightHingePanel` | `LeafR` / `LeafR_Wood` |
| `leftHingeSide` / `rightHingeSide` | `Left` / `Right` |
| `doubleOpenAngle` | 90° |
| `invertDoubleSwing` | false (если створки распахиваются не туда — включить/поменять знак) |
| `startOpen` / `openDuration` / `autoCloseDelay` | false / 1.2 с / 0 |

`GetSetupIssues()` на префабе: **0 ошибок, 0 предупреждений**.
Обе створки открываются одновременно, каждая вокруг своей кромки (движок `HingedDouble` в скрипте).

## 4. Генератор (воспроизведение 1:1)

`DoorPrefabBuilder.BuildDouble()`:
1. строит меши из **ориентированных наружу боксов** (24 вершины / 12 треугольников на бокс);
2. у каждого меша проверяет **знаковый объём > 0** (та же страховка, что в постмортеме выворотки
   `02_SINGLE_DOOR_PREFABS.md` §7.1) и пишет ошибку в консоль при отрицательном;
3. сохраняет меши как ассеты `Prefabs/City/Doors/Meshes/PM_DOOR_DOUBLE_A_<часть>.asset`
   (иначе префаб сохраняет пустую ссылку — проверено на одиночных);
4. собирает иерархию, коллайдеры, `DoorController` через `SerializedObject`;
5. `PrefabUtility.SaveAsPrefabAsset` (GUID префаба при пересборке сохраняется — ссылки в сцене живы).

Там же — `BuildSingle(...)` для аварийного восстановления трёх одиночных
(габариты/материалы/структура те же, рисунок филёнок может отличаться — кнопка помечена
«(восстановление)» и в обычном цикле не используется).

## 5. Куда ставится (правила расстановщика)

Двустворчатый префаб используется в трёх случаях (см. `03_MASS_PLACEMENT.md` §4):

| Случай | Признак | Кол-во |
|---|---|---|
| Пара створок двумя группами | соседние `…_DOOR_LEAF` + `…_DOOR_LEAF_L`: общий низ, копланарны, зазор ≤ 0.12 м, объединённая ширина 1.15–1.75 м | **80** |
| «Дверь + неподвижная панель» одной группой | внутри широкой группы ровно один остров-полотно, ширина группы ≤ 1.78 м | **30** |
| — | итого двустворчатых префабов | **110** |

Масштаб: `scale = (W_проёма / 1.36, H / 2.50, clamp(T / 0.22, 0.6, 1.6))`.
Фактические ширины поставленных: 1.24 (61), 1.25 (2), 1.41–1.54 (13), 1.50 (17), 1.65 (9), 1.74 (7), 1.77 (1).

## 6. Ограничения

* Петли/сторона открывания выбираются соглашением (петли наружу, створки распахиваются в сторону +Z) —
  как и у одиночных; переворот лечится `invertDoubleSwing` / знаком угла.
* Дворцовые и административные двустворчатые (1.5 и 1.8 м, единой группой, GLD/ADMIN) **не заменяются**
  этим префабом — для них планируется отдельный набор (288 проёмов ждут).
* Проёмы шире 1.78 м этим префабом не закрываются (растяжение > 30 %) — нужен набор ворот/витрин.
