# 04 — Сервер: ростер, пулы, лизы, бюджеты

> Сервер не думает за толпу. Он ведёт учёт (ростер), выдаёт право думать (пулы/лизы) и хранит итоги (отношение, обиды, квесты). Этот файл — модель данных и правила, без кода.

## 4.1 Ростер (Roster) — единственное, что сервер знает о каждом

Одна запись на человека. Порядок — десятки байт, тысячи записей — мегабайты, 0 тиков.

```
CrowdEntry {
  crowdId:        string   // "cr_gigant_deckB_042", стабилен, переживает сессии
  zoneId:         string   // "gigant" / "primum_alley_3" (для бюджетов и AOI)
  homeAnchorId:   string   // дом-якорь (куда возвращаться после событий)
  templateId:     byte     // профессия-шаблон (докер/страж/пассажир/...)
  appearSeed:     uint     // внешность/имя/голос (детерминировано)
  factionRef:     id       // как FactionDefinition-ref в NpcDefinition
  hp, maxHp:      int16    // по умолчанию 30 (как NpcTarget), меняется только событием
  alive:          bool + respawnAt (по respawnPolicy)
  attitude:       int16    // NpcAttitude-эквивалент, правится ModifyNpcAttitude-подобно
  grudgeUntil:    time     // обида на конкретных clientId (GrudgeTable-эквивалент)
  heroUntil:      time     // «герой на день» (0 = обычный)
  questFlags:     bits     // talked / offered / turnedIn / failed (по квестовым ID)
  persona:        6 чисел  // храбрость, flee/surrender-пороги, болтливость, жадность
  leaseRef:       slotId?  // null = толпа; иначе — герой (см. §4.3)
}
```

Правила:

- Ростер — **авторитет по существованию**: нет записи — нет человека (клиент такого не рисует; запрос с неизвестным `crowdId` — reject).
- Ростер **не тикает**: записи меняются только событиями (урон, диалог, скрипт, таймер респавна пачкой раз в N секунд, а не per-entry в `Update`).
- Ростер **зонирован**: `zoneId` = единица бюджета и AOI (палуба, отсек, квартал). Суммарный ростер мира может быть огромным, одновременно «горячих» зон — единицы.
- Связь с существующим: `ShipCrewManifest` — это прообраз ростера для фиксированного экипажа (`memberId, npcDefinition, role, spawnAnchorId, seatAnchorId, respawnPolicy`). Ростер толпы — тот же смысл, но на тысячи + `heroUntil/questFlags/persona`. Манифест корабля = «ростер с именами», толпа = «ростер с сидами».

## 4.2 HeroRegistry — кто сейчас герой

Лёгкий индекс поверх ростера: `slotId → crowdId`, `crowdId → slotId`, `clientId → [slotIds]`. Отвечает на вопросы «этот — герой?», «чьи герои у этого игрока?», «что освободить при дисконнекте?».

Инварианты:

- Один `crowdId` — максимум одна активная лиза (бой ИЛИ диалог, не обе; приоритет боя, см. `03 §3.6`).
- Один игрок — максимум 1 активный диалог (как сейчас в `QuestWorld`: stale-сессия закрывается) + максимум K боевых slachtopffer-связей (жертв/обидчиков), где K — бюджет (§4.4).
- Дисконнект игрока → его диалоговые лизы закрываются немедленно, боевые — переводятся на ближайшего наблюдателя или распускаются по TTL (не висят).

## 4.3 Пулы и лизы (аренды)

Два независимых пула на зону (цены разные, смешивать нельзя):

**BrainPool (бой):** слоты combat-тика. Слот = право на `{aggroTarget, cooldown-статус, Brawl-tick 5 Гц, ответный ResolveAttack}`. Старт: 6 («Гигант») / 8 (квартал). Занят — значит кто-то реально дерётся или идёт по `Alarm`.

**DialogPool (разговор):** слоты сессий. Активных — 1 на игрока (ограничение `QuestWorld`), «тёплых» (grace) — до 4–6 на зону. Занят — значит открыта `OpenDialog`-сессия или не истёк grace.

**Лиза (общая форма):**

```
Lease {
  slotId, crowdId, zoneId,
  reason: Combat | Dialog | Script,
  ownerClientId,            // кто вызвал (обидчик / собеседник / скрипт)
  observers: [clientIds],   // кому слать дельты
  expiresAt,                // TTL слота
  heroUntil,                // «герой на день» (может пережить expiresAt)
  renewOn: [DamageEvent, DialogAdvance, AlarmRefresh],
  outcome: ?                // заполняется при демоуте
}
```

Правила лиз:

- Продление — только живыми событиями из `renewOn`. Афк-держание слота запрещено (иначе игрок «повесит» 6 слотов, встав в толпу).
- `heroUntil` может быть дольше `expiresAt` (см. `01 §1.5`): тик кончился, права остались.
- Лиза видна наблюдателям как `HERO_UP` (при выдаче) / `HERO_DOWN` (при возврате) — см. `06`.

## 4.4 Бюджеты (стартовые гипотезы, калибровать Profiler'ом)

| Зона | BrainPool | Атакующих на 1 игрока | Dialog активных / тёплых | Видимых тел (клиент, см. `05`) |
|---|---|---|---|---|
| «Гигант» (палуба/отсек) | 6 | ≤3 одновременно бьют, остальные — шум/окружение | 1 / 4 | 40–60 |
| Квартал города | 8 | ≤4 | 1 / 6 | 50–80 |
| Пустырь/ферма | 3 | ≤2 | 1 / 2 | 10–20 |

Почему так мало: один боевой тик героя ≈ 1/10 цены полного `NpcBrain` (нет NavMesh-погони, нет полного `SocialTick`), но 8 таких + 10 героев по должности + игроки + корабль — уже заметная доля серверного кадра на хосте. Бюджет — это страховка от «пинок = лаг всем».

Очередь при переполнении: боевая — не очередь, а фолбэк (бегут/капитулируют, см. `02 §2.5`); диалоговая — короткий «занят» (см. `03 §3.6`). Длинных очередей не держать — это плохой UX и залипшие лизы.

## 4.5 Персистентность (что переживает рестарт)

Ростер — персистентен (как квестовые состояния через `JsonQuestStateRepository`-подход): `crowdId → {alive, hp, attitude, questFlags, heroUntil}`. Не персистентны: точные позы (есть дом-якоря), активные лизы (при рестарте все герои демоутятся в `Calm`), клиентские пулы.

Ротация толпы: убитые с `respawnPolicy=AfterDelay` возвращаются с новым `appearSeed` («другой человек»), но тем же `crowdId`-слотом якоря. Именные (`heroUntil`-носители, квестовые) — `Never` без скрипта (пустой якорь виден миру — это тоже история).

## 4.6 Расписания и якоря (чтобы толпа не стояла столбом)

Ростер без расписания = манекены. Минимум: `homeAnchorId + shiftTable {утро/день/ночь → anchorId}` + `activityId (Work/Sit/Sleep/Socialize)` — reuse `Activity Anchors` (T-NPC-S23: `AnchorState NeedMove→Moving→Active`) и `NpcIdleActivity`. Сервер хранит только таблицу (данные), клиент исполняет переходы локально. Смена вахты = смена якоря по времени (`TimeManager`/календарь уже есть), а не приказ каждому.

## 4.7 Связь с экономикой и миром (тонко, не глубоко)

Толпа — датчик и потребитель мира, не симулятор:

- Потребление: еда/товары списываются агрегатом по зоне раз в `MarketTick` (как `NpcShipCargoManifest`-хуки в `npc_ship/03 §6`), а не покупкой каждого докера.
- События: цены/шторм/прибытие корабля меняют `lastTopicSeed` + шаблоны реплик (слухи, см. `03 §3.5`), а не поведение каждого.
- Квесты: толпа — источник `questOffers` (флаги), исполнители — герои/игроки.
