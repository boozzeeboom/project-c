## 2. Что выяснилось на пилоте и стало стандартом (обязательно для всего города)

Пилот вскрыл, что процедурные графы и городские меши были несовместимы. Принятое решение — **три слоя
исправлений**, без любого из них материалы в городе выглядят неверно:

### 2.1 Меши: Y-up, метры, общий кадр чанка, тангенсы (меню 388)

* FBX города: поворот X 270° (Z-up), масштаб ×100, пивот у дома/чанка, **нет UV** → импортёр ставит
  всем вершинам tangent (1,0,0,−1): на гранях ±X базис TBN вырожден → чёрные мелькающие треугольники.
* `PrimumMeshRebase.RebaseChunk` (меню `ProjectC/World/PRIMUM/Материалы: Y-up меши всего выделенного чанка (1:1)`, 388):
  вершины в пространство корня чанка (Y-up, метры) — **одно object space на весь чанк** (иначе
  совпадающие грани одного материала дают видимый z-fight), тангенс строится из нормали, меши —
  саб-ассеты одного файла `Assets/_Project/Art/Models/Primum/Rebased/<чанк>/<чанк>_YUP_meshes.asset`,
  подмена 1:1 (пилот: расхождение 3.1·10⁻⁵ м), одна Undo-группа, иерархия и имена не меняются.
* **Пресеты материалов теперь в метрах** (`*_Scale` = периодов на метр, `*_Stretch` тянет по вертикали).
  Следствие: **на не подменённых чанках рисунок сейчас в ~100 раз крупнее** и тангенсы вырождены —
  все чанки нужно подменить до или вместе с мапингом.

### 2.2 Графы: точная позиция и точный рельеф (меню 400, 401)

Файлы — в `Assets/_Project/Editor/Materials/PrecisionBumpPatcher.cs` и `Assets/_Project/Shaders/ProceduralBumpPrecise.hlsl`.

| Дефект | Лечение | Где |
|---|---|---|
| во фрагменте `ObjectSpacePosition = TransformWorldToObject(positionWS)` — квантование ~4 мм в 40 км (**корень шума рельефа**) | custom interpolator `PC_PositionOS` (точная `positionOS` из вершины) | меню 401, `PatchPreciseObjectPos` — 19 графов |
| штатный Normal From Height: производная мировой позиции, выбросы, NaN, обратная TBN | `PC_NormalFromHeightPrecise` (object-space производные, наклон ≤ ~27°, NaN → 0, перевод в TS транспонированием) | меню 400, `PatchAndVerify` — 17 графов |
| EdgeDetection (`UseNormalEdges`) рисует контур по рельефу → чёрные точки | в проходах DepthNormals функция отдаёт нормаль без рельефа | `ProceduralBumpPrecise.hlsl` |
| кровли — одиночные тонкие грани | граф `Tiles` → `Render Face = Both` (только `Tiles`) | шаг 2b |

Пропатчены: `Bark`, `Brick`, `Bronze`*, `Cobble`, `Concrete`, `Fabric`, `Foliage`, `Glass`, `IronRust`, `Lantern`, `Lava`,
`Lava_animated`, `Marble`, `Parquet`, `Plastic`, `Plate`, `Steel_v2`*, `Tiles`, `Wood` (* — только `PC_PositionOS`, своего
Normal From Height нет). Не тронуты: `BronzeEdgeNoise_forTEST` (frozen), `BronzeEdgeNoise` (архив), `Fabric_v2`
(не используется), `Terrain` (пользователь), `Steel`, `Steel/test`. Новые графы собирать сразу с `PC_PositionOS` и
`PC_NormalFromHeightPrecise`.

### 2.3 HLSL узоров: полоса пропускания (антиалиасинг мелких деталей)

Слой, чей период меньше нескольких пикселей, плавно сводится к среднему; гребни ridged-шума скруглены.

| HLSL | Пороги (периода на пиксель) | Статус |
|---|---|---|
| `ProceduralCobbleNoise.hlsl` (`PCCobble_Band`, автор — пользователь) | 0.22 / 0.55 | принято |
| `ProceduralConcreteNoise.hlsl` | 0.22 / 0.55 | шума нет; виден только crack bump (см. §5) |
| `ProceduralWoodNoise.hlsl` | 0.08 / 0.25 (+ непрерывные кольца) | принято |
| `ProceduralGlassNoise.hlsl` | 0.08 / 0.25 | визуал `NOT RUN` |

Строгие 0.08/0.25 ставились до находки настоящей причины (2p); рекомендуется после визуальной проверки
выровнять Wood/Glass на 0.22/0.55. Сигнатуры CF-функций при всех правках не менялись (T-BRONZE01).

### 2.4 Правила материалов

* Одна форма на семейство `M_PC_<Family>`, цвет — Material Variant `M_PC_<Family>_<Color>`.
* **Нецветовые настройки — на базе**, варианты наследуют. Исключения, оставленные намеренно:
  `M_PC_IronRust_Lead` (`_Rust_Amount` 0 — свинец) и `M_PC_Wood_White` (пользователь: краска без волокна/пор —
  `_Grain_*`, `_Pores_Amount`, `_Ring_Amount`, `_Rings_*`). Настройки, сделанные пользователем на варианте, переносятся
  в базу (шаг 2m: Cobble_Beige → `M_PC_Cobble`, Glass_Green → `M_PC_Glass`).
* Настройка размера: бамп без шума виден, пока период детали ≥ ~4.5 пикс → для дистанции D м `*_Scale` ≲ **160 / D**
  (для Wood/Glass с 0.08/0.25 — ≈ 60 / D). У `Wood` сила Normal From Height = 1 (у большинства 0.01) —
  рабочий `*_Bump` дерева в 100 раз меньше.
