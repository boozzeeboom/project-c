# T-LIGHT01 — тени: причина «прыгающих гигантских квадратов» и исправление конфига

**Дата:** 2026-10-31 · **Проект:** `C:\Projects\ProjectC_client` · Unity `6000.5.2f1`, URP `17.5.0`
**Жалоба:** «тени вблизи прыгают и ужасные; тень персонажа — гигантские прыгающие квадраты; так было
до всей оптимизации, с момента первого включения глобального света».
**Статус:** причина найдена и устранена в конфиге пайплайна. **Визуально принято пользователем**
2026-10-31 — «тени стали хорошие, визуально всё хорошо» (Play Mode, пп. 1–4 §5). Первый замер
после правки — §7: цена исправления ≈ +75 DC на ближнем ракурсе, тени не подорожали заметно.

---

## 1. Причина — не размеры объектов и не оптимизация

Раньше предполагалось, что «тени от домов плохие из-за разницы размеров объектов». Это неверно.
Дело в разрешении теневой карты на метр сцены, и оно одинаково плохое для всего: и для домов,
и для персонажа.

Фактические настройки `Assets/_Project/Settings/ProjectC_URP.asset` (активный пайплайн,
подтверждено `GraphicsSettings.currentRenderPipeline`):

| Параметр | Было | Следствие |
|---|---:|---|
| `m_ShadowDistance` | **1000** | ближний каскад покрывал 0…250 м |
| `m_ShadowCascadeCount` | **2** | на карте 2048×2048 → тайл каскада **1024** px |
| `m_Cascade2Split` | **0.25** | каскад 0 = 0…250 м |
| `m_CascadeBorder` | **0.2** | каскад дополнительно расширен на 20 % |
| `m_MainLightShadowmapResolution` | 2048 | 2048 / 2 каскада = 1024 px на каскад |
| `m_SoftShadowsSupported` | **0** | мягкие тени выключены глобально |
| `Sun.shadows` (сцена) | **Soft** | свет просит мягкие, пайплайн их не умеет → жёсткие |

Размер тайла считается самим URP: `ShadowUtils.GetMaxTileResolutionInAtlas(2048, 2048, 2) = 1024`
(`Library/PackageCache/com.unity.render-pipelines.universal@748d7458cc62/Runtime/UniversalRenderPipeline.cs:2017`).
Мягкие тени включаются только если их разрешает ассет:
`shadowData.supportsSoftShadows = urpAsset.supportsSoftShadows && …` (там же, строка 1992).

### Сколько это в сантиметрах

Каскад 0 покрывал **0…250 м**. Камерный срез такой глубины (FOV 60, 16:9, near 0.1) описывается
сферой диаметром ≈ **589 м**, и она раскладывается на **1024** текселя:

```
589 м / 1024 = 57.5 см на тексель  ← было
```

Тень человека шириной 0.4–0.6 м занимает **1 тексель**. Отсюда ровно то, что видно: гигантские
квадраты, которые дискретно перескакивают на пол-метра при движении персонажа или камеры
(«прыгают»). Дома выглядят так же, только их квадраты крупнее по площади.

## 2. Что исправлено (`ProjectC_URP.asset`)

| Параметр | Стало | Почему |
|---|---:|---|
| `m_ShadowDistance` | **400** | heavy-корабль 325 м длиной: при 250 м его тень обрезалась бы на полкорпуса при съёмке с 200 м |
| `m_ShadowCascadeCount` | **4** | ближний каскад становится узким, остальное достаётся дальним |
| `m_Cascade4Split` | `{0.04, 0.1, 0.3}` | каскады 0…16 / 40 / 120 / 400 м |
| `m_CascadeBorder` | **0.1** | меньше расширение каскада — плотнее тексели |
| `m_SoftShadowsSupported` | **1** | `Sun` просит Soft, теперь это работает (PCF вместо жёсткой кромки); `m_SoftShadowQuality` уже был 2 (High) |
| `m_MainLightShadowmapResolution` | 2048 (без изменений) | 4096 дал бы ещё мельче тексель, но вчетверо больше растровой работы теней |

Порядок величин после правки (та же формула, тайл 1024 px):

| Каскад | Глубина | Диаметр сферы | Тексель |
|---|---:|---:|---:|
| 0 | 0…16 м | 37.7 м | **3.7 см** |
| 1 | 16…40 м | 94.2 м | 9.2 см |
| 2 | 40…120 м | 282.6 м | 27.6 см |
| 3 | 120…400 м | 942.1 м | 92.0 см |

Ближняя тень стала плотнее в **15.5 раза** (57.5 → 3.7 см), плюс включены мягкие тени.
Персонаж и двери попадают в каскад 0/1 — там теперь 4–9 см на тексель вместо 58.

## 3. Чем это платится

- **Дальше 400 м падающих теней больше нет вообще.** Вместо блочных теней на 600–1000 м — их
  отсутствие. Это осознанный выбор: блоки на такой дистанции читаются как артефакт.
- **4 каскада вместо 2** = вчетверо больше теневых слайсов, плюс мягкие тени. Пиксельная работа
  теней выросла (4 × 1024² = 4.2 Мпикс против 2 × 1024² = 2.1 Мпикс), мягкие тени добавляют выборок.
  Ожидается рост стоимости теневого прохода; DC при этом должен **упасть** — кастеры дальше 400 м
  больше не рисуются в теневую карту.
- **Ночью теней нет by design:** в сцене два directional-света, `Sun` (Soft) и `Moon`
  (`shadows = None`). URP держит только один main light, а `m_AdditionalLightShadowsSupported = 0`,
  поэтому ночные тени не появятся, пока у `Moon` не включат тени и он не станет main.
  Это отдельное решение, здесь не менялось.

## 4. Что это ломает в измерениях (важно для T-CULL01)

Все замеры DC, сделанные при `shadowDistance = 1000`, **несравнимы** с новыми:

- Stage 0/2 baseline (`P1 27 131 → 6 094 DC`) и Stage 3 (`LOD0 1538 / LOD1 235 / LOD2 104` на
  80/400/1200 м) сняты со старым тенями — их надо перемерить, прежде чем ссылаться на них.
- Опора проекции Stage 3c (`1538 DC = 555 слотов + 983 теневых draw при 593 кастерах`) становится
  недействительной: при дистанции теней 400 м состав теневого прохода другой.
- `ShipShadowBudget` (Stage 3c) остаётся осмысленным — он гасит тени мелочи дальше 150 м, а такие
  части теперь всё равно были бы в теневой карте до 400 м — но его выигрыш нужно перемерить,
  и, возможно, пере-подобрать порог `smallPartMaxAxis`.

## 5. Как проверить (выполнено пользователем 2026-10-31)

1. Тень персонажа на 3 / 10 / 30 м — не должна быть квадратами и не должна «прыгать».
2. Тени дверей и мелких деталей города вблизи — кромка мягкая, без лестницы.
3. Heavy-корабль с ~200 м — тень целиком (не обрезана по корпусу).
4. Ночь — теней нет (ожидаемо, см. §3).
5. Бюджет DC: `Project C → Culling → Stage 3 Ship Bench → Run`; замер теперь **не входит в Play Mode
   сам** — сначала Run (взводит), затем обычный старт игры через `Play → «Одиночная игра»`.

**Результат:** пп. 1–4 приняты пользователем («тени стали хорошие»), п. 5 выполнен — см. §7.
