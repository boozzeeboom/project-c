# Polybrush — анализ: НЕ ставить (решение)

Date: 2026-10-04. Статус: ANALYSED, вердикт — отказ. Ничего не ставилось.

## Вердикт коротко

Polybrush — инструмент художника, не агента. И на нашей версии Unity его
вообще нельзя ставить: **пакет deprecated и не поддерживается в Unity 6.3+**
(docs.unity3d.com, `com.unity.polybrush@1.2`), а у нас **6000.5.2f1**
(то есть Unity 6.5). Установка = заведомо unsupported-зависимость.

## Почему агент им пользоваться не может

- Polybrush — это интерактивные кисти в Scene view
  (`Tools → Polybrush → окно → мазки рукой`). Режима «запечь маски по правилу»
  у него нет, API мазков для автоматизации — нет, MCP-тула для него — нет.
- Гнать через него vertex colors программно = писать свой код поверх
  deprecated-пакета вместо того, чтобы писать тот же код без него.

## Чем закрываем ту же задачу (маски R/G/B) — всё доступно агенту

1. **Blender MCP (уже подключён):** bake Pointiness/AO → vertex colors,
   экспорт FBX. Первичный массовый bake — делает агент. Осталось
   провалидировать в спайке `TODO-BAKE`.
2. **Unity MCP `manage_probuilder` → `set_face_color`:** ProBuilder 6.1.2
   уже стоит, тул умеет красить vertex colors по фейсам. Докраска
   простых форм и тестовых мешей — делает агент, без новых пакетов.
3. **Свой Editor-скрипт (план):** проход по мешу (двугранные углы →
   вогнутость/выпуклость, normal.y → верх, шум → рваность) → запись
   `Mesh.colors` по договору каналов. Полностью автоматический bake
   для всего процедурного контента. Пишется за один заход, когда
   закроем визуал v1.

## Итог

Ручная докраска «художником-человеком» в проекте сейчас не предусмотрена —
все пути закрываются агентом (Blender-bake + ProBuilder + свой скрипт).
Polybrush не ставить, вопрос закрыт. Если позже появится человек-художник
и попросит кисти — пересмотреть (но и тогда смотреть замену, не deprecated).

## Зачем

Красить маски R/G/B (стык/кромка/вариация) прямо в редакторе на уже
импортированных мешах — без похода в Blender за каждой докраской шва.
Для пайплайна SteelRust это главный ускоритель итераций художника.

## Что это

`com.unity.polybrush` — бесплатный официальный пакет Unity (ProBuilder team).
Кисти vertex colors + sculpt на мешах в сцене. URP-независим (работает
с данными меша, не с рендером). Совместим с Unity 6 (ветка 2.x).

## План установки (после твоего «да»)

1. `Window → Package Manager → + → Add package by name`:
   `com.unity.polybrush`, версия latest 2.x (уточнить в окне PM).
   Альтернатива — git URL при отсутствии в списке (проверить по факту).
2. Проверка: Console → 0 errors; `Tools → Polybrush → Polybrush Window`
   открывается; тестовая покраска вертексов на примитиве.
3. В доках `docs/Materials/README.md` обновить §3: Polybrush — основной
   инструмент докраски; Blender-bake остаётся для первичного AO/Pointiness.
4. HARD RULES: `Packages/manifest.json` меняется только пакетным менеджером
   под твоим наблюдением; агент сам не ставит — по запросу выполню через
   MCP `manage_packages` с твоего явного одобрения и сразу проверю консоль.

## Риски (низкие)

- Новый пакет = +время импорта, +зависимости. Polybrush лёгкий, тянет только
  ProBuilder-зависимости (ProBuilder 6.1.2 уже стоит).
- Вертексные правки мешей в сцене — это правки префабов/сцен, под FO-правилами
  §3.1 (простой контент, каталог не нужен, пока нет новых NetworkObject).

## Если откажешься

v1 живёт без него: первичный bake R/G в Blender + ручная доводка через
перезапечку. Медленнее на итерациях, но рабочий цикл замкнут.
