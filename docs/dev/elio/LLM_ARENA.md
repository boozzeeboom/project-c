# Эльо — LLM Arena: могут ли разные модели OpenCode играть друг против друга

> Дата: 2026-11-08. Проверка: OpenCode Desktop 1.15.11, 69 chat-моделей в каталоге. Тест `subagent` с `model=opencode/iceman-free` — успешно.
> Фактический оркестратор турнира/дуэли — `opencode-cli api` (Desktop API) + отдельные сессии; `subagent` проверен, но для длинных матчей не использовался.

---

## 0. Ответ

**Да, можем.** В OpenCode Desktop есть штатный механизм: `subagent` с параметром `model` (provider/model). Тест прошёл: субагент на `opencode/iceman-free` вернул `OK`. Значит, каждая фракция может управляться своей моделью, а движок Эльо будет рефери.

`opencode run --model ...` из CLI **не сработал** в этом окружении: `Unexpected server error` (похоже, CLI не может поднять/подцепить сервер рядом с работающим Desktop). Обходной путь — `subagent` (нативный) или прямой API.

## 2. Архитектура матча

### Вариант A — субагенты (рекомендуется, проверен)

- 3 постоянные сессии: `Plus`, `Minus`, `Zero`, каждая со своей моделью.
- На каждом ходу оркестратор (главный агент) шлёт в сессию:
  - краткий state (доска, фигуры, поддержки, «Ц», hold, режим, moveNumber);
  - список **легальных действий** (move / support / skip) из движка;
  - требование: ответить **только JSON**.
- Ответ валидируется движком; при ошибке — ретрай с текстом ошибки (до 2 раз).
- Ход применяется, лог пишется, сессия получает следующий state.

**Плюсы:** работает в Desktop; модель на фракцию; сессии сохраняют контекст.
**Минусы:** каждое действие — отдельный вызов (латентность, токены); агент может «шуметь» инструментами; лимиты free-моделей.

### Вариант B — CLI `opencode run`

- `opencode run --model provider/model --format json "..."` — не работает в текущем окружении (`Unexpected server error`).
- Можно попробовать `--attach http://localhost:<port>` к серверу Desktop; порт надо найти. Не проверено.

### Вариант C — прямой API

- Использовать API-ключи провайдеров (OpenAI-совместимые endpoint’ы), слать state, парсить JSON.
- Максимальный контроль и скорость, но нужна настройка ключей/endpoint’ов.

**Рекомендация:** начать с A (1 игра, 3 бесплатные модели), затем при необходимости — C для турнира. **Фактически** турнир и дуэль сыграны через Desktop API + отдельные сессии (см. §6–§9).

## 3. Формат хода

```json
{"kind":"move","pieceId":"P-D7","to":{"q":2,"r":-2}}
{"kind":"support","zeroId":"Z-F27","targetId":"Z-C25"}
{"kind":"skip"}
```

Оркестратор даёт модели **список легальных** действий, чтобы она не изобретала нелегальные. Если модель ответила не-JSON или нелегально — ретрай с сообщением об ошибке.

### State для промпта (компактно)

```
Режим: Цикл + Основной. Ход 12. Ходят: Минусы.
Ц: Z-F27 (Нули, hold Z=1). Hold: P0/M0/Z1.
Твои фигуры: M-L11 A5 (-5,5) line; M-H12 B4 (-4,4) heavy; ...
Поддержки: Z-F28 -> P-D7; ...
Легальные действия:
- move M-H12 -> (-2,2)
- move M-F20 -> (-2,1)
- support ...
Выбери одно действие. Ответ — только JSON.
```

## 4. Ограничения и риски

1. **Стоимость/латентность:** 30–90 ходов × 3 модели = 90–270 вызовов; на бесплатных моделях — лимиты, на платных — деньги.
2. **Формат:** LLM может ответить текстом, а не JSON; нужен ретрай.
3. **Понимание поля:** гексагональная геометрия сложна; давать координаты и легальные ходы.
4. **Контекст:** не пихать всю историю; только текущий state + краткие правила.
5. **Инструменты:** `general`-агент имеет инструменты; просить «no tools, only JSON» или использовать агент без инструментов.
6. **Free limit:** мы уже ловили «Free usage limit reached» на субагентах; для турнира нужен запас лимита/платный план.

## 6. Результаты первых матчей (v1.3, Стрелка + Длинный, лимит 30)

### 6.1. 3 LLM сражаются (ротация)

| Матч | Расклад | Победитель | Причина | Ходов |
|---|---|---|---|---|
| 1 | DeepSeek=П, Beam=М, GLM=Н | **Плюсы (DeepSeek)** | hold | 14 |
| 2 | DeepSeek=М, Beam=Н, GLM=П | **Плюсы (GLM)** | hold | 23 |
| 3 | DeepSeek=Н, Beam=П, GLM=М | **Плюсы (Beam)** | hold | 28 |

- **Плюсы выиграли все 3 матча** — каждая модель по разу, когда играла за Плюсов.
- Модели **неразличимы** по силе в этом сэмпле: 1 победа у каждой, все — за Плюсов.
- Все победы — удержанием «Ц»; **0 убийств Линейного**.
- Логи показывают **shallow play**: Линкор/Бомбардир ходят туда-обратно, нули повторяют один и тот же support, короля не атакуют, центр занимают «случайно».
- Вывод: **фракция (Плюсы, первый ход) важнее модели**; 3 матчей мало, чтобы ранжировать LLM.

### 6.2. AI vs LLM (гибрид)

- Матч: **Плюсы = встроенный ИИ**, Минусы = DeepSeek, Нули = GLM.
- Результат: **ничья на лимите 30** (Ц пуст). Встроенный ИИ не смог удержать центр; LLM-фракции не дали ему выиграть.
- Это не доказывает, что LLM сильнее: один матч, лимит 30, ИИ играл за Плюсов. Но и не показывает превосходства ИИ.

### 6.3. Что это значит

- LLM-арена **технически работает** (низкий reasoning-вариант + лимит 30 + короткий промпт).
- Но как инструмент ранжирования моделей она **пока слаба**: доминирует фракция/первый ход, а не модель.
- Чтобы честно сравнить модели, нужно:
  1. **Фиксировать фракцию** и играть много матчей (например, 5 матчей только за Плюсов, 5 — только за Минусов, 5 — только за Нулей).
  2. **Убрать первый ход** из преимущества: стартовать со случайной фракции или давать компенсацию.
  3. **Улучшить промпт**: короткие правила, топ-12 действий, запрет «ходить туда-обратно», явная цель «убить Линейного или удержать Ц».
  4. **Лимит 45–60**, чтобы партии были содержательнее.
- Встроенный ИИ тоже не «гений»: в гибриде он не обыграл LLM. Это ещё один аргумент, что **правила/фракции** важнее интеллекта игрока.

### 6.4. Анализ ходов LLM (3 матча, 65 действий)

Логи трёх LLM-матчей лежат в `elio_arena_results.json` (файл `elio_arena_match1.json` позже перезаписан гибридом).

| Метрика | Значение |
|---|---:|
| Действий всего | 65 |
| Ходов | 54 |
| Поддержек | 11 |
| **Пустых поддержек** (повтор той же цели) | **7 / 11 = 64 %** |
| **Осцилляций** (фигура возвращается на прошлую клетку) | **7 / 54 = 13 %** |

| Ходов на ворота/«Ц» | 14 / 54 = 26 % |

**Примеры:**

- DeepSeek (Минусы), Линкор `M-B12`: `MZ-1 → M-A1 → MZ-1` — ход туда-обратно.
- GLM (Минусы), Линкор `M-B12`: `Z-B1 → Z-C1 → Z-B1` — дважды.
- Beam (Плюсы), `P-B2` и `P-L1`: `P-B4 → P-C1 → P-B4` — фигуры меняются местами.

**Вывод:** LLM понимают формат JSON и легальность, но играют **поверхностно**: повторяют поддержки, гоняют одну фигуру, почти не создают угроз королю. Это не «плохие правила» — это ограничение модели в пространственном планировании.

## 8. Что исправлено в ИИ и балансе

По итогам LLM-матчей в ИИ v1.3c внесены три правки:

1. **Запрет пустых поддержек** — повтор той же цели больше не рассматривается.
2. **Анти-осцилляция** — ход, возвращающий фигуру на прошлую клетку, получает штраф (кроме взятия, «Ц» и ворот).
3. **Длинный режим: не бросать накопленный «Ц»** — при hold ≥ 1 ИИ не снимает фигуру с центра ради убийства Линейного.

**Качество ходов (Стрелка + Длинный; v1.3 — 100 партий, v1.3c — 400):**

| Метрика | AI v1.3 | AI v1.3c |
|---|---:|---:|
| Пустые поддержки | 4.6 % | **0 %** |
| Осцилляции | 5.0 % | **2.0 %** |
| Повтор одной фигуры | 22.2 % | 22.7 % |

Ничьи в Длинном режиме: 7/400 (1.8 %) — следствие фикса инертного «Ц» (центр может быть заблокирован инертной фигурой), а не правок ИИ.

**Баланс (400 партий, два seed’а, после фикса инертного «Ц»):**

| Первый ход | Плюсы | Минусы | Нули | Ср. длина |
|---|---:|---:|---:|---:|
| Фиксированные Плюсы (отклонено) | 39.2 | 34.0 | 25.4 | 38.8 |
| **Случайный (принято)** | **35.9** | **33.4** | **29.3** | 37.7 |

- Главный фикс — **инертный «Ц»**: выбывшая фракция больше не удерживает центр и не приносит победу по лимиту.
- После фикса «Плюсы первые» дают лучший баланс; случайный первый ход проверен и **отклонён**.
- В «Цикле» первый ход по-прежнему у Плюсов — это историческое правило; цикл остаётся учебным.
- Внедрено в `elio_engine.js`: `occupantAt` игнорирует инертные фигуры.

### 9.3. Почему ИИ выиграл

| Метрика за 3 партии | GLM | Встроенный ИИ |
|---|---:|---:|
| Действий | 34 | 76 |
| Взятий | 1 | 7 |
| Осцилляций | 3 | 1 |
| Повтор одной фигуры | 26 (76 %) | 16 (21 %) |
| Ходов на ворота/«Ц» | 6 | 18 |
| Center ticks | 2 | 20 |
| Max hold | 1 | 2 |

- **Центр — главная разница:** ИИ был на «Ц» в 20 полуходах, GLM — в 2. За Нулей GLM сделал 11 ходов, но **0 ходов на ворота и 0 center ticks** — он вообще не боролся за центр.
- GLM повторял одну фигуру в 76 % действий; ИИ — в 21 %.
- ИИ чаще брал фигуры (7 против 1) и лучше использовал поддержки (9 против 0).
- Это не единичная ошибка формата: GLM легально отыграл все 3 партии, но проиграл стратегически.

### 9.4. Вывод по дуэли

- **Встроенный ИИ v1.3c сильнее лучшей LLM** в этом регламенте: 3–0.
- LLM понимают JSON и правила, но не строят план на центр и повторяют одну фигуру.
- Это подтверждает: игра «глубокая» для эвристик, но современные LLM пока играют в неё поверхностно.
